# 공유 Mac 운영

같은 Mac에서 Unity·빌드·측정을 하는 모든 에이전트(Claude Code, Codex, Astra)가 따른다. 목적은 두 가지다.

- 밤 측정 대기열(C05 등)의 결과가 다른 작업 때문에 무효가 되지 않게 한다.
- 에이전트끼리 같은 Unity 프로젝트·작업 폴더를 동시에 건드리지 않게 한다.

이 문서의 경로에서 `$MV`는 `$HOME/orca/workspaces/bs-mobile/stack-move/artifacts/main-verify`다.

## 1. 잠금 파일

- **경로:** `$MV/agent-busy.lock`
- **내용:** 한 줄 `YYYY-MM-DD HH:MM:SS <작업 설명> (pid N)`.
- **잡는 때:**
  - Unity Editor를 띄우는 모든 작업: `tools/unity-tests.sh`, Mac 빌드, Editor 캡처.
  - 몇 분 넘게 CPU를 크게 쓰는 작업.
- **작성 권한:** `$MV` 안 잠금도 쓰기이므로 Claude Code 야간 측정 담당자만 생성·해제한다. 다른 에이전트는 잠금을 읽기만 하고 담당자의 잠금 조율이 끝나기 전 Unity·빌드를 시작하지 않는다. 아래 명령은 담당자 전용이며, 잠금 권한을 얻기 위해 `$MV` 쓰기 금지를 우회하지 않는다.
- **잡는 법(담당자):** 파일 만들기 자체로 잡는다. `noclobber`로 이미 있으면 실패하게 해서, 두 에이전트가 동시에 잡지 못하게 한다. 실패하면 기다렸다가 다시 시도한다. 남의 잠금은 지우지 않는다. 잡은 뒤에만 지우기 `trap`을 걸고, 끝날 때(실패해도) 지운다.

```bash
L="$MV/agent-busy.lock"
until ( set -o noclobber; echo "$(date '+%F %T') unity-tests feat/x (pid $$)" > "$L" ) 2>/dev/null; do sleep 30; done
trap 'rm -f "$L"' EXIT
while pgrep -x "Sow and Siege" > /dev/null; do sleep 15; done   # 측정 중인 앱이 끝나기를 기다림
./tools/unity-tests.sh
```

- **대기열과의 관계:** 측정 대기열은 이 파일이 있으면 다음 작업을 시작하지 않고 기다린다. 이미 진행 중인 측정은 멈추지 않는다. 그래서 잠금을 잡은 뒤에도 측정 앱(`Sow and Siege`)이 끝나기를 기다린 다음에 시작한다.
- **푸는 법(담당자):** 위 `trap`처럼 작업 프로세스가 끝나면 자동으로 지운다. 셸을 강제로 끊어 파일이 남았다면 담당자가 확인해 해제한다. 다른 에이전트는 남은 잠금을 지우지 않는다.

## 2. 밤 측정 시간대

- **23:00~07:00은 측정 대기열의 시간이다.**
  - 이 시간에는 Unity·빌드·무거운 작업을 하지 않는다.
  - 23:00 전에 끝나지 않을 Unity 작업은 시작하지 않는다. 관찰값으로 Unity 테스트 두 프로필은 10~30분, Mac 개발 빌드는 10~15분이 걸린다.
  - 시간대 안에서 꼭 필요하면 사용자 지시를 받고 잠금을 잡는다.
- 2026-10-24에 한 에이전트가 22시 후반에 잠금 없이 Unity 기록을 시작해 23:46까지 돌았다. 대기열의 첫 측정이 그 위에서 시작됐다. 잠금과 시작 시각 규칙은 이 사고 때문에 있다.
- **낮 예외:** `$MV/day-ok-until`에 끝 시각(epoch 초)이 있으면 낮에도 측정이 돈다. 이 파일은 사용자가 정할 때만 만든다.
- **01:00~06:00 삭제 금지:** 브랜치·파일·Release를 지우지 않는다. 머지 후 브랜치를 자동으로 지우는 squash 머지도 포함한다.

## 3. 측정 대기열이 쓰는 것 (건드리지 말 것)

- **`$MV` 폴더 전체는 정리 대상에서 항상 제외한다.** 쓰기·삭제는 Claude Code의 야간 측정 담당자만 한다. 다른 에이전트는 앱·로그·잠금 등을 모두 읽기만 한다. 사용자 대량 삭제 승인은 이 소유권 경계를 해제하지 않는다.
  - 보호 대상:
  - 대기열 스크립트: `run-queue.sh`, `run-night-*.sh`, `c05-lib.sh`, `idle-sampler.sh`, `run-estate-demo.sh` 등.
  - 결과: `$MV/c05/`, 로그 `$MV/c05/night.log`.
  - 측정용 앱 빌드: `base-*`, `decor-*`, `estate-demo-*`, `e35*-*` 같은 폴더.
- **`stack-move` 작업 폴더:** 측정 앱의 원본이다. checkout·reset·빌드하지 않는다.
- **실행 중인 프로세스:** `Sow and Siege` 앱, `caffeinate`, 대기열 셸은 종료하지 않는다.
- **다른 프로젝트·에이전트의 프로세스:** 종료하지 않는다. 예: `worldsim_probe`, `rustc`, `save_load`, 다른 Chrome·Unity 프로젝트. 측정 스크립트는 이 프로세스가 돌면 기다린다.

## 4. 작업 폴더 분리

- 에이전트마다 자기 git worktree에서 일한다. 다른 에이전트의 worktree에서 checkout·reset·clean·stash를 하지 않는다.
- **git stash는 모든 worktree가 공유한다.** 이름 없는 `git stash`·`git stash pop`을 쓰지 않는다. 필요하면 임시 커밋을 쓴다.
- **Unity 프로젝트 하나에는 Editor 하나만 연다.** 같은 worktree에서 Unity를 동시에 띄우지 않는다.
- **공유하는 Unity 기록용 worktree(예: `c05base-261`)를 쓸 때:**
  - 잠금을 잡는다.
  - 끝나면 원래 커밋으로 되돌린다.
  - Unity가 바꾼 추적 파일(예: 새 `.meta`)은 원복하거나, 자기 브랜치에 Unity가 쓴 형태로 커밋한다.
- 큰 산출물(빌드, 캡처, 녹화)은 자기 worktree의 `artifacts/`나 개인 임시 폴더에 둔다. `$MV`에 새 폴더를 만들지 않는다. 대기열에 넣을 앱은 Claude Code 야간 측정 담당자만 만든다.

## 5. Unity 기록

- `unity/`를 바꾸는 PR은 병합 전에 `./tools/unity-tests.sh`로 두 프로필(first-playable·wave-1a)의 EditMode·PlayMode를 모두 돌린다. 결과 블록은 PR 본문 `## Unity tests`에 붙인다([Unity 테스트 기록](unity-tests.md), ADR0068).
- PR 정책 검사는 다음을 확인한다.
  - 기록 커밋이 PR head의 조상이다.
  - 그 뒤 `unity/`가 바뀌지 않았다.
  - `unity/`를 다시 바꾸면 다시 기록한다.
- 실행 중에 Unity가 추적 파일을 바꾸면 그 기록은 무효다. Unity가 쓴 형태를 커밋하고 다시 돌린다.
- 기록은 잠금을 잡고, 밤 시간대 밖에서, 23:00 전에 끝날 때만 시작한다.

## 6. C05·캡처·녹화 조건

성능 측정, 자동 플레이 캡처, 녹화는 Mac이 쉬고 있을 때만 한다.

- **시작 조건:**
  - 사용자 입력이 일정 시간 없다. 녹화는 20분이다.
  - 다른 프로세스의 CPU가 100% 이하다.
  - 잠금·Unity Editor·blocker 프로세스가 없다.
- **무효 조건:** 측정 중에 다른 프로세스가 150%를 넘거나 사용자 입력이 있으면 그 실행은 무효다. 무효 실행은 지우지 않고 표시한 뒤 다시 돌린다.
- **계약과 절차:** 고정 C05 계약(`benchmarks/wave-c05/contract.json`)과 [밀도 벤치마크 런북](wave-density-benchmark.md)을 따른다.
- **기록:** 결과에 환경(커밋, 화면 크기, 무효 사유)을 남긴다. 특정 Mac의 통과를 모바일 성능으로 일반화하지 않는다.

## 7. 멈춤 조건

다음이면 작업을 멈추고 사용자에게 보고한다.

- 잠금 파일이 오래 남아 있는데 그 pid가 없다. 지우지 말고 보고한다.
- 밤 측정 중인데 무거운 작업이 꼭 필요하다.
- 내 작업 때문에 측정이 무효가 됐을 수 있다. 시각과 작업을 적어 보고한다.
- 같은 문제가 두 번 실패했다.
- Core 규칙이나 기존 리플레이·골든 해시를 바꿔야 한다.
- 다른 에이전트의 worktree·프로세스·대기열 파일을 건드려야만 진행할 수 있다.

## 8. 정리·삭제의 소유권과 사전 승인

2026-10-25 10:55 정리에서 다른 작업의 `$MV` 측정 앱 22개가 삭제됐다([#387](https://github.com/hyunlord/bs-mobile/issues/387)). Git 미추적·생성 파일·현재 미실행이라는 사실만으로 삭제 권한이나 불필요함을 판단하지 않는다.

1. 실행 전에 삭제 후보를 명시적 목록으로 만든다. **모든 항목**에 정확한 경로, 크기, 소유 작업(이슈/PR), 소유 에이전트, 현재 용도, 삭제 근거를 적는다. 소유자가 불명확하면 제외한다.
2. **자기 작업·에이전트 소유가 아닌 경로는 목록에 넣지 않는다.** 다른 에이전트의 worktree와 출력 폴더, `$MV` 전체는 항상 제외한다. 공통 상위 폴더의 glob·재귀 탐색으로 다른 소유자의 파일을 끌어들이지 않으며 실제 경로도 확인한다.
3. 진행 중인 PR 검증·비교 기준 앱·Release 배포·녹화·측정 대상은 보존한다. 최신 앱 하나가 다른 커밋·설정·프로필의 앱을 대체한다고 간주하지 않는다.
4. **10개 이상 또는 합계 5GiB 이상**이면 실행 전에 목록 요약(경로별 소유자·개수·크기·용도·보존 대상)을 사용자에게 보고하고, **그 목록에 대한 명시적 승인 후** 실행한다. 일반적인 “정리해 줘”는 대량 삭제 목록 승인이 아니다. 같은 정리의 명령·폴더·시도를 나누어 임계값을 피하지 않는다. 목록이나 범위가 늘어나면 다시 승인받는다.
5. 실행 직전에 소유권·진행 작업 사용 여부·승인 목록과의 일치를 재확인한다. `rm`, `git clean`, `find -delete`, `shutil.rmtree`, 빌드 출력 정리 등 수단과 무관하게 같은 규칙을 적용한다.
6. **01:00~06:00 삭제 금지**는 승인 여부와 관계없이 유지한다. 승인받은 정리도 이 시간에는 실행하지 않는다.

이 문서 보강 PR은 문서만 변경하며 사용자 승인 전 병합·자동 병합 예약을 하지 않는다. 앱 복구와 재빌드는 별도 담당 작업이다.
