# 판 밖 성장 저장·복구

대상: 2단계 A 로컬 계정. Fold7 실기 관문과 서버 권위는 별도다.

- Unity의 `Application.persistentDataPath` 아래 실제 경로는 `MetaProgression` 생성부를 확인한다. 개발 검증은 `MetaDirectoryOverride`로 격리하며 사용자 저장을 지우지 않는다.
- `progress.bin`은 현재 상태, `.bak`은 마지막 정상본, `.tmp`는 교체 전 완전 기록용이다. 버전·길이·체크섬·데이터 참조·상한을 모두 검사한다.
- `terminal.bin`은 정산 직전/직후 상태 의도다. 완료 정산 전에 기록하고 기본 저장 실패 후 재시작에서도 같은 결과를 한 번만 복구한다. 이미 반영된 이전 의도는 중복 지급하지 않는다.
- 미정산 판에 완료 의도가 없으면 재시작 시 포기로 종료한다. 완료 의도가 다른 상태를 가리키거나 진행보다 앞서면 자동 리셋하지 않는다.
- 현재본이 손상되면 검증 가능한 백업을 사용한다. 알 수 없는 더 최신 저장 버전은 하위 버전으로 덮어쓰지 않는다.

## 정산 저장 오류

1. 게임의 정산 재시도 화면을 유지하고 저장 공간·디렉터리 쓰기 가능 여부를 확인한다.
2. 같은 결과로 `정산 저장 다시 시도`를 실행한다. 새 판을 먼저 시작해 종료 결과를 포기로 대체하지 않는다.
3. 앱이 종료됐다면 다음 실행에서 미정산 순번과 의도의 직전 상태가 일치할 때 복구한다. 저널 기록 자체가 실패한 경우 디스크에 남기지 못한 완료 결과까지 복구했다고 주장하지 않는다.
4. 오류를 조사할 때 저장 원본·백업·의도 파일을 별도 안전한 로컬 위치에 보존한다. 사용자 승인 없이 삭제·초기화·다른 버전으로 덮어쓰지 않는다. 서버 동기화나 클라우드 백업은 설치하지 않았다.

## 검증 범위

호스트 테스트는 실제 임시 디렉터리에 쓰기 장애를 만들어 완료 의도 복구, 이미 반영된 의도의 중복 방지, 새 미완료 판에 대한 옛 의도 거절, 저널 기록 실패 시 미반영을 검증한다. Unity PlayMode는 종료 결과 저장 실패와 같은 화면의 재시도를 검사한다. 격리된 강화·성장 시각 fixture는 정상 플레이로 얻은 계정이라고 보고하지 않는다.
