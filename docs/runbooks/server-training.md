# 서버 병영 훈련

상태: 구현 초안, 2026-10-30. [#583](https://github.com/hyunlord/bs-mobile/issues/583),
[GDD15](../design/gdd/15-slg-troops-proposal.md)의 훈련 범위만 구현한다.
병종 비용·시간·상한은 [opt-in 가설 데이터](../../data/opt-in/slg-training-v1.json)이며 #126 확정 경제값이 아니다.

## 계약

- 공통 `POST /v1/account/commands` 봉투의 `domain`은 `training`이다.
- `operation: start`, `payload: {"unitId":"slg:levy","count":1}`은 완공 병영·해금·대기 칸·총 점유량·재화를 검사한다.
- `operation: cancel-waiting`, `payload: {"jobId":"대기 작업 UUID"}`는 대기 묶음만 취소한다. 작업 ID는 시작 명령 ID다.
- `GET /v1/account`와 다른 계정 명령도 같은 단일 writer에서 먼저 훈련을 정산한다. 클라이언트의 완료/재접속 요청으로 병사를 추가하지 않는다.
- 실제 차감 비용은 예약 때 저장한다. 대기 작업의 속도·시각은 활성으로 넘어가는 때 고정한다. 활성 종료 시각부터 다음 작업을 시작하며, 긴 미접속이면 두 작업이 같은 정산에서 완료될 수 있다.
- 현재 승인·연결된 속도 효과 공급원은 없으므로 서버 보너스는 0이다. 클라이언트 `bonusPermille` 필드는 거부한다. 향후 효과는 서버만 계산한다.
- 시간 계산은 GDD15의 초 단위 `ceil(baseSeconds × 1000 / (1000 + min(bonus, cap)))`를 한 번 적용한 뒤 UTC 밀리초로 환산한다. 예: 20초, 30%이면 16초다. 생산 보관 상한으로 훈련 경과를 잘라내지 않는다.
- `R/D/W/Q`는 각각 준비/출전/부상/예약이다. 이번 단계는 예약·완료·취소만 변경하고 출정·치료·병력 판매·월드 전투는 추가하지 않는다.

## 미정 경계

대기 중 생산을 받아 지갑이 가득 찬 뒤 취소하는 경우의 전액 환불 보관 정책은 사용자 결정 대기다.
초과액을 버리거나 기존 지갑 상한을 넘겨 지급하지 않는다. 해당 경계는 `refund-policy-pending`으로 실패하고 비용·예약을 보존한다.
이 미정 정책을 해결하기 전 훈련 전체를 완료/출시 가능으로 보고하지 않는다.

## 화면 계약

`domains.training`은 병영 단계, 상한, 묶음 상한, 총 점유량, 서버 UTC와 병종별 네 수량을 반환한다.
비용은 `[{materialId,amount}]` 배열이며 Unity에 새 JSON 의존성을 요구하지 않는다.
활성 작업에는 시작/완료 UTC가 있고 대기 작업에는 없다. 대기의 시간은 기본 시간이며 실제 활성 시점의 속도로 다시 고정한다.
`TrainingHandler.View`는 최종 계정 상태를 읽기만 하므로, 같은 명령으로 병영이 완공된 뒤에도 이전 단계 표시를 반환하지 않는다.

## 검증

`server/tests/SowSiege.Server.Tests/TrainingTests.cs`는 단계·병종·수량·재화·상한·대기 칸, 정확한 완료 경계,
긴 미접속의 연속 완료, 실제 차감액 환불, 수량 보존, 잘못된 payload와 저장 예약 불일치를 검사한다.
HTTP 재전송·계정 행 잠금·원자 DB 저장은 공통 서버 검사와 실제 계정 훈련 흐름에서 별도로 확인한다.
단위 테스트의 완공/재화 fixture는 정상 플레이 지급 경로가 아니며 실제 HTTP 검증에서는 기존 건설·생산 명령으로 진행한다.
