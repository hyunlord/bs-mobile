# ADR 0057: 병합과 업로드가 끝난 로컬 산출물을 지운다

- 상태: 승인 — #249의 사용자 운영 요청을 적용, Release·저장소 이력의 보존 규칙은 바꾸지 않음
- 날짜: 2026-10-12
- 관련: [#249](https://github.com/hyunlord/bs-mobile/issues/249), AGENTS.md 「금지와 증거」

## 맥락

2026-10-12 13:58 KST 측정에서 Mac 데이터 볼륨의 남은 공간은 60GiB(97% 사용)였다. bs-mobile·lattice worktree 135개(일부는 병합 PR), `~/bs-mobile/artifacts` 63GB(이 중 mp4로 만든 뒤 남은 프레임 JPG/PNG 41GB), `/private/tmp` 221GB(lattice 측정 임시 123GB 포함), `$TMPDIR` 29GB가 남아 있었다. Release에 이미 올라간 Mac 빌드 ZIP·영상의 로컬 사본도 그대로였다. 기존 계약은 무엇을 올리고 보존하는지만 정했고, 로컬 사본을 언제 지우는지는 정하지 않았다.

## 결정

AGENTS.md에 「운영: 로컬 산출물과 디스크」 절을 둔다.

- PR이 병합되면 그 PR의 worktree와 로컬 산출물을 지운다. 커밋하지 않은 변경이나 원격에 없는 커밋이 있으면 지우지 않고 보고한다.
- 검토용 Mac 빌드는 로컬에 최신 2개만 남긴다. 나머지는 Release에서 받는다. 진행 중인 측정이 고정한 빌드는 개수와 별도로 보존한다.
- 영상은 mp4로 만든 직후 중간 프레임 PNG·JPG를 지운다.
- 증거 원본은 Release나 저장소에 올라간 것을 확인한 뒤 로컬에서 지운다. 올리지 않는 원자료는 표 결과가 저장소에 남아 있는지 확인한 뒤 지운다.
- 작업을 끝낼 때마다 보고 끝에 이번 작업으로 늘어난 용량과 정리한 용량을 한 줄로 적는다.
- 남은 디스크 공간이 50GB 아래면 새 빌드나 측정을 시작하기 전에 먼저 정리를 제안한다.

대상 목록을 만들고 사용자 승인 뒤에 지우는 것은 한 번의 정리 작업 절차다. 위의 병합 후 정리는 그 작업의 담당 에이전트가 수행한다.

## 결과·비용

재생성 가능한 Unity `Library/` 등을 지우면 다시 열 때 재임포트 시간이 든다. Release에 없는 로컬 빌드가 필요하면 다시 빌드해야 한다. Unity Hub·에디터·라이선스, 열린 PR의 worktree, 예약된 측정의 빌드·도구, 사용자 개인 파일, Charter & Kin 저장소는 이 규칙의 삭제 대상이 아니다.

## 거절한 대안

- 자동 정리 스크립트: 병렬 에이전트의 작업 중 산출물과 고정 빌드를 경로만으로 구별할 수 없다. 이번에는 절차 규칙만 둔다.
- Release·과거 ZIP 정리: 「금지와 증거」의 역사 보존 규칙과 충돌하므로 범위 밖이다. 이 결정은 로컬 사본에만 적용한다.

## 검증

문서 계약 변경이다. `node tools/check-docs.mjs`와 docs-only CI로 링크와 형식을 확인한다. 실제 정리량은 #249 보고에 전·후 표로 남긴다.
