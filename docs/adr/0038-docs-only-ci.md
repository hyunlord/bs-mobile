# ADR0038: 문서 전용 PR의 검사 범위

- 상태: #140 사용자 요청에 따른 결정, 보호된 PR 병합으로 적용
- 날짜: 2026-10-10
- 근거: [#140](https://github.com/hyunlord/bs-mobile/issues/140)

## 결정

PR의 merge-base부터 정확한 head SHA까지 모든 변경 경로가 `docs/` 아래일 때만 문서 관문을 선택한다. Git의 NUL 구분 name-status 출력으로 추가·수정·삭제와 이름 변경의 원본/목적지 경로를 모두 판정한다. 코드가 문서 경로로 이동해도 전체 관문이다. 빈 diff, 알 수 없는 상태, 누락 SHA, 비교 실패는 전체 관문으로 보수적으로 처리한다. `main` push와 수동/의존성 dispatch는 기존 전체 관문을 유지한다.

`quality`와 `secrets` 필수 job 이름을 유지하며 workflow 수준 `paths-ignore`를 사용하지 않는다. 따라서 문서 PR도 보호 규칙의 결과를 게시한다. `quality` 내부에서 문서 관문 또는 전체 관문을 선택하고 비밀 검사는 양쪽에 남긴다. 문서 관문에는 .NET 설치·테스트·결정론 교차 검증·리그를 실행하지 않는다. 전체 관문에서는 범위 판정의 회귀 검사도 실행한다. 새 의존성은 추가하지 않는다.

## 문서 관문

기존 PR 정책(이슈·템플릿·ADR·주석 규약)과 저장소 용량 검사를 재사용한다. 추가·변경·이동된 Markdown은 마지막 개행, 충돌 표식, 본문 inline/reference 링크의 로컬 파일 존재를 검사한다. 삭제된 Markdown은 읽지 않는다. 코드 블록·인라인 코드·외부 URL·앵커의 유효성은 검사하지 않는다. 이 검사는 전체 CommonMark 파서나 외부 링크 가용성 검사, 문서 내용의 사실 검증을 대신하지 않는다. 삭제 파일을 가리키는 변경되지 않은 문서의 링크는 이번 집중 검사 범위 밖이다.

문서 전용 PR은 런타임 증거 파일을 생성하지 않으므로 기존 런타임 artifact 업로드를 생략한다. 관문 실패 로그는 종류별로 보존한다. 문서가 읽힌다는 사실을 게임 기능·성능 검증으로 보고하지 않는다.

## 로컬 검증과 운영 증거

로컬은 변경에 맞는 집중 검사만 실행하며 CI와 같은 전체 런타임 검사를 중복 실행하지 않는다. 문서 CLI는 `node tools/check-docs.mjs`이며 커밋된 `origin/main...HEAD`를 비교한다. CI에서는 이벤트의 정확한 base/head를 쓴다. 커밋 전 편집 내용은 Git diff와 별도 읽기로 확인한다.

이 변경 PR은 CI/도구 변경이므로 전체 CI가 필수다. 병합 이후 별도의 실제 `docs/` 전용 PR에서 `Document gate` 성공, `.NET setup`·`Full gate`·런타임 artifact 업로드 생략, `quality`·`secrets` 성공을 확인한다. 집중 테스트는 혼합 변경·이름 변경·삭제·불확실한 입력을 검사하며 이 실제 CI 증거를 대신하지 않는다.

## 대안

workflow 전체를 경로로 생략하는 방법은 필수 결과가 대기 상태로 남을 수 있어 채택하지 않았다. 코드 경로 일부만 열거하는 allowlist는 새 실행 경로를 놓칠 수 있어 채택하지 않았다. `docs/`만 예외로 두고 나머지는 기존 관문을 유지한다.
