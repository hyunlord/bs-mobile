# ADR 0049: 밀집 적의 몸을 결정론적으로 분리한다

- 상태: 승인된 사용자 설계 변경의 구현 (#204)
- 날짜: 2026-10-10
- 대체하지 않는 것: ADR0044~0046의 역사 C05, #126 수치·밸런스 보류, #98 실기 보류

## 결정

`WaveRuntimeDefinition.enemySeparation`이 있는 카탈로그만 정수 좌표 기반 분리를 실행한다. `version: 1`은 거리 계산·ID 순서·경계 처리·잔여 겹침 배치의 알고리즘 계약이다. Core에 영웅·영지·적 콘텐츠 ID를 박지 않는다. 기존 체력·이동 속도·공격 거리·피해·경험치·스폰 값은 변경하지 않는다. 이 변경은 적 위치와 전투 결과를 바꾸는 **설계 변경**이며 수치 보정이나 단순 시각 변경으로 보고하지 않는다.

`bodyWidths`는 기존 적 idle 그림의 최종 가로 너비를 Core 좌표로 올림한 값이다. 출처는 `unity/Assets/Art/wave1a-manifest.json`의 binding→role.worldSize, `WorldRenderer.WaveEnemySize`의 최대 크기 0.64와 말벌 배율 0.55, `data/presentation.json`의 1000 world units/Unity unit이다. 현재 값은 약탈병 475, 씨앗 진드기 489, 작물 포식자 412, 돌진 주자 446, 방패 약탈병 528, 발효 말벌 258이다. 공격 `Range`를 몸 너비로 쓰지 않는다. 아트 너비가 달라지면 이 출처와 실루엣 증거도 함께 검토한다.

서로 다른 너비의 쌍은 **두 몸 너비의 산술평균 × 0.6**을 최소 중심 거리로 해석한다. 보스는 분리 대상 및 겹침 관문에서 제외한다. 살아 있는 적을 ID 오름차순으로 처리하며 정수 제곱거리, 정수 제곱근, 재사용 SpatialHash/목록을 쓴다. RNG를 소비하지 않는다. 먼저 두 차례 국소 투영으로 겹침을 줄인 다음, 남은 겹침만 ID 순서로 가까운 정수 격자 둘레를 탐색해 빈 위치로 옮긴다. 먼저 확정된 낮은 ID와 진행 중인 돌진을 침범하지 않는다. 경계에서 버려진 이동은 상대에게 넘긴다. 맵 전체의 가능한 격자 탐색에도 자리가 없으면 현재 위치를 유지하고 `enemy-separation-unresolved` 카운터를 올린다. 게임을 중단하지 않으며 이 카운터가 있는 실행은 분리 관문 실패로 보고한다. 최초에 수백 개체를 한 점에 주입한 스트레스에서는 큰 초기 분산이 가능하므로 정상 스폰 화면의 부드러움 증거와 구별한다.

## 예고와 돌진

현재 틱이 `UntilTick` 미만인 진행 중 `charge`만 분리에서 고정되어 기존 잠긴 선분·피해 검사를 보존한다. 나머지 적이 그 주변에서 분리된다. 둘 다 돌진 중이면 일시적 통과를 허용한다. 현재 돌진 주자의 activeTicks=30, tickRate=30이므로 두 돌진끼리 겹칠 수 있는 구간은 1초 이하이며, 끝난 틱부터 다시 분리한다. 정지 상태 때문에 Advance가 건너뛰어져도 만료한 비보스 돌진은 그 틱에 회복으로 전환한다. 이후 정지가 풀릴 때 만료한 돌진의 이동이나 피해를 한 번 더 실행하지 않고 정상 회복/새 예고 흐름으로 돌아간다. 이 처리는 새 분리 계약이 있을 때만 적용해 역사 재생과 보스 동작은 보존한다. 장래 콘텐츠가 더 긴 돌진을 추가하면 이 예외를 재검토해야 한다.

예고 중인 적이 밀리면 `WaveEnemyAction.Origin`을 실제 위치로 갱신하고 이미 고정한 `Target`은 바꾸지 않는다. 방향은 갱신된 Origin→Target으로 그리며, 과거 enemy-tell 사건의 최초 좌표를 현재 경로로 재사용하지 않는다. 새 표적을 잡거나 예고·회복 시간을 늘리지 않는다. 건물·밭·강 그림은 기존과 같이 통과 가능하며 지형 충돌을 이번 변경에 추가하지 않는다.

## 역사와 해시

선택적 계약이 없으면 실행 경로와 portable codec의 기존 바이트를 그대로 유지한다. false 존재 플래그도 역사 codec에 추가하지 않는다. 계약이 있으면 `wave-enemy-separation-v1` 태그·버전·정렬된 bodyWidths를 해시에 포함하므로 새 카탈로그와 재생의 해시는 의도적으로 바뀐다. 기존 replay format/state codec 버전을 일괄 교체하거나 역사 골든을 덮어쓰지 않는다. 동결 C05/27000틱 재생은 계약 없는 원본 카탈로그로 검증한다. 현재 콘텐츠 재생은 새 계약을 포함한 데이터 해시로 별도 생성한다.

## 검증과 한계

집중 검사: 정확히 같은 점의 850개체를 중앙/모서리에서 90틱 실행하고 모든 비보스 쌍의 연속 겹침 틱을 검사한다. gate는 30틱을 넘은 쌍 0이다. 추가로 보스·진행 중 돌진 불변, 예고 Origin/Target, 기존 계약 없는 적 동작, 정상 입력 재생 검사를 수행한다. 이 인위적 혼잡 검사는 실제 사용자 6:15 화면 재현과 실시간 영상 판독을 대신하지 않는다. 최종 커밋의 두 Core 대상 해시 및 역사 재생은 CI 안전망에서 확인한다. C05 Mac 성능 재측정은 사용자 보류를 유지한다.

구현 시 관측: 새 계약을 포함한 portable catalog hash는 `638E1956EE9FF187AD4708E5A2D428EABBF4B03DA927DF89BBBF233D5F791B9F`, 같은 카탈로그에서 계약만 생략한 hash는 `D108BA8D527BFE93A00C5FB78111AE2B8D4F53B4047CEA269AFE78D551CFC58E`다. 이는 카탈로그 해시이며 한 판의 최종 상태 해시가 아니다. 850개체 × 90틱 중앙/모서리 스트레스 두 경우 모두 관측한 연속 겹침 최대 0틱, unresolved 0이었다. 집중 적/재생 검사 32개가 통과했고, 출력 보강 후 분리 6개도 다시 통과했다. netstandard2.1 Core 빌드는 경고·오류 0이었다. 이 결과는 두 타깃 실행 해시나 역사 27000틱 재생의 최종 CI 결과를 대신하지 않는다.

역사 catalog hash는 실제 `533a12d`의 Core·Sim·data·Directory.Build.props를 분리된 임시 디렉터리에서 빌드해 독립 확인했다. 현재 코드에서 계약을 생략한 hash와 같으며 집중 검사에 상수로 고정했다.

## AG003 알고리즘 상수 검토

ArchitectureGuard의 기존 **정확한 심볼 + 값 + 사유** 등록 방식을 그대로 쓴다. separation-v1의 정수 계산을 이름으로 명시하고 등록했으며 검사기 구현·범위·기본 금지는 변경하지 않았다. 사용자 승인 기하 조건 `0.6 × 두 몸 너비의 평균`은 `몸 너비 합 × 3/10`으로 고정된 버전 계약이다. 이는 임의의 피해·속도·스폰 계수가 아니며 변경 시 분리 계약 버전과 재생 증거를 갱신한다. 나머지는 두 번의 국소 투영, 정수 반올림 여유, 쌍 ID의 결정론적 방향 해시, 네 방향 판별 및 잔여 탐색 격자 분할이다. 정확한 중점·양분 계산에는 기존 `WaveGeometry.MidpointDivisor`를 재사용한다. 런타임 데이터·상수 값·계산 순서·분기·직렬화는 바꾸지 않는다.
