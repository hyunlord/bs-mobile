# ADR 0058: 실제 피해 귀속과 소리 포함 기사 검토를 규칙 변경 없이 관측한다

- 상태: 승인 범위 구현 — 네이티브 피해·비용 확인, 진입 직후 피해 비악화 실패·첫 AV 캡처 실패, 사용자 시각 판정 대기
- 날짜: 2026-10-12
- 연결 이슈: [#254](https://github.com/hyunlord/bs-mobile/issues/254), [PR255](https://github.com/hyunlord/bs-mobile/pull/255)
- 관련: [순수 Core](0002-pure-csharp-core.md), [고정 벤치마크](0044-fixed-native-wave-benchmark.md), [M1-1 표현 비교](0057-view-only-impact-and-hero-motion-comparison.md), [GDD 결정](../design/gdd/00-index.md), [손맛](../design/gdd/06-feedback.md), [아트](../design/gdd/07-art-character.md)

## 맥락

사용자는 기본 영웅 A 정통 개척 기사·무료 Unity 2D Animation 실시간 뼈대와 카메라 1.4배를 선택했다. 기존 M1-1의 방식 선택 대기는 이 결정으로 종료됐지만, 기존 B 리그와 구운 모션·실시간 모션 비교 원본은 역사 기록으로 남긴다. 적은 구운 이미지 방식을 유지하고 유료 도구·운영 SDK를 추가하지 않는다.

`7bc241f`의 배율 비교는 공격 거리 진입을 대리 접촉으로 셌다. 당시 선택된 원본 C05 구간에는 실제 피해가 없었고 기존 `lord-hit`의 정의 ID만으로 실제 공격자 개체를 알아낼 수 없었다. 또한 실제 피해는 `Advance` 내부 틱 T에 발생하고 표시 스냅샷은 T+1이므로 같은 틱이라고 비교하면 관측 누락이 생긴다.

손맛 실시간 영상은 VFR 누락 실패 표본이었다. 사용자는 이를 보존하면서 오프라인 고정 60fps에 실제 게임 소리를 넣은 동일 시점 전후와 영웅 주변 2배 확대본을 요구했다. 표시 시계와 벽시계가 다른 오프라인 실행에 실시간 녹음만 붙이면 오디오 동기를 보장할 수 없다.

## 결정

### 1. 실제 양수 HP 손실을 관측 계약으로 노출한다

Core는 순수 BCL 관측 인터페이스로 **실제로 차감된 양수 HP 손실**을 전달한다. 피해 사건은 안정 공격자 개체 ID, 정의 ID, 투사체라면 별도 투사체 ID, 피해 종류·양과 원래 사건 틱 T를 담는다. 소유자를 알 수 없는 경우 `-1`로 남기고 근처 적·정의 ID로 추정하지 않는다. 무효 타격·공격 거리 진입을 실제 피해로 세지 않는다.

관측기는 선택적이며 Core의 입력·규칙·RNG·상태 전이·결정론 해시에 포함하지 않는다. 투사체 소유권 등의 진단 메타데이터도 해시 계약을 바꾸지 않는다. 출력 파일과 화면 이력 분석은 Core 밖에서 처리한다. 관측 콜백은 상태를 바꾸지 않아야 하고 관측 버퍼 누락은 성공으로 숨기지 않는다.

Unity 관측기는 사건 틱 **T와 post-Advance 스냅샷 T+1**을 명시적으로 연결한다. CSV에 두 시각을 따로 기록하고, 측정 구간 시작·끝은 스냅샷 틱에 맞춘다. 화면 이력은 피해 직후 첫 표시 표본이며 물리 충돌 순간의 부분 틱 시야라고 주장하지 않는다.

전경이며 귀속·화면 이력이 확인된 실제 피해 사건을 분모로, 관측된 화면 밖→안 진입 후 1초 이내 피해 사건을 분자로 센다. 이력 미확인·소유자 미확인·분류 누락·버퍼 초과는 따로 남긴다. 분모 0은 미확인이지 0%가 아니다. 같은 입력에서 경고 ON/OFF는 피해와 해시를 보존해야 하므로, 경고가 사람의 회피 행동을 개선했다는 인과는 별도 플레이 입력 없이는 주장하지 않는다.

### 2. 선택된 기사와 위험 표시는 View에 한정한다

A 기사·1.4배는 표시 기본값이며 영웅·적·이펙트를 함께 확대한다. Core 크기·좌표·판정·피해·스폰은 바꾸지 않는다. 실시간 뼈대는 영웅 1명만 적용한다. 서기·걷기·이동 중 철날 검·진화 큰 휘두름·피격·쓰러짐·레벨업 7동작을 구현·검증하며 기존 B 자료는 삭제하지 않는다.

화살표 최대 6개와 돌진 표시 예고 0.5초는 사용자 제시 **표현 가설**이다. Core 적 공격 준비 시간을 바꾸는 값이 아니다. 카드 창 등 모달 화면 뒤에서 레벨업 포즈가 소모되지 않도록 표시 큐가 화면 복귀를 기다린다. 이 역시 Core의 레벨업 시점을 미루지 않는다.

### 3. 고정 영상 프레임과 오디오 샘플 시계를 묶는다

명시적 `--offline-replay-capture --offline-replay-audio` 실행에서 Unity `AudioRenderer`로 실제 게임 믹스를 렌더한다. 최종 WAV의 60fps 영상 한 장에는 정수 오디오 샘플 프레임 수를 대응시키되, **믹서가 매 호출마다 그만큼 반환한다고 가정하지 않는다.** 48kHz의 영상 한 장은 800샘플 프레임이지만 실제 DSP는 1024샘플 블록과 0샘플을 반환한다. 영상 프레임·Unity 프레임·Core 틱·보간 alpha·시작 샘플·샘플 수를 기록한다. 지원하지 않는 채널 구성이나 60으로 나누어떨어지지 않는 샘플레이트는 조용히 변환하지 않고 실패시킨다.

프레임·오디오 버퍼를 미리 준비하고 **보고된 DSP 블록 크기 그대로 Render한 샘플을 순서 보존 FIFO로 받아 800샘플 프레임 단위로 다시 묶는 방식**을 사용한다. 이것은 샘플 재생성·리샘플링·무음 패딩이 아니다. 캡처 구간은 샘플 클록으로 지정하고, 마지막 표본이 DSP 블록에 남으면 후행 렌더로 배출해 정확한 구간을 완성한다. 선행/후행 구간과 최종 WAV 구간의 인덱스를 구분해 실제 목표 샘플을 버리거나 복제하지 않았음을 검증한다.

이 FIFO 수정은 네이티브 재검증 전 구현 방향이며 완료 증거가 아니다. 캡처 인덱스와 오디오 인덱스의 시각·길이, 실제 기록된 샘플, 소스 재생 시각을 확인한 뒤 전후 영상과 확대본을 조립한다. `AudioRenderer.Render`의 반환값 true만으로 샘플 기록을 판단하지 않는다. OS 녹화·손쉬운 사용 권한을 요구하지 않는다. 이 경로는 명시적 검토 실행에만 쓰며 일반 플레이 오디오나 실시간 성능 계측을 대체하지 않는다. 무음·합성 PCM 검사만으로 실제 게임 소리 전달을 통과 처리하지 않는다.

### 4. 실패 재생은 원본과 별도 입력으로 보존한다

새 `benchmarks/m1-254/generator` 프로젝트는 Core를 사용하는 별도 재생 생성 도구다. 원본 C05를 덮어쓰거나 출시 규칙을 바꾸지 않고, 고정 접두 명령 뒤에 허용되는 이동·카드 입력을 넣어 실제 피해가 있는 실패 표본을 생성한다. seed·원본 입력 SHA·변경 구간·새 입력 SHA·종료 해시를 남긴다.

candidate2는 원본 C05의 틱 13500 이전 입력을 보존하고 이후 이동을 바꾼 별도 재생이다. 생성 검증에서 814–824마리 구간의 양수 피해 160건·HP 손실 1778, 143틱(약 4.77초) 뒤 사망을 기록했다. 이는 30초 생존이나 원본 C05 성능 표본이 아니다. 원본 C05의 선택된 구간에 피해가 없다는 사실과 후보 실패를 모두 보존하며, 성공처럼 보이도록 체력·무적·스폰을 변경하지 않는다.

## 결과와 비용

순수 Core 경계와 역사 해시를 유지하면서 실제 피해의 출처를 관측할 수 있다. 관측 자료·소유권 필드·고정 크기 수집 버퍼의 유지 비용과 검토 도구 프로젝트가 추가되므로 별도 테스트와 캡처 없는 비용 검증이 필요하다. 화면 이력은 표시 표본의 이산 관측이며 사건 시점과 완전히 같은 시야라고 단정할 수 없다.

고정 60fps 영상은 프레임 누락 없는 시각 비교를 가능하게 하지만 실시간 프레임 간격을 증명하지 않는다. A 기사 7동작의 테스트용 포즈 장면도 실제 판의 자연스러움·군중 실루엣 승인을 대신하지 않는다. #223의 10/13 01:00–06:00 야간 측정과 #126·#98·#224·1b 보류는 별도 유지한다.

## 거절한 대안

- 공격 거리 접촉을 실제 피해로 보고: 피해 미발생과 공격자 귀속을 구분하지 못한다.
- 피해 틱 T를 스냅샷 T와 비교: 실제 `Advance` 경계의 T+1 표시 상태와 어긋난다.
- 진단 ID를 결정론 해시에 추가: 관측 확장을 이유로 역사 재생 계약을 불필요하게 바꾼다.
- 같은 입력의 경고 표시에서 피해 감소를 연출: 화면 정보와 행동 변화의 인과를 날조한다.
- 원본 C05 체력·무적·스폰 수정: 고정 회귀 입력의 비교 가능성을 깨뜨린다.
- 벽시계 녹음을 오프라인 영상에 그대로 붙임: 프레임·오디오 샘플 시계의 정합성을 보장하지 못한다.
- 믹서 블록과 무관하게 매번 800샘플 Render를 요구: 네이티브 격리 실험에서 true를 반환해도 90프레임 동안 샘플 버퍼·소스 시계가 전혀 진행하지 않았다.
- 적 전체를 실시간 뼈대로 전환: 사용자 승인 범위가 영웅 1명이다.

## 검증과 남은 관문

`2bf5295` 구현의 집중 기록은 Core 관측 검사 8/8·netstandard2.1 컴파일, Unity EditMode 26/26·통합 26/26·마지막 14/14, 모달 3초 뒤 레벨업 포즈 PlayMode 1/1이다. 검사 묶음이 겹칠 수 있어 고유 개수로 합산하지 않는다. 실제 `Session.Advance` T→T+1 피해 경계를 검사하며 원본 C05 최종 해시 `B056B090575693A13CEEAB514E909F5C2C346FF2B1007598A4EE6E9B2DE8AEE8`를 보존했다.

후속 `2bf5295` 네이티브 검증은 [M1-254 보고](../review/m1-254-knight-impact.md)에 기록했다. candidate2의 실제 피해 사건 160건·총1778은 세 조건에서 같았지만 진입 1초 이내 피해는 1.0배 0/160, 1.4배 경고 OFF/ON 모두 2/160으로 **비악화 실패**다. 누락·미분류·소유자 미확인은 없었다. 같은 입력이므로 경고의 회피 개선을 주장하지 않는다.

원본 C05 800+ 30초에서 A 기사 live와 보존 B live를 각 1회 비교한 장 p95는 16.7632/17.1221ms, 최대 22.1638/23.2842ms, >25ms는 모두 0%였다. Unity 할당 p95 차이 +0.0625MiB는 두 실시간 리그의 차이이며 RSS·구운 방식 대비 차이가 아니다. SpriteSkin 전체 마커는 수집 불가다. 짧은 각 1회 표본으로 개선·#223 완료를 주장하지 않는다. 별도 피해 1.0배 표본의 최대 65.0648ms 실패도 보존한다.

첫 실제 오디오 캡처는 AudioRenderer가 한 고정 영상 프레임보다 큰 블록을 반환해 영상 0/1800·오디오 0샘플로 중단했다. Node의 오디오 계약·합성 PCM 조립 검사는 실제 게임 AV를 증명하지 않는다. 고정 60fps+소리 전후·확대본의 동기, 최종 프레임 수, 사용자 시각 판정은 수정 후 실제 캡처로 확인해야 한다. ADR 추가나 CI 정책 통과만으로 이 관문들을 통과했다고 쓰지 않는다.

`6ffa` 후속 실패의 연속 181개 렌더 표본은 1024 또는 0샘플을 보고했고 합계144384는 `floor(181×800/1024)×1024`와 같았다(영상 클록 목표144800). 첫 캡처 프레임441은 800이 아닌1024를 반환해 중단했다. 격리 네이티브 실험의 `reported.csv`는 보고된 길이로 렌더할 때 버퍼를 모두 기록하고 소스 시각을 진행시켰다. `fixed.csv`는 800을 강제로 요청하면 90프레임 모두 true였으나 스테레오1600개 NaN이 남고 `timeSamples=0`, DSP시각2.112가 고정됐다. 두 실패는 보존한다. FIFO·후행 배출이 이 문제를 해결했는지는 실제 재캡처까지 미확인이다.
