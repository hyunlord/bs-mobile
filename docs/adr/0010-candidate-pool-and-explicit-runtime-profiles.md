# ADR 0010: 후보 풀과 실행 집합을 명시적으로 분리한다

- 상태: 채택, S3 데이터 계약
- 연결: #36, 기본 영주·영지 선택은 needs-decision #32

## 문제

S3의 후보 수백 개를 디렉터리 검색으로 S2 실행에 자동 포함하면 데이터 작성만으로 카드 풀·적 분포와 기존 결정론 해시가 달라진다. 반대로 후보를 별도 비검증 문서로만 두면 참조·태그·조합 오류를 CI에서 잡을 수 없다.

## 결정

모든 후보는 열 종류의 정본 JSON과 엄격한 스키마로 관리한다. CI는 전체 후보와 테스트 레코드를 검사한다. 실행기는 명시한 프로필의 ID 집합만 엄격한 DTO로 읽고, 실행에 필요한 기존 필드만 순수 코어로 투영한다. 기본 프로필은 S2의 무기 세 개·도구 세 개·적 네 종류·기본 영주와 영지를 선택한다. 테스트용 대체 영주·영지는 명시적 테스트 선택으로만 더한다.

후보 레코드의 한국어 이름, 비용, 발동 형태와 피해 계수, 순환 연결은 설계 설명이다. 피해 계수를 기존 정수 피해에 중복 적용하지 않는다. `s2-runtime`도 부가 고유 효과가 모두 구현됐다는 의미가 아니다. S4는 별도의 실행 집합과 구현 증거로 선택된 후보를 연결한다.

기본 영웅·영지는 한 쌍만 데이터에 둔다. 세 후보 비교와 확장 영웅 여덟·영지 여섯의 이름은 문서에만 기록한다. 사용자 선택 전에는 현재 들판과 영주의 이름·능력을 잠정안으로 명시한다.

## 검증과 한계

기존 S2 수치·ID와 같은 입력의 상태 해시를 회귀 검사한다. 전체 후보는 수량, 태그당 레코드 수, 성장 필드, 참조, 진화 유형, 반시너지, 외형의 수치 금지, 기본 순환 연결을 자동 검사한다. 생성된 사람용 표가 정본 JSON과 같은지도 검사한다.

스키마는 문장이 재미있는지, 비용이 실제로 균형을 잡는지, 광고 장면이 대중에게 통하는지 증명하지 못한다. 의미 검토와 향후 실제 구현·리그·플레이 검증을 구분해 보고한다.

## 기각한 대안

- 모든 JSON 자동 실행: 후보 추가가 승인 없는 동작 변경이 된다.
- 알 수 없는 DTO 필드 무시: 오타와 계약 이탈을 조용히 숨긴다.
- 후보용 ID 사본을 별도 폴더에 유지: 같은 ID에 두 정본이 생긴다.
- 영웅·영지 후보를 모두 실행 레코드로 등록: 사용자 선택 전 기본 한 쌍 범위를 넘긴다.
