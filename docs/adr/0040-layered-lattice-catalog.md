# ADR0040: 설계 카탈로그와 런타임 지도의 분리

- 상태: 승인 (#141 사용자 요청의 설계와 런타임 분리)
- 날짜: 2026-10-10
- 연결 이슈: [#141](https://github.com/hyunlord/bs-mobile/issues/141)
- 관련 결정: [ADR0037](0037-lattice-map.md), [ADR0039](0039-versioned-design-catalog.md)

## 맥락

D3 카탈로그는 런타임과 같은 ID를 사용할 수 있지만 설계 제안이다. 두 소스를 합산하거나 설계 관계를 런타임 구현 증거로 해석하면 지도의 의미가 달라진다. ADR0037의 초기 지도에 독립 설계 층과 비교 기능을 추가한다.

## 결정

`.lattice/lens.json`이 `data/system-design-v1.json`을 designed-v1 층으로 읽고 런타임·이전 후보 층과 구분한다. 그래프 ID에는 층을 붙이고 원래 ID를 별도로 보존한다. 대응 간선은 유효한 designRef를 우선하며, 없으면 같은 종류와 ID를 사용한다. 대응 자체는 구현·발동·승인 증거가 아니다.

카탈로그의 content·systems·implementationWaves·influenceMatrix를 스키마 구조로 읽는다. 영향 행렬은 행에서 열로 향한다. 도메인 간선·발견 조건은 bs-mobile 렌즈가 소유하고 Lattice 엔진에는 범용 표현과 보기를 둔다. 설계 발견은 warning이며 사용자 승인 전에는 gate로 바꾸지 않는다.

Pages 워크플로는 검증된 Lattice main 커밋5377931708923f783d0384ce1d41be09649e87e4를 고정한다. 역사 기준de2a571과 현재 소스를 동일한 현재 렌즈로 다시 계산해 현재 렌즈 투영임을 표시한다. 노드·발견·간선·facet의 변화와 층별 개수를 비교하며 원본 JSON을 변경하지 않는다.

## 결과와 비용

홈·목록·상세·영향 행렬에서 설계를 따로 검토할 수 있다. 이후 카탈로그 변경은 Pages 트리거를 통해 다시 게시된다. 기준 스냅샷을 재계산하므로 전체 Git 이력 checkout이 필요하고 빌드 시간이 늘어난다. 역사 재현값은 기준 커밋에만 검증하며 현재 콘텐츠 수량을 고정하지 않는다.

## 거절한 대안

- 같은 ID를 하나의 노드로 병합: 설계 제안과 런타임 증거를 혼동한다.
- 엔진에 게임 전용 분기 추가: 범용 도구와 도메인 규칙의 경계를 깨뜨린다.
- 현재 발견을 즉시 CI gate로 사용: 사용자 승인 전 warning-only 요청에 어긋난다.

## 검증

실제 기준 그래프에서 요청값6/15/11/7/12/0, 콘텐츠151개의 웨이브 소속, 시스템13개의 방향 영향 간선41개를 대조했다. 브라우저375/768/1280에서 네 화면을 확인했다. 도구 PR16의 Node20/22/24 CI가 통과했다. 소비자 PR CI와 배포 상태는 PR149의 실행 결과를 정본으로 둔다. v1.1이 아직 병합되지 않은 시점의 결과를 v1.1 검증으로 표현하지 않는다.
