# ADR 0029: 첫 플레이 가능판의 실행 계약과 역사 분리

- 상태: 승인된 사용자 범위의 구현 결정
- 날짜: 2026-10-09
- 연결: [#94](https://github.com/hyunlord/bs-mobile/issues/94), [M1 #95](https://github.com/hyunlord/bs-mobile/issues/95)
- 대체 범위: ADR0023의 당시 기본 실행 프로필 선택만 새 Unity 빌드에서 확장한다. 역사 production의 데이터와 결과는 대체하지 않는다.

## 맥락

사용자는 1단계 A의 도형 회색 상자로 게임을 판단할 수 없다고 보고, 로직·콘텐츠·비주얼·흐름을 갖춘 15분 첫 플레이 가능판을 승인했다. 기존 production은 30Hz 21600틱(12분), 무기4/도구4/특허4/물품12/진화2/적6의 실행 집합이다. 기존 파일 수만 세거나 모양 이름만 추가해서는 새 목표를 충족하지 않는다.

## 결정

1. `first-playable`을 명시적인 새 실행 프로필로 만든다. 총27000틱, 네 계절 각6750틱이다. 기존 production/tuning/실험 프로필과 골든 기대값은 유지한다. 이번 사용자 의뢰서가 15분 실행의 승인 근거다.
2. Core Catalog에 nullable·버전 있는 FirstPlayable 계약을 추가한다. null이면 기존 RNG 호출 순서·상태 직렬화·행동을 그대로 유지한다. 새 계약이 존재할 때만 persistent attacks, 이벤트, 스케줄, 건설 진행, 카드 희귀도 등 미래 상태를 결정하는 필드를 도메인 태그와 함께 해시에 포함한다. 모든 콘텐츠 선택은 외부 ID 참조이며 영웅·영지 ID를 Core에 박지 않는다.
3. 무기 성장 수치는 각 무기의 정본 12레벨 표 하나에서 온다. 새 계약은 비행 속도·지속 시간 등 새 형태에 필요한 규칙을 소유하며 같은 피해/범위/빈도 성장표를 복제하지 않는다. 기존 콘텐츠의 효과가 역사 프로필과 달라져야 하는 경우 새 프로필의 명시적인 runtime override 한 개만 유효하도록 로더가 선택한다. 이중 적용이나 암묵적 fallback은 거부한다.
4. 투사체 이동, 관통 예산, 궤도 접촉, 지속 장판, 연쇄 및 왕복은 실제 Core 상태와 시간에 따라 실행한다. 단순 원형 즉시 피해의 시각적 이름 변경을 새로운 형태로 세지 않는다. 정예와 겨울 끝 보스는 별도 스케줄을 갖고, 사람을 직접 노리는 적을 지원한다. 보스는 마지막 겨울 구간에 등장하며 요약은 보스 처치와 시간 생존을 구별한다.
5. 상인(식량 비용), 성소(회복/경험치), 약탈 수레(공격해 파괴 후 보상)는 구별되는 지도 사건이다. 태그 조건 물품과 진화 레벨/성장 조건을 실제로 검사한다. 화면용 카드 희귀도는 제안 시 확정해 고정/리롤/선택 간 모순을 막는다.
6. Core는 사람 활동, 건설 단계, 진행 중 공격, 지도 사건, 보스, 장비/특허/물품/진화, 피해/처치/수확 등 읽기 전용 사실을 내보낸다. Unity가 별도 피해·성장·진화 판정을 만들지 않는다. 아트 역할/스프라이트 크기는 표현 계약이며 전투 반경이 아니다.
7. 신규 holdout40000–40031에서 사람규칙A/B/C×6정책으로 리그를 실행한다. 기존(b)와 c′ 함수의 판정 의미는 그대로 사용하고 혼합 생존수≥random인 묶음이2개 이상인지 추가 검사한다. random생존0은 c′ 평가 불가다. 기존 정책 코드에 정책별 보너스를 넣어 관문을 통과시키지 않는다. 실패한 후보도 설정·seed·소스·CSV를 보존한다.
8. 500+ 성능 관문은 순간 최대치만으로 통과시키지 않는다. 적500이상인 지속된 1배속 측정 구간과 그 구간의 모든 적격 프레임을 명시하고, 전체 구간의 최장 프레임·일시중지·열 상태도 보존한다. 측정 창과 제외 규칙은 시험 전에 고정한다.

## 비용과 거절한 대안

새 opt-in 계약과 별도 로더 검증이 필요하지만 역사 실험을 새 규칙으로 소급 판정하지 않는다. 기존 production을 바로 덮어쓰는 방식은 이전 재생을 잃으므로 거절했다. JSON 수량만 늘리는 방식, Unity에서 사건/전투를 추측하는 방식, 성능을 맞추려고 적을 숨기거나 효과를 없애는 방식도 요구사항과 맞지 않는다.

## 검증 계획과 현재 한계

새 동작의 양성·음성 테스트, 기존 골든 불변, 실제 두 .NET 대상 재생, 실행 콘텐츠별 행동 증거,576사례 리그, Unity/실제 Android 재생, 최종 화면과 기기 성능으로 검증한다. 이 ADR은 구현·리그·화면·실기 관문의 통과 증거가 아니다. M1–M4의 실제 결과는 각각 이슈/PR/CI와 선택한 Release 표본에 기록한다. 물리적 힌지 조작은 기존 #83 사용자 대기를 유지한다.
