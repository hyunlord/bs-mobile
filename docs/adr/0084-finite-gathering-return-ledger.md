# ADR0084: 유한 채집 원천과 귀환 지급 원장

- 상태: 구현 초안, 런타임 검증 대기
- 날짜: 2026-11-02
- 추적: [#626](https://github.com/hyunlord/bs-mobile/issues/626)
- 선행: [ADR0078](0078-server-domain-command-transactions.md), [ADR0082](0082-world-map-storage-and-allocation.md), [GDD18](../design/gdd/18-slg-world-map-proposal.md)

## 결정

`gathering_schema` v1은 공통 `server_schema`와 별도다. 월드 행 → 계정 UUID 오름차순 → 자원/도착/영수증 순으로 잠근다.
연맹 행을 역순으로 획득하지 않는다. 콘텐츠 바이트 해시와 스키마 버전이 바뀌면 명시적 이관 전 초기화를 거절한다.

자원 노드는 서버 전용 opt-in 데이터의 재고·병사당 분당 생산·적재·재생성 지연을 사용한다. 수치 600/1/10/10분은 가설이다.
생성 재고 = 잔량 + 누적 채집 확정량을 매 전이 검증하며 완료 세대는 별도 원장으로 보존한다.
도착 순서는 월드 잠금을 얻은 트랜잭션의 sequence로 배정한다. 같은 marchId의 다른 편성/목표/시간 계약은 거절한다.
점유 경합 패자는 화물 없이 회군하며 재시도로 권리를 얻지 못한다. 경과 시간을 누적 계산하여 분할 조회의 소수 손실을 막는다.

채집 완료는 지갑을 바꾸지 않는다. 화물과 귀환 마감을 영수증에 저장하며 귀환 때 공통 `AccountStore` writer의
`DomainCredit`를 사용한다. 지갑 상한 초과는 기존 계정 보관함으로 들어가며 반환 marchId가 그 원천 명령 ID다.
계정 버전·분야 상태·화물 완료 표식·자원 사건·outbox가 동일 트랜잭션으로 커밋된다. 실패하면 모두 롤백한다.

## 행군 연결 경계

클라이언트가 병력·화물·시각을 제출해 자원을 받는 HTTP 경로는 없다. `GatheringArrival`은 검증된 서버 행군 snapshot이다.
행군 담당은 같은 월드 트랜잭션의 `ArriveAsync`/`ProcessActivityAsync`로 도착/채집/회군을 처리하며,
`ReturnCreditsAsync`를 병력·영웅·슬롯 해제와 같은 공통 writer callback에서 호출한다.

독립 저장소 복구는 `(dueAt, sequence, entityId)`로 노드 완료·재생성·귀환을 처리한다. 뒤로 간 UTC는 월드 high-watermark로 막는다.
행군 저장소가 설치되었거나 행군 관리 중인 채집이 있으면 독립 도착·취소·복구를 거절하고 행군 스케줄러에 맡긴다. 행군은 원래 사건 마감 시각을 전달하고
도착할 노드만 그 시각까지 지연 복구한다. 장기 중단 뒤 이동 도착까지 포함하는 전체 사건 병합은 행군 PR의 책임이다.
호스트는 저장소를 등록/초기화하지만 독립 복구를 백그라운드로 실행하지 않는다. 이 PR을 클라이언트 출정 완성으로 세지 않는다.

## 삭제·복원

삭제 유예 중인 계정의 귀환은 조회 대상에서 제외하여 보류한다. 다른 계정의 due 사건을 가로막지 않으며 복원 뒤 다시 처리한다.
영구 삭제 시 도착 원장의 소유 계정 FK는 NULL이 되어 계정 삭제를 막지 않는다. 남은 화물 원천량은 보존하고 지급은 포기 처리한다.
자원 자체는 계정 삭제와 무관하게 해제·재생성된다. 익명화된 원천 원장의 장기 보존 기간은 운영 데이터 정책의 후속 대상이다.

## 검증

순수 상태 경계·동시 도착·중복 계약·귀환 마감 직전/정확히 도착·롤백·재시작·세대 재생성·보관함 연결 테스트를 작성한다.
실제 PostgreSQL 실행은 공유 Mac 잠금과 낮 시간 허용 후 기록한다. Core·리플레이·골든·Unity 변경은 없다.
