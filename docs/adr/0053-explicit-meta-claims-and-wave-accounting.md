# ADR0053: 받기 원장과 wave 계정 기록을 전투 규칙에서 분리한다

- 상태: #226 구현 결정, UI 통합·화면 관문 검증 전
- 날짜: 2026-10-11
- 관련: [#226](https://github.com/hyunlord/bs-mobile/issues/226), [ADR0034](0034-bounded-meta-progression.md), [화면 흐름 v0](../design/screen-flow-v0.md)
- 번호:0053 후보. 선행 화면 PR #229가 아직 CI 중이므로 그 병합 뒤 main으로 준비 가지를 rebase하고, 공개·병합 직전 main에서 번호 충돌을 다시 확인한다.

## 맥락

새 화면은 방치 생산과 도전의 명시적 `받기`를 요구한다. 기존 저장은 자동 지급이므로 버튼만 추가하면 이미 받은 보상을 다시 지급할 위험이 있다. 또한 기존 first-playable 메타 투영을 wave에 적용하면 화면 작업이 승인되지 않은 전투 능력 변경이 된다. 실제 wave 결산의 사람 수는 화면에 남은 패배 집단까지 세면 안 된다.

## 결정

계정 저장 schema4에 `NextClaimSequence`와 `PendingClaims`를 둔다. 방치·도전의 미수령 내역은 Kind·SourceId·Sequence·보상·방치 시간으로 식별하며, `Claim(sequence)`가 기록과 지급을 함께 갱신한다. 같은 sequence를 다시 받아도 지급하지 않는다. 저장 성공 후 상태를 공개하는 `MetaProgression`과 기존 원자적 저장·terminal 저널을 재사용한다. 새 UI가 지갑이나 받은 도전 목록을 직접 편집하지 않는다.

`MetaRewardDelivery.PendingClaims`는 새 명시적 받기 흐름이며 `LegacyAutoCredit`는 기존 경로의 기본값으로 유지한다. 구형 저장의 완료 도전은 이미 받은 내역으로 보존하고 pending 보상을 재생성하지 않는다. schema4를 도입했다고 역사 보상을 새 기능의 첫 보상으로 다시 지급하지 않는다. 도전 해금은 실제 claim 성공 시 반영하고, 완료 조건을 만족한 미수령 도전을 `해금 완료`로 표시하지 않는다.

wave 계정 화면은 `MetaProjectionPolicy.AccountOnlyWave`를 명시한다. 출정 원본 ContentCatalog를 그대로 사용하고 메타 ReplayContext는 null이며 별도 `.meta` sidecar를 만들지 않는다. 장원·가신의 계정 상태를 저장할 수 있어도 공격·체력·이동·성장·아군·경험치 보너스를 전투에 새로 투영하지 않는다. 기존 LegacyProjectCatalog·역사 재생 경로는 유지한다.

wave 집단 표시 레코드는 기존 상태의 Health를 관측 값으로 노출한다. 결산 사람 수는 Health가 양수인 집단만 세며, 패배 뒤에도 남아 있는 집단의 Phase로 생사를 추정하지 않는다. 이는 결산 사실 매핑 수정이며 적 생성·보상 계수·전투 상태·codec을 바꾸지 않는다.

## 실제 지급과 표시의 경계

현재 카탈로그의 조각 규칙은 최소 보상 시간 이상 진행하고 포기하지 않은 클리어에서 **동행한 가신당2개**, 단 조각 상한까지다. 죽음0·포기0·최소 시간 미달0이며 상한 때문에 실제 증가가2보다 작을 수 있다. 결산은 실제 전후 Fragments 차이를 표시한다. 항상 `+2`를 붙이거나 개발 화면을 맞추기 위해 조각을 지급하지 않는다. #126 경제·수치 보류는 계속 유지하며 이 문서는 기존 값을 재조정하지 않는다.

새 화면은 가신6명을 모두 보여 주고 출정 칸3개를 표시하되, 해금과 열린 칸 수는 기존 계정 규칙으로 제한한다. 실제 wave 플레이는 챕터1뿐이다. 챕터2–7은 미리보기이며1b 콘텐츠를 실행 가능한 것으로 표시하지 않는다. #224 부활, #227 광고·상점, #98 실기와 #223 성능 실패는 별도 경계다.

## 대안과 검증 범위

버튼에서 기존 보상을 추가 지급하는 대안은 중복 지급 위험 때문에, wave에 기존 메타 능력을 일괄 적용하는 대안은 전투 규칙 변경 때문에 채택하지 않는다. 표시와 저장의 원장을 나눠 다른 지급 기준을 만드는 대안도 피한다.

구현 커밋의 계정 API·저장 변경과 UI 통합 결과는 별도다. schema 이전·중복 claim·IO 실패·종료 복구·원본 Catalog 보존·과거 재생 해시를 검증하고,5화면의 실제 캡처·Back·lifecycle·잠금·문구를 확인해야 한다. 이 ADR은 그러한 검증을 통과했다는 보고가 아니다.
