# ADR0060: 프레임 영웅의 표시 계약과 해시를 보존하는 진단 도구

- 상태: 승인 — 2026-10-13 사용자 M1-4 제작 결정. 영상·성능 관문 통과는 별도.
- 날짜: 2026-10-13
- 연결: [#258](https://github.com/hyunlord/bs-mobile/issues/258), [PR261](https://github.com/hyunlord/bs-mobile/pull/261), [M1-4 계약](../design/m1-4-frame-hero-impact.md)
- 관계: ADR0065(처음 번호 0057)의 제작 방식 비교는 역사 기준선으로 보존하고 프레임 영웅 선택은 이 결정으로 대체한다. ADR0066(처음 번호 0058)의 관측/캡처 경계와 ADR0059의 별도 근접 조준 규칙은 유지한다.

## 맥락

사용자는 2D 프레임 영웅을 선택하고 3D 굽기를 중단했다. 좌우 반전으로 검 쥔 손이 바뀌거나 미제작 방향을 숨기면 선택한 그림의 계약을 지키지 못한다. 죽음 이후 Core를 더 진행해 쓰러짐을 촬영하는 것도 역사 재생을 바꾼다. 한편 실제8종 결합 실행의 긴 프레임은 Core 비용 후보를 보였지만 근본 원인은 확정하지 못했다. 새 `tools/M1CombinedProfile` 프로젝트와 표시 계약을 같은 PR에서 명시한다.

## 결정

### 프레임 영웅과 종료 표시

A 기사·1.4배를 유지한다. 선택된 프레임 영웅의 엄격 검증 경로는8방향 각각 `idle`, `walk`, `slash-light`, `hit`, `death`를 요구한다. 방향/동작 중복, 반전, `authoredDirection`과 표시 방향 불일치를 거부한다. 검 오른손·그림 비례의 실제 품질은 원화와 연속 영상으로 별도 검사한다. 메타데이터 검증만으로 독립 저작이나 미술 통과를 증명하지 않는다. 기존 비교 자료를 읽는 비엄격 경로는 역사 재생용이며 새 선택 경로의 누락을 감추는 대체로 쓰지 않는다.

걷기는 이동 방향, 공격은 실제 공격 사건에서 고정한 표적 방향을 표시한다. 죽음·피격·공격·이동·서기의 우선순위와 일회성 동작의 마지막 프레임 고정을 View가 소유한다. ADR0059의 조준 판정은 Core가 소유하며 그림의 방향 변경을 판정 변경으로 보고하지 않는다.

명시적 `--hero-production-terminal-tail`은 영웅 검토의 오프라인 캡처에서만 허용하며60표시프레임을 추가한다. 실제 죽은 종료 스냅샷을 유지한 채 표시 시계만 진행하고 Core 명령·틱·최종 해시는 바꾸지 않는다. 캡처 기록에 종료 표시 프레임을 구분하며 이 꼬리를 추가 생존 시간·추가 게임 사건으로 세지 않는다. 일반 플레이와 캡처 없는 성능 측정에는 켜지 않는다. 타깃 선택·공격 방향·표시 동작은 연속 관측으로 남긴다.

### 호스트 전용 결합 프로파일러

`tools/M1CombinedProfile`은 기존 Sim 프로젝트를 참조하는 .NET 콘솔 도구이며 Unity나 운영 SDK 의존성을 추가하지 않는다. 순수 Core 안으로 파일 I/O·시계·GC 조회를 옮기지 않는다. 고정 C05 데이터, 결합 사례 JSON, 기존 입력 리플레이와 출력 경로를 명시적으로 받는다.

도구는 검토 카탈로그 해시를 리플레이 헤더와 대조하고 같은 명령을 `InteractiveSession.Apply`로 실행한다. 기존 `IRuntimeDiagnostics` 관측 지점으로 단계별 경과 시간·할당을 측정하며, 관측 행 저장소는 측정 전에 준비하고 파일 출력은 측정 틱 밖에서 한다. 각 실행의 종료 해시를 리플레이에 기록된 해시와 대조하며 다르면 실패한다. 기존 출력 파일 덮어쓰기를 거부한다. 관측 비용도 포함될 수 있는 호스트 진단 표본이며 Mono·GPU·네이티브 장 간격의 대체가 아니다.

불변 결합 기준선 `C5050C0EE8DBF8837865CFBE83E7C59113109C0439BDE89B8BA9EB851CE5510F`와 이후 바뀐 최종 쇼케이스를 분리한다. 최적화 전후는 동일 데이터·입력으로 검증한다. 사용자 요청으로 현재 측정은 보류이며 도구 추가가 측정 재개나 성능 통과를 뜻하지 않는다.

## 결과·비용

독립 방향별 그림과5동작 때문에 제작량·아틀라스 비용이 늘어난다. 엄격 검증은 미완성 그림을 조기에 드러내며 기존 시험 매니페스트를 새 완성 영웅으로 취급하지 못하게 한다. 종료 꼬리는 영상 출처에 추가 구분이 필요하다. 호스트 프로파일러는 재현 가능한 단계 비용을 제공하지만 별도의 실제 두 DLL 재생 비교와 네이티브 최종3회 관문은 여전히 필요하다.

## 거절한 대안

- 좌우 반전으로8방향 충족: 오른손 검·비대칭 장비 계약 위반.
- 사망 후 Core를 진행해 모션 촬영: 종료 상태·재생 의미 변경.
- 새 도구의 시간 측정을 Core 내부 파일/시계 의존성으로 구현: 순수 결정론 경계 위반.
- 다른 입력이나 완화한 검토 수치로 기존 실패를 덮기: 비용 비교의 기준선 손실.
- ADR 검사 우회: 구조 결정은 같은 PR의 문서·검증으로 충족한다.

## 검증과 남은 관문

- 문서 작성 시 실제 프레임 매니페스트 검증·종료 표시 인자/경로·프로파일러 소스를 읽어 위 경계를 확인했다. 새 실행 결과나 측정 통과를 만들지 않았다.
- 구현 관문: 잘못된 방향·중복·반전·누락 거부, 종료 표시 중 Core 해시 불변, 카탈로그/종료 해시 불일치 및 출력 덮어쓰기 거부, 역사 C05와 실제 두 대상 DLL 비교를 해당 집중 검사와 필수 CI에서 확인한다.
- 성능 관문: 측정 재개 후 최종 후보 캡처OFF 네이티브3회에서 최대≤50ms·25ms 초과≤0.2%. 전체/화면 안 밀도를 구별한다. 영상 승인은 사용자 담당이며 PR255·257 초안을 자동 병합하지 않는다.
- 번호 확인: 원격 main `da26edf`의 마지막 번호0057, 현재 작업·원격 추적 가지의 최대0059를 확인하고0060을 선택했다. 기존0057 두 제목의 역사 충돌은 이 문서로 숨기거나 재번호하지 않는다. 병합 직전 main과 열린 가지에서 번호 충돌을 다시 확인한다.
