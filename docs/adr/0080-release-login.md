# ADR0080 · 출시용 로그인: 게스트 + 기기 키 → Apple/Google 연결

상태: **결정(2026-11-01 사용자) — 선택지 A**. 2026-11-01, §5.1 데이터 정책 추가(2026-11-01). 연결 [#615](https://github.com/hyunlord/bs-mobile/issues/615). 선행: [ADR0077](0077-authoritative-slg-server.md), [ADR0078](0078-server-domain-command-transactions.md). 문서만 바꾸고 코드·SDK·설정은 바꾸지 않는다. 비용·일정 수치는 추정이며 확인된 값이 아니다.

## 1. 현재 상태 (코드 사실)

- `POST /prototype/accounts`는 Development이면서 `Prototype:Enabled=true`일 때만 열린다. 계정 ID와 32바이트 무작위 토큰을 만들고, DB에는 **토큰의 SHA-256만** 저장한다. 세션 만료는 1일이다.
- 로그인·기기 키·소셜 계정 연결·계정 복구·계정 삭제·토큰 갱신은 없다. 계정은 토큰을 잃으면 되찾을 수 없다.
- 결제(#122)·분석 SDK는 보류 중이다.

## 2. 스토어 요구 (2026-11-01 확인한 공식 문서)

- **Apple 4.8 Login Services:** 제3자·소셜 로그인으로 **주 계정**을 만들거나 인증하면, 개인정보 조건(이름·이메일만 수집, 이메일 비공개 선택 가능, 동의 없는 광고 목적 수집 없음)을 갖춘 **동등한 로그인 방식도 함께** 제공해야 한다. Sign in with Apple은 이 조건을 충족한다. 현행 문구가 "Sign in with Apple 필수"는 아니지만, 실제 심사에서는 Sign in with Apple을 요구받은 사례가 많아 넣는 것이 안전하다. 출처: [App Review Guidelines](https://developer.apple.com/app-store/review/guidelines/), [변경 공지](https://developer.apple.com/news/?id=7j1f99yf).
- **Apple 5.1.1(v):** 계정 생성을 지원하는 앱은 앱 안에서 계정 삭제를 시작할 수 있어야 한다. **자동으로 만들어지는 게스트 계정도 포함된다.** 출처: [5.1.1(v)](https://developer.apple.com/help/app-review/guideline-reference/5-1-1-account-deletion/).
- **Google Play User data 정책:** 앱에서 계정을 만들 수 있으면 **앱 안의 삭제 경로와 웹 삭제 요청 링크** 둘 다 있어야 하고, Data safety 양식에 웹 링크를 적어야 한다. 출처: [Play 계정 삭제 요구](https://support.google.com/googleplay/android-developer/answer/13327111?hl=en).
- 미확인: 출시 국가별 개인정보·연령 규정(GDD16 §9와 같이 출시 전 별도 검토).

## 3. 선택지

| | A. 게스트 + 기기 키 → 나중에 Apple/Google 연결 | B. 처음부터 소셜 로그인만 | C. 게스트 + 기기 키만(연결 없음) |
|---|---|---|---|
| 첫 진입 | 버튼 없이 바로 시작 | 로그인 화면 필요 | 바로 시작 |
| 구현 범위 | 기기 키 등록·서명 검증, 토큰 갱신, 나중 연결(Apple·Google ID 토큰 서버 검증), 연결 충돌(이미 다른 계정에 연결된 소셜 ID) 처리, 계정 삭제(앱·웹) | Apple·Google ID 토큰 서버 검증, 토큰 갱신, 계정 삭제(앱·웹) | 기기 키·토큰 갱신, 계정 삭제(앱·웹) |
| 기기 변경·복구 | 연결한 계정은 새 기기에서 소셜 로그인으로 복구. 연결 전 게스트는 복구 불가(앱 삭제·기기 분실 시 손실) | 항상 복구 가능 | 복구 불가(또는 별도 복구 코드) |
| Apple 4.8 | 소셜 연결을 주 계정 인증에 쓰므로 Sign in with Apple을 함께 제공 | 같음 | 해당 없음 |
| 이탈 위험 | 낮음 | 첫 화면 이탈 가능 | 낮음, 대신 진행 손실 불만 |
| 서버 상태 모델 | 계정 1 : 인증 수단 N(기기 키, Apple, Google) | 계정 1 : 소셜 ID N | 계정 1 : 기기 키 1 |
| 비용(추정) | Apple Developer Program 연 99 USD(iOS 출시에 이미 필요), Google Play 등록 1회 25 USD. 소셜 토큰 검증은 공개키 검증이라 별도 과금 없음. 관리형 인증 서비스를 쓰면 그 요금 추가 | 같음 | 같음 |

## 4. 권고

**A(게스트 + 기기 키로 시작하고, 진행을 지킬 수단으로 Apple·Google 연결 제공)**를 권고한다. 첫 판까지 마찰이 없고, 연결하면 기기 변경과 복구가 해결된다. 서버의 "계정 1 : 인증 수단 N" 모델은 B로도 확장할 수 있다. 연결 전 게스트의 손실 위험은 화면에서 미리 알린다(예: 일정 진행 뒤 연결 권유).

## 5. 보안 주의 (어떤 선택지든)

- **토큰 저장:** 클라이언트는 iOS Keychain·Android Keystore 같은 OS 보안 저장소에 두고, 일반 파일·PlayerPrefs·로그에는 두지 않는다. 서버는 지금처럼 해시만 저장한다.
- **수명:** 짧은 접근 토큰 + 회전하는 갱신 토큰을 쓴다. 재사용이 감지되면 그 계열의 토큰을 모두 폐기한다. 로그아웃·계정 삭제 시 서버에서 폐기한다.
- **기기 키:** 기기에서 만든 비밀키는 기기 밖으로 내보내지 않는다. 서버는 공개키와 서명(재전송 방지 nonce 포함)만 검증한다.
- **소셜 토큰:** Apple·Google ID 토큰은 서버에서 서명·발급자(iss)·대상(aud)·만료·nonce를 검증한다. 클라이언트가 보낸 사용자 ID를 그대로 믿지 않는다.
- **비밀 값:** Apple 비공개 키, Google 클라이언트 비밀, 서명 키, 시드 키는 **서버 설정(비밀 저장소)에만** 둔다. 저장소·PR·이슈·Unity 빌드에 넣지 않는다.
- **운영:** 로그인 시도 rate limit, 계정 삭제 뒤 데이터 보존·삭제 범위 명시, 개발용 `/prototype/accounts`는 출시 빌드에서 계속 열리지 않게 유지한다(현재 Development 가드).

### 5.1 계정 삭제 뒤 데이터 정책 (사용자 결정 2026-11-01)

[#620](https://github.com/hyunlord/bs-mobile/pull/620)에서 질문한 항목의 결정이다. 구현은 별도 PR이다.

1. **30일 유예 → 영구 삭제.** 삭제 요청 즉시 접근·갱신 토큰을 폐기하고 연맹에서 나간다(연맹장은 GDD19 §10.1 승계). 유예 중 **같은 기기 키로 로그인하면 삭제가 취소되어 복구**된다(응답 `restored: true`). 연맹 소속은 복구되지 않는다. 유예가 끝나면 그 기기 키도 거절되고, 주기 작업이 영구 삭제한다. 삭제 응답은 영구 삭제 시각(`purgeAt`)을 돌려준다. 앱의 삭제 확인 화면과 안내 문구에 30일 유예와 복구 방법을 명시한다(클라이언트 문구는 클라이언트 세션 담당).
2. **보존과 가명화.** 구매 원장은 5년(국내 전자상거래 기준, 결제가 생긴 뒤 적용), 신고·제재 기록은 현행 180일 보존한다. 둘 다 계정 ID를 **키 있는 해시(HMAC-SHA256, `p1:` 접두)**로 바꿔 보존한다. 키는 서버 설정 `Auth:PseudonymKey`(비밀 저장소)에만 둔다. 같은 키로 같은 ID를 해시하면 같은 값이므로 운영은 증거를 이어 볼 수 있다.
3. **연맹 채팅.** 탈퇴·삭제한 계정의 메시지는 작성자 없이(“삭제된 사용자”) 보인다. 본문은 연맹당 최근 200건 보관 규칙을 그대로 따른다. 신고 snapshot은 2번 규칙(180일, 가명화)을 따른다.
4. **Google Play 웹 삭제 링크.** 웹에서의 본인 확인은 2단계(Apple/Google 연결)로 한다. 연결하지 않은 게스트는 **앱 안에서만 삭제할 수 있다**고 웹 페이지에 안내한다.

영구 삭제 시 처리(주기 작업 `AccountPurgeService`, 기본 60분 간격, 계정당 한 트랜잭션):

| 구분 | 대상 |
|---|---|
| 삭제 | 계정·세션·갱신 토큰·기기 키·nonce·rate 창, 명령 기록·자원/도메인 이벤트·outbox·도메인 상태·작업 시계·보류 재료, 연맹 회원·신청·제한·차단(양방향)·도움 요청·도움 기록 |
| 가명화 후 보존 | 연맹 채팅 작성자(`author_ref`, 본문은 200건 규칙), 신고 snapshot의 신고자·작성자(`reporter_ref`·`author_ref`, 180일), 다른 계정의 명령 응답 캐시 안의 ID 문자열 |
| 비움 | 해산된 연맹의 `leader` |
| 결제 후 추가 | 구매 원장(5년, 가명화) |

테스트가 이 표를 고정한다: 영구 삭제 뒤 DB의 모든 uuid·text·jsonb 열에서 그 계정 ID를 찾지 못해야 한다. 나중에 계정 ID를 담는 표가 생기면 이 테스트가 실패하므로 표와 처리에 함께 추가한다.

## 6. 결정이 필요한 것

1. A / B / C 중 선택(권고 A).
2. 연결 권유 시점과, 연결 전 게스트의 진행 손실을 어떻게 알릴지.
3. 관리형 인증 서비스를 쓸지, 직접 검증할지(SDK 도입은 #122처럼 별도 승인 대상).

## 7. 결정 (2026-11-01 사용자)

**선택지 A**를 채택한다: 게스트 + 기기 키로 시작하고, 진행을 지킬 수단으로 Apple·Google 계정 연결을 제공한다. 구현은 연맹 서버 PR 다음의 별도 PR이다. 구현할 때 다음을 반드시 포함한다.

1. **앱 안 계정 삭제(Apple 5.1.1(v)):** 자동 생성된 게스트 계정을 포함해 모든 계정은 앱 안에서 삭제를 시작할 수 있다. 연결한 Apple 계정은 삭제 시 Apple 토큰 폐기 요청도 함께 처리한다.
2. **웹 삭제 링크(Google Play):** 앱 밖에서 삭제를 요청할 수 있는 웹 경로를 두고, Play Console Data safety에 그 링크를 적는다. 웹 요청은 본인 확인을 거친다.
3. **연결 전 손실 안내:** 연결하지 않은 게스트는 앱 삭제·기기 분실·기기 변경 시 **복구할 수 없다**. 이 사실을 첫 진입 뒤와 연결 권유 화면, 계정 설정에서 글로 알리고 연결을 권한다.
4. **Apple 4.8:** Google 연결을 제공하므로 Sign in with Apple도 함께 제공한다.
5. **SDK:** 소셜 토큰은 서버가 공개키로 직접 검증하는 것을 기본으로 하고, 관리형 인증 서비스나 클라이언트 SDK 도입은 #122처럼 별도 승인 대상으로 둔다.
