# ADR0035: 권한 요청 대신 앱 내부의 명시적 Mac 자동 실행 증거

- 상태: 채택, 2026-10-09 사용자 후속 결정.
- 추적: [#129](https://github.com/hyunlord/bs-mobile/issues/129), [P1 #113](https://github.com/hyunlord/bs-mobile/issues/113).
- 대체: [ADR0033](0033-mac-playable-and-editor-capture.md)의 깨끗한 OS 계정·외부 입력/화면 캡처 관문. 과거 미검증 기록은 보존한다.

## 결정과 경계

사용자는 macOS 화면 기록·손쉬운 사용 권한을 제공하지 않기로 했다. Mac Release에 명시적으로 `--autoplay-capture`를 준 경우에만 앱 자체의 자동 입력과 렌더 결과 저장을 실행한다. 타이틀→정상 속도 한 판→결산→재시작의 실제 네이티브 화면과 실행 기록을 새 관문 증거로 사용한다. 사람이 마우스·키보드로 실행을 확인하는 것은 사용자가 직접 맡으며 자동 입력 성공을 사람 조작 합격으로 보고하지 않는다.

이것은 운영체제 권한을 우회해 다른 창을 읽거나 입력하는 기능이 아니다. 게임 자신의 화면만 저장하고 기존 게임 입력 경로를 사용한다. 일반 실행에는 자동 조작·자동 종료·별도 저장 경로를 적용하지 않는다. 광고·분석·결제 SDK나 외부 영상 SDK를 설치하지 않는다.

## 자동 실행 계약

자동 실행은 빈 독립 출력/저장 경로에서 시작해 실제 빌드·소스·데이터·seed와 입력 방식, 결과·재시작·리플레이 검증을 기록한다. 기존 사용자 계정의 저장·설정을 덮어쓰지 않는다. 정상 틱/시간 속도, 피해·보스·보상 규칙을 유지하며 무적, 레벨/자재 부여, 적 감소, 시간 건너뛰기, 디버그 메뉴를 노출하지 않는다. 자동 실행에 한해서 포커스 없이도 정상 시간으로 계속 진행할 수 있게 하고 이 차이를 기록한다.

실패를 성공 화면으로 대체하지 않는다. 정상 한 판 생존·보스 격파·결산·재시작과 실제 화면/리플레이를 모두 확인한 경우에만 자동 실행 관문 통과로 보고한다. 기기·성능·사람 입력 관문으로 확대하지 않는다. Fold7 #98은 계속 보류한다.

## Recorder와 전달

Unity Recorder 영상은 에디터 증거로 별도 표시한다. P2 메타가 있는 프로젝트에서도 P1 영상은 기존 중립 first-playable 규칙을 명시적으로 선택한다. 인코더의 첫 영상 프레임 이전 준비 시간은 실제 플레이 구간과 구별하며, 실행 시작 뒤의 미디어/게임 시각 허용 오차를 완화하거나 중간에 기준을 재설정하지 않는다. 초기 실패와 약관 처리 전후 기록은 보존한다.

사용자 지시대로 빌드와 영상은 준비되는 대로 Release에 제공하고 짧게 보고한다. 앱 배포 ZIP 하나의 예외와 실패·선정 표본만 공개하는 규칙은 유지한다. 새 증거 ZIP·CRC·전달 영수증은 만들지 않는다.
