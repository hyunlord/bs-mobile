# ADR 0027: 플레이어 소스 식별과 프레임 지표 분리

- 상태: 채택
- 관련: #89, #90, ADR 0024, ADR 0026

## 맥락

Unity의 빌드 GUID만으로는 APK를 만든 저장소 커밋과 미커밋 수정 여부를 알 수 없다. Core 틱 시간과 실제 기기의 렌더 프레임 시간도 서로 다른 측정값이다.

## 결정

준비 도구가 Git HEAD의40자리 커밋, 소스 수정 여부, 입력 파일 내용의 SHA-256을 생성 코드에 넣는다. 입력에는 Core·데이터뿐 아니라 Unity 코드·에셋·설정·패키지 잠금 파일과 도구가 포함된다. 생성 출력과 테스트 전용 데이터는 제외한다. 준비 후 커밋 또는 입력이 바뀌면 검증은 실패한다. Unity가 새 메타 파일을 만든 경우에도 입력이 안정된 뒤 다시 준비한다.

로컬 개발 빌드는 수정 여부와 소스 해시를 함께 기록한다. 최종 기기 측정용 빌드는 커밋된 소스로 다시 만들고 그 식별자를 기록한다. 소스 해시는 APK 바이트 해시를 대체하지 않는다.

기기 집계 기록의 커밋과 `METRICS_SHA`가 다르면 게시를 거부한다. 기존 Core 측정의 커밋 주입 동작을 기기 기록에 적용하여 실행 소스를 바꾸지 않는다. 익명 세션 ID는 원자료 연결 정보이며 계열을 나누는 설정에 넣지 않는다.

기존 지표 스키마1의 Core 틱 기록은 보존한다. 스키마2는 기기 모델·OS·화면·접힘 상태와 측정 범위를 구분하여 프레임 p95·최대값·표본 수·후반 구간 완전성을 저장한다. Core 틱과 밸런스 분산 필드는 null이다. 후반1배속 표본이 없으면 프레임 값도 null이며, 미측정을0으로 보고하지 않는다. 원본 프레임 CSV는 로컬에 두고 집계 결과만 기존 추이에 연결한다.

`Time.unscaledDeltaTime`은 이전 프레임에서 이어진 시간이다. 이전 프레임의 틱·배속·활동 상태를 보관했다가 다음 Update에서 측정값과 결합한다. 카드가 열린 뒤의 상태로 직전 활동 프레임을 정지 표본으로 바꾸지 않는다. 판 종료도 마지막 간격을 다음 Update에서 수집한 뒤 통계를 닫는다. 앱 중단 간격과 중도 종료 시 완성되지 않은 간격은 원본 CSV에 각각 표시하여 보존하며 정상 렌더 프레임 p95와 구분한다. 완전한 종료 표본이 없으면 후반 관문을 완전하다고 표시하지 않는다.

## 결과

다른 기기·화면·측정 범위는 별도 계열이다. Editor 및 합성 테스트 결과를 Android 실기 성능으로 대체할 수 없다. 사람의 실제 플레이 기록과 물리 접힘 검증은 별도 실기 관문으로 남는다.
