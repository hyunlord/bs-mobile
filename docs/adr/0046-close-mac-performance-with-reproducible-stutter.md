# ADR 0046: 비재현 환경 지연을 기록하고 Mac 성능 작업을 종료

- 상태: 승인 (2026-10-10 사용자 최종 판정)
- 날짜: 2026-10-10
- 연결: [#169](https://github.com/hyunlord/bs-mobile/issues/169), [#98](https://github.com/hyunlord/bs-mobile/issues/98)
- 대체 범위: [ADR0045](0045-separate-pacing-and-stutter.md)의 100ms 초과 프레임 실패 집계 및 원인 미확정 시 #169를 열어 두는 조건. 나머지 비용 추세·유효성·보존 규칙은 유지한다.

## 맥락

[C05 재측정 보고](../review/wave-c05-pacing-stutter.md)의 상한 없는 밀도별 통합 p95는 2.3098 / 2.7083 / 3.4953ms다. 사용자는 800+를 포함한 이 비용에 16.7ms 대비 큰 여유가 있다고 평가하고 Mac 성능 작업 종료를 승인했다. 이 비교를 상한 있는 프레임 간격이나 Fold7의 실측 합격으로 확대하지 않는다.

사용자는 이번 176ms 및 과거 369/167ms 지연을 0명령·시뮬레이션 0·GC 증가 0·낮은 화면 구성 비용, 동일 구간 재생의 정상 관측을 근거로 게임 코드가 아닌 실행 환경의 비재현 지연으로 최종 분류했다. 이는 **사용자의 관문 판정**이다. 기존 보고의 원인 미확정과 캡처 범위 한계는 보존하며, 이번 문서 변경으로 새 프로파일 증거나 근본 원인 규명이 생겼다고 주장하지 않는다.

## 결정

1. #169를 종료하고 추가 Mac 성능 측정·최적화를 중단한다.
2. 이후 웨이브마다 동일 C05·환경·설정의 상한 없는 3회 통합 p95를 비교한다. 각 밀도 기준보다 20% 넘게 증가하면 경고한다. 조건이 달라지면 별도 기준을 세운다.
3. 상한 있는 실제 설정의 **100ms 초과 프레임**은 다음 중 하나에 해당할 때만 게임 실패로 센다: 같은 입력 재생의 같은 구간에서 재현되거나, 그 프레임에 게임 작업(시뮬레이션·화면 구성·GC)이 있는 경우. 비재현·무작업 환경 지연은 실패로 세지 않고 기록만 남긴다. 이번 세 지연의 환경 분류는 사용자 승인 사례이며, 임의의 시간 임계값이나 `0명령` 하나만으로 미래 지연을 자동 면제하지 않는다. 근거가 부족한 사례는 미확인으로 기록한다.
4. 밀도·반복별 33ms 초과 프레임 비율 ≤0.1%는 유지한다. 원자료의 모든 지연·따라잡기 프레임, 포커스 및 해시 유효성 검사는 보존한다. 원시 초과 횟수와 보정 후 게임 실패 횟수를 구분한다.
5. 실제 성능 합격선은 Fold7 #98에서 같은 하네스로 검증한다. 기기 보류를 해제하거나 기기 합격을 선언하지 않는다. #126은 보류하고, 1b는 사용자 직접 플레이 소감 후 시작한다. 그 전까지 대기한다.

## 결과와 비용

기존 [v2 계약](../../benchmarks/wave-c05/contract-v2.json)·분석기·CSV·보고·Release는 당시 원시 임계값 판정의 재생성 자료로 보존한다. 이 문서 PR은 분석기나 게임 코드를 바꾸지 않는다. v2의 `fail` 출력은 역사적 원시 판정이며 이번 사용자 최종 분류를 자동 구현한 결과가 아니다. 이후 재사용 시 원시 통계와 이 ADR에 따른 근거 있는 사례 판정을 함께 기록한다.

## 거절한 대안

- 원인을 확정할 때까지 Mac 조사를 계속하기: 사용자가 승인한 종료·대기 범위를 벗어난다.
- 기존 실패 프레임을 삭제하거나 과거 보고를 통과로 덮어쓰기: 관측 사실과 판정 변경의 이력을 잃는다.
- 모든 0명령 지연을 자동 면제하기: 화면 구성·GC 및 재현되는 문제를 놓칠 수 있다.

## 검증

문서 링크·형식 검사와 docs-only CI로 변경을 검증한다. 새 실행·코드 수정·기기 검증은 수행하지 않는다. ADR 번호는 병합 직전 main 기준으로 확인한다.
