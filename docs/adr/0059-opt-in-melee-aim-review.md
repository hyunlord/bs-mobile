# ADR0059: 검토 프로필의 근접 무기만 가까운 적을 향한다

- 상태: 승인 — #256의 구현 범위. 출시 기본값 전환은 영상 승인 전 보류.
- 날짜: 2026-10-12
- 연결: https://github.com/hyunlord/bs-mobile/issues/256

## 맥락

칼이 영주의 이동 방향만 향하면 가까운 적을 공격하는 몸동작과 판정이 어긋난다. 사용자 승인에 따라 조준 규칙은 실제 Core에서 바꾸되, 역사 재생과 기존 실행 프로필은 보존한다. 그림만 바꾸어 판정도 바뀐 것처럼 보이게 하지 않는다.

## 결정

`m1-showcase-review`는 `wave-1a`의 별도 복제 프로필이다. 실행 데이터의 해당 무기에 `aim: nearest-enemy`를 지정한다. Core의 영웅·무기 ID 분기는 없다. Unity는 실제 로드한 카탈로그의 선언을 보고 `MeleeAimOptions(Version: 1)`을 생성한다. 기존 카탈로그에는 선언이 없으므로 옵션도 없다.

근접 부채꼴·내려찍기 공격이 발동할 때 살아 있는 가장 가까운 적을 거리 제곱→안정 ID 순으로 고른다. 조준 대상은 사거리 밖이어도 되지만 타격 거리·피해·대상 수는 그대로다. 대상이 없거나 정확히 같은 위치이면 기존 방향을 유지한다. 진화는 기반 무기의 선언을 이어받는다.

옵션이 있는 판만 재생 형식 v6를 쓴다. 헤더에 조준 계약 버전을 저장하고 상태·카탈로그 codec에는 옵션/선언이 있을 때만 태그를 추가한다. v1~v5의 바이트 배치와 기존 C05 입력의 해시는 보존한다. Core 규칙 codec의 기존 버전 번호를 일괄 올리지 않는다.

Unity의 생성 `IsWave`는 카탈로그 형태에서 정한다. 검토 프로필은 기존 wave 아트·HUD를 사용하지만 실제 프로필 이름·데이터 해시는 유지한다. frozen C05 export는 계속 `wave-1a`만 허용한다. 검토 전용 v6 검증은 seed 30001, 일반 입력 600틱의 별도 fixture이며 기존 5seed·3000틱 관문을 대체하지 않는다. 8종 무기 시각 시안은 이 조준 변경과 별개이며 미구현 공격 규칙을 구현한 것으로 표시하지 않는다.

## 검토 전투 카탈로그 확장

초기 시각 전용 쇼케이스와 새 실제 Core 전투 24사례(8종×lv1/max/evolved)를 구별한다. [검토 데이터](../../data/review/m1-weapon-combat-cases.json)의 `m1-review-composition-v1`은 `ReviewShowcaseCatalog`가 baseline의 복제본으로 만든 격리 카탈로그다. 다른 장비의 발동·성장, 물품·진화, 보스·다른 적 출현은 이 표본에서 억제한다. 각 사례는 600틱 중 앞300틱 준비, 뒤300틱(10초) 촬영이며 사례별 데이터 해시·입력 SHA·실제 피해/처치 사건을 기록한다.

`lv1/max/evolved`는 **사전 구성한 제안 단계**다. 레벨업이나 진화 획득을 정상 플레이로 달성한 증거가 아니다. 공격 피해·범위·횟수·주기와 arena의 적 체력·속도·상한·출현 간격·`enemyDamage=1` 등은 검토 전용 [가설]이다. production 데이터·스폰·경제 밸런스를 변경하거나 #126을 확정하지 않는다.

`WaveAttackComposition` v1은 배치(nearest-target/forward-line), 지연 틱, 순차 간격, 배치 간격, 반경으로 실제 예약 타격을 조립한다. 예약 시점 위치에 예고를 내고 예정 틱에 반경 안 적에게 Core 피해를 적용한다. 거리→ID 순서, 안정 사건 ID, 같은 발동의 중복 대상 제한 및 예약 상태 codec을 사용한다. 이는 단순 이펙트 확대와 다르며, 새 계약·카탈로그가 없는 역사 재생에는 적용하지 않는다. 화면의 국소 히트스톱·번쩍임·반동은 여전히 View만 담당한다.

## 결과·비용

새 검토 프로필의 데이터와 재생은 기존 프로필과 명시적으로 구분된다. 공격 발동당 살아 있는 적을 한 번 검색하며 렌더 프레임마다 추가 할당하지 않는다. 검토 프로필과 원본이 분기되므로 이후 데이터 변경 시 양쪽 의도를 확인해야 한다.

## 거절한 대안

- 전체 프로필의 조준을 즉시 전환: 역사 재생과 사용자 영상 선택 경계를 침범한다.
- Unity에서만 검 방향 회전: 보이는 공격과 실제 타격 판정이 다르다.
- 적이 사거리 안일 때만 조준: 접근 중인 가장 가까운 적도 바라보라는 사용자 결정과 다르다.

## 검증

- 초기 조준 구현의 집중 .NET 검사 52개 통과(역사 실적): 거리·ID 동률, 사거리 밖 조준, 빈/죽은/동일 위치 대상, v6 직렬화, v1~v5 헤더 바이트, 역사 재생.
- 같은 고정 데이터와 입력을 실제 net8.0 / netstandard2.1 DLL로 실행: 검토 v6 600틱 해시 `2829CFE4B0AAE09EFFAE256647A704AB359ECDB040C22ECC20A17A14AF22A601`, 재생 바이트 동일.
- 원본 C05 14400틱은 두 DLL 모두 `B056B090575693A13CEEAB514E909F5C2C346FF2B1007598A4EE6E9B2DE8AEE8` 유지.
- Unity Editor Mono fixture 검사와 실제 Mac 실행은 별도 증거가 필요하며 위 .NET 결과가 대신하지 않는다. `MeleeAimReplayParityTests`는 실행 시 해당 범위만 기록한다.
- 후속 실제 전투 candidate2: `.omo/evidence/m1-256-combat-candidate2/focused-tests.log`의 집중 검사 56/56 통과. 초기52와 중복 범위이므로 더하지 않는다. 같은 폴더의 24개 case JSON·events CSV·replay와 `summary.csv`가 실제 피해·처치·최대 적·해시 근거이며 스키마 검사도 통과했다. `c05-regression.json`은 원본 C05 14400틱의 위 역사 해시 유지다. 이 결과는 Unity 영상·네이티브800+ 비용·사용자 손맛 통과를 증명하지 않는다.
- 번호 선택 시 원격 main `ff61296f7c4a7ebaac18f499155441ba6908a399`의 마지막 ADR은 0057. 로컬 0058 다음 0059를 사용한다. 병합 직전 번호 충돌을 다시 확인한다.
