# ADR 0022: 무기 성장의 타격 전달을 데이터로 분리한다

- 상태: 승인된 #61의 1+2안 구현 후보, 밸런스 관문은 실행 전 미검증
- 날짜: 2026-10-08
- 연결: [#61 결정](https://github.com/hyunlord/bs-mobile/issues/61), [#79 구현](https://github.com/hyunlord/bs-mobile/issues/79)

## 맥락

사용자는 진단 검토 후 공격 형태와 성장 곡선 개선을 함께 승인하고 사람형 잔여 경로 분해(3안)는 보류했다. 기존 진단은 무기 슬롯 부족을 지지하지 않았고, 검·낫의 높은 과잉 피해와 표적 없는 발동을 관측했다. 이 관측이 새 후보의 성공을 증명하지는 않는다. 이번 변경은 0단계 후속 헤드리스 후보이며 Unity 1단계를 시작하지 않는다.

## 결정

기존 프로필과 역사 결과를 보존하기 위해 프로필의 선택적 `weaponCombat` 계약으로만 새 경로를 연다. 계약 버전1과 별도 성장표 파일을 명시하고 선택한 모든 무기의 정의가 정확히 있어야 한다. 누락 무기의 구식 피해 배수 방식으로 조용히 대체하지 않는다. Core는 콘텐츠 ID로 정의를 조회할 뿐 영웅·영지·무기 ID를 코드 분기에 넣지 않는다. 계약과 현재 바라보는 방향은 상태 해시에 포함한다. 새 계약이 없는 catalog/World에는 nullable 확장 필드를 직렬화하지 않으므로 기존 게임 해시 입력을 유지한다.

각 무기는 **12개의 절대값 레벨 행**을 가진다. 행은 피해, 범위, 공격 간격(tick), 타격/발사 수, 추가 관통 수, 밀치기를 정의한다. 모든 축을 매 레벨 동시에 올리는 대신 무기 성격에 맞게 교대로 성장시킨다. 장비 rank가 행의 레벨이다. 희귀도 +1/+2/+3은 도착 레벨을 선택하며 마지막 레벨12를 넘으면12로 제한한다. 초과분 보상은 없고 레벨12 무기는 카드 후보에서 빠진다. 무기 슬롯·도구·헌장·정책 가중치·XP·위협 수치는 그대로다. 새로운 상한은 기존 진단의 'rank 상한 없음'을 과거에 소급해 바꾸지 않는다.

| 무기 성격 | 판정 | 피해 시작→끝 | 범위 | 간격(tick) | 타격/발사 수 | 추가 관통 |
|---|---|---:|---:|---:|---:|---:|
| 검 | 정면90도 부채꼴 | 22→88 | 850→1450 | 30→14 | 3→10 | 0 |
| 낫 | 정면180도 부채꼴 | 24→100 | 1000→1800 | 40→20 | 5→16 | 0 |
| 지팡이 | 즉시 광선형 타격 | 16→60 | 1700→2200 | 24→12 | 1→4 | 0→2 |
| 고리 | 안쪽 빈 영역 없는 원판 | 12→44 | 1000→1500 | 20→10 | 3→12 | 0 |

이 값은 결과를 보기 전 정한 **한 후보**다. 형태·성장·상한을 함께 바꾸므로 성공하거나 실패해도 개별 축의 인과효과로 분해하지 않는다. 초기 관통·범위·성장 수치가 균형을 보장한다는 가정도 하지 않는다.

## 결정론적 판정

바라보는 방향은 실제 영주 이동의 마지막 0이 아닌 벡터이며, 정지 중에는 유지한다. 초기 방향은 (+1,0)이다. 이동 목표를 향하지만 실제로 이동하지 않은 경우 방향을 바꾸지 않는다. 검은 `dot >= abs(cross)`, 낫은 `dot >= 0`과 거리 조건을 함께 사용한다. 경계와 영주 위치에 겹친 적을 포함하며 삼각함수·부동소수 각도 계산을 쓰지 않는다.

부채꼴과 원판의 수는 가까운 적부터 고르는 최대 고유 타격 대상 수다. 같은 거리면 entity ID 순이다. 지팡이의 수는 가까운 살아 있는 서로 다른 초기 목표를 향한 별도 발사 수다. 목표가 일직선이면 여러 발사가 같은 방향·통로를 사용할 수 있다. 각 발사는 데이터의 폭 안에서 앞쪽 적을 거리 투영·ID 순으로 최대 `1+관통`명에게 전달한다. 같은 발동에서 같은 적을 여러 번 때리지 않으며, 뒤의 발사는 이미 타격한 적을 건너뛰고 다음 적에 전달할 수 있다. 따라서 같은 통로 전체의 타격 상한을 `1+관통`으로 제한하지 않고 발사별로 제한한다. 관통은 처치 여부가 아니라 적에게 전달한 타격으로 소비한다. 현재 구현은 **즉시 판정**이며 이동하는 투사체·애니메이션·Unity 충돌체를 구현했다고 주장하지 않는다. 광선 너비 계산에는 필요한 정수 정밀도를 사용한다.

성장표 피해에 장비 레벨을 다시 곱하지 않는다. 기존 영웅·runtime 피해/간격/밀치기 수정은 실제 발동에서 적용하고 `attack` 이벤트는 타격 수와 무관하게 발동당 한 번이다. RNG는 실제 타격에서만 소비하며 새 후보의 후속 카드·난수 경로는 역사 실행과 달라질 수 있다. 전체 프레임을 공유 난수 고정 실험으로 해석하지 않는다.

## 계측과 사전 선언

요청 피해와 실제 적 HP 감소를 계속 기록한다. control의 실제 무기 공격에 대해 과잉 피해는 요청−적용, 비율은 합계끼리 계산한다. 도구/pulse를 무기 공격에 중복 합산하지 않는다. 기존 `noTargetAttempts`는 반경 후보0회 의미를 보존하고, 새 후보는 형태 조건까지 적용한 실제 허공 발동을 별도로 기록한다. 분모는 실제 발동 수다. 생존 시간이 서로 다르므로 종결 누적 비율은 기전 기술 통계이며 인과적 개선율이 아니다.

[사전 선언과 실행 절차](../runbooks/run-weapon-holdout.md)에 따라 seed20000–20031 × 사람 규칙A/B/C × 정책6 =576조건을 실제3회씩 실행한다. 총1,728회이며 독립 사례를1,728개로 세지 않는다. 코드·데이터·프로필·DLL·소스 commit을 동결하고 holdout은 후보가 CI를 통과해 병합된 뒤 한 번만 연다. smoke는 다른 seed9100을 쓴다. 원래 R2/R3와 c′ 재판정은 보존한다.

## 비용과 거절한 대안

- 전역 교체는 역사 해시와 회귀 근거를 없애므로 거절했다. 명시적 프로필 확장의 유지 비용을 감수한다.
- 피해만 무한 증가시키는 마지막 행 이후 꼬리는 이번 레벨별 혼합 성장 요구와 맞지 않아 거절했다. 상한에서 카드 선택 분포가 바뀌는 영향은 후보의 일부다.
- 조건 행렬을 늘린 축별 최적화·사람 경로 추가 제거는 승인 범위 밖이다. 단일 후보를 실패 후 다시 보정하지 않는다.
- 더 많은 고유 타격과 광선 판정은 CPU 비용을 늘릴 수 있다. 헤드리스 결정론·검사와 실제 실행만 검증하며 모바일 성능·시인성·조작성을 보증하지 않는다.

## 검증

공간 경계, 상하·대각 방향, 정지 방향 유지, 행 선택·희귀도 상한·최대 레벨 후보 제외, 광선 수·관통·중복 방지, 실제 HP 장부·허공 발동을 기능 검사한다. 잘못된/누락된 데이터는 loader와 스키마에서 거부한다. 역사 결정론 fixture는 바꾸지 않고 실제 net8.0/netstandard2.1 DLL의 후보 결과도 비교한다. 전체 `tools/check.sh`, PR CI와 동결576조건의 관문은 실행 후 별도 결과로 연결한다.

기존 parity 기준의 `data` 입력은 기준 파일이 지정한 과거 commit에서 파일별로 추출한다. 새 프로필·스키마 파일을 추가하면 전체 데이터 디렉터리 해시가 달라지기 때문이다. 역사15조건은 그 고정 입력에서 기존 gameplay/metadata 해시를 모두 비교하고, 후보1조건은 현재 데이터로 실제 두 DLL을 비교한다. 역사 golden JSON을 새 해시로 덮거나 metadata 검사를 약화하지 않는다. 이는15×3×2 +1×3×2 =96실행이다. 원본 commit이 없는 얕은 clone은 명확히 실패하며 CI는 전체 이력을 가져온다.

진단의 기존 `rankIncrements`는 희귀도가 요청한 증가량을 세므로 레벨12에서 실제 적용된 증가량과 다를 수 있다. 성장표 적용 레벨은 정본 `weapon-equipment.csv`의 실제 종결 rank로 확인하며 요청 증가량을 실제 성장으로 해석하지 않는다.
