# ADR0041: 승인된 설계를 공통 동작 단위로 검증하고 별도 실행으로 연결

- 상태: 승인
- 날짜: 2026-10-10
- 연결 이슈: [#143](https://github.com/hyunlord/bs-mobile/issues/143), [#147](https://github.com/hyunlord/bs-mobile/issues/147), [#148](https://github.com/hyunlord/bs-mobile/issues/148)
- 선행: [ADR0039](0039-versioned-design-catalog.md)의 카탈로그 경계를 유지하고 로스터 검토 대기 상태를 이번 승인으로 대체한다.

## 맥락

v1의 도구 경험치·진화·물품 연결이 일부 빌드에 몰려 있었고 긴 설명을 공통 구현 단위로 셀 수 없었다. 사용자는11개 수정 후 설계 병합과 별도 wave-1a 구현을 승인했다. 기존 실행·역사 해시·미확정 경제 수치는 보존해야 한다.

## 결정

동일 카탈로그 파일의 개정을 designed-v1.1로 올리고 approvalStatus를 approved로 둔다. designStatus는 designed-v1 분류를 유지한다. 기존 레코드 ID·종류·계보는 보존하며 원래 v1은 Git 역사에 남긴다. 현재 실행 프로필에 설계 데이터를 합치지 않는다.

모든 콘텐츠에 짧은 cardText와 유한 공통 primitives·형식화된 params·bespoke 예외를 둔다. 단위 레지스트리의 operationSupport는 문법 허용·처리기·프로필 선택·관측·고유 의미 일치를 분리한다. 설계 승인이나 처리기 존재를 실제 동작 완료로 세지 않는다. 스키마·분포·참조·완료 사건·웨이브 검사는 CI에서 자동 실행한다.

재료 목표는 해당 초기 도구를 지원하는 프로필에서만 열고 클리어 기본분은 네 재료에 독립 지급한다. 행동으로 번 추가분과 기본 지급의 원장을 분리한다. 아군 무리는 하나의 Core 개체로 표현하며 공유 동시 개체 예산을 두되 숫자는 측정 전 확정하지 않는다.

설계 PR의 CI 통과·병합 후 기존 실행을 보존하는 새 wave-1a 프로필을 별도 PR로 구현한다. 실행 designRef는 catalog·revision·동일 ID·동일 kind를 엄격히 검사하고 동작 증거를 함께 남긴다. 현재 설계 PR에서 실행 로더나 Core를 변경하지 않는다.

## 결과와 비용

163개 설계를 같은 문법으로 검사할 수 있지만 표현할 수 없는 고유 동작은 bespoke로 드러나 후속 구현 책임이 남는다. 파일 바이트 변경으로 전체 데이터 출처 해시가 달라져도 역사 상태 해시 알고리즘은 바꾸지 않는다. 사람 판독성·재미·성능은 정적 검사로 판정하지 않는다. #126·#98 보류는 유지한다.

## 거절한 대안

- 기존 프로필 덮어쓰기: 이전 실행과 새 설계의 차이를 분리할 수 없어 거절했다.
- 자유 서술문을 공통 단위 이름만 붙여 포장하기: 파라미터 계약과 구현 여부 집계가 불가능해 거절했다.
- 모든 물품에 강제 대가: 사용자가 철회했으며 동작에 없는 불이익을 만들므로 거절했다.
- 승인까지 다시 대기: 사용자가 수정 조건 충족 후 재승인 불필요를 명시했다.

## 검증

[카탈로그 계약](../design/designed-v1-catalog-contract.md)과 [공통 단위](../design/mechanic-primitives.md)의 자동 규칙, 설계 전용 diff와 원본 보존을 PR에서 확인한다. 실제 CI 결과는 병합 PR 링크가 정본이다. 1a의 최종 검증은 Mac 플레이와 영상이며 이 ADR 자체는 실행 증거가 아니다.
