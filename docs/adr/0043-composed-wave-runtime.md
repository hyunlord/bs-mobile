# ADR 0043: 기록된 한 판을 보존하는 공통 동작 조립

- 상태: 승인된 사용자 요구에 따른 구현 완료, PR·CI 병합 검증 대기
- 날짜: 2026-10-10
- 연결: [#167](https://github.com/hyunlord/bs-mobile/issues/167), [#166](https://github.com/hyunlord/bs-mobile/issues/166)
- 선행: [ADR0042](0042-wave1a-runtime-isolation.md)

## 맥락

wave-1a의 종류별 분기는 승인 설계의 공통 단위를 실행하는 범용 문법이 아니다. 물품 분기가 공격·작업·적 처리에 흩어져 있다. 사용자는 28개 레코드의 동작과 결정론 해시를 유지하면서 단위와 파라미터로 조립하고, 물품을 사건 구독으로 옮기도록 지시했다. 1a 선택에는 bespoke 예외가 없으며 설계 전체의 44개 예외를 새 임의 전용 코드의 허가로 해석하지 않는다.

## 결정

공격 형태·작업 잔류물·성장·완료 원장·아군 작업·발동 조건과 효과·진화 교체의 실행 프로그램을 명시한다. 콘텐츠 ID는 참조이며 처리기 선택 조건이 아니다. 역사 enum은 기존 데이터 어댑터와 직렬화 호환 경계에 남길 수 있으나 새 런타임의 레코드별 분기 역할을 하지 않는다.

물품 구독은 같은 틱의 원래 호출 위치에서 동기 실행한다. 소유 순서·타깃 정렬과 동률·난수 소비·원장 식별자·공개 사건 순서를 보존한다. 내부 통지를 공개 사건으로 다시 발행하거나 다음 틱으로 미루지 않는다.

실행 프로그램이 역사 정의와 정확하게 같을 때만 기존 codec 바이트를 유지한다. 새 단위나 실행 파라미터 변경은 정규화된 버전 식별값에 반영한다. ID나 revision만 같다는 이유로 실행 차이를 해시에서 제외하지 않는다. null wave 및 역사 프로필의 직렬화는 변경하지 않는다.

원래 리플레이는 원래 데이터 디렉터리와 새 바이너리로 검사한다. 데이터 파일 전체를 포함하는 DataHash와 시뮬레이션 해시는 서로 다른 계약이다. 기록의 DataHash를 바꾸거나 검사 우회를 넣지 않는다. 별도로 같은 입력에서 기존1a의 체크포인트·최종 해시와 사건 순서를 대조한다.

1b의 데이터 확장 증명은 독립된 검사 표본이며 제품 프로필에 편입하지 않는다. 공통 처리기를 먼저 고정한 뒤 데이터만 추가하여 실제 상태 변화와 음성 대조를 검증한다. Lattice에는 단위별 지원 파라미터·제한·검증 경로를 기록하며 문법 사용량을 구현률로 승격하지 않는다.

## 결과와 비용

엄격한 문법 검사·호환 어댑터·실행 검증을 함께 유지해야 한다. 지원 범위는 26개 부분 실행 단위, 1개 표현 경계, 2개 로더 경계이며 9개 단위는 미지원이다. 이는 38개 단위의 전체 구현이나 임의 파라미터 조합 지원을 뜻하지 않는다. 물·건물·아군·쌍 성장·적 예고의 미지원 조합은 실행 전에 거부한다. 역사 파일 복사본은 검증용 로컬 입력이며 새 배포 데이터의 이중 정본이 아니다. 수치·경제(#126), Fold7(#98), 1b 제품 구현은 계속 보류한다.

## 거절한 대안

- 종류 enum 이름만 단위로 변경: 레코드별 분기와 확장 비용이 남는다.
- 새 파라미터를 해시에서 제외: 다른 규칙이 같은 해시를 갖게 된다.
- 골든을 새 결과로 교체: 과거 한 판의 보존을 증명하지 못한다.
- 비동기 사건 큐: 기존 효과 적용 순서를 바꾼다.

## 검증

- 대상 Wave 테스트 114개와 Node 콘텐츠 검사 14개 통과. 전체 로컬 검사는 중복 실행하지 않았으며 전체 검사·타깃 교차 검증은 PR CI가 담당한다.
- 기존 입력 5seed × 3000틱 골든을 보존했다. 원본 native07·A03 재생은 각각 27000틱이며 원본 `537d506` 데이터와 실제 net8.0/netstandard2.1 DLL에서 모두 통과했다(총 4회). native07 최종 해시는 `97152EB9E83B4158DB8714AAA76CE73435595B3CC3A62E918918E87480A219ED`, A03은 `2E394387DDE118A2F84E76419FC381474C4F071BCAF06D5E0C8A694EF8CE5FE6`이다. 마지막 검증 전용 수정은 시작 시 허용 조합을 좁히며 실행 순서·규칙을 바꾸지 않는다.
- 새 데이터로 옛 재생을 실행하면 `Consumed data hash mismatch`로 거부한다. 새 authored programs의 원자료 DataHash가 옛 데이터와 다름을 숨기지 않는다.
- 일반 처리기·검사 하네스를 먼저 커밋한 다음 JSON만 추가한 표본에서 경계돌 망치의 전방 타격과 유인 자갈함의 명중 후 경로 전환을 확인했다. 미소유 음성 대조와 사건 순서를 포함한다. 1b 제품 편입·전체 설계 문구·아트 검증은 아니다.
- 독립 리뷰 Rawls2의 단위 제거·진화 형태·유효 튜플 교환 문제를 15개 실패 재현 검사로 고정하고 수정했다. 리뷰 봇 검사 한도를 독립 리뷰로 대체하며 CI 통과와 리뷰를 구분한다.
- Lattice는 승인 설계의 단위 사용량과 실제 프로그램 참조를 별도로 센다. 기존 역사 조건을 명시한 진화의 실행 전용 event-gate 3개를 설계 사용량에 더하지 않는다.

이 ADR 자체는 성능·화면 판독·재미 관문 증거가 아니다. PR 준비 시 최신 main `03c5f22`의 마지막 ADR은 0042였고 0043을 사용했다. 0040은 보존한다. 병합 직전 최신 main의 번호를 다시 확인한다.
