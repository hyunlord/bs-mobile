# ADR0073: 선택적 GitHub 게시의 API 사용량과 실패 경계

- 상태: 제안 — 구현·검증은 승인 범위이며 병합은 사용자 검토 대기
- 날짜: 2026-10-28
- 연결 이슈: [#469](https://github.com/hyunlord/bs-mobile/issues/469)

## 맥락

Durable metrics는 CI가 성공할 때 과거 JSON 전체를 내려받고 다시 올렸다.
2026-10-28 읽기 전용 조회에서 metrics-history의 JSON 자산 429개를 확인했다.
PR·수동 CI까지 보관하면 선택적 기록 작업이 API 할당량을 추가로 소비한다.
Lattice의 지도 생성과 선택적 PR 댓글 게시도 서로 다른 성공 조건이다.
품질·비밀 검사의 실패를 선택적 게시의 할당량 부족과 혼동하면 안 된다.

## 결정

- metrics는 같은 저장소의 main push로 시작해 성공한 CI workflow_run만 보관한다.
  생성기는 신뢰하는 main에서 가져오고 입력 JSON은 기존 생성기로 검증한다.
- 생성 시각 기준 최신 30개 기록만 내려받는다. 새 기록을 포함한 HTML은 최대
  31개 기록을 표시한다. 새 JSON 한 개와 index.html만 올리며 과거 자산은 삭제하지 않는다.
- 게시 명령은 HTTP 429 또는 할당량 소진 근거가 있는 HTTP 403만 1초·2초 간격으로
  재시도한다. 최초 실행 포함 최대 3회 후 명시적인 SKIPPED notice와 종료 코드 0을 낸다.
  권한 403, 인증 401, 누락 404, 서버·네트워크·JSON 검증 오류는 실패한다.
- 부분 다운로드 후 재시도할 때 artifact는 시도마다 새 임시 디렉터리에 받는다.
  Release 다운로드는 이번 실행의 임시 경로에서만 덮어쓴다. 공유 경로를 정리하지 않는다.
- Lattice 댓글의 동일한 경계는 [upstream PR #112](https://github.com/hyunlord/lattice/pull/112)의
  고정 SHA `3ee0c196f3b373d172df5a57a1670c3d44a3080e`로 가져온다. workflow와 tool pin을
  함께 갱신한다. 기존 pin에서의 좁은 backport로 무관한 upstream 변경 343개를 피한다.
- quality·secrets 정의와 필수 검사, 지도 생성·검증의 실패 조건은 유지한다.
  두 PR은 draft로 남기며 자동 병합하지 않는다.

## 결과·비용

과거 JSON은 Release에서 계속 접근할 수 있지만 HTML은 전체 역사 대신 최근 창을 보여 준다.
할당량 소진 시 해당 실행의 게시가 생략될 수 있으며 notice로 구별한다.
여러 자산 업로드는 원자적이지 않아 일부 업로드 뒤 SKIPPED가 날 수 있다.
일반 API 오류와 입력 손상은 계속 실패하므로 자동 복구나 성공으로 숨기지 않는다.

## 거절한 대안

- 모든 JSON 다운로드·재업로드: 기록이 늘수록 API 사용량도 계속 늘어난다.
- 모든 403 또는 모든 게시 오류 무시: 권한·검증 문제를 감춘다.
- 무한 재시도·과거 자산 삭제: 유한 실행과 역사 보존 조건을 위반한다.
- Lattice 최신 main 전체 도입: 댓글 실패 처리와 무관한 변경까지 넓어진다.

## 검증

Node 22.23.4의 실제 fake-gh 실행으로 API 단계별 제한 재시도, SKIPPED 종료,
일반 오류 실패, 부분 파일 복구, 429개 중 30개 다운로드와 두 파일 업로드를 검사했다.
관련 metrics 35개와 정책 35개 검사가 통과했다. 초기 CI의 오래된 dispatch 문자열
단언 실패와 ADR 누락 실패는 기록으로 보존하며 최종 CI를 별도로 확인한다.
실제 main 게시·실제 할당량 소진·Unity·기기 실행의 증거로 확대하지 않는다.
