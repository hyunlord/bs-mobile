# ADR0082 · 월드 지도 저장과 원자적 도시 배정

상태: 구현 초안, 실행 검증 대기. 날짜: 2026-11-02. 연결: [#625](https://github.com/hyunlord/bs-mobile/issues/625).
근거: [GDD18](../design/gdd/18-slg-world-map-proposal.md), [ADR0078](0078-server-domain-command-transactions.md).
main의 최대 ADR 번호 0081을 확인하고 0082를 사용한다. 직접 전투 Core 계약 제안은 별도 ADR0083이다.

## 맥락과 범위

서버 하나에 공유 지형과 도시 주소가 필요하다. 계정 생성 뒤 별도 요청으로 도시를
만들면 수용량 부족 시 도시 없는 신규 계정이 남는다. 계정별 도메인 JSON에 지도를
복제하면 타일 유일성과 여러 계정 간 배정을 보장하지 못한다.

이번 범위는 지도·주소·표식·AOI 조회와 도시 배정이다. 행군, 채집 재고, 보호막,
전투·보상은 후속 PR이다. Core·Unity·리플레이·기존 server_schema 3은 변경하지 않는다.

## 결정

- `data/opt-in/slg/world-map-v1.json`이 지도 크기·청크·지형 패치·시작권역·초기 표식의
  정본이다. 512×512, 32×32, 등록 목표 10,000과 좌표는 모두 [가설]이다.
  패치는 파일 순서대로 적용한다. 다리 패치가 물 위를 덮으며 플레이어가 지형을 변경하지 않는다.
- 시작 앵커에서 4방향으로 연결된 통과 가능 시작권역만 도시 후보가 된다. 평지·숲·다리는
  통과하고 산·물은 막힌다. 시작권역의 고립된 통과 가능 타일이나 고립된 표식은 로딩을 거부한다.
  표식 좌표는 도시 후보에서 제외한다. 도시는 통행 장애물이 아니다.
- 최단경로는 BFS, 다음 좌표 `(x,y)` 오름차순으로 동률을 고정한다. 반환값에 양 끝점을
  포함하고 같은 좌표는 한 점, 불통 경로는 null이다. 공개 경로 발령 API는 아직 없다.
- `world_schema` 1, `world_instances`, `world_locations`, `world_targets`를 별도 생성한다.
  초기화는 transaction advisory lock 아래 수행한다. 미래 schema를 거절하고 이미 생성된
  월드의 ID·콘텐츠 해시가 달라지면 자동 재배치 대신 실패한다. 재시작은 기존 대상을 보존한다.
- `world_locations`는 검증된 도시 후보와 초기 목표 타일 목록이다. DB의 복합 FK가
  목록 밖/다른 용도의 위치를 막고, unique `(world_id,x,y)`가 한 타일의 중복 대상을 막는다.
  도시 소유 계정도 unique이며 `target_id + generation`으로 대상 사건을 식별한다.
- 도시 ID는 계정 ID에서 안정적으로 유도한다. 배정 순서는 빈 후보의 `(x,y)` 오름차순이다.
  초기 generation 1은 식별 프로토콜이며 재생성 시간이나 게임 수치가 아니다.
- 신규 `AccountStore.CreateAsync`는 같은 트랜잭션에서 월드 잠금 → 계정 INSERT → 도시
  INSERT → 세션 INSERT 순서로 실행한다. 만원이면 `world-capacity-exhausted`(HTTP 409)로
  전부 rollback한다. 새 서버를 자동 생성하거나 기존 도시를 겹치지 않는다. Host는 WorldStore를
  항상 등록한다. 기존 독립 계정 단위 테스트의 선택적 world 미주입 경로는 그대로 유지한다.
- 기존 계정은 인증된 `POST /v1/world/city`로 한 번 배정한다. 요청에 좌표나 시간을 받지 않고
  기존 배정이 있으면 그대로 반환한다. 계정 payload/version을 재작성하지 않는다.
  GET은 배정하지 않는다. 배정 전 기존 계정 조회는 404 `city-not-assigned`다.

## 잠금과 시간

배정: **월드 행 → 계정 행**. 계정 행을 잡은 공통 writer가 월드를 역순으로 요청하지 않는다.
기존 계정 등록은 계정 잠금 뒤 삭제 여부를 재확인한다. 신규 계정은 월드 잠금을 잡은 뒤
계정 INSERT를 하므로 동일 순서다. 월드 시간은 서버 UTC와 저장 high-watermark 중 큰 값으로
갱신하며 배정 `created_ms`에 사용한다. 이 값은 기존 계정의 실제 생성시각이 아니므로
후속 신규 보호막의 기준으로 재사용하면 안 된다.

후속 다계정 상호작용은 월드 → 필요한 연맹 UUID 오름차순 → 계정 UUID 오름차순으로
확장할 계획이다. 현재 연맹 writer/계정 삭제는 연맹 → 계정 순서를 유지한다. 월드 행을
그 뒤에 획득하는 훅을 추가하지 않는다. 실제 교착 검사는 낮 PostgreSQL 실행 관문이다.

## 공개 조회와 데이터 정책 경계

`GET /v1/world/chunks/{chunkX}/{chunkY}`는 인증 후 한 청크의 지형과 표식만 반환한다.
범위 밖 청크는 400, 잘못된 인증은 401이다. 청크별 최대 타일 수는 데이터의 chunkSize²다.
목표와 현재 연맹명은 같은 DB 읽기 snapshot에서 가져온다. 지갑·병력·큐·인증 정보는 없다.
연맹 이름은 현 회원 관계를 조회하며 과거 복사본을 저장하지 않는다.

가정: 현재 계정 공개 이름 필드가 없으므로 도시에는 AccountId만 반환한다. 표시용 계정명은
②의 공개 이름 계약 이후 연결한다. 지금 이를 이름 표시 완료로 보지 않는다. 자원 종류와
PvE 콘텐츠 ID는 제공하지만 아직 별도 등급 필드가 없으며 후속 목표 콘텐츠 계약에서 다룬다.
삭제 계정 도시는 AOI에서 숨기고 위치/원장은 보존한다. 자동 재사용/삭제는 하지 않으며
②의 유예·복원·익명화 정책 PR과 합칠 때 이를 다시 검증한다.

현재 초기 배치는 자원지 3개와 PvE 표식 5개인 서버 검증용 [가설] 배치다. 최종 플레이
밀도·분포, 10,000계정의 목표 접근거리, 1,000 CCU/5,000 행군 성능을 증명하지 않는다.

## 거절한 대안과 비용

- 계정 생성과 도시 배정의 분리 커밋: 수용량 실패 시 반쪽 계정이 남는다.
- 계정 도메인마다 월드 사본 저장: 다계정 원자성과 중복 타일을 보장하지 못한다.
- 서버 코드에 지도 수치 상수: AG003 위반. 명시적 입력 검증의 메모리 한도만 코드에 둔다.
- 자동 콘텐츠 해시 교체/초기 표식 재삽입: 과거 세대나 도시를 덮을 위험이 있어 명시적 이관을 요구한다.

단일 월드 행은 배정을 직렬화한다. 초안의 단순한 정합성 선택이며 처리량 합격 주장이 아니다.
현행 서버 Development/Prototype 가드를 유지하고 공개 배포는 하지 않는다.

## 검증

야간 코드·테스트 작성 상태: **.NET 빌드, 단위/DB/HTTP 테스트 NOT_RUN**.
경계 좌표·동률 경로·다리/섬·목표 겹침·수용량을 단위 검사하고, 독립 PostgreSQL에서
동시 생성·기존 계정 중복 배정·수용량 rollback·재시작·미래 schema/해시 거절·삭제 계정
숨김·인증/AOI 경계를 검사한다. 실제 테스트 수치와 동일 SHA 증거는 낮 실행 후 기록한다.
