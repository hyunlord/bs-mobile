# ADR 0012: 검증 원본을 보존하면서 작업 트리를 작게 유지한다

- 상태: 채택, R1 / #44
- 사용자 결정: Projects 미사용, 라벨·마일스톤 대체(#2); #32·#42 권고 승인

## 문제와 결정

S0–S5의 원자료를 커밋한 결과 사례별 JSON, 중복 CSV, 압축 보관본과 화면 캡처가 작업 트리를 크게 만들었다. 기존 결과와 S4 실패 판정은 변경하지 않는다. 과거 git 이력은 재작성하지 않는다. 기준 커밋 `b3f4830bb8c441343f61362e2b39e474f5709290`의 증거와 리그 파일 전체를 별도 GitHub Release `phase0-evidence-original-20261008`에 보관한다. 저장소에는 요약 CSV, 보고서, SHA-256 매니페스트와 다운로드·재현 설명을 남긴다.

원본을 트리에서 제거하기 전에 업로드한 자산을 새 디렉터리에 다시 다운로드한다. 자산 SHA-256, 깨끗한 압축 해제, 정확한 파일 집합, 모든 파일의 SHA-256과 바이트 크기가 매니페스트와 같아야 한다. 실패하면 삭제하지 않는다. Release 자산은 덮어쓰지 않으며 정정은 새 버전으로 추가한다. Actions 아티팩트는 실행 중 임시 증거로 사용할 수 있으나 최종 단계 증거는 만료 없는 Release 자산으로 남긴다. GitHub Release를 관리자가 삭제할 가능성까지 막는 저장소 수준의 WORM 보장은 아니다.

앞으로 대량 실행 JSON, 사례별 CSV, 스크린샷 묶음, 압축 원자료는 `artifacts/` 같은 무시 경로에서 생성하고 Release로 전달한다. 저장소 매니페스트는 CSV로 유지한다. 전체 다운로드 없이도 보고서의 결론과 관문, 소스 SHA·데이터 해시·실험 조건·표본 수·독립 반복 수·실패 이유를 읽을 수 있어야 한다. 원본 결과와 수정 실험은 각각 다른 이름과 자산으로 보관한다.

## 예산과 도구

PR의 merge-base에서 실제 head까지 새 파일의 git blob 크기 합과 기존 파일의 양의 증가분을 합해 **5,000,000바이트**를 초과하면 CI 실패다. 5MB는 십진 단위이며 정확히 경계인 경우 허용한다. 삭제량은 추가량을 상쇄하지 않는다. 이름 변경·복사도 새 경로의 전체 크기를 센다. 이는 작은 파일을 먼저 추가한 뒤 크게 늘리는 우회를 막기 위해 사용자 요구의 신규 파일 예산보다 엄격하다. 기준 ref를 해석할 수 없으면 실패한다.

`docs/` 아래 압축 파일과 압축 시그니처, `raw`·`raw-*` 디렉터리, `docs/evidence/` 아래 새 JSON은 차단한다. Python 확장자·Python 실행 shebang 및 symlink/submodule도 가드에서 차단한다. 임의로 이름을 바꾼 파일의 모든 의미를 자동 판별한다는 주장은 하지 않는다. 보고서·매니페스트만 유지하는 정책은 코드 리뷰에서도 확인한다.

저장소 도구 언어는 .NET과 Node다. 기존 shell 파일은 두 런타임을 호출하는 얇은 진입점으로 유지한다. 그래프는 Node 표준 라이브러리로 SVG·PNG를 생성한다. 패키징은 Node가 tracked 파일 스냅샷·시스템 zip/unzip·CRC·깨끗한 추출·파일 집합·해시 검증을 수행한다. 새로운 패키지 의존성을 추가하지 않는다. 과거 ADR0011과 S4 보고서의 Python 명령은 당시 재현 환경의 기록이며, 현재 재현은 `docs/runbooks/run-league.md`의 Node 명령을 따른다.

## 보고와 작업 체계

새 보고서는 첫 줄에 `관문: 통과/실패/부분`을 쓰고, 첫 10줄 이내에 변경 사항·관문 결과·사용자 결정 필요 여부를 요약한다. 역사적 원본 보고서는 원문과 실패 결론을 보존하고 별도 현행 안내에서 변경 사항을 설명한다. 원자료의 이동은 과거 검증 결과를 재검증하거나 새 실험의 통과로 바꾸지 않는다.

Projects 보드는 만들지 않는다. GitHub 이슈 라벨·마일스톤과 이슈→PR→CI를 공식 작업 추적으로 사용한다. 추가 Projects 권한을 요구하지 않으며 #2는 사용자 선택을 기록해 닫는다. 의존성 운영은 ADR0013을 따른다.

## 검증 범위와 기각한 대안

트리 전후 크기는 동일한 git-tracked 파일의 합으로 보고하고 `.git`과 무시된 빌드 산출물은 따로 구분한다. 과거 blob이 `.git` 이력에 남으므로 clone 전송량까지 줄었다고 주장하지 않는다. 실제 5MB 초과 PR을 만들어 CI 실패 후 병합 없이 닫는다. 정상 PR·로컬 경계 테스트와 실제 Release 다운로드 검증을 함께 남긴다.

- 과거 history rewrite: 사용자 금지이며 기존 증거 SHA·링크를 손상한다.
- 원본 삭제 후 업로드: 다운로드 불능이나 손상 시 되돌릴 검증된 보관본이 없다.
- Actions 만료 아티팩트만 최종 증거로 사용: 장기 재현에 불충분하다.
- 압축해서 git에 유지: 크기와 조회 비용을 숨기며 새 정책과 맞지 않는다.
