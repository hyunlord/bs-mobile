# ADR 0042: wave-1a의 실행 경계와 동작 증거

- 상태: 승인된 #143 범위의 구현 결정
- 날짜: 2026-10-10
- 연결: [#148](https://github.com/hyunlord/bs-mobile/issues/148), [#152](https://github.com/hyunlord/bs-mobile/issues/152), [#153](https://github.com/hyunlord/bs-mobile/issues/153)

## 결정

`wave-1a`는 별도 실행 프로필이다. 기존 production·실험·first-playable 데이터와 재생을 보존한다. 선택 집합은 무기5·도구4·진화3·연결 물품6·범용 물품2·일반 적6·보스1·챕터1이다. 기존 영웅·영지 참조는 외부 데이터에서 선택하며 Core에 ID를 고정하지 않는다.

실행 레코드는 승인된 designed-v1.1 레코드를 `designRef`로 가리킨다. 설계의 primitive와 파라미터를 확인하는 로더·검사기가 참조 누락과 설계 변경을 거부한다. 이 일치는 실제 동작 증거를 대신하지 않는다. 구현된 공격·작업·적 행동은 typed 계약으로 Core에서 결정하고 Unity는 읽기 전용 상태와 사건을 표현한다.

무기는 레벨별 성장표로 피해 외 범위·빈도·타격 수 등 형태에 맞는 축을 키운다. 궤도·유도탄·연쇄는 위치와 시간을 가진 실제 공격이다. 도구의 경험치는 성숙 자체가 아니라 수확 접촉, 실제 관개, 유한 재료의 출고, 임무 완료·귀환과 연결한다. 작업·보상 식별자로 중복 지급을 막고 파손·수리가 새 지급 권리를 만들지 않게 한다. 사람 무리는 대표 스프라이트를 사용하는 한 개체로 취급한다.

새 상태와 재생 버전은 wave 계약이 존재할 때만 적용한다. 기존 계약이 null인 상태의 직렬화에 새 표식이나 필드를 덧붙이지 않는다. 같은 정상 입력 재생을 net8.0과 netstandard2.1 구현에서 반복하고 결정론 해시를 비교한다. Unity 에디터와 실행판 검증은 별도 표면의 증거로 보고한다.

## 보류와 검증 경계

실행에 필요한 새 상수는 기능 확인용 잠정값이다. 기존 수치를 물려받은 부분과 새 형태 때문에 정한 부분은 실행 데이터에서 구별한다. #126의 수치·밸런스·경제 승인으로 해석하지 않는다. 봇 검사는 결정론·무충돌에 한정하고 우세 정책·생존율을 판정하지 않는다. #98 Fold7 검증도 보류한다.

Mac 영상은 실제 Core 상태가 바뀌는 플레이에서 캡처한다. 자동 입력은 정상 카드 선택과 이동을 사용하고 무적·경험치 지급으로 증거를 대체하지 않는다. 가속된 구성요소 QA와 정상 속도 플레이 증거를 구별한다. 최종 관문은 플레이 가능한 Mac 빌드와 무기·수확·진화·적 예고·보스 국면이 보이는 영상이다.

## 거절한 대안

기존 프로필을 덮어쓰면 역사 재생을 잃으므로 거절했다. Unity에서 효과를 흉내 내고 Core 동작으로 세는 방식, 설계 참조만 연결한 것을 구현 완료로 세는 방식도 거절했다. 이 ADR 자체는 구현·CI·화면 관문의 통과 증거가 아니다.
