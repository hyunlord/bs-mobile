# ADR0034: 판 밖 상태와 한 판 규칙을 분리한 상한 있는 성장

- 상태: 채택, 2026-10-09. 수치·경제 목표는 실험 가설이며 관측된 리텐션이 아니다.
- 추적: [#115](https://github.com/hyunlord/bs-mobile/issues/115), [2단계 A P2](../design/07_ASTRA_GOAL_bs-mobile_phase2a.md)

## 구조

순수 Core의 `MetaCatalog`/`MetaState`/`MetaEngine`이 판 밖 규칙을 소유한다. Unity는 파일·시간을 읽어 명시적 입력으로 전달하고 화면을 그린다. 기존 `RunOptions`, 역사 해시, first-playable 정본은 보존한다. `MetaRunAdapter`는 선택한 챕터·해금·가신의 유한 배율을 별도 콘텐츠 사본에 적용한다. 메타가 없으면 기존 객체를 그대로 반환한다. 계정 재고를 판의 점수나 전투력으로 직접 읽지 않는다.

대안인 기존 시뮬레이션에 계정 상태를 직접 연결하는 방식은 역사 재현과 파일/시계 경계를 흐리므로 채택하지 않는다. Unity 전용 성장 규칙도 CLI 경제 검증과 달라질 수 있어 채택하지 않는다. 영웅·영지 ID는 추가로 고정하지 않는다. 6가신은 데이터가 지정한 공격/체력/이동/성장/아군/경험치 배율 중 하나를 실제 한 판에 주입한다. 장원 대장간은 가신의 강화 가능 상한만 열며 별도 힘 축을 만들지 않는다.

## 환산·성장·반복

자재 이름·상한·환산 계수는 데이터다. 수확·살아 있는 밭/건물/사람·도달 레벨·보스 결과로 환산하며 식량 재고 자체를 점수로 쓰지 않는다. 챕터별 판당 상한, 사망/포기/반복 배율, 계정 지갑 상한을 순서대로 적용한다. 클리어는 전체 길이 생존과 보스 처치가 모두 필요하다. 판 시작 전에 증가 순번·챕터·seed를 저장하며 일치하는 미정산 판 한 번만 정산한다. 완료 정산 의도가 저장되지 않은 중단 판은 다시 접속할 때 포기로 종료한다. 완료 의도가 남은 판은 아래 복구 절차로 실제 완료 결과를 한 번만 반영한다.

장원은 우선 깃발 하나를 먼저 고려하고, 지불 가능한 다른 건물도 결정적인 순서로 자동 성장한다. 재료 부족은 설명하며 자동 부채나 무한 생산을 만들지 않는다. 가신 레벨1~20과 조각 승급, 20도전의 누적 진행·실제 콘텐츠 해금은 별도로 저장한다. 모든 계수와 수량은 양수/상한/참조 검사를 거친다.

## 시간과 저장

Core는 시계를 읽지 않는다. 호스트의 단조 초와 UTC초 두 관측을 받아 단조 시간 차를 생산 기준으로 사용한다. 역행·재시작 불일치·두 시간 차의 허용 오차 초과에는 생산하지 않고 기준만 갱신한다. 시간 조작으로 한 번 큰 보상을 받거나 이후 정당한 시간을 무한 선취하지 않도록 보상은 데이터 상한을 적용한다. 오프라인 로컬 저장은 사용자가 파일 자체를 변조하는 공격을 막는 서버 권위가 아니다.

BCL 바이너리 codec은 버전·길이·체크섬·유한 상태를 검증하며 단계별 이행을 수행한다. Unity 파일 호스트는 임시본의 완전 기록 뒤 현재본을 교체하고 마지막 정상본을 보존한다. 손상 시 정상 백업을 복구하되, 더 최신의 알 수 없는 버전을 빈 저장으로 덮어쓰지 않는다. 완료·포기 정산은 검증된 직전/직후 상태를 `terminal.bin`에 먼저 원자적으로 기록한 뒤 `progress.bin`을 교체한다. 현재 미정산 순번과 직전 상태가 모두 일치할 때만 재시작 시 완료 의도를 복구한다. 이미 반영된 의도와 이전 순번은 중복 지급하지 않는다. 새 판의 미완료 결과에 옛 의도를 적용하지 않는다. 원본 상태와 의도가 충돌하거나 의도가 진행보다 앞서면 빈 상태로 리셋하지 않고 실패를 드러낸다. UI는 저장 성공 뒤에만 리플레이를 확정하고, 실패 시 같은 종료 결과의 재시도를 제공한다. 파일 I/O는 Core로 들어가지 않는다.

## 검증

중립 메타의 기존 해시/리그 (b)·c′, 챕터별 실제 지도/적/보스 차이, 여섯 능력의 실행 효과, 환산 상한·중복 정산, 시간 역행/전진, 저장 왕복·단계 이행·손상 복구를 검사한다. 경제 시뮬레이션은 세 플레이 빈도 가설과 실제 사용한 계수를 공개하고 목표가 실패하면 그대로 보고한다. 실기 #98과 깨끗한 계정 #114 관문을 Core/에디터 결과로 대신하지 않는다.
