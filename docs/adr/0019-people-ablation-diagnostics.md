# ADR 0019: 사람의 피해와 가로채기를 분리하고 무기 저생존을 진단한다

- 상태: 사전 선언, #68 / 원인 분석 및 보정안 검토 #61
- 승인 범위: 진단용 제거 실험과 계측. 밸런스 수치·콘텐츠 보정은 하지 않는다.

## 질문과 입력 동결

사람 정책의 생존 우위가 사람의 직접 피해, 적 공격 가로채기, 둘의 상호작용 중 무엇과 연결되는지 같은 초기 seed로 비교한다. 무기 정책은 실제 무기 칸·획득·rank 성장·공격 형태·위협 대비 실제 화력을 함께 관찰한다. 기본 영웅·영지 ID는 CLI 데이터 선택에만 있고 Core 분기에 넣지 않는다.

주 실험은 기존 R3의 s4b-02와 현재 승인 데이터를 유지한다. people·weapon × 사람 규칙 A/B/C × seed42–73 × control/offense-off/interception-off/both-off = 768조건이다. 각 조건을 3회 반복하며 21,600틱 또는 자연 사망까지 실행한다. R2의 무기 생존 5/6/5를 R3의 4/8/5와 혼동하지 않도록 동결 R2 fixture로 weapon control 96조건도 같은 방식으로 실행한다. 총864조건·2,592실행이며 독립성 단위는 대응된32 seed 블록이다. 반복3회를 독립 표본 수로 세지 않는다. R2 control96개와 R3 control192개는 역사 runs/determinism CSV에서 가져온 개별 해시·틱·생존과 비교한다.

## 제거 경계

- offense-off: 사람 객체가 낸 공격의 실제 적 HP 감소만 억제한다. peasant/militia/vassal/guard/공격 가능한 returning과 도구 성장에서 나온 사람도 포함한다. 이동·목표 탐색·공격 cooldown 진행·노동·식량·징집·복귀 규칙은 유지한다. 건물 공격·도구 직접 발동·runtime pulse는 유지한다. AllyDamage만 0으로 만드는 것으로 대체하지 않는다.
- interception-off: 적이 근처 사람에게 공격을 넘기는 분기만 건너뛴다. 원래 영주·농지·건물 목표의 거리·cooldown 규칙은 지킨다. 사람 근처였다는 이유로 범위 밖의 원래 목표를 때리게 하지 않는다. 기존 코드는 사람의 물리 충돌 차단을 구현하지 않으므로 결과를 충돌/길막 효과로 부르지 않는다.
- both-off: 위 두 경계를 함께 적용한다. control은 같은 observer를 사용하지만 게임 동작을 바꾸지 않는다.

가로채기 관측을 위해 control에서 변경 가능한 Target()을 추가 호출하지 않는다. 캐시된 원래 목표와 refresh 필요 여부는 읽기 전용 관측이며 진짜 반사실적 목표와 구분한다. 사람 피해가 없어지면 적 생존·XP·카드·위협이 변하고, 가로채기가 없어지면 사람 생존·노동도 변한다. 따라서 같은 seed 대응은 초기 조건을 맞추는 것이며 이후 RNG·카드·목표 경로까지 같게 고정하지 않는다. 총효과 실험으로 해석하고 순수 직접효과로 주장하지 않는다.

## 계측과 결정론

진단 options/observer는 기존 RunOptions·World·catalog 해시 입력 밖에 둔다. 필수 IStateHasher 생성자 인자는 유지한다. 기존 gameplay hash와 별도로 진단 버전·제거 arm·입력/소스 식별자·결정론적 계측 digest를 묶는다. observer 자체는 RNG·게임 entity ID를 쓰거나 iteration 순서를 바꾸지 않는다. control observer 유무의 게임 해시 일치를 검사한다.

실제 HP 감소와 요청/억제 피해를 분리하며 사람·건물·도구 직접 발동·도구 성장·무기·pulse 출처를 구분한다. 무기는 실제 cap/보유 수/선택 후보/선택·rank(기존 카드 offer/chosen/rarity/level/tick 기록을 사용), 활성화·범위와 형태 조건·타격·요청/적용 피해를 기록한다. 위협은 생성 요청/허용/상한 차단·허용 HP·생존 HP·영주 근처 적·실제 공격과 목표별 피해로 표현한다. 임의의 합성 위협 점수를 만들지 않는다. slot 제외 카운터는 후보 자격 검사 호출 횟수이며 서로 다른 무기 개수나 실제 선택 기회를 뜻하지 않는다. 전체 rank 증가 카운터에는 도구·헌장도 포함되므로 무기 성장 곡선은 무기별 카드 이력·장비 표본으로 해석한다. 노동·인구·성장·음식은 살아 있는 구간의 관측으로 기록한다.

초기·300틱 간격·실제 종료 시점에 표본을 기록한다. 완주하면 초기 포함73개이며 죽은 뒤 표본을 채우지 않는다. snapshots.csv는 정규 300틱 격자 집계이며 nAlive/nDead/nAtRisk와 실제 관측 분모를 함께 둔다. 격자 밖 사망을 포함한 각 사례의 실제 마지막 표본은 terminal-counters.csv에 종료 틱과 함께 보존한다. RNG 누적 draw trace는 손실 없이 보존하며 최초 RNG 분기와 300틱 단위 `firstSampledTelemetryDivergenceTick`를 구분한다. 후자는 전체 World의 최초 상태 변화 시점이 아니다.

## 분석과 보관

대응 생존 전환(생존→사망 등), 21,600틱 상한 내 생존 틱 차이, 양쪽이 살아 있던 구간의 기전 지표를 비교한다. 2×2 상호작용은 `both - offense - interception + control`로 기록한다. 사망 뒤 결측과 실제 0을 섞지 않고 생존자만 남는 시점의 선택 편향을 표시한다. R2 계측 재현과 R3 제거 실험의 인과 해석을 분리한다. 보정 후보는 원인·기대 효과·위험·다음 검증 조건을 제안하고 적용하지 않는다.

최대4개 자식 프로세스, 프로세스당600초 제한으로 실행한다. 누락·중복·타임아웃·3반복 불일치·역사 control 불일치는 최종 판정을 차단한다. 일반 실행은 compact 진단 패킷과 해시만 저장하며 전체 SimulationResult JSON을 전량 생성하지 않는다. 반복2/3 상세를 중복 저장하지 않고 실제 실행 비교 증거를 남긴다.

공개 원자료는 R3 seed42/C의 2정책×4arm=8고정 사례와 추가 최대8사례뿐이다. 추가 선택은 caseId 사전순의 invariant 실패를 먼저, 남은 용량에는 사전순의 control/treatment 생존 전환 완전한 쌍을 중복 없이 넣는다. 쌍 전체가 들어가지 않으면 넣지 않는다. 필요한 원본을 재실행해 확보할 때 최초 gameplay/diagnostic hash와 일치해야 하며 최초 실패를 성공 재실행으로 덮지 않는다. 작은 정본 CSV·코드·원본 CSV 출처 해시는 Git에 남기고, CSV에서 재생성 가능한 보고·그래프·집계 파일을 원자료 Release에 중복 업로드하지 않는다. 신규 ZIP·CRC·전달 영수증은 없다.

## 검증 경계

단위 검사는 control 불변, 도구 출신 사람과 공유 Attack 경계, 건물/pulse 보존, 원래 목표 범위와 복귀 guard, 실제 피해 장부를 보호한다. 전체 리그는 위 표본·반복·source 조건을 만족해야 해석한다. Unity Editor·모바일 성능·조작성·재미의 검증은 포함하지 않는다.
