# ADR 0057: 타격 시점과 영웅 제작 방식을 규칙 변경 없이 비교한다

- 상태: 승인 범위 구현 — 최종 영웅·모션 방식은 사용자 영상 선택 대기
- 날짜: 2026-10-12
- 관련: [#246](https://github.com/hyunlord/bs-mobile/issues/246), [손맛](../design/gdd/06-feedback.md), [아트·캐릭터](../design/gdd/07-art-character.md)

## 결정

Core의 피해·처치·진화 사건으로 View 반응을 만든다. 적 그림 반동은 실제 위치나 충돌에 영향을 주지 않는다. 일반 처치에는 전체 히트스톱을 쓰지 않는다. 치명타 신호가 없는 상태에서 피해량으로 치명타를 추정하지 않는다([#247](https://github.com/hyunlord/bs-mobile/issues/247)).

보스 정지·처치 슬로는 표시 시계만 지연한다. 32개의 미리 준비한 Run/Wave 스냅샷 버퍼가 borrowed enemy storage의 수명을 보장한다. 세계·효과·소리는 표시 틱에서 전달하고 보간용 다음 상태는 사건 없이 참조한다. Core 입력·틱·해시와 HUD는 원래 시점을 유지한다. 저장 공간이 부족하면 미전달 사건을 순서대로 전달하고 표시 지연을 해제하며 복구 횟수를 기록한다. Time.timeScale이나 Core 따라잡기 정책은 바꾸지 않는다.

사용자는 같은 기존 B 부위로 (b) 관절 저작 후 굽기와 (c) 실시간 뼈대를 모두 시험하도록 승인했다. 무료 `com.unity.2d.animation` 16.0.1을 영웅 한 명에만 사용한다. 유료 도구·적 뼈대 전환은 하지 않는다. 같은 관절·동작 표본에서 b는 아틀라스를, c는 SpriteSkin 가중치 메시를 만들며 두 방식 모두 하체 걷기와 상체 공격을 합성한다. 기본 방식은 기존 B를 유지하고 `--hero-motion baked|live`가 명시된 검토 실행에서만 시제품을 선택한다.

추가 패키지의 빌드 크기와 실제 메모리·프레임 비용은 별도 실측하며, c의 자세 계산 시간만을 SpriteSkin 전체 비용으로 보고하지 않는다. 캡처 실행을 성능 증거로 쓰지 않는다. 새 컨셉 세 안은 모션 비교 원화를 바꾸지 않는다.

## 검증과 남은 관문

집중 Unity EditMode 38건, PlayMode 7건 통과 기록을 확보했다. 이후 통합 변경은 해당 검사를 다시 실행한다. 실제 같은 입력 영상·C05 800+ 효과 비용·사용자 손맛 및 최종 모션 선택은 아직 통과하지 않았다. PR은 이 증거와 한계를 그대로 보고한다.

## 거절한 대안

- Core 시간을 멈춤: 같은 입력 재생 및 화면만 변경하는 범위를 위반한다.
- 공유 스냅샷 참조만 보관: 다음 틱에 enemy 배열이 재사용되어 과거 상태가 바뀐다.
- 런타임 뼈대를 적 전체에 적용: 이번 승인 대상은 영웅 한 명이다.
- b 또는 c를 먼저 확정: 영상과 측정 후 사용자가 선택한다.
