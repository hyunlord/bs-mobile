# ADR0052: 세로 화면 흐름을 규칙과 분리한 표시 모드로 둔다

- 상태: 사용자 승인 범위의 구현 결정, 실제 UI 관문 검증 전
- 날짜: 2026-10-11
- 관련: #225·#226·#227, [화면 정본](../design/screen-flow-v0.md), [ADR0048](0048-continuous-presentation-and-live-capture.md)
- 번호 확인: 원격 main `e3c4691d511089a9131e5b45946ed668d258ab83`의 ADR은0051까지다. 병합 직전 main에0052가 추가되면 이 문서 번호와 참조를 갱신한다.

## 맥락

새 화면 계약은390×844 세로 화면, 전장90%,44pt 입력,13개 화면의 일관된 복귀를 요구한다. 기존900폭 적응형 화면을 전역 수정하면 역사 프로필과 Mac 입력·카메라의 좌표 계약까지 섞인다. canvas Logic 표를 직접 보지 못한 상태에서 미정 경제·부활·재시작 규칙을 UI 구현으로 확정할 수 없다.

## 결정

UiShell에 선택적 portrait 모드를 두며 레거시 기본 경로를 유지한다. 새 모드의 safe area·가운데 세로 뷰포트는 카메라·Canvas·입력이 공유한다. 독립 토큰과 기존 아트 자원을 사용하고 새 의존성을 넣지 않는다. 하단 장비 막대 대신 작은 상단 HUD를 사용한다.

App의 명시적 내비게이션이 현재 화면·복귀 원점·카드 제안 상태를 소유한다. 메뉴가 Core를 진행시키지 않으며, 카드 진입 보호·Back·설정 복귀·포기 확인·전경 복귀의 명시적 일시정지를 렌더링과 분리한다. 화면 재구성은 새 판 시작이나 보상 지급 사건이 아니다.

13개 화면을 세 PR로 나눈다. #225는 흐름·플레이 표면만, #226은 실제 진행 화면과 저장/받기 계약, #227은 승인된 BM 자리만 구현한다. 뒤 단계는 앞 단계 main 병합 후 새 가지에서 수행한다. 표시는 기존 콘텐츠·실행 규칙을 소유하지 않는다. canvas 미확인 부분은 서면 정본의 `[잠정]`으로 남긴다.

## 경계와 결과

이 ADR은 BM 가격·수량·부활 체력·위치·무적·일일 기준을 결정하지 않는다. #224·#126 미정은 유지하고 `[n]`을 실행 값으로 쓰지 않는다. #98·1b 보류와 #223 성능 실패도 유지한다. UI 껍데기·기기 비율 시뮬레이션·단위 테스트를 완성 화면·실기·사용자 승인으로 확대하지 않는다.

기존 UiTokens를 전역 치환하는 대안은 구형 경로와 좌표 계약의 회귀 위험 때문에 채택하지 않는다. Core에 화면 상태를 넣는 대안은 결정론 규칙과 플랫폼 lifecycle을 섞으므로 채택하지 않는다. 실제 화면·입력·복귀·전환 시간 검증은 별도 증거로 남긴다.
