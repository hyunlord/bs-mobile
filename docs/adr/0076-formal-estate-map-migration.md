# ADR0076: 신규 정식 계정의 r8 지도와 서버 저장

- 상태: 승인 — 2026-10-30 사용자 축소안 최종 승인, 수치는 [가설] 유지
- 날짜: 2026-10-30
- 연결: [#546](https://github.com/hyunlord/bs-mobile/issues/546), [GDD14](../design/gdd/14-estate-map-release-proposal.md), [PR547](https://github.com/hyunlord/bs-mobile/pull/547)

## 맥락

사용자는 정식 영지를 r8 지도로 시작하고 정식 계정을 서버에 저장하기로 결정했다. 사용자 전제는 출시 전이며 실제 사용자 저장이 없다는 것이다. 따라서 개발 자동 장원 저장을 정식 계정으로 이관할 필요가 없다. 이전 로컬 이관안의 승인·예약과 별개로, 2026-10-30 사용자가 이 축소안의 병합을 최종 승인했다.

## 결정

신규 정식 계정은 서버 정본에서 생성하며 첫 영지 진입부터 r8 지도와 온보딩 07~09를 사용한다. 타이틀→첫 출정→귀환 순서는 유지한다. 개발 자동 장원·개발 지도 저장은 원본 그대로 개발 빌드 읽기 전용으로 남긴다. 정식 계정으로 지갑·장부·가신·효과·공사 상태를 복사하거나 합치지 않는다.

GDD14의 지도 L1/L2/L3→효과 E3/E6/E10 대응은 [가설]로 유지한다. 신규 네 효과 장부 E0에서 시작하고 실제 완료 때만 `min(10,max(현재 E,완료 단계 target))`로 갱신한다. 현행 가신 상한·슬롯·연구 규칙을 유지하며 효과를 중복 합산하지 않는다. 곡창의 보관시간 후보와 생산속도는 구별한다.

C# 서버의 구조·저장 스키마·계정 권한·동시성·내구 커밋·설정 의미 검증·시간·재시도·백업/복구 세대·장애 주입·롤백은 Codex의 별도 서버 ADR 책임이다. 로컬 v6 재사용이나 계정 경로 단일 writer/primary 재읽기/manifest 구현을 이 ADR에서 고정하지 않는다. 서버 저장 실패를 개발 로컬 파일로 복구하지 않는다.

## 대체되는 이전 설계

이전 문서의 v1~5→v6 일회 이관, imported 효과 보존/시각 레벨 역매핑, 구형 방치 마지막 정산, 로컬 원장 복사·복구 세대 및 롤백 실행 계약은 제품 설계에서 폐기한다. 기존 v6 L3/낮은 E의 이관 예외도 신규 서버 계정 출시 관문이 아니다. 이전 설계와 검토는 Git 이력 `301cac91` 및 PR 토론에 보존한다.

[ADR0071](0071-account-estate-state-and-save-version-six.md)의 역사 codec·저장 테스트·개발 자료는 이 문서로 변경하거나 삭제하지 않는다. r3~r7 설정과 리플레이·골든도 동결한다. 실제 사용자 저장이 생긴 이후의 변경은 새 서버 운영 계약으로 다룬다.

## 결과와 검증

복잡한 개발 저장 이관을 출시 전 필수 작업에서 제외하고 신규 지도 흐름·효과 연결과 서버 설계 책임을 분리한다. 서버가 아직 구현/검증됐다는 뜻은 아니다. 신규 생성·재접속·완료 중복 방지·개발 저장 미수입·읽기 전용·서버 장애 관문은 후속 구현에서 검증한다. 이번은 문서 검사만 수행하며 게임 코드·데이터·Unity·빌드 변경은 없다. 사용자 승인에 따라 06:00 이후 최신 main·CI 확인 후 squash 병합한다.
