# 농로 돌파 Core 구현 계약 (#678)

- 날짜: 2026-11-04. 상태: **구현·검증 진행 중**. [승인 계약](active-hero-effects-contract-674.md)과 [GDD16 §10](../design/gdd/16-slg-heroes-proposal.md)을 따른다. 실제 관문 결과는 PR에 기록한다.
- 범위: 직접 월드 PvE의 명시적 `hero-active-v1` 돌진. 도발/장판은 다음 PR이며 이 버전은 미지원 능력을 거절한다. 영웅 ID를 실행 분기로 사용하지 않는다. 영웅 전체 콘텐츠·밸런스·아트 완성을 주장하지 않는다.

## 1. 발급과 데이터 경계

`HeroActiveOptions`는 영웅/소유자·시작 무기 슬롯·교체 공격·skill ID/version/hash·돌진 정의·영웅 반경·벽·적 몸체를 전달한다. `ContentCatalog.HeroActive`는 서버가 신뢰한 콘텐츠 정의다. 세션은 발급 옵션의 canonical bytes와 이 catalog를 대조하고, 월드 snapshot의 영웅/전체 skill 목록 및 규칙/content hash를 검증한다. checksum 재계산만으로 서버 발급을 승인하지 않는다. catalog와 실행 옵션의 능동 정의는 모두 있거나 모두 없어야 한다. 한쪽만 있으면 명시적으로 거절하여 catalog만 추가된 상태가 absent 실행 바이트를 바꾸지 않게 한다.

준비 틱·위협 반경·틱당 이동 거리·최대 거리·지속·재사용·동시 인스턴스는 입력 데이터다. 이 버전은 동시 돌진 한 개만 지원한다. 좌표/반경의 `MaximumCoordinate`는 정수 산술 방어를 위한 프로토콜 범위이며 밸런스 수치가 아니다. 벽은 안정 ID와 정수 AABB, 적 몸체는 enemy ID별 반경과 발동 대상 적격 여부를 가진다. 사거리와 몸체 반경을 혼용하지 않는다. 시각적 지형에서 통행 불가를 추정하지 않는다.

## 2. 틱 내 이동 선분과 충돌

일반 이동의 실제 변위로 준비하되 벽·전장 경계에 일부만 이동하고 막힌 틱도 준비를 초기화한다. 준비 완료와 적 조건을 만족하면 현재 비영 입력 방향을 고정한다. 재사용은 발동 시점부터이며 실제 돌진 이동은 다음 틱부터다. 이동 입력을 놓으면 다음 이동 전에 종료한다. 패시브 이동 보너스를 돌진 변위에 곱하지 않는다. max-axis 방향 정규화와 축별 정수 나머지를 상태에 보존한다.

제안 끝점까지의 전체 선분을 검사한다. 전장 bounds는 영웅 반경만큼 줄이고 벽 AABB는 영웅 반경만큼 확장한다. 살아 있는 적의 몸체는 영웅 반경과 적 반경의 합을 사용한다. 벽 또는 적 몸체의 최초 접촉에서 돌진을 끝낸다. 단순 끝점 거리 검사로 얇은 벽이나 적을 건너뛰지 않는다.

AABB 접촉은 유리수 비교를 사용한다. 원 접점은 무리수일 수 있으므로 최대축 변위의 정수 구간 경계로 최초 접촉을 이분 탐색하고 이전 위치로 보수적으로 멈춘다. 이때 `decimal`은 96비트 **정수 중간식**의 덧셈·뺄셈·곱셈·비교에만 사용한다. 부동소수점 위치, 근삿값 제곱근, 시간 의존 계산은 사용하지 않는다. 발급 좌표 상한 1,000,000 및 확장 기하 상한 4,000,000에서 이차식 절댓값 항의 합은 최대 3.2768×10²⁸로 96비트 decimal 정수 범위 안이다. 이 두 안전상한, schema 식별자 2, 이분 탐색/이차식 계수 2만 명명된 알고리즘 상수로 AG003에 등록한다. 게임 수치 예외는 추가하지 않는다.

정수 좌표로 반올림한 최종 선분을 전체 벽/몸체에 다시 검사한다. 반올림이 침투를 만들면 안전한 시작점에 머무른다. 따라서 일부 접선/미세 접촉은 보수적으로 짧게 이동할 수 있다. 이는 벽 관통을 허용하는 오차가 아니다. 같은 접촉 구간은 canonical 벽 ID와 안정 entity ID 순서를 유지한다. 경계 위에서 바깥쪽 또는 경계를 따라 빠져나가는 이동은 허용하고 내부로 파고드는 이동은 막는다.

## 3. 경로 피격·공격·사망 순서

월드 전투는 일반 wave의 적 AI/투사체 접촉 경로를 우회한다. 따라서 새 경로는 실제 `WorldCombatState.TickEnemies`에 연결한다. 틱 시작에 존재한 적만 지나간 영웅 경로를 검사한다. 뒤에 생성된 적이 과거 이동 경로를 공격하지 않는다.

기존 적의 목표 우선순위(영웅, 상비 슬롯, 표식)를 보존한다. 돌진 경로의 목표 선택 기준은 이동 시작 위치로 고정하며, 상비군/표식을 선택한 적의 공격을 영웅에게 복제하지 않는다. 영웅이 선택됐을 때 기존 적 위치와 잘린 영웅 선분을 **기존 공격 사거리**로 검사한다. 이후 적 이동과 영웅 끝점의 교차/거리도 같은 공격 사건으로 합친다. `AttackTick` 재사용과 기존 `DamageWorldHero`/`Hurt` 면역·피해·사망 처리를 한 번만 적용한다. 경로와 끝점에서 같은 공격을 두 번 소비하지 않는다. 사건 순서는 기존 적 순서를 따른다.

돌진은 공격 피해·무적·피해 감소를 주지 않는다. 돌진 중 시작 공격 슬롯 및 그 진화의 새 발사를 억제하되 공격 시계는 진행한다. 마지막 이동/충돌 틱도 억제하며 종료 후 밀린 발사를 몰아 실행하지 않는다. 다른 슬롯과 이미 생성된 공격은 기존 생명주기를 따른다. 사망/종료/quit은 능동 상태를 해제한다. `hold-marker`는 실제 마지막 위치와 살아 있는 적으로 판정하고 기존 실패→성공→시간 초과 순서를 보존한다.

## 4. 바이트와 복구

- 옵션 없음: format1~8 및 기존 format9 envelope1 헤더·월드 payload·state·recovery-v1 bytes를 그대로 쓴다. 빈 능동 필드도 추가하지 않는다.
- 옵션 있음: format9 envelope2의 필수 길이 제한 `hero-active-v1` 블록, 별도 catalog/options/runtime state 블록과 `SowSiege-world-recovery-v2`를 쓴다. 기존 `world-combat-v1`/`world-end-v1` payload는 바꾸지 않는다.
- 준비·재사용·발동 sequence·방향·나머지·지속/거리 상태를 hash/복구에 포함한다. 틱 내부 경로는 다음 틱 시작에 초기화되며 복구는 승인 prefix 재실행으로 재현한다.
- 빈/미지원/비정규 블록, 참조 불일치, 잘못된 recovery/header 버전 조합을 거절한다. 구 reader가 새 버전을 거절하는지 실제 기준 DLL로 검사한다.
- `VerifyResult`는 기존처럼 서버 저장 `acceptedRecovery`와 전체 발급 헤더·확정 prefix·최초 terminal을 비교한다. no-input frontier는 실제 0 입력으로 돌진 중단을 재현한다.

## 5. 검증 관문

기준은 #669 `709869e654df948bec2a1a158a190244cc9ec6ce`다. 기준 DLL에서 schema1 헤더 8조합과 tick0/중간/terminal의 state/runtime/recovery 및 terminal replay/end bytes를 동결하고 새 구현과 비교한다. 기존 absent16+추가 역사14·역사 replay·golden도 유지한다.

얇은 벽, 중간 적/공격, 벽 뒤 적, 접선/끝점/시작 겹침, 경계 탈출, 최대 좌표, 동률, 경로+끝점 중복, 다른 대상의 공격, 입력 해제·사망·만료·정수 잔여·진화 슬롯·prefix/복구를 손계산 fixture로 확인한다. 두 실제 Core DLL 결과, Unity 네 묶음·보충2·crowd-411 및 C05 3:3은 별도 관문이다. 검증 전 PASS나 측정 준비 완료를 기록하지 않는다.

이번 Core PR은 데이터 주입/API와 실행 규칙을 제공한다. 실제 영웅 콘텐츠 배포, 무료 PvE 해금, 그림과 플레이 시인성, 기사 대비 동일 전투 예산은 별도 콘텐츠/서버/클라이언트 관문으로 남는다. C05 측정은 신규 능동 효과의 재미나 판독성을 증명하지 않는다.
