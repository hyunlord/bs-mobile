사용자가 선택한 A 정통 개척 기사를 1.4배에서 표시한다. 무료 Unity 2D Animation 실시간 뼈대는 영웅 1명에만 쓰고 적은 기존 구운 이미지를 유지한다. 서기·걷기·이동 중 철날 검·진화 큰 휘두름·피격·쓰러짐·레벨업 7동작을 구현했다. 테스트용 동작 확인은 실제 판의 자연스러움·군중 실루엣 승인과 구분한다.

화면 밖 위험 화살표 최대 6개·돌진 예고 0.5초는 사용자 제시 표시 가설이다. Core 크기·판정·피해·스폰·공격 준비 시간을 바꾸지 않는다. 기존 B 부위와 (b) 구운 모션 자료, `7bc241f` 배율 비교, 과거 실패 자료는 보존한다.

## 실제 피해 관문: 실패

[정본 측정 CSV](../../benchmarks/m1-254/native-measurements-2bf5295.csv), [선정한 사건 3건×3조건 CSV](../../benchmarks/m1-254/native-hit-examples-2bf5295.csv). 표의 비율은 공격 거리 진입 대리 지표가 아니라 **실제 양수 HP 손실 사건 중, 공격자가 화면에 들어온 지 1초 이내인 사건**이다.

| 표시 조건 | 진입 1초 이내 / 실제 피해 | 비율 | 이력·공격자 미확인 | 총 HP 손실 | 장 p95 / 최대(ms) | >25ms |
|---|---:|---:|---:|---:|---:|---:|
| 현재 1.0배 · 경고 OFF | 0 / 160 | 0% | 0 / 0 | 1778 | 17.0583 / **65.0648** | 0.70922% |
| 1.4배 · 경고 OFF | 2 / 160 | 1.25% | 0 / 0 | 1778 | 17.6082 / 32.8641 | 0.35088% |
| 1.4배 · 경고 ON | 2 / 160 | 1.25% | 0 / 0 | 1778 | 16.6990 / 33.0108 | 0.70175% |

1.4배는 1.0배 대비 **+1.25%p**로 진입 직후 피해 비악화 조건을 충족하지 못했다. 실제 피해 160건과 합계 1778은 세 조건 모두 같다. 경고 ON도 2/160이며, 경고가 피해를 줄였다는 주장을 하지 않는다. 같은 입력에서 표시만 바꾸므로 피해 사건이 같아야 한다. 사람이 경고를 보고 달리 피하는 효과는 새 플레이 입력 없이는 검증할 수 없다.

원래 피해 틱 T와 표시 스냅샷 T+1을 연결했다. 두 진입 직후 사례는 돌진 주자 ID916의 T13549→13550, ID967의 T13557→13558이며 피해는 각 10이다. 비교용 세 번째 사례는 ID916의 T13635→13636, 피해10으로 세 조건 모두 진입 직후가 아니다. 이 3건은 바뀐 두 판정과 같은 공격자의 뒤 타격을 함께 확인하기 위해 선정했다. 정확한 화면 진입 틱은 이 CSV에 없으며 `recent_entry`는 1초 이내 관측 분류만 증명한다. 프레임 시간 결합은 원래 사건 틱이 아닌 `snapshot_tick`으로 했다.

1.0배 실행의 최대 65.0648ms도 그대로 보존한다. 이 보고에서 원인을 해결하거나 환경 잡음으로 제외하지 않았으며 #223 최대50ms 관문 통과가 아니다.

## 소리 포함 영상: 역사 실패 두 건과 수정 검증

`2bf5295`의 `mid-before`에서 AudioRenderer 반환 블록이 고정 영상 한 장의 샘플 수보다 커서 중단했다. 실제 매니페스트는 영상0/1800장·오디오0샘플·`complete=false`, 오류 `Unity audio returned more than one fixed frame; refusing resampling or sample loss.`다. 첫 렌더 프레임은 워밍업으로 버려졌고 전달 가능한 게임 오디오는 없다.

48kHz·스테레오 설정 자체나 Node 합성 PCM 검사 통과는 실제 게임 AV 완료가 아니다. 오디오를 임의로 자르거나 무음·대체 음원으로 통과 처리하지 않는다. 소리 포함 고정60fps 전후·영웅 주변2배 확대본은 수정 후 실제 게임 캡처의 프레임·샘플 인덱스 정합성을 검증해야 한다. 실패 원본은 `artifacts/m1-254/plans-first/captures/mid-before/`에 보존한다.

### 오디오 블록 원인 확인 · 두 번째 실패의 역사 기록

`6ffa` 후속 실행의 `artifacts/m1-254/plans-audio-retry/captures/mid-before/offline-audio-render.csv`는 181개 연속 프레임에서 1024 또는0샘플을 보고했다. 합계144384는 `floor(181×800/1024)×1024`이며 영상 시계의 목표144800과 다르다. 첫 실제 캡처 표시가 있는 Unity프레임441은 800이 아닌1024샘플을 반환해 실패했고 결과는 여전히 영상0/1800·오디오0샘플이다.

별도 네이티브 격리 실험(`/tmp/bs-audio-probe254/`)은 다음을 확인했다.

| 요청 방식·90프레임 | Render 반환 | 버퍼 기록·소스 시계 | 판정 |
|---|---|---|---|
| `reported.csv`: 믹서가 보고한 0/1024 길이 그대로 | true | 남은 NaN 0, 소스 `timeSamples`가0→71680으로 증가, DSP시각 진행 | 보고된 블록의 실제 샘플 출력 확인 |

따라서 믹서의 실제1024샘플 블록을 순서 보존 FIFO로 받고 최종 영상용800샘플 단위로 다시 묶으며, 마지막 목표 샘플은 후행 렌더로 배출하도록 수정했다. 샘플 순서·값을 유지하며 리샘플링·무음 패딩·목표 구간 샘플 버림으로 길이를 맞추지 않는다. 두 실패 원본과 격리 실험은 아래 성공 원본과 함께 보존한다.

### 전후 차이와 화면 표본의 한계

같은 시점의 원본 1800장 중 전후가 다른 장은146장이다. 짧은 타격이 없는 5초 간격 정지 표본만 보면 차이를 놓칠 수 있다. 사건 시점 표본에서 적용 후 프레임420에는 피해 숫자 `24`, 프레임640에는 `12`가 보였다. 프레임420의 흰 번쩍임은 **전후 양쪽에 있으므로 이번에 새로 생긴 차이라고 설명하지 않는다.** 숫자·반동·파편이 실제 화면에서 충분히 읽히는지는 사용자가 영상으로 판단한다.

역사 C05의 프레임300(판 시간06:05)은 영웅 머리가 원본 화면 경계에 잘려 있다. 확대본은 원본 영상 경계 안으로 자를 영역을 제한했고 전후 각각511/1800장에서 제한이 적용됐다. 영웅 기준점이 원본 세로 화면 밖인 장은0이지만 확대 화면 중심에서 최대174.1296px 벗어나므로 기준점이 안에 있다는 사실을 전신이 안 잘렸다는 뜻으로 쓰지 않는다. 사라진 머리 부분을 복원하거나 원본 잘림을 해결한 것처럼 보이게 하지 않았고 원본 전체 장면은 보존했다. 이 입력은 구형 경계 지도이고 현재 끝없는 들판의 검증을 대신하지 않는다. 아래 별도 정상 출정 표본과 출처를 구분한다.

Release의 나란히 표본은 `before-after-1x.mp4`와 `before-after-2x.mp4`다. 현재 A 기사의 전체7동작이나 사용자 모션 승인이 이 중반 타격 영상 하나로 완료됐다고 쓰지 않는다. 사용자 질문은 **“소리를 끄고 봐도 맞았다는 게 느껴지나”**다.

## 현재 끝없는 들판의 별도 시각 표본

이 실시간 캡처의 `capture-result.json`은 **failed**이며 원인은 60Hz 슬롯 누락이다. 표시 표본으로만 보존하고 60fps·프레임 간격·성능 통과나 정상 판 완주라고 부르지 않는다. 실패 매니페스트의 `completedTick=0`, 빈 `stateHash`를 원장 확인 대신 성공 상태로 고치지 않는다. 해당 원장·표본은 실제 진행을 보여 주지만 실패한 최종 캡처 절차와 구분한다.
