# #169 C05 네이티브 고정 성능 비교

관문: 실패 — 세 밀도 모두 전후3회 유효 측정을 완료했지만, 최적화 후 프레임 p95 17.209–17.373ms로16.7ms를 넘었다. 역사 해시 보존과 회귀 하네스 검증은 통과했다.

## 조건과 구현 경계

공격·연쇄·궤도·아군의 적 후보를 공간 격자로 수집하고, 표적 Id 조회를 사전으로 바꿨다. 연산마다 기존 거리→Id, Id 단독, 젖은 대상 우선, 원래 목록 순서를 유지한다. 넉백은 즉시 격자에 반영하며 중첩 검색 버퍼와 비공개 단위·레벨 캐시를 사용한다. 수치·스폰·프로필·공개 상태 해시는 바꾸지 않았다.

전후 빌드는 동일한 C05 원본 입력과 역사 카탈로그, 동일 벤치마크 하네스를 사용한다. 기준 소스는 `47c1a7aaf129b16b88a1b4c9136cef21cff014a0`, 최적화 소스는 `1d674a3b817fca0510a1fe350a56f81c8191f778`이다. 이후 분석기·문서 커밋을 네이티브 빌드 소스로 잘못 표시하지 않는다.

| 조건 | 값 |
| --- | --- |
| 기기 / OS | Mac16,5 / Mac OS X 27.0.1 |
| 런타임 | Unity6000.6.4f1, ARM64 Mono, Metal, 네이티브 Release |
| 화면 / 품질 | 1600×900 / Ultra / 목표60fps / vSync0 |
| 준비 | 원본0–7200틱 재생 후120렌더 프레임 제외 |
| 측정 | 7200–9900, 10200–12900, 13200–14400틱, 정상30Hz 입력 |
| 반복 | 전후 각각3회, 느린 프레임·입력 없는 프레임·따라잡기 프레임 포함 |
| 병행 부하 | 측정 중 로컬 빌드·테스트·Recorder·영상 인코딩 없음 |
| 잠자기 / 열 | 별도 잠자기 방지 도구 미사용, 열 상태 카운터 미지원 |

원본 SHA·dataHash·종결 해시와 고정 계약은 [런북](../runbooks/wave-density-benchmark.md) 및 [fixture](../../benchmarks/wave-c05/contract.json)에 있다. 현재 새 콘텐츠의 대표 성능·Fold7 실기·재미·일반 녹화 판독성을 대신하지 않는다.

## 전후 측정

전체 프레임 p95(ms), 괄호는3회 반복의 최소–최대다. 모든 반복의3개 밀도가16.7ms를 넘었다.

| 적 수 | 전 p95 (반복 범위) | 후 p95 (반복 범위) | 전→후 시뮬레이션 p95 | 후 판정 |
| --- | --- | --- | --- | --- |
| 400–599 | 17.121 (17.084–17.138) | 17.373 (17.335–17.393) | 7.402→3.500 | 실패 |
| 600–799 | 17.032 (16.997–17.074) | 17.280 (17.265–17.301) | 8.495→3.936 | 실패 |
| 800+ | 17.042 (17.011–17.080) | 17.209 (17.155–17.248) | 7.468→4.624 | 실패 |

총 프레임 전39295/후39162개. 3회 통합 p95는 요약용이며 판정은 반복별로 수행했다. 아래는 후 버전의 비중첩 CPU 구간 p95(ms)다. 서로 다른 p95를 합산하지 않는다.

| 적 수 | 시뮬레이션 | 스냅샷 | 새 상태 수용 | 화면 구성 | HUD | 전체 프레임 최대 | GC 수집 전→후 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 400–599 | 3.500 | 0.529 | 0.193 | 2.331 | 0.029 | 369.199 | 5102→603 |
| 600–799 | 3.936 | 0.601 | 0.240 | 2.588 | 0.025 | 166.786 | 6290→656 |
| 800+ | 4.624 | 0.647 | 0.264 | 2.876 | 0.022 | 29.792 | 3519→304 |

GPU와 렌더 스레드는 지연된 FrameTimingManager 관측이다. 준비 및 측정 구간 전체를 포함하며 특정 밀도와 결합하지 않은 원인 조사 지표다. CPU 메인 스레드 시간은 수면·대기를 포함할 수 있어 순수 게임 코드 CPU 시간으로 해석하지 않는다.

| 지연 관측 p95(ms) | 전 | 후 |
| --- | --- | --- |
| 렌더 스레드 | 0.266 | 0.407 |
| GPU | 1.217 | 1.227 |
| Present 대기 | 4.759 | 6.901 |
| 메인 스레드 | 16.628 | 16.626 |

GC 수집 합계는14911→1563회로 줄었지만 할당 바이트와 GC 정지 시간은 측정 불가다. 후400–599구간의369.199ms와600–799구간의166.786ms 지연도 삭제하지 않았다. 시뮬레이션 비용 감소를 전체 프레임 개선으로 표현하지 않는다. 목표60fps의 프레임 간격16.667ms와 관문16.7ms가 가깝지만, 프레임 제한이나 기준을 바꾸지 않았다.

잔여 비용 중 화면 구성 p95는 전2.082/2.299/1.877ms에서 후2.331/2.588/2.876ms로 늘었다. 원인은 아직 확정하지 않았다. 순수 GPU p95는 약1.22ms지만 렌더/대기 관측은 밀도와 동기화되지 않으므로 이것만으로 병목을 배제하지 않는다. 다음 후보 한 개는 같은 C05에서 `WaveRuntimeState.Capture`의 적 행동 정렬·객체 복사 비용을 별도 계측하는 것이다. 현재 `snapshotMs`에는 Core 캡처와 표현 Envelope·카드 캡처가 함께 들어간다. 추가 최적화는 적용하지 않았다.

반복별 평균·p95·최대·표본 수·GC·빌드 소스는 [정본 CSV](../metrics/wave-c05-native-2026-10-10.csv)에 있다. 원자료는 [Release `perf169-c05-20261010`](https://github.com/hyunlord/bs-mobile/releases/tag/perf169-c05-20261010)에 연결한다. 사전 고정한 C05의전후3회는 모두 성능 관문 실패 사례여서 원본 CSV·빌드/기기 메타데이터만 게시한다. 포커스 이탈 첫 실패1개와 준비 화면1장도 표본으로 남긴다. 재생성 가능한 JSON·그래프·보고서와 앱·증거 ZIP은 올리지 않는다.

재생성: Release의 `before-run-N-*`/`after-run-N-*` 파일을 각각 `before/run-N/`/`after/run-N/`에 접두사 없이 놓고 `node tools/summarize-wave-benchmark.mjs before after`를 실행한다. 원본 역사 해시는 `node tools/verify-wave-history-parity.mjs <새 출력 경로>`로 확인한다.


## 해시·검토·실패 기록

- 원본 C07·A03 각각27000틱과 C05 14400틱을 실제 net8.0/netstandard2.1 DLL로 실행한6개 조합 모두 역사 종결 해시와 일치했다. 네이티브 측정도 원본 C05 종결 해시를 확인한다.
- 집중 Wave 회귀121개, Unity 준비20개, 분석기20개와 URP 복원4개 통과. 전체 검사는 원격 CI를 사용했고 로컬에서 같은 전체 검사를 중복 실행하지 않았다.
- [독립 코드 검토](wave-density-code-review.md)는 검색·정렬·넉백·캐시·하네스·분석기·빌드 복원 범위를 다룬다. 리뷰 없이 병합한 변경이 아니다.
- 초기 기준 실행2개는 종결 해시가 맞았지만 각각2프레임/1프레임의 포커스 이탈로 무효였다. 이 행을 삭제하거나 유효3회에 섞지 않았다. 실패 자료는 별도로 보존했다.
- Mono 할당 카운터가 전부0인 실행은 할당0이 아니라 측정 불가다. GC 수집 횟수와 GPU/렌더 타이밍은 각각 별도 계측이며 GC 정지 시간으로 환산하지 않는다.

## 남은 범위

#126 수치·스폰·경제, Fold7 #98은 보류한다. 성능은1b 시작 조건에서 제외됐지만 사용자 직접 플레이 소감 전에는1b를 시작하지 않는다. 성능 관문이 미달이면 #169를 열어 두며 이번 구현·회귀 하네스 이슈 #183만 닫는다.
