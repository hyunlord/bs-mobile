관문: 규칙 — 신규 보고서는 첫머리 요약을 10줄 이내로 작성한다.
변경: 관문·변경점·결정·한계를 본문보다 먼저 읽을 수 있게 통일한다.
결정: 보관된 원본 보고서와 증거의 바이트는 형식 정리를 이유로 변경하지 않는다.

# 보고서 형식과 보관 원본

신규 단계·실험 보고서는 첫 줄에 관문 결과(PASS·FAIL·PARTIAL·미검증 등)를 쓴다. 이어 변경점, 필요한 결정 또는 결정 없음, 검증 범위·남은 한계를 적는다. 첫 본문 제목 전의 요약은 빈 줄을 포함해 10줄 이내로 유지한다. 결정이 미승인이라면 해당 needs-decision 이슈를 연결하고 승인처럼 표현하지 않는다. 실행 검증 통과와 밸런스·제품 관문 실패를 합쳐 전체 PASS로 쓰지 않는다.

기존 인계 보고서에는 당시 시점을 명시한 짧은 요약과 보관 링크만 추가할 수 있다. 수치·결과를 최신 실험 값으로 덮어쓰지 않는다. 원본 설계 문서, Release에 보관한 원본 보고서·ZIP·해시, CSV에서 생성한 역사적 [S4 원본 보고서](../league/S4-report.md)는 형식 적용 대상에서 제외하고 바이트를 보존한다. 원본의 오래된 실행 명령은 고치지 않고 [현재 리그 런북](../runbooks/run-league.md)과 [보관 안내](../league/README.md)를 함께 제공한다.

후속 결과는 새 보고서에 기록하고 원본을 연결한다. 제거된 원자료의 링크는 브랜치 최신 주소 대신 고정 커밋 또는 검증한 Release 자산을 사용한다.
