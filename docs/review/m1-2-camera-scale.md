## 무엇을 비교하는가

영웅·적·이펙트를 함께 현재/1.4배/1.8배로 확대했다. Core 판정·개체 크기·입력·콘텐츠 수치는 바꾸지 않았다. 기본 영웅 **A 정통 개척 기사**와 **(c) 무료 Unity 2D Animation 실시간 뼈대** 선택은 [00 결정 기록](../design/gdd/00-index.md)·[07 정본](../design/gdd/07-art-character.md)에 반영했다. 이번 배율 비교에는 공통으로 **기존 B 시안 부위와 (c) 모션**을 썼다. 새 A 원화 리그를 완성했다는 뜻이 아니다.

영상은 **오프라인 고정 60fps·무음**이다. 각 구간 30초·1,800장, 총 9개 원본 캡처가 모두 예상 장 수와 일치했다. 모션·배율 비교용이며 프레임 간격·실시간 성능의 증거가 아니다. 손맛 전후 고정 60fps+소리와 영웅 주변 2배 확대본은 사용자 배율 선택 뒤 B·C 단계에서 만든다.

## 화면 안 적 수·접촉 지표와 비용

각 조건 30초 1회, 총 9회다. Mac16,5·macOS 27.0.1·Unity 6000.6.4f1 Mono/Metal Release, 1920×1080 창의 중앙 세로 시야, vSyncCount=2(120Hz에서 60fps)로 2026-10-12 16:32–16:40 KST에 측정했다. 화면 안 적 수는 p50/p95이며 접촉 비율에는 분자/분모를 함께 적었다. 반올림 전 값과 표본 수는 [정본 CSV](../metrics/m1-2-camera-scale.csv)에 있다.

06:00의 1.8배는 최대 50.0178ms, >25ms 0.61763%를 그대로 보존한다. 각 1회 표본이므로 배율 자체가 지연 원인이라고 단정하거나 통계적으로 가장 빠른 배율을 고르지 않는다. 전체 800+ 세 실행의 >25ms 0건도 #223 반복 관문 통과가 아니다.

화면 안 적 수는 Core 틱마다 공급된 렌더 경계와 카메라 시야의 교차로 센다. 이미지의 픽셀을 분할해 센 값이나 전체 적 수가 아니다. 동일 Core 틱의 첫 표시 프레임을 관측하며, 화면 진입은 렌더 경계, 접촉은 현재 Core 중심 좌표를 쓴다. 두 표본이 정확히 같은 시점의 물리 충돌을 뜻하지 않는다.

**현재 관측기는 실제 피격자의 공격자별 귀속을 제공하지 않는다.** `lord-hit` 사건에 적 개체 ID가 없고 정의 ID만 있으므로 ‘화면 밖에서 들어온 적이 실제로 때린 비율’을 주장할 수 없다. 대신 기존 일반 적 공격 거리인 `catalog.Enemies[definitionId].Range` 안으로 적 중심이 들어온 사건을 안정 개체 ID별로 센다(영주 반지름 0). 이는 공격 범위 접촉 대리 지표이며 몸 충돌·피해 발생이 아니다.

분모는 이력이 확인된 공격 거리 진입 사건, 분자는 관측된 화면 밖→안 전환 후 30틱(1초) 이내에 생긴 해당 진입 사건이다. 이력 미확인은 06:00의 세 배율 각각 1건을 제외했고 나머지 구간은 0건이다. 분모 0이면 `해당 없음`이며 0%로 쓰지 않는다. 이번 9회 모두 실제 영주 피해 사건은 0건이었다. **실제 화면 밖 진입 적의 피격 비율은 미확인(null)이며 0%가 아니다.** 실제 피격 비율 요청을 이 대리 지표로 완료 처리하지 않는다.

비용은 별도 캡처 OFF 네이티브 실행, 같은 창 크기·세로 시야·배율·입력·60fps 설정으로 측정했다. 전경 유지 구간만 사용하며 배경 구간은 제외하고 계속 재생하는 계약이다. 이번 9회 `excludedIntervals`는 모두 0개다. 외부 전경 기록의 Google Chrome은 시작·종료 전환이고 유효 측정 중 제외 구간은 없었다. 이 세로 배율 실험은 역사 C05 회귀 하네스의 화면 구성과 다르므로 #223 기준선이나 과거 C05 수치에 직접 합치지 않는다.

## 시야 축소 보완 제안

아래는 아직 적용하지 않은 제안이며, 배율을 대신 선택하거나 Core 난도를 보정한 구현이 아니다.

| 보완안 | 목적 | 화면 판독 경계 |
|---|---|---|
| 화면 밖 위협 방향 표시 | 좁아진 시야에서 접근 방향을 미리 알림 | 적마다 모두 표시하지 않고 가까운 위험을 합쳐 가장자리에 제한 |
| 돌진·큰 공격의 가장자리 예고 | 출발점이 안 보여도 화면으로 들어오는 위험을 읽음 | 기존 전용 경고와 중복되지 않게 하고 영주·HUD를 가리지 않음 |
| 위협 중요도에 따른 표시 우선순위 | 큰 배율의 혼잡에서 필요한 정보만 보존 | 붉은색은 위험에만 사용, 상시 원·긴 선을 늘리지 않음 |

사용자가 배율을 고르면 A 기사 부위 분리·리깅, 방향 수 결정, 이동하면서 휘두르기·큰 휘두르기·피격·쓰러짐·레벨업 포즈를 검증한다. 이후 선택 배율로 손맛 전후를 소리 포함 고정 60fps와 2배 확대본으로 다시 비교한다. B·C 외형 후보는 능력치 차이 없이 보존하고 적은 구운 이미지 방식으로 유지한다.
