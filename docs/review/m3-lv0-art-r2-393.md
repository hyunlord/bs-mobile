## 바닥 변경과 확인

작고 균등한 얼룩을 큰 불규칙 분포로 다시 그렸다. B/C 첫 후보는 대각선/수평 띠가 반복되어 보여 재생성했으며 최종 후보를 별도로 확인했다. 생성 그림은 built-in image_gen으로 만들고, 512px 내보내기에는 periodic-plus-smooth 경계 보정을 적용했다. r1의 넓은 경계 대칭 블렌딩은 사용하지 않았다.

각 2×2 확인 이미지의 네 사분면은 해당 최종 PNG와 픽셀 단위로 동일하다. 경계를 숨기는 마스크·회전·다른 타일 혼합은 없다. 512×512/1024×1024 크기와 불투명 알파를 검사했다.

| 변형 | 맞닿는 경계 RGB 평균차 | 내부 인접 RGB 평균차 |
|---|---:|---:|
| A | 3.5254 | 7.5456 |
| B | 4.9993 | 11.1572 |
| C | 4.5954 | 10.2643 |

이는 경계 불연속의 수치 참고다. 육안으로 기존의 작은 바둑판과 뚜렷한 경계선은 줄어들었으나 동일 그림을 반복하면 큰 분포의 반복을 찾아볼 수 있다. **반복이 완전히 보이지 않는다는 승인을 대신하지 않는다.** A/B/C는 각각 자기 반복용이며 서로 다른 변형을 맞대는 경계 호환은 보장하지 않는다. 혼합 진단판은 경계가 드러나 납품 확인 이미지에서 제외했다.

## 실제 r7 집과 길

기존 미리보기의 초가집 house-s1은 잘못된 선택이었다. 이번에는 [r7 집 매핑](https://github.com/hyunlord/bs-mobile/blob/53fb8af/unity/Assets/Game/App/Resources/EstateDecorRules.json#L134)의 `m3a:home → manor`, 단계 [1,2]에 따라 시작 완성 집 **manor-s2**를 사용했다. 사용자가 함께 언급한 fallow-growth에는 별도의 붉은 지붕 작업장이 있으므로, r7 실제 집과 혼동하지 않는다.

- 원본: 기존 `buildings-30-body-atlas.png`의 좌상단 crop(256,0,256,320).
- 원본 바닥 기준점 (128,280); r7 격자 중심(29,28)에 배치.
- [r7 크기 계산](https://github.com/hyunlord/bs-mobile/blob/53fb8af/unity/Assets/Game/App/EstateDecor.cs#L300): 화면 배율390/768 × 건물 폭192/원본폭256 = 0.380859375. 캔버스97.5×121.875, 불투명 집 높이 약46px.
- r1의 누락된 0.5 배율과 불필요한 수직 오프셋도 바로잡았다.
- 집 문 원본 기준점(147,267)에서 집 앞 빈칸(29,29)으로 연결하고, 9개 부지의 앞쪽 경계까지 빈칸 경로로 연결했다.
- 길 재료는 기존 `ground-path-straight-512.png`의 흙 중앙 띠 crop(0,224,512,64). 연결부는 같은 그림의 둥근 마스크와 얇은 가장자리 블렌딩으로 조립했다. 새 벡터 단색 길로 대체하지 않았다.
- 12×12 시작 구역, 집1/Lv0 9, 점유40/빈칸104, r7 좌표와 승인 부지 그림은 유지했다.
- 빈칸 경로 검사: 9/9 도달, 부지 점유 칸 침범0. 최종390×844 그림에서 집·부지·길 연결을 확인했다. 실제 게임의 경로 알고리즘이나 실행 화면을 증명하는 자료는 아니다.

## 제작과 보존

공통 생성 지시: 승인 C의 잉크·과슈와 따뜻한 흙/올리브 풀 색, 큰 불규칙 연결 분포, 서로 다른 덩어리 크기, 네 방향 반복, 격자·바둑판·띠·중앙 상징·물체·도로·비네트 금지. B/C 수정 지시: 방향성 띠를 제거하고 5~8개 서로 다른 크기의 불규칙 분포와 낮은 대비를 사용.

전체 프롬프트·원본·보류 후보·기계 검사는 로컬 `output/m3-lv0/r2/`에 보존했다. Swift 내보내기/조립 typecheck 및 실행 통과. 기존 승인 PNG는 재생성·색보정하지 않았다. 게임 코드·데이터·Unity 자산 변경0, 추가 의존성0. 문서 기록만 저장소에 추가한다.
