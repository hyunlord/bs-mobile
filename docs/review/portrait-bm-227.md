현재 source 구현 식별자는 `1f9609c`(재생 보상), `18a1252`(원자적 계정 보상), `c15565f`(BM UI)다. 선행 main 반영 시 바뀔 수 있으므로 최종 공개 커밋·PR·CI는 따로 기록한다. 실제 net8.0·netstandard2.1 DLL의 명시적 v5 fixture 재생 해시는 모두 `44476CDB3FA0449EBCE6B907E43B754FCA6F52C3AD71B5BC68587ACA2B164F48`이다. 이 CLI fixture의 해시와 Unity PlayMode에서 기록한 별도 죽음/부활 판의 해시 일치 검사는 서로 다른 증거다.

Unity 원자료는 `artifacts/portrait-227/BmEdit.xml`(17/17: 광고 정책14·Meta 통합3), `Flow.xml`(12/13), `BmFlowRetry.xml`(5/5)이다. 최초 실패는 재시작 뒤 그래픽이 raycast 목록에 등록되기 전에 확인한 BM 검사였다. 렌더 대기와 assertion을 보강한 뒤 BM5개를 다시 실행했으며 최초 실패 XML은 보존했다. 따라서 13개를 한 실행에서 전부 통과했다고 합쳐 쓰지 않는다. 최초 검사에서 선행 PR1·PR2 화면8개는 통과했다. 수정 후 BM 검사에는 실제 부활 버튼과 최종 재생 해시 검증, 광고 실패 무지급/무소비, 광고 제거 직접 지급, 재시작 후 정확히 한 번 받기가 포함된다.

위 검사는 Unity Editor의 실제 화면·버튼 경로 검증이다. Mac Release 프레임 관문이나 Fold7 실기 증거가 아니며, 네이티브 성능은 아직 미측정이다.

## 실제 제품 경계

일반 Release에는 가짜 광고 제공자와 성공 토글이 없다. Editor/Development에서만 가짜 성공/실패를 고를 수 있다. 광고 제거는 테스트용 권한 주입을 검증할 뿐 실제 구매 기능이 아니다. 광고·결제·분석 SDK와 실제 상점 결제는 추가하지 않는다.

방치 광고2배는 실제 방치 claim에 추가1배를 적용하되 기존 지갑 상한을 유지한다. 하루3회는 가설이다. 결산 광고 보상은 실제 지급된 자재만 기준으로 삼으며 가신 조각을 늘리지 않는다. 별도 결산 배율·상한 #126은 설정되지 않았으므로 일반 실행에서는 제안을 숨긴다. 부활 #224도 생산 체력·위치·무적 수치를 임의로 만들지 않아 제안을 숨긴다. 명시적 테스트 fixture의 부활 화면과 명령 증거는 생산 부활 승인으로 표현하지 않는다.

재생 v5는 host 보상 옵션이 있는 새 판에서만 사용한다. 기존 v1–v4 판의 형식과 해시 경로는 보존한다. 실행 중 보상은 명령으로 기록하고, 계정 보상은 완료 ID와 판/claim sequence를 원장에 저장하여 다시 받아도 지급하지 않는다. 지급 저장 후 host 확인이 실패한 경우 기존 영수증을 확인해 완료 처리를 재시도한다.

## 최종 보고에 필요한 산출물

실제 화면 비교 시트는 확인하지 못한 원격 canvas 자체와 비교했다고 쓰지 않고 사용자 서면 규격 보드와 나란히 표시한다.390×844 기준과1080×2520 기기 비율 시뮬레이션은 서로 구분하며 #98 Fold7 실기로 표기하지 않는다. 실패·숨김·광고 제거 즉시 지급·첫 판/첫날·한도·복귀 상태를 테스트와 캡처에서 구분한다.

최종 공개 커밋·PR·CI, 화면 비교 시트, Mac 빌드 링크와 네이티브 끊김 표는 아직 없다. 파일이 생기기 전에 링크나 통과 수치를 만들지 않는다. CSV에서 재생성할 수 있는 그래프·보고서를 Release 원자료로 중복 업로드하지 않는다. 소스·작은 정본 CSV·재생성 명령을 유지하고 필요한 실패/표본과 Mac 배포물만 전달한다.
