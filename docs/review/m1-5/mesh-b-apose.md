## 입력과 실행

승인 입력 `a-knight-apose-v2.png` 1024×1536, SHA256 `1e43458a2a0b92009bd9576596db42cd596eb98af6598b6086e65fab824c9da4`. BiRefNet 배경 제거 RGBA의 RGB는 승인 이미지와 바이트 단위 일치한다. [입력 비교 기록](apose-b-input-review.md)을 기준으로 한다.

DGX Spark의 격리된 TRELLIS.2에서 seed42, `1024_cascade`로 실제 실행했다. 생성397초, exit0. 원본 고밀도 PLY와 속성 볼륨은 로컬/원격에 보존했다. 생성에 사용한 비상업 제한 의존성은 없으며 공식 `to_glb`를 호출하지 않았다.

## 감량 실패와 재시도

첫25,000 목표 직접 감량은24,237삼각형이 됐지만 최대 연결 성분이5,836삼각형에 불과해 몸체가 조각났다. 텍스처 작업을 중단하고 `rejected-direct-simplify/` 및 `texture-export/rejected-fragmented-target/`에 실패를 보존했다.

원본을 다시 읽어 MIT CuMesh의 작은 성분 정리(면적 임계1e-5)·비다양체 정리 후75,000→25,000 단계 감량과 xatlas UV를 수행했다. 최종22,445삼각형 중 최대 연결 성분20,425(91.0%), 용접 기준951성분이 남는다. 미세 조각이 남아 있으므로 완전한 단일 몸체나 리깅 준비 완료로 판정하지 않는다. 원본 대비 축별 경계 차이는 최대 약0.0016모델 단위이며, 이는 얼굴·손·옷의 국소 형상 보존을 대신하지 않는다.

첫 원본 표면 광선 베이크는 얇은 옷의 반대편 색을 가져와 삼각 얼룩을 만들었다. 조명 없는 Emission에서도 얼룩이 남고 회색 clay에서는 사라져 색 투영 문제로 분류했다. 광선 범위를 줄이면 얼룩은 사라졌지만 검정 미투영점이 생겼다. 두 실패를 보존하고 원본 속성 볼륨을 UV의 실제 위치에서 직접 조회하는 방식으로 바꿨다.

최종 UV 내부10,576,216텍셀 중98.7244%는 원본 볼륨 RGB, 미지원134,908텍셀(1.2756%)만 원본 고밀도 삼각면 최근접 위치의 barycentric 색 보간이다. 보완 표면 거리 p95=0.001884/최대0.004427(캐릭터 높이 약1인 원좌표). 새 색·그림 생성이나 저밀도 정점색 감량은 없다. 원본 정점1,024곳의 조회 RGB는 저장 원본과 바이트 일치한다.

중간 PNG 저장의 중복 감마 변환으로 어두워진 후보도 보존했다. 변환 수정 후 저장 PNG와 입력 RGB 차이는 평균0.00098/최대0.001966으로1바이트 양자화 이내다. 공식 exporter의 PBR 전체 속성 재현을 주장하지 않는다.

## 검토와 다음 관문

정면·측면·후면, 얼굴·양손 확대, 약100px 정지 표본을 **최종 텍스처 GLB 재불러오기 렌더**로 제출한다. 승인 입력 및 고밀도 원본 렌더는 별도로 표시한다. 정지 화면은 걷기 변형 검사나 게임 실행 증거가 아니다.

직접 렌더 확인: 넓은/좁은 광선 베이크의 삼각 얼룩과 검정 빈점, 중복 감마의 색 변화는 최종 후보에서 해소됐다. 금발·푸른 목장식·상아색 옷은 유지되나 얼굴의 면각과 눈 세부 손실, 장갑 손가락 뭉침, 어깨 문양 흐림은 남는다. 이것을 사용자 허용으로 간주하지 않는다. [검토 표본 Release](https://github.com/hyunlord/bs-mobile/releases/tag/m1-5-mesh-b-apose-v2)의 정본은 아래 SHA의 최종 GLB에서 만든 시트다.

메시 확인 후에만 별도 검·망토 부착과 Mixamo 걷기1동작·1방향 시험으로 진행한다. 그때 팔·옆구리·망토·다리 사이뿐 아니라 **겉옷 앞판이 다리 사이에서 늘어나는지** 확대 확인한다. 사용자 걷기 승인 전 베기·피격·8방향 확장은 금지한다. 원본 FBX는 Git/Release에 올리지 않는다.
