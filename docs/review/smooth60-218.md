## 무엇이 바뀌었고 무엇이 남았나

기본 Mac 표시를 60fps로 맞췄다(120Hz vSync2, 60Hz vSync1). 화면 주사율 변경을 추적한다. 새 설정 버전은 기존 저장에도 한 번 빠른 걸음·피격 표현을 켜고, 접촉 즉시 피격·체력100은 끈다. 이후 사용자가 바꾼 선택은 유지한다. 영주 B의 몸 높이를 1.25배 복원하면서 발·그림자·발밑 링은 유지하고, 경고는 영주 쪽 짧은 구간·출발 쪽 페이드·화면 가장자리 화살표로 바꿨다. 같은 틱10800의 실제 캡처 비교에서 몸 높이 복원과 발·링 고정, 짧고 옅어지는 경고를 확인했다. 내부 시각 검토92점은 사용자 승인이나 성능 통과가 아니다. 화면 품질의 최종 판정은 사용자 직접 플레이다.

Core는 제한된 크기의 평면 격자와 희소 영역 대체 경로, O(1) 셀 이동, 익은 밭 조건 캐시, hot path의 LINQ·클로저 제거, 재사용 스냅샷 버퍼를 적용했다. 공개 스냅샷은 별도 소유권을 유지해 후속 틱이 이전 값을 바꾸지 않는다. 거리→Id와 실행 순서·규칙·수치는 보존했다.

그러나 최종 네이티브 진단 730틱에서 평균 Advance 4.841ms 중 Enemy 4.517ms, Separation 2.124ms, Residual 0.752ms가 남았다. Enemy 안에 Separation, 그 안에 Residual이 있으므로 더하면 안 된다. 비중은 각각 전체 평균의 93.30%, 43.88%, 15.53%다. Work 0.095ms, Attack 0.208ms다. 분리 외 Enemy 작업도 평균 2.392ms로 남아 있다. .NET의 할당 감소만으로 Mono의 GC 목표를 달성했다고 주장하지 않는다.

C05 화면 비용 증가는 부분적으로 **`7ee40b6`의 개체 발밑 표시**로 좁혔다. 같은 `52cea1f` 바이너리에서 이 표시만 끈 진단을 한 번씩 비교하면 화면 구성 평균은 밀도별 1.320→1.118 / 1.718→1.455 / 2.031→1.750ms였다. 약 0.202/0.264/0.280ms(13.8~15.4%)가 이 변경의 측정된 기여다. 적 구성 평균도 0.812→0.602 / 1.130→0.854 / 1.363→1.068ms로 줄었다. `ShapeBatch.Add`의 511개 중간 제출은 적 구성 범위 안에서 일어나므로 최종 Submit 시간만 보면 빠진다. **표시 제거는 진단 전용이며 제품에 적용하지 않았다.** 이것으로 전체 회귀를 설명하거나 해결했다고 하지 않는다.

C05에서 휴경 마스크 갱신·업로드·페인트 방문은 모든 진단 행에서 0이었다. 이 하네스의 회귀 원인으로 마스크를 지목하지 않는다. GPU의 이전544→eed 비교에는 같은 증가가 없었고, 이번 GPU 값은 달라져 환경·작업량 측정치로만 기록한다. 남은 주된 CPU 비용은 적 화면 구성이다. C05 상세 정본과 반복별 수치·출처는 [smooth60-c05.csv](../metrics/smooth60-c05.csv)에 있다.

과거 830.8411ms 장은 0명령·시뮬레이션0·GC0이었고 다음 장의 23명령 따라잡기와 구분했다. 이번 정상3회 및 진단2회에서 100ms 초과는 0장이며 같은 틱7920~7935 최대는 정상 반복별 3.358/3.415/3.237ms였다. **재현되지 않았다는 관측이며 OS·드라이버 원인 확정이나 수정 완료가 아니다.**

## 증거 경계와 재현

- 네이티브 앱 정본은 깨끗한 `52cea1f5d09d4a1abec749a0fb1529193b0d07d3`, sourceHash `F49861D232E04AC141C8FB0ED67E09BEC1CC77C635261001D8F1CB496162186C`다. 이후 `1a30081`·`f7e2b92`는 테스트/에디터 검증 후속이다. 앱을 f7 빌드라고 표기하지 않는다.
- 실제 net8.0·netstandard2.1 DLL 및 네이티브는 411의 `59805294…43619`(11530틱), C05의 `B056B090…8AEE8`(14400틱)가 일치했다. 이는 Android IL2CPP/Fold7 증거가 아니다.
- Unity EditMode 73개 및 공개 스냅샷 경계 후속2개 통과. `f7e2b92` 전체 CI가 통과했고, 로컬에서 같은 전체 검사를 중복하지 않았다. 공개 스냅샷·오프라인 캡처·진단 분리의 별도 코드 검토도 완료했다.
- C05 FrameTiming 수치는 관측 프레임 ±16의 33장이 모두 같은 밀도·전경일 때만 연결했다. GPU 표본 포함률은 99.94/99.92/99.79%다. 실제 GPU 원본 프레임과 타임스탬프로 조인한 것은 아니다. 서로 다른 단계의 p95를 빼서 비용을 만들지 않았다.
- 오프라인 영상은 `Time.captureFramerate=60`으로 생성한 표시 검토 자료다. 실제 장 간격·조작 지연·성능 증거는 위 캡처 없는 실행이며, 영상의 부드러움으로 성능 실패를 통과 처리하지 않는다. 전후 캡처 모두1460/1460장·연속 인덱스·종결 해시를 검증했고, 모든 프레임의 틱과 보간 alpha가 일치했다. Metal JPEG의 상하 반전은 인코딩과 비교 그림에서 모든 프레임에 동일한 `vflip`으로 바로잡는다.
- 전후 그림의 이전 쪽은 **통제된 표시 비교 빌드**다. f7 소스의 시각 파일6개만 `466c84b`로 바꿨으며, dirty sourceHash는 `736001638B82457A79BFEFF3AD1BCF938A721BF85197D5BF3F960B5003D8BCEE`다. Core·입력·카메라를 맞춘 비교이지, 원본544 바이너리의 캡처가 아니다. 이후 쪽은 깨끗한52 앱이다. 비교 후 임시 소스 변경은 모두 복구했다.
