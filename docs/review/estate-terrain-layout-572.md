# 승인 r8 영지 배치의 데이터 추출

상태: 데이터/오프라인 재현 검증 통과, 사용자 승인 대기. [#572](https://github.com/hyunlord/bs-mobile/issues/572).

## 목적과 원본

[#496](https://github.com/hyunlord/bs-mobile/pull/496)의 두 번의 밀도 실패는 보존한다. 이번 작업은 새로운 자동 산포 규칙을 만드는 것이 아니라 승인된 75px 장면의 배치를 명시적인 좌표 데이터로 내보내는 작업이다. Unity 로더·게임 규칙은 변경하지 않는다.

원본은 [승인 자산 Release](https://github.com/hyunlord/bs-mobile/releases/tag/estate-r8-terrain-488-20261028)의 `DENSE-SCENES-r2.json`이다. 내부 제작판 r9를 공개 r2로 동결했으며 2,110개 배치, 바닥 영역 13개, 카메라 3개가 남아 있다. 기존 그림은 다시 생성하지 않는다.

- 시작 마을: 격자 중심 (28,29).
- 강·다리: (45,34).
- 숲·언덕: (21,16).
- 75px 배율: 75/98.7. 승인본의 1칸 투영은 (32(x-y),16(x+y)).

현재 r8 설정과 원본의 13구역 ID·좌표·크기는 모두 일치한다. 면적은 1,664칸이다. 시작 땅은 (24,24)부터 12×12칸이다.

## 원본 재현과 예약 칸 정리

원본은 일부 건물 그림의 투명 여백 아래 낮은 정원 소품을 허용했다. 최신 사용자 요구는 부지·건물·길 칸을 비우는 것이므로 두 결과를 구분한다.

1. **원본 재현:** 승인 배치를 좌표 계약으로 변환한 결과. 승인 PNG와 차이를 측정한다.
2. **최종 배치:** 보호 영역과 접지 면적이 겹치는 소품을 제외한 결과. 제외 목록과 화면 차이를 남긴다. 이 결과를 원본과 픽셀 단위로 동일하다고 주장하지 않는다.

나무 수관의 시각적 돌출과 지면을 점유하는 바닥 면적은 구분한다. 그림만 보고 실제 충돌체가 있다고 주장하지 않는다. 리뷰용 기존 건물은 게임의 기존 건물을 다시 그리는 중복 지시가 되지 않도록 구분한다.

## 검증 및 한계

오프라인 합성이 실제 게임의 draw call·저장·카메라·성능 검증을 대신하지 않는다. 최종 화면 승인은 사용자에게 있다.

## 최종 데이터와 결과

[배치 JSON](../../data/opt-in/estate/terrain-layout-r8.json)과 [로더/재현 계약](../../data/opt-in/estate/README.md)을 제공한다. 원본 2,110개를 최종 지형 2,055개, 보호영역 제외 45개, 비교용 기존 건물 10개로 보존한다. 지형 배치 중 시작/인접 범위는 355개, 나머지 구역은 354개, 외곽 숲·안개는 1,346개다. 67개 자산은 Release URL·SHA·크기·앵커 또는 조합/crop 계약으로 해석된다.

원본에서 겹친 45개는 재산포하지 않고 제외했다. 10개는 건물/Lv0, 34개는 길, 1개는 강 영역과 겹쳤다. 최종본의 명목 접지 면적과 예약 영역 간 겹침은 0이다. 작은 수관/그림자까지 전부 겹침 0이라는 뜻은 아니다.

| 75px 장면 | 승인본→JSON 원본재현 RGBA 차이 | 예약칸 정리 후 변경 픽셀 | 승인본 빈 땅 | 정리 후 빈 땅 |
|---|---:|---:|---:|---:|
| 시작 마을 | 0 / 329,160 | 21,060 (6.398%) | 21.4467% | 25.0365% |
| 강·다리 | 0 / 329,160 | 6,767 (2.056%) | 33.3886% | 35.0082% |
| 숲·언덕 | 0 / 329,160 | 14,410 (4.378%) | 19.3836% | 22.7172% |

밀도는 승인본의 동일한 strict visual-water 측정 방식으로 비교했다. 앞에서 뒤로 쌓인 소품의 알파 기여도를 계산하고 물 면적을 분모에서 제외한다. 새 방식의 더 낮은 보조 수치를 기존 지표로 대체하지 않았다. 세 장면은 모두 40% 이하이며, 실제 게임 #496 실패 수치를 덮어쓰지 않는다.

빈 원격 캐시에서 Release 다운로드→atlas crop→강12조각 합성→67개 원본 PNG 바이트 SHA 일치→JSON-only 재조립을 실행했다. 승인 PNG는 차이 비교에만 쓰고 배치·바닥 생성에는 쓰지 않는다. 원본 작업 폴더 없이 재현한다. 기존 PNG/실패 후보는 보존한다.

## 로더 인계 주의

- 최종 `instances`만 지형으로 그린다. 기존 건물 10개와 제외 45개는 `reviewOnly`에 있어 게임에서 다시 그리지 않는다.
- `zoneId`는 앵커 소속이다. 강·길·다리 등 구역 경계를 가로지르는 그림의 가시성을 단일 구역 ID만으로 끄지 않는다. 이번 결과는 전체 회복 배치이며, 잠긴 구역 클립·어둠 처리는 실제 로더의 별도 검증 대상이다.
- 시작/인접 그림은 우선 추출 범위 확인용이다. 실제 신규 계정의 해금 상태를 모사하지 않는다.
- 현재 좌표는 명시적 배치다. RNG·카메라별 임의 배치·다른 빈 공간 채움 알고리즘을 넣으면 승인본 재현 계약을 잃는다.

- Unity·휴대폰·실제 신규 계정·잠긴 구역·draw call·저장 동작은 **NOT_RUN**. 최종 그림 승인은 사용자 대기다.

## 공개 비교와 측정 입력

[검토 Release](https://github.com/hyunlord/bs-mobile/releases/tag/estate-terrain-layout-572-20261030)에 시작·강·숲 비교판 3장과 13구역 개관판을 선정한다. 각 비교판은 승인 원본 / JSON 무손실 재현 / 예약칸 보호본 순서다. 각 화면 패널은 390×844 원배율이다. [작은 결과 CSV](estate-terrain-layout-572.csv)에 차이·밀도·보이는 소품 수를 보존한다.

strict 밀도 평가는 원본 r9의 `density-{camera}-house75-r9-land.png` 및 `density-{camera}-house75-r9-visual-water.png` 총 6장(54,908bytes)을 고정한 검증 입력으로 사용한다. 이 입력도 새 Release에 함께 공개한다. 그림 합성에는 사용하지 않으며 측정 분모만 원본과 맞춘다. 원본 비교 PNG와 마스크가 없더라도 JSON+자산만으로 그림 생성이 가능하고, 두 경로의 출력 PNG 동일성을 확인했다. 마스크를 다운로드하지 않은 실행은 이 strict 평가가 미실행임을 표시한다.

```sh
mkdir -p artifacts/terrain-layout-review/preview
gh release download estate-terrain-layout-572-20261030 -R hyunlord/bs-mobile --pattern 'density-*.png' --dir artifacts/terrain-layout-review/preview
```

위 `preview`는 재현 명령의 `reference` 폴더와 같은 부모 아래에 둔다. 모든 성공 중간 산출물을 중복 업로드하지 않는다. 새 자동 배치나 그림 보정으로 40%를 맞춘 것이 아니라, 원본 배치를 추출하고 예약칸 충돌만 제외한 결과다.
