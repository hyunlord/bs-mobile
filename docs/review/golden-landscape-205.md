# #205 가로 화면·약한 빌드 후속 검토

관문: 부분 — 최종 소스 `11d991b`의 세 해상도 카드·HUD는 실제 화면 검토를 통과했다. 약한 빌드의 6분 영상, 혼잡 장면 경고와 활성 조이스틱 확인은 대기다. 이전 움직임 판정과 실패 자료는 보존한다.

## 범위와 검증 경계

- 1920×1080·1440×900·1280×800에서 카드 전체 문구·선택·금지·고정·다시 뽑기와 첫 카드 도움말을 동시에 확인한다.
- 가로 HUD와 장비 막대는 각각 높이 11% 이내, 장비는 한 줄이다. 조이스틱 그림은 1080p 환산 지름 160px 이내·반투명이며 입력 반경은 그대로다.
- 돌진 출발점 대신 경로의 화면 교차를 검사한다. 실제 HUD 영역 아래로 경고를 자르고 어두운 테두리와 방향 화살표를 유지한다. 영주 외곽선을 강화하고 성장 문구는 하나씩 표시한다.
- `--capture-weak-build`는 정상 입력으로 외곽을 이동하며 아이템·기존 장비를 우선한다. 무기 최대 2개·진화 없이 필요한 카드만 선택한다. 경험치·레벨·적 수·시각을 강제로 바꾸지 않는다. 6분 이전 사망은 실패 증거로 보존한다.
- `--normal-gc-probe`는 영상·오디오 캡처 없이 별도 프로필에서 정상 UI 입력으로 6분을 진행한다. 미리 할당한 숫자 행에 GC 세대별 증가와 현재/다음 프레임 시간을 기록한다. 이는 GC 슬라이스의 소요 시간 자체를 측정한 자료는 아니다.

이번 가로 화면 후속(`a8c2f31`→`11d991b`)에는 Core·실행 데이터·수치 변경이 없다. PR #205 앞부분의 승인된 적 분리 변경과 역사 해시 기록은 별도다. #126·#98·1b 및 별도 C05 측정 보류는 유지한다. 전체 .NET 검사는 CI에 맡기며 로컬에서 중복 실행하지 않는다.

## 검증 기록

최초 Unity 컴파일의 `Game.Debug` 이름 충돌과 테스트의 아트 프로필 불일치는 수정했다. 실패 로그는 `artifacts/golden-minute/landscape-205/`에 보존한다. 집중 EditMode 03은 35개 중 34개 통과·실패 0·1개 생략이다. 생략은 Unity Mono가 할당 바이트 카운터를 지원하지 않는 큐 검사이며 무할당 통과로 부르지 않는다. 독립 코드 검토에서 발견한 첫 카드 도움말 null 참조와 가장자리 화살표 누락을 수정하고 재검토했다.

최종 집중 EditMode 04는 60개 중 59개 통과·실패 0·같은 할당 카운터 1개 생략이다. 경험치 알림은 표시 중 문구를 보존하면서 4종 대기를 합치고 XP 합계를 유지한다. 실제 7·8건 연속 수집 회귀를 포함한다. 자동 카드 선택의 컨테이너 의존도 공통 버튼 이름으로 제거했다. 독립 최종 소스 검토에서 추가 차단 결함은 없었다.

아래 실제 실행 결과와 미완료 항목을 구별한다. 정적 검사로 실제 가로 화면을 통과 처리하지 않는다.

첫 네이티브 `a8c2f31/ui-01`은 세 해상도 모두 전경·정확한 크기였으나 실패했다. 1920×1080의 화면 밖/잘린 요소25개, 1440×900의 본문 넘침2개가 있었고 1280×800은 기하 검사상0개였다. 창 크기는 바뀌었지만 Canvas 배율·RectTransform 크기가 늦게 갱신된 것이 원인이다. 생성 전 배율 동기화와 실제 UI 크기 캐시를 추가하고 첫 이동 도움말을 HUD 안으로 옮겼다. 집중 EditMode 05는61개 중60통과·0실패·할당 카운터1생략이며, 지연된 배율 회귀를 포함한다. 첫 실패 캡처는 보존한다.

`38f3180/ui-02`의 세 크기 카드 캡처는 기하 검사와 독립 실제 이미지 검토를 모두 통과했다. 그러나 세로에서 생성된 활성 이동 도움말은 창 변경 후에도 큰 패널로 남아 전장을 가렸다. 따라서 HUD가 계산상78%를 비운다는 사실만으로 전투 화면 통과를 선언하지 않는다. 활성 도움말의 크기·방향 변경도 재배치하고 세로 복귀를 복원했다. 집중 EditMode06은60통과·0실패·같은1생략이며 이동·수확·징집 문구의 실제 글꼴 높이와 양방향 재배치를 검사했다.


## 최종 가로 화면: `11d991b/ui-04`

`ui-03`에서는 도움말의 장식 테두리가 글자를 침범했다. 이 실패도 보존하고 프레임 배율을 5로 고친 뒤 같은 경로를 재검증했다. `ui-04`는 요청한 세 크기에서 전투·카드 화면을 각각 한 장씩, 총 여섯 장을 실제 네이티브 실행으로 확인했다.

| 실제 크기 | 전투·카드 화면 | 기하 검사 문제 | 독립 시각 검토 |
|---|---:|---:|---|
| 1920×1080 | 2장 | 0 | 통과 |
| 1440×900 | 2장 | 0 | 통과 |
| 1280×800 | 2장 | 0 | 통과 |

카드 본문·조건·선택·금지·고정·다시 뽑기·설정과 첫 도움말을 확인했다. 장비 막대는 한 줄·화면 높이 11%, HUD와 장비 막대를 제외한 중앙 전장은 78%다. 최종 `LandscapeUiTests`는 7/7 통과했다. 독립 최종 소스 검토에서 차단 결함은 없었다. 사용자 요청 1~3의 구현과 집중 검사·위 UI 증거는 확보했지만, 실제 혼잡 경고와 활성 조이스틱은 후속 영상에서 확인해야 한다.

## 캡처를 끈 정상 6분 GC 관측

정상 UI 실행 `seed=30000`은 `captureOff=true` 상태에서 틱 0→10800을 완료했다. 벽시계 443.5469684초·50327프레임 중 일시정지 9823프레임, 포커스 이탈 0프레임, 카드 선택 41회다. 일시정지·카드 선택을 포함한 벽시계와 6분의 게임 시간을 혼동하지 않는다.

| 관측 항목 | 결과 |
|---|---:|
| Gen0 / Gen1 / Gen2 증가 | 각각 452 |
| GC 증가를 관측한 프레임 p95 / 최대 | 16.3495 / 118.5983 ms |
| 같은 프레임 중 33ms 초과 / 100ms 초과 | 1 / 1 |
| 다음 프레임 표본 수 | 451 |
| 다음 프레임 p95 / 최대 | 10.8643 / 12.0417 ms |

정본 표본은 [GC 이벤트 CSV](../metrics/golden-landscape-205-gc-events.csv)다. 선정 규칙은 `normal-gc-frames.csv`의 `delta0 > 0`인 모든 행(452개)이며, 일반 성공 프레임 전체는 올리지 않는다. 소스 `11d991b`, seed30000, `--normal-gc-probe` 명령은 [런북](../runbooks/golden-readability-review.md)에 있다. p95는 정렬한 N개 값의 `ceil(0.95×N)`번째, 초 단위를 ms로 환산한다.

세대별 증가 452는 같은 GC 주기에 대한 관측이며 **1356회로 합산하지 않는다**. 프레임 시간에는 게임 전체·재생 기록·UI 작업이 포함된다. GC가 늘어난 프레임과 다음 프레임의 관측값이며 GC 슬라이스 자체의 비용이나 118.5983ms의 원인을 특정한 결과가 아니다.

## 약한 빌드 영상 관문: 미완료

첫 `seed=30000`은 틱8296(4분36.53초), 레벨10에서 사망했다. 무기는 철날 검 하나였고 처치 경험치930·수확 경험치0이었다. 종료 해시는 `697E305806E81981DAF5D997EF3503DF4DEE7F7572955D4EB936C3759BAA1EA3`이다. 이 실패를 보존하며 6분 관문 통과로 세지 않는다.

두 번째 시도의 `weak-live-02`는 게임 시작 전에 녹화 길이150초가 허용 상한60초를 넘어 거부되었다. 이 명령 실패를 보존한다. 실제 재시도 `weak-live-03`은 `seed=30001`로 0부터 정상 진행했으나 틱9944(5분31.47초), 레벨10에서 사망했다. 무기 철날 검 하나·처치 경험치910·수확 경험치0, 해시는 `6841D77C342F520769591CA65338CE6848F3F50A79F55620E010679F31FEAE2B`다. 요청한 6분 장면에 미도달했다. 두 번째 무기를 도구보다 후순위로 피하던 관측 정책만 허용 범위(무기 최대2개·진화 없음)에 맞게 바꿔 재시도한다. 게임 규칙·수치·자원은 바꾸지 않는다. 혼잡 경고·활성 조이스틱 판정은 실제 영상 확인 전까지 대기다. 위의 캡처 없는 GC 실행을 약한 빌드 영상의 대체 증거로 사용하지 않는다.
