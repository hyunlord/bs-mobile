# 종 도둑·휘파람 사냥꾼 걷기 #428

관문: 두 종 제작·내부 전16장 검사 통과. 사용자 그림 승인과 게임 적용은 별도다.

[Release](https://github.com/hyunlord/bs-mobile/releases/tag/m3-bell-whistle-walk-review-428-20261027) · [이슈 #428](https://github.com/hyunlord/bs-mobile/issues/428)

감사표 순서대로 종 도둑을 먼저 제작·전달·보고한 후 휘파람 사냥꾼을 제작했다. 이전 [#425 Release](https://github.com/hyunlord/bs-mobile/releases/tag/m3-rope-ember-walk-review-425-20261027)의 올가미 적 r1·불씨 공병 r1은 2026-10-27 사용자 승인이다. 해당 Release에 승인을 기록하고 과거 파일과 제작 당시 판정을 보존했다.

## 납품

|role|걷기|atlas/셀|바닥 기준점(좌상단)|표시|
|---|---|---|---|---|
|enemy.core.bell_thief.walk|16×40ms=.64초|4096×256/256×256|(128,225)|110px 셀, 몸 약86px|
|enemy.core.whistle_hunter.walk|16×40ms=.64초|4096×256/256×256|(128,225)|89px 셀, 창 포함 약71px|

각각 개별 투명 PNG16장, 개별 전신 접사16장, 전체판, 손–소품 검사표, 1배·3배 반복영상을 제공한다. 미설치 manifest 후보와 제작 원화·설정·C#·내보내기 스크립트는 Release에 있으며 게임에 설치하지 않았다. 셀은 inset0이다.

종 도둑은 상체·손·종 손잡이·종추, 휘파람 사냥꾼은 상체·양손·휘파람·창을 각각 한 연결 원화로 유지하고 양다리를 실제 SpriteSkin 고정 길이 IK와 발목 가중치로 변형한다. 먼 다리 색 배율은 (.42,.45,.58)이다. 가려진 관절을 보인다고 간주하지 않으며 검사표의 O는 확인 불가, O/P는 관절은 가려졌으나 옷 경계는 연속이라는 뜻이다.

## 검증

Unity6000.6.4f1/2DAnimation16.0.1 격리 프로젝트에서 80위상+닫힘+정지 기준을 Camera.Render로 캡처했다. 공유 Mac 잠금을 지키고 낮 시간대에 실행했다. 게임 프로젝트와 원본 atlas는 변경하지 않았다.

- 종 도둑: 독립 검토자의 개별 전신 접사00–15 확인, root 전체판 검토. 앞손가락→종 손잡이 연속, 종 테두리·종추 잘림 없음. 뒤 손목·목은 가림으로 기록.
- 종 도둑: 고유 프레임16/16, 캔버스 가장자리 알파0. 고정 뼈길이 변화 최대0.00003소스px, 같은 재질 지지점 이동 최대0.00010px, 지면Y오차0.
- 종 도둑 닫힘000↔080: 9픽셀에서 채널 최대1/255 차이. 픽셀 완전동일 주장은 하지 않는다.
- 종 도둑 영상2개: 각각160프레임/10주기/6.4초. ffprobe 확인과 ffmpeg 전체 디코딩 종료0.

- 휘파람 사냥꾼: 독립 검토자의 개별 전신 접사00–15 확인, root 전체판 검토. 손–휘파람과 반대 손–창대 연결 유지, 창끝·하단 잘림 없음. 정확한 입술 접촉부는 가림으로 기록.
- 휘파람 사냥꾼: 고유 프레임16/16, 캔버스 가장자리 알파0. 고정 뼈길이 변화 최대0.00004소스px, 같은 재질 지지점 이동 최대0.00010px, 지면Y오차0. 닫힘5픽셀에서 최대채널1/255 차이. 영상2개 각각160프레임/6.4초, 전체 디코딩 종료0.

실제 게임 이동속도 동기화, 전투 화면 판독성, 실기 성능 및 사용자의 최종 그림 승인을 대신하는 검사가 아니다. 정지 접사·연속 위상·영상 인코딩 검증과 사용자의 실시간 재생 판정을 구별한다.
