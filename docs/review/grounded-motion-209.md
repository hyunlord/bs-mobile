관문: 부분 — 영주 B의 12자세·분리된 공격 자세와 검은 분신 제거를 적용했다. 구형 맵의 캡처 없는 혼잡 재생 p95는 16.603→13.792ms이며, 보행의 사용자 판정·적 애니메이션·네 가지 체감 실험·들판 비교는 아직 완료하지 않았다.

영주가 공격할 때 상체만 공격 자세로 바뀌고 다리는 이동 거리에 맞춰 걷는다. 발 디딤의 수학적 접촉 검사와 실제 GPU 영상은 구별하며, 실제 화면의 발 미끄러짐 0을 확정하지 않는다. 세로 이동은 더 짧은 투영 보폭을 사용하므로 종종걸음처럼 보이는지는 사용자 검토가 필요하다.

2배 확대 전후 비교의 로컬 표본은 `artifacts/grounded-motion/hero-b-before-after-2x.png`와 `hero-b-before-after-2x.mp4`다. 원본은 같은 seed 30001·오른쪽 일정 입력·1920×1080·실시간 5초의 `old-b-landscape-01`(019c5e3, 60.027fps)과 `new-b-landscape-03`(94676f3, 59.925fps)이며, 각각 301프레임·누락 슬롯 0이다. 확대 편집은 새 플레이 증거가 아니며 원본 녹화 시각을 유지한다.

화면 구성은 CPU 제출 비용이며 GPU 완료 시간이 아니다. 그리기 호출은 월드 배치만 세며 UI·렌더 파이프라인 전체 호출 수가 아니다. GC는 프로세스 전체 Gen0 횟수이고 할당 바이트 계측은 사용 불가였다. 배열 스냅샷의 LINQ 제거, 적 분리의 몸 너비·돌진 상태 캐시, 중복 영주 외곽선 제거를 적용했지만 세 변경의 기여를 각각 분리 측정한 것은 아니다. 평균 FPS나 캡처 켠 영상의 GC를 이 표와 혼합하지 않는다.

실패 표본도 보존한다. `after-invisible-hero-failure`(3bc824b)는 빌드에서 영주 셰이더의 instancing variant가 제거되어 영주가 보이지 않았으므로 성능 개선 판정에서 제외했다. Resources의 instancing material을 유지한 94676f3의 영주가 보이는 실행만 위 이후 표에 썼다. 세로 위쪽 보행 `new-b-portrait-up-01`은 900×1600, 59.608fps, 누락 슬롯 **2개**로 60fps 관문 실패다. 이 자료의 일반 설명 문자열은 오른쪽 입력이라고 남아 있으나 실제 `movementProtocol`은 `tick-walk-up-v1`이므로 후자를 기준으로 읽는다.

[PR #211](https://github.com/hyunlord/bs-mobile/pull/211)의 GPU 검사에서 사용한 reflection이 Unity 경계 CI에 걸렸다. 수정 커밋 `d164b353be9aafb1ec4b2cf6078f22a91f837812`는 editor 전용 테스트 동작으로 대체하며, 고립 작업 트리에서 경계 검사 9개 assembly와 player 소스 무변경 비교를 통과했다. 이 초안은 해당 수정의 PR CI 완료나 GPU 재실행을 주장하지 않는다. 병합 보고에는 실제 최종 커밋·CI 실행 링크를 추가해야 한다.

[#210 들판](https://github.com/hyunlord/bs-mobile/issues/210)의 한 방향 1분·귀환 영상·같은 seed 6분 전후 비교는 별도 진행 중이다. 적 6종의 관절 애니메이션과 군중 비용 측정은 들판 다음 순서로 남아 있다. #126·#98·1b 보류를 유지한다. 새 원자료 묶음·그래프 업로드는 만들지 않으며, 공개 전달은 검토용 빌드와 선정된 영상/실패 표본에 한정한다.
