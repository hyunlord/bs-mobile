망토 색 표본은 화면 ROI x840..1009, y470..599에서 HSV hue .55..72, saturation>.4, value>.2로 선택했다. 중앙 S/V는 10장 .726/.435, 11장 .915/.514다. 이는 대략적인 렌더된 파랑 영역 비교이며 원화 재질의 정밀 색도 측정이 아니다. 색 보정 후 다시 실제 재생으로 확인한다. 기존 실패 원화와 캡처는 보존한다.

### 후속 v4 표본

v3 원본을 보존하고 망토 색만 보정한 v4를 같은 빌드·입력으로 다시 캡처했다. 같은 화면 ROI의 11장 S/V는 .627/.439, 26장은 .656/.427로 밝기 급변이 줄었다. 베기 망토는 걷기보다 약 10~14% 덜 선명하다. 독립 시각 검토에서 나머지 방향을 저작하는 기준으로 사용할 수 있다고 판단했으며 사용자 승인은 아니다. 피격 사각형 제거와 접촉 시점 일치도 재확인했다.

[E 방향 중간 표본 Release](https://github.com/hyunlord/bs-mobile/releases/tag/m1-4-pilot-819c370)에 초반 30초 걷기·베기 비교, 346장 접촉·피격·쓰러짐 비교, 접촉 연속 12장 시트를 남겼다. 모두 2배 비교이며 소리 트랙을 포함한다. E 강제 파일럿을 실제 최근접 조준 증거로 사용하지 않는다.

## 검증과 남은 관문

집중 Unity EditMode 74/74와 [819c370 CI](https://github.com/hyunlord/bs-mobile/actions/runs/38355731983)가 통과했다. 독립 코드 검토에서 접촉 프레임, 메모리 가용 여부, 종료 표현, 뿔나팔 불투명도 변경의 기능 결함은 발견되지 않았다. 이것이 아트·동작 사용자 승인을 대신하지 않는다.

Release에서는 텍스처 메모리 측정 API가 값을 제공하지 않아 `-1`, `available=false`로 기록한다. v3의 명목 RGBA 합계 14,242,776바이트는 아틀라스 폭×높이×4이며 실제 상주 메모리나 전체 증가량이 아니다.

전체 방향의 필수 동작, 실제 근접 조준 연속 프레임, 새 영웅을 넣은 무기별 30초 영상은 아직 미완료다. 네이티브 최대 50ms·25ms 초과 비율 관문은 측정 재개 후 확인한다. #126·#98·#224·1b 및 SDK 미도입은 유지한다.
