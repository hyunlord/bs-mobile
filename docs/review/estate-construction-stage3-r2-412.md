# 공사 3단계 연속성 수정 r2 (#412)

관문: 제작·내부 검사 통과, 최종 그림 승인 대기.

사용자는 밭1~3단계, 건물1·2단계, 소품4종, 정지 일꾼2포즈를 승인했다. 건물3단계 r1은2단계보다 낮고 넓어 공사 진행이 퇴행하는 문제로 반려했으며, 해당 기록과 파일을 보존했다.

## 수정과 납품

[기존 공사 Release에 r2 추가](https://github.com/hyunlord/bs-mobile/releases/tag/m3-construction-review-407-20261026).

승인2단계의 기둥 위치·높이를 기준으로 A자 서까래와 마룻대를 올리고, 하부 벽 일부에 욋가지·회반죽을 채웠다. 한쪽 비계·사다리를 유지했다. 네 PNG `building-stage3-{lit|dark}-r2-{1x|2x}.png`, 같은 기준점 겹침 비교판, `r7-construction-stages-r2.png`, 크기·기준점 목록과 프롬프트를 제공한다.

1배 캔버스136×160, 바닥중앙(68,124), 바닥128×64는 그대로다. 2배는272×320, 기준점(136,248). r7 조립판은 승인 r4 바닥과 기존 배치·다른 그림을 유지하고 세 번째 패널의 건물3단계만 바꿨다.

## 검증과 한계

2배 alpha>128 기준 꼭대기는2단계 y86→r2 y44로42px 높다. 사용자 관측 y85와1px 차이는 가장자리 알파 임계값 차이다. 단순 총bbox가 아닌 기존 기둥 상단·밑단의 겹침도 확인했으며 상세 좌표는 Release의 ASSET-LIST-r2.md에 남겼다.

첫 후보는 서까래를 넣으면서 기둥을 압축하여 제외했다. 승인2단계 원본 위에 투명400px를 추가한 입력으로 재편집한 후보를 선택했다. 기존 그림 전체를 줄이지 않고 추가 지붕 공간을 확보했다. 모든 원본과 제외 후보는 `output/m3-construction/r2/`에 보존했다.

built-in image_gen으로 그림 편집, Swift로 기계적 크기·앵커 정렬/비교/합성. 생성 편집의 미세한 붓질과 알파 차이가 남아 원본 픽셀 동일을 주장하지 않는다. 최종 그림 승인은 사용자 담당이며 실제 게임 실행 검증은 하지 않았다. 기존 납품 파일과 원본 atlas·게임 코드·데이터는 변경하지 않았다. 저장소 변경은 이 결과 문서뿐이다.
