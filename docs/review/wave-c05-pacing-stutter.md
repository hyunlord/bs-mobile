## Development 동일 구간 진단

### 후보와 중단 판정

- GC: 캡처 구간에서는 대규모 할당이 확인됐지만 관측 정지 최대는약3ms다. 문제 Release 프레임에는 이 raw 마커가 없어 과거·신규 지연 원인으로 확정할 수 없다.
- 셰이더: 확인된 큰 컴파일은 프로파일러 자신의 스크린샷에서 발생했다. 제품 멈칫과 연결하는 증거가 없다.
- 에셋 로드: 캡처에 `Resources.Load`·`LoadAsset`·`AssetBundle` 명명 마커는 없었다. 이름 없는 샘플이 있으므로 로드가 절대 없었다고 단정하지 않는다.
- 격자: 세 최초 Release 심각 지연(과거9118/11387, 이번7356)은0명령이므로 해당 프레임의 Core 격자 재구축이 직접 원인은 아니다.
- 프레임 대기·스케줄과 화면 구성: 잔여 후보다. 캡처의 `WaitForTargetFPS` 이벤트 p95는14.30608/14.54742/14.51879ms였지만 Release 문제 프레임과 연결되지 않는다. 전후 화면 구성 증가도 단일 Development 실행으로 인과를 분리하지 못했다.

사용자 중단 조건에 따라 **추정 수정 없이 조사 종료**, #169는 열린 상태로 둔다. #126·#98·1b에는 착수하지 않는다. 이번 PR은 측정과 진단 결과의 보존이며 끊김 해결 보고가 아니다.

## 검증과 리뷰

분석기49검사·Unity EditMode19검사, 두 네이티브 빌드, Release6회 및 Development1회 실제 실행, 세 raw 실제 추출을 확인했다.
