# 나루의 도전 Core 구현 계약 (#686)

- 날짜: 2026-11-04. 상태: Core 구현·기능 검증 완료, Unity·CI·C05 관문 별도.
- 근거: [승인 능동 효과 계약](active-hero-effects-contract-674.md) §5–8,
  [GDD16](../design/gdd/16-slg-heroes-proposal.md) §10.
- 직접 월드 PvE에서 정지 준비 후 자동 발동하는 도발과 방향성 단발 방패다.
  성장·해금·UTC·병상·army-auto 규칙은 추가하지 않는다.

## 발급과 상한

`HeroActiveDefinition`의 명시적 `TauntShield` 종류에만
`HeroTauntParameters`를 허용한다. 준비·반경·정지 반경·지속·재사용·대상 수·
방향 원뿔의 cosine permille·피해 감소와 자체 상한은 발급 데이터다.
명시적 적 정책과 catalog를 대조하며 보스·이동 불가 적은 도발 대상에서 제외한다.

정의가 여러 개라도 owner·종류의 동시 인스턴스 한도를 합산한다.
같은 발급의 도발 정의는 공통 인스턴스 한도와 능동 DR cap에 동의해야 한다.
같은 틱의 신규 발동은 정의 ID ordinal 순서로 남은 슬롯을 사용한다.
상한에서는 기존 인스턴스를 교체하지 않고 준비를 유지하며 cooldown을 소비하지 않는다.
정지 조건을 잃으면 유지한 준비도 초기화한다. Dash 정의는 최대 한 개다.

전체 인스턴스·claim 저장량은 checked 정수 합산으로 발급 시 제한한다.
UTF-8 ID 길이와 최대 상태 직렬화 크기도 기존 1MiB 이내인지 확인한다.
프로토콜 방어 한도는 실제 게임 수치를 대신하지 않는다.

## 접근 우선권과 이동

실제로 위치가 변하지 않은 틱으로 준비한다. 발동 틱이 첫 지속 틱이다.
중심과 방패 방향은 발동 때 고정하고, 입력 이동·넉백 등 실제 owner 이동은
해당 도발·방패를 즉시 해제한다. 별도 cooldown은 환급하지 않는다.

틱 시작 만료 처리 후, 현재 틱 소환을 마친 위치에서 한 번 membership을 갱신한다.
각 인스턴스는 살아 있고 적격이며 반경 안에 있는 기존 claim을 유지하고,
빈자리만 거리→entity ID로 채운다. 우선권에서 진 claim도 자기 상한에 센다.
동일 owner의 승자는 시작 틱→발동 sequence 순이다. 오래된 claim이 사라지면
이미 유효한 다음 claim이 즉시 드러난다. 이 API는 한 조작 영웅을 발급하며
다중 조작 영웅 전투 지원을 주장하지 않는다.

현재 월드 cohort의 접근 단계만 고정 중심으로 유도한다. 원래 이동속도·정지 상태를
보존하고 정지 반경에서 접근을 끝낸다. 이미 확정된 공격 표적·사거리·주기를
새 영웅 타격으로 바꾸지 않는다. 도발이 없는 이동은 기존 호출 경로를 유지한다.
적 이동·넉백·사망 직후 유효하지 않은 claim을 제거하며 같은 틱 빈자리를
재충원하지 않는다. 다음 전역 membership 단계에서 다시 선택한다.

## 방향 방패와 피해

방향은 발동 시 가장 가까운 도발 가능 적을 향하고 동위치라면 기존 조준 방향을 쓴다.
유효한 방향이 없거나 피해 origin이 없거나 owner와 동위치라면 방패는 부적격이다.
방향 원뿔 판정은 정수 내적과 유리수 비교이며 삼각함수·부동소수점 근사를 쓰지 않는다.

기존 면역 거절 → 기존 어둠 등 피해 보정 → 능동 DR → HP 차감 순서다.
적용 가능한 양수 raw DR을 합산하고 공통 능동 cap을 한 번 적용한다.
남은 피해는 `floor(D × (1000 - cappedDR) / 1000)`이며 0을 허용한다.
기여한 일회 방패를 모두 소비한다. 원래 면역으로 거절된 피격, 부적격 방향,
raw 0 방패는 charge를 소비하지 않는다.

완전 감소는 새 피격 면역·넉백을 부여하지 않는다. 기존 HP 피해 관찰 의미는 유지하고
실제 방패 감소량은 별도 `hero-active-reduced` 사건으로 구별한다.
기존 `estate-dark-hit`은 DR 이전의 어둠 증가량을 유지한다.
부분 피격 후 넉백이 일어나면 같은 틱 다음 타격 전에 남은 도발·방패를 해제한다.

## 상태·바이트·관문

옵션 없음과 기존 schema1, Dash-only schema2의 계약·상태·복구 바이트를 유지한다.
도발을 포함한 새 계약은 kind별 payload와 새 명시적 active runtime 버전으로
준비·재사용·인스턴스·중심·방향·charge·claim을 기록한다.
기존 accepted-prefix 재실행과 전체 runtime 비교로 복구를 검증하며
외부가 보낸 runtime을 직접 신뢰하지 않는다.

owner 사망·quit·terminal은 자체 능동 상태를 해제한다. 표식 점유는 기존 실제 위치와
살아 있는 적으로만 판단하고 도발 구역 자체는 점유자가 아니다.
실행 결과는 PR에 실제 수치로 기록한다. Core·두 DLL·Unity·C05 관문은 서로 대체하지 않는다.
