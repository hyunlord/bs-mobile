# 판 밖 경제 v0: 실제 Core 봇 관측

- 범위: [#115](https://github.com/hyunlord/bs-mobile/issues/115), 2단계 A P2. 수치는 출시 약속이나 실제 사용자 행동 관측이 아닌 설계 가설이다.
- 실행 모델: 가벼움 하루2판, 보통6판, 많이12판을 각각21일 관찰한다. 각 판은 실제 `MetaRunAdapter.ProjectCatalog`와 `SimulationFactory.Create`의27000틱 정상 전투를 끝까지 실행한다. 생존율을 임의의 확률이나 챕터별 정답표로 넣지 않는다.
- 표본 한계: 유형당 가상 계정1개, 서로 다른 seed 경로다. 세 유형의 차이를 판수만의 인과 효과나 모집단 생존율로 해석하지 않으며 신뢰구간을 주장하지 않는다.
- 입력 가설: 기존 `mixed` 카드 봇, `circuit` 이동, 사람규칙C, 매 판 최고 해금 챕터에 도전. 가신은 공격→체력→ID 순으로 빈 슬롯에 넣고 구매 가능한 강화·승급을 적용한다. 장원은 처음 대장간 우선 깃발을 유지한다. 이 입력은 사람 조작의 숙련도·재미·회피 능력을 대표하지 않는다.
- 시간 가설: 하루 한 세션, 다음 날에만24시간의 단조시간/UTC 경과를 함께 전달하여 방치 생산을 한 번 청구한다. 첫 날에는 설치 이전 방치 보상을 주지 않는다. 매 판 중간에 추가 방치 보상을 청구하지 않는다. 하루6판을 모두15분 생존하면90분이므로 ‘보통’이라는 명칭 자체도 사용자 조사 없이 정한 가설이다.
- 실제 청산: 판의 생존·보스 처치·레벨·밭·건물·사람·처치·수확을 읽어 `MetaEngine.SettleRun`에 전달한다. 한 종류의 보스만 포함된 챕터에서 `enemy:boss:kill` 실측을 보스 처치로 읽는다. 처치와 생존을 둘 다 만족해야 다음 챕터가 열린다.

## 재생성

```sh
PATH="$HOME/.dotnet:$PATH" bash tools/meta-economy.sh artifacts/economy-rerun.csv 21
node tools/meta-economy-report.mjs artifacts/economy-rerun.csv
```

`meta-economy` CLI는 기존 출력 파일을 덮어쓰지 않는다. 세 유형은 병렬로 실행하지만 각각의 상태는 순차 갱신하며 최종 CSV 순서는 light→normal→heavy로 고정한다. seed는 `710000 + 유형번호×100000 + 일차×100 + 일중판수`이다. 동시 실행 순서가 seed와 성장에 영향을 주지 않는다. 출력 옆 `.유형.partial.csv`는 실행 중단 시 완료된 날짜까지 남기는 로컬 진단 자료다. 완성본 CSV가 정본이며 부분 자료는 배포하지 않는다.

CSV의 `data_hash`는 로딩 시점 전체 정본 data JSON의 기존 `ContentLoader.Hash`이다. `run_hash`는 실제 전투 결과, `state_hash`는 정산·자동 성장·가신 구매 이후 `MetaSaveCodec`의 SHA256이다. 판정 대상은 이 CSV에 기록된 실행이다. Unity 화면과 실기 성능, 리텐션, 결제 전환을 증명하지 않는다.

## 관문 정의

‘챕터 도달일’은 잠금이 풀린 다음 **실제로 그 챕터를 처음 시도한 날**이다. 클리어일을 별도 집계하여 둘을 섞지 않는다. 보통 유형의 임시 목표는 챕터3 첫 시도1~2일, 챕터6 첫 시도5~9일(‘1주 안팎’의 이번 검사 해석), 챕터10 첫 시도14일 이후이다. 21일까지 도달하지 못한 경우에는 관측 구간 미도달로 실패 처리하며 목표에 맞춰 도달일을 추정하지 않는다.

지갑은 곡물20000·목재16000·철재12000·인장6000 상한, 가신은 레벨20·승급5, 장원은 건물별10레벨, 방치 생산은2~4시간 상한이다. 매 행에서 `이전 지갑 + credited - spent = wallet`과0~상한을 검증한다. `credited`는 판/방치 및 새 도전의 실제 입금 합계, `spent`는 자동 장원 성장과 가신 강화의 실제 비용 합계, `overflow`는 그 행에서 상한으로 버린 요청량이다. 조각은 별도 상한1000이며 승급 때 소비한다. 이 구조적 상한은 단기 관찰에서 지갑이 아직 가득 차지 않았어도 무제한 재고를 허용하지 않는다.

## 보존한 초기 실패

첫1일 파일 `artifacts/economy-pilot-01.csv`는 실행 경로와 장부 검증을 위한 로컬 표본이다. 파일을 읽어 자재 보존 검증은 통과했으나 첫 날 설치 이전24시간의 방치 생산을 잘못 지급한 가정이 있었다. 이를 첫 날0초로 수정하고21일 정본 관측을 새 파일에서 시작했다. 초기 파일은 수정하지 않았으며 최종 목표 판정에 사용하지 않는다. 이 수정은 게임 경제 계수 보정이 아니라 시뮬레이션의 시간 입력 가정 수정이다.

## 관측 provenance

정본 CSV 입력 해시는 `F7B7067CB7656AF297DDA5E20EEF4BA6C72942D3E95052EA2E0757C11CABC42D`다. 실제 실행은 격리한 Release Core DLL `5d513955f53a73a65b52646896a9a9a2043d4420ff9234e10baeb71faf1f07cf`, Sim DLL `0ae6064a7a5038480e334a92b14174d0418ad57418e067af33c2f6d153e56eea`를 사용했다. 컴파일 전후 Core 소스 해시는 같았다. 관측 중 이후 코드 형식 정리는 괄호·공백뿐이며, 후속 바이너리와의 바이트 일치를 주장하지 않는다.

최초420판 입력 해시 `F73171990E952122CB979FD299C092C8ED8F9EDE288276C13C5C2F9AED77D0A1`에는 이전 스키마 선언과 그림 참조가 들어 있다. 첫 관측을 덮어쓰지 않고 Draft2020-12 검사 통합·최종 그림 참조 뒤 전체420판을 다시 실행했다. 두 실행의 경제 계수는 같으며 결과483행을 입력 해시 열을 제외하고 전부 비교해 일치함을 확인했다. 부분 CSV·중복 보고서·원시 실행 전체 JSON은 배포 산출물이 아니다.
