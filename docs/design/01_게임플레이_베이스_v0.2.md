# 01 게임플레이 베이스 v0.2 — Sow & Siege

작성 2026-10-09 · 증거 갱신 2026-10-10 · 2단계 A P4 · 짝 문서: [02 BM·경제 골격 v0.2](02_BM_경제_골격_v0.2.md)

[확정]은 사용자 결정, [구현]은 현재 소스에 실행 경로가 있음, [가설]은 조정 가능한 데이터 수치, [권고]는 제안, [대기]는 검증·결정 미완료다. 구현 표시는 병합·CI·플레이 관문 통과와 같지 않다. [원본 v0.1](01_게임플레이_베이스_v0.1.md)은 변경하지 않는다. 현재 전달 관문과 증거 링크는 [02 §11](02_BM_경제_골격_v0.2.md#11-검증전달-경계)에 모은다.

## 0. 한 문장과 현재 범위

무기뿐 아니라 영지·건물·사람을 키우는 도구를 함께 고르고, 도구가 화면에서 발동하며 지도에 성장물을 남기는 판타지 생존 액션이다. 빌드의 절반은 지도 위에 심어진다.

[확정] 모바일 Unity F2P를 지향하며 기본 영웅 하나·기본 영지 전통 하나로 먼저 게임 전체를 완성한다. 추가 영웅·영지, 장비, 서버, PvP·동맹은 이번 범위 밖이다. 광고·결제·분석은 구조와 조사만 준비하며 SDK를 설치하지 않는다. 맥 실행판은 폰 없이 직접 판단하기 위한 별도 전달 경로다.

정본 범위는 [2단계 A 의뢰서](07_ASTRA_GOAL_bs-mobile_phase2a.md), [P2 #115](https://github.com/hyunlord/bs-mobile/issues/115), [ADR0034](../adr/0034-bounded-meta-progression.md)다.

## 2. 한 판의 모양

[구현] `first-playable`은 30Hz, 27,000틱, 15분이다. 봄·여름·가을·겨울이 각각 6,750틱(3분 45초)이며 겨울 보스 처치와 전체 길이 생존이 함께 있어야 챕터 클리어다. 보스만 일찍 쓰러뜨린 뒤 죽거나 포기하면 클리어가 아니다.

| 계절 | 데이터 리듬 [가설] | 플레이 의미 |
|---|---|---|
| 봄 | 성장 2, 출현 1 | 초기 무기와 성장 기반을 고른다 |
| 여름 | 성장 2, 출현 1 | 밭·터·사람의 연결을 만든다 |
| 가을 | 성장 1, 출현 2 | 수확과 방어의 이동 경로를 조절한다 |
| 겨울 | 성장 1, 출현 2 | 생존과 보스 대응을 마친다 |

v0.1의 겨울 성장 정지는 현재 규칙이 아니다. 계절 경계는 향후 보상·복귀 설계 후보이며 현재 광고를 재생하지 않는다. 보스 뒤 무한 연장은 [대기]다.

## 3. 조작·카메라·지도

[구현] 공격은 자동이며 이동 방향/가까운 적 자동 조준을 설정으로 고른다. 모바일은 떠다니는 스틱, 맥은 마우스 드래그와 WASD, 카드 클릭을 사용한다. 맥 창 크기를 바꿀 수 있고 F1/F2/F3으로 세로·접힌 비율·펼친 비율을 확인한다. 이것은 폴드7의 물리 접힘 검증이 아니다.

지도는 경계가 있다. 챕터별 폭·높이, 터 수·간격, 밭 상한이 실제 Core 설정으로 달라진다. 강·숲·언덕의 위치와 그림 역할은 챕터 데이터가 지정한다. [대기] 지형 표시는 Unity 결과와 별도로 확인해야 하며 지형 데이터가 있다는 사실만으로 강 충돌·숲 감속·언덕 공격 보너스가 구현됐다고 보지 않는다. 현재 어댑터는 이런 지형별 전투 효과를 추가하지 않는다.

## 4. 판 안 구성과 실제 슬롯

| 요소 | 출시 후보 총 풀 [구현] | 동시 슬롯 / 제한 |
|---|---:|---|
| 무기 | 10 | 5칸, 각 12레벨 성장표 |
| 도구 | 8 | 4칸, 땅3·건물3·사람2 |
| 특허장 | 8 | 4칸, 공격과 영지 양쪽 효과 |
| 물품 | 30 | 장비 슬롯 없이 중첩; 획득·조건은 데이터 |
| 진화 | 8 | 보유 입력과 레벨·성장 조건을 만족할 때 |

무기·도구·특허장은 하나의 카드 풀에서 뽑되 슬롯은 분리한다. 위 5/4/4는 `first-playable`의 런타임 슬롯이다. 공통 튜닝 파일의 과거 3/3 또는 판 밖 가신 슬롯 1~3과 혼동하지 않는다.

[구현] 새 메타 저장은 전체 풀을 즉시 열지 않는다. 현재 데이터의 초기 무기3·도구5·물품6에서 20도전으로 풀을 넓힌다. 특허장은 별도 해금 필터를 적용하지 않는다. 시작 무기와 모든 선택 가능 영웅의 시작 도구는 항상 포함되어야 한다. 진화 입력이 잠겨 있으면 관련 진화도 제거하여 끊어진 참조나 잠긴 카드 제시를 막는다.

## 5. 무기와 도구

[구현] 무기는 레벨별 피해·범위·공격 주기·타격 수·관통·밀침을 데이터로 가진다. 검·낫은 바라보는 방향의 부채꼴 판정이다. 투사체·일제사격·공전·장판·관통·연쇄·부메랑·폭발은 서로 다른 실행 형태다. 과잉 타격 낭비와 허공 발동 비율을 계속 기록한다.

도구는 공격과 성장 기능을 함께 가진다. 땅은 이동하며 남기고, 건물은 터에서 작업을 쌓아 건설·수리하며, 사람은 소집·징집·귀환과 일을 통해 힘을 보탠다. 씨앗 자루, 물국자, 목수 망치, 뿔나팔 등은 역할과 데이터로 연결한다. v0.1의 예시 목록 전체가 출시 구현 목록인 것은 아니다.

[가설] 도구 최초 화력 바닥과 중반 교차 시점은 검토 지표이며 60~70%, 6~8분을 자동 승인 수치로 취급하지 않는다. 무기형 관문 및 c′ 결과로 조정안을 판단한다.

## 6. 성장물과 사람

밭은 고정된 면, 건물은 터에 놓인 점, 사람은 이동하는 무리다. 밭·터·인구·식량에는 데이터 상한이 있다. 파괴·손실은 재심기·재건·재소집 경로와 연결한다.

[구현] 사람 규칙 A(군대형)·B(일꾼형)·C(징집·귀농형)를 비교할 수 있으며 기본 first-playable은 C다. 부대의 표시 개체와 구성원 수는 다르므로 인원 환산에는 구성원 수를 사용한다. 징집·귀환에 시간 비용이 있고 백성의 노동과 전투 기여를 따로 진단한다.

판 밖 가신 6명은 수집·강화 데이터이며 현재 각각 하나의 배율을 한 판에 주입한다. 이것이 화면의 사람 개체 6명을 추가 소환한다는 뜻은 아니다. 판 안 사람 수와 판 밖 출전 슬롯은 독립이다.

## 7. 경험치·카드·진화·적

경험치 바는 하나이며 처치·수확·세금·일부 지도 이벤트가 채운다. 최근 경험치 출처는 카드 가중치에 반영된다. 현재 카드 기본3장, 희귀도 일반/희귀/영웅과 강화량1/2/3, 리롤·금지·고정 각1회는 데이터 가설이다. 행운으로 4장을 제시하거나 모든 레벨 초과분을 금화로 바꾸는 v0.1 제안은 현재 완료 기능으로 세지 않는다.

진화는 장비 조합·최소 레벨·성장 상태 조건을 검사한다. 태그는 물품 효과와 조합을 연결한다. 일반적10종·정예2종·보스1종의 기본 풀에서 챕터가 적 명단을 고른다. 시간과 번영에 따른 위협은 유지되며 챕터 배율은 출현 주기·적 체력·피해에 적용된다.

[구현] 지도 이벤트는 상인·성소·수레 세 종류다. 마녀 오두막·장원 재판 등 v0.1 아이디어는 확장 후보로 남긴다.

## 9. 판 결과 → 장원 → 다음 판

판 종료 시 남은 밭, 살아 있는 완성 건물, 사람 구성원 수, 누적 수확, 도달 레벨, 보스 결과를 자재4종으로 환산한다. 식량 잔고 자체는 환산 점수가 아니다. 최소 실행 시간, 챕터별 판당 상한, 결과 배율, 지갑 상한을 적용한다. 사망·포기·반복은 별도 규칙을 가지며 중복 정산은 거부한다. 구체식은 02 §3이다.

장원은 자재가 되면 자동 성장한다. 플레이어는 우선 깃발 하나만 고른다. 대장간은 가신 레벨 상한, 기록소는 도전 연구 조건, 곡물창고는 방치 생산 시간 상한, 병영은 출전 슬롯을 연다. 건물 자체 공격 배율을 별도 과금 힘 축으로 만들지 않는다.

## 10. 가신 6명과 판 안 주입

| 가신 | 시작 상태 | 능력 [구현] |
|---|---|---|
| 고랑 방패수 | 해금·출전 | 무기 성장표 및 도구 발동 피해 증가 |
| 황금밭 호위 | 도전 해금 | 영주 최대 체력 증가 |
| 귀환 대장 | 도전 해금 | 영주 이동 속도 증가 |
| 비옥도 측량관 | 도전 해금 | 농지 단계·건설 작업·모집 주기 단축 |
| 징집 조장 | 도전 해금 | 아군 피해 및 사람 체력 증가 |
| 수확 서기 | 도전 해금 | 처치·수확·세금·이벤트 경험치 증가 |

[가설] 레벨1~20, 승급0~5, 기본3% + 레벨당1% + 승급당2%다. 활성 가신의 해당 채널 기여를 더한다. 레벨20·승급5의 단일 채널 최대 보너스는32%다. 정수 피해/체력/속도/경험치는 올림, 기간은 내림 후 최소1틱이므로 낮은 기초값에서 실제 비율은 표시 비율과 다를 수 있다.

현재 구현은 시작 레벨·시작 도구를 메타 보상으로 변경하지 않고, 가신 레벨·승급으로 계산한 전역 배율을 별도 콘텐츠 사본에 주입한다. 메타가 없으면 기존 콘텐츠 객체를 그대로 사용하여 역사 실행을 보존한다. 재생 증거에는 seed·입력뿐 아니라 실제 챕터·메타 적용 콘텐츠를 복원할 정보가 필요하다.

## 11. 해금·저장·화면

20도전은 출정·수확·처치·건물·사람·클리어·챕터·생존 시간·가신 레벨·보스 지표와 기록소 연구 조건을 함께 본다. 보상은 콘텐츠 풀 확대, 가신 해금, 유한 자재다. 현재 건물/사람 지표는 판 종료에 남은 구성의 누적이지, 한 판 안에서 생겼던 모든 건설·소집 이벤트 누적이 아니다.

[구현] 로컬 저장은 스키마1→2→3 단계 이행, 길이·체크섬·참조 검증, 직전 정상본 복구를 제공한다. 알 수 없는 미래 버전은 빈 저장으로 덮지 않는다. 종료 정산은 정산 전·후 스냅샷을 가진 터미널 저널을 먼저 원자적으로 기록한 뒤 진행 저장을 교체한다. 그 사이 중단되면 저널의 완료 결과를 한 번만 복원하며 이미 적용된 결과를 중복 지급하지 않는다. 저널이 없는 미정산 판만 보상 없는 포기로 정리한다. 단조 시간과 UTC 관측이 불일치하면 방치 보상을 주지 않는다. 파일 조작까지 막는 서버 권위는 아니다.

[대기] 챕터 선택, 결산 환산, 장원 성장, 가신, 도전 화면은 기존 화풍·UI 시스템을 사용하고 최종 Unity 플레이·캡처로 별도 판정한다. Core 테스트만으로 화면 전달을 승인하지 않는다.

## 12. 판정과 남은 결정

- 메타 없는 기준: 역사 해시, 기존 리그 (b), c′를 보존한다. c′는 같은 사람 규칙 묶음에서 무기·땅·건물·사람 정책 생존율 각각이 random의0.6~1.5배다.
- 신규 메타: 실제 챕터·가신 효과, 저장 왕복·이행·손상 복구, 자원 상한·중복 정산·시계 불일치, 경제 목표를 확인한다.
- [수정 전후 일치 관측] 21일 실제420판·방치63행에서 지갑 상한과483행 장부 보존은 통과했다. 보통(하루6판)의 챕터3/6/10 첫 시도는2/3/12일, 첫 클리어는2/3/15일이다. 첫 시도 목표1~2/5~9/14일 이상 기준은 챕터6·10에서 실패했다. [경제 보고](../economy/sim-v0.md)에 역사 판정을 보존하며 수정 후 [정본 CSV](../economy/sim-v0.csv)도483행 전체가 바이트까지 같아 동일한 실패 판정을 유지한다. [#126](https://github.com/hyunlord/bs-mobile/issues/126)에서 도달 의미와 다음 후보를 결정한다. 챕터4~6 체력만10% 높이는 단일 후보는 미적용이다.
- [보류] [Fold7 #98](https://github.com/hyunlord/bs-mobile/issues/98)은 사용자 재개 지시 전까지 연결·설치·조작하지 않는다. 맥/Editor 결과로 닫지 않는다.
- 운영 스택은 [P3 #116](https://github.com/hyunlord/bs-mobile/issues/116), [후보 결정 #120](https://github.com/hyunlord/bs-mobile/issues/120), [국가·연령·예산 #121](https://github.com/hyunlord/bs-mobile/issues/121), [지급 원장 #122](https://github.com/hyunlord/bs-mobile/issues/122)에서 따로 결정한다.
- [확정] 사용자 후속 결정과 [ADR0035](../adr/0035-opt-in-native-mac-capture.md)에 따라 깨끗한 OS 계정·외부 클릭/캡처 관문을 앱 내부 `--autoplay-capture`로 대체한다. 화면 기록·손쉬운 사용 권한은 요청하지 않는다. 빈 독립 저장/출력 경로에서 타이틀→정상 속도 한 판 생존·보스 처치→결산→재시작의 실제 네이티브 화면과 리플레이를 확인한다. 자동 입력 성공은 사람 클릭 합격이 아니며 사람이 직접 조작하는 검증은 사용자가 맡는다.
- 네이티브와 Recorder의 현재 관문은 [02 §11](02_BM_경제_골격_v0.2.md#11-검증전달-경계)을 따른다. Recorder는 Editor 증거로 표시한다. 과거 OS 계정 미검증 [#114](https://github.com/hyunlord/bs-mobile/issues/114) 기록은 보존하되 현행 차단 관문으로 이어 쓰지 않는다. P4 재배포·사용자 재미 판단은 별도다.
