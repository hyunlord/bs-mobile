# Astra 의뢰서 — bs-mobile 1단계 B: 첫 플레이 가능판(First Playable)

작성 2026-10-09 · 기준 main `9b126bd` · 공통 규칙은 AGENTS.md 그대로(이슈 → PR → CI, 보고 첫 줄 관문 + 커밋·PR·CI 링크, ZIP 없음, needs-decision 이슈, Charter & Kin 커밋 금지).

## 왜 바뀌었나
1단계 A는 도형 회색 상자라 사용자가 판단할 거리가 없었다. 사용자 결정: **게임플레이·로직·콘텐츠·비주얼 네 축이 모두 "게임처럼" 갖춰진 상태가 되어야 사람 판정을 한다.** 그래서 이번 단계의 산출물은 "처음 보는 사람이 설명 없이 깔아서 15분 한 판을 하고, 이게 어떤 게임인지 말할 수 있는 빌드"다.

**품질 기준(목표선)**: 완성작이 아니라 **잘 만든 게임잼 출품작 ~ 얼리 액세스 초기 수준**. 그림은 최종 아트가 아니어도 되지만 **한 가지 화풍으로 통일**돼 있어야 하고, 도형이나 기본 UI 컨트롤이 화면에 남아 있으면 안 된다.

## 원칙 (유지)
- Core가 규칙, Unity는 화면. 새 규칙·수치는 Core와 `data/`에.
- 그림은 **역할 ID → 그림** 계약으로 연결(01 P6). 나중에 아트를 통째로 바꿔도 코드가 안 바뀌게.
- 사용자에게 중간 판정을 기다리지 않는다. 매 마일스톤 보고는 남기되 다음 마일스톤으로 바로 진행.

## M1. 로직과 콘텐츠 (Core, 헤드리스 검증)
S3 데이터 중 상당수가 "설계 설명"만 있고 구현이 안 돼 있다. 이번에 **실제로 도는 것**으로 만든다.

| 축 | 이번 목표 | 비고 |
|---|---|---|
| 무기 | 10 | 성장표 12레벨, 형태가 서로 겹치지 않게(근접 부채꼴·투사체·궤도·장판·관통·연쇄 등) |
| 도구 | 8 | 땅 3·건물 3·사람 2. 전부 발동 면 + 성장 면 |
| 특허장 | 8 | 무기와 영지 **양쪽**에 걸리는 전역 수치 |
| 물품 | 30 | 태그 조건 효과. 상자·약탈 수레·이벤트에서 획득 |
| 진화 | 8 | 무기×도구 교차 4 이상 포함. 진화 조건이 레벨업 카드나 상자 화면에 보이게 |
| 적 | 10 + 정예 2 + 보스 1 | 목표 분화(영주·씨앗·익은 밭·건물·사람) 유지. 보스는 겨울 끝 |
| 지도 이벤트 | 3 | 예: 떠돌이 상인, 순례 성소, 약탈 수레 |
| 영지 성장 표현 | — | 작물 4단계, 건물 짓기 중·완성·파손·폐허, 백성 걷기·일하기·징집 이동 |

- 기본 영지(새싹 변경)·영웅(개척 기사) 1개씩 유지. 가신 1명 시작 고정.
- 레벨업 카드: 리롤·금지·고정, 희귀도, 진화 가능 표시.
- 새 콘텐츠가 들어가도 **봇 리그 관문 (b)·c′ 유지**(32 seed × 규칙 3 × 정책 6). 실패하면 전역 값부터 조정하고 기록.
- **혼합 정책이 가장 낮은 문제**를 이번에 같이 본다. 이 게임의 논지가 "무기와 도구를 섞기"라, 진화·특허장이 섞는 빌드에 보상을 주는지 확인. 관문: 혼합 정책이 세 묶음 중 최소 둘에서 random 이상.

## M2. 비주얼과 손맛
1. **아트 방향 먼저(짧게)**: 판타지 변경 영지에 맞는 화풍 후보 3개를 **같은 장면의 목업 화면 1장씩**으로 만든다. 폰 세로 화면, 판 중반(영지가 자라고 적이 몰리는 장면). 판독성(01 P5)으로 스스로 평가해 1안을 골라 **바로 진행**하고, 세 장은 보고에 붙인다. 사용자가 나중에 다른 안을 고르면 그림 계약으로 갈아끼운다.
2. **아트 바이블 v0**(1~2쪽): 시점(탑다운 3/4 권장), 기준 크기(영주·적·작물·건물의 화면 픽셀 크기), 팔레트, 윤곽선 규칙, 적·아군·성장물의 색 층 규칙.
3. **스프라이트 세트**: 영주·가신·백성(일·징집 상태), 적 13종, 무기 투사체·이펙트, 작물 4단계 × 작물 종류, 건물 단계, 상자·이벤트 오브젝트, 지형 타일(경계 있는 지도, 계절 4가지 색조). 움직임은 2~4프레임 또는 트윈.
4. **손맛(juice)**: 피격 번쩍임, 넉백, 처치 터짐, 경험치 구슬 자석 흡수, 수확 금빛 터짐, 레벨업 연출, 진화 연출, 화면 흔들림(설정으로 끄기), 피해 숫자(설정으로 끄기), 보스 등장 경고.
5. **계절 전환**이 눈에 보이게: 지형 색조가 천천히 바뀌고, 계절 이름이 짧게 뜬다.

## M3. UI·흐름·소리
1. **화면 흐름**: 타이틀 → (첫 실행) 짧은 안내 → 판 → 결산 → 다시 하기. 설정 화면(소리·진동·화면 흔들림·피해 숫자·자동 조준).
2. **HUD**: 경험치 바, 계절과 남은 시간, 영주 체력, 장착 무기·도구·특허장 아이콘 줄. 상시 큰 패널 금지.
3. **레벨업 카드**: 아이콘 + 이름 + 한 줄 효과 + 현재→다음 레벨 변화 + 진화 단서.
4. **첫 판 안내**: 대사창 대신 화면 안 짧은 힌트 3~4개(움직이기 / 카드 고르기 / 익은 밭 거두기 / 징집). 한 번 보면 다시 안 뜸.
5. **결산**: 생존·레벨·처치·수확량·경험치 출처 비율·도구 대 무기 피해 비중·이번 판 빌드 아이콘.
6. **UI 화풍 통일**: 버튼·카드·셀렉트·슬라이더까지 같은 디자인. 엔진 기본 컨트롤 금지.
7. **소리**: 효과음(타격·처치·수확·레벨업·진화·피격·보스) + 배경음 1곡 반복 + 계절별 변주가 있으면 좋음. 외부 소스는 CC0 등 상업 사용 가능한 것만, `docs/licenses/assets.md`에 출처·라이선스 기록.

## M4. 실기 품질
1. **성능**: 폴드7에서 적 **500마리 이상** 장면 1배속 프레임 시간 p95 16.7ms 이하. 지금은 147마리에서 16.58ms라 여유가 없다. 병목을 계측하고 고친다. 50ms 이상 끊김의 원인도 찾는다. 상시 지표 축적 유지.
2. **폴드 대응** 유지: 펼친 화면·접은 화면 둘 다 판독성 확인(에뮬레이터 비율로 자체 확인, 물리 접기 시험은 사용자 대기 #83 그대로).
3. **자체 QA**: 사용자에게 넘기기 전에 Astra가 폴드7에서 처음부터 끝까지 3판 이상을 직접 돌리고, **판 초반·중반·후반·보스·결산 화면 캡처와 30초 이상 화면 녹화 2개**(`adb shell screenrecord`)를 Release에 올린다. 체크리스트: 도형·기본 컨트롤이 남아 있지 않은가 / 적과 아군이 구분되는가 / 무엇을 해야 하는지 첫 판에 알 수 있는가 / 도구가 뭘 했는지 화면에서 보이는가 / 손맛 연출이 다 들어갔는가. 발견한 문제는 고치고, 남은 것은 이슈로.

## 하지 않을 것
메타(판 밖 성장), 광고·결제·분석 SDK, 서버, 추가 영웅·영지, 아이폰 관문(Xcode 준비되면 같은 빌드를 올려 보는 것은 해도 됨).

## 관문
1. M1: Core 테스트·결정론·확장성 검사 통과, 콘텐츠 수량 충족(스키마·구현 여부 자동 검사), 리그 (b)·c′·혼합 정책 관문.
2. M2·M3: 화면에 도형·기본 컨트롤 0(자체 QA 체크리스트 + 캡처로 증빙), 아트 바이블과 그림 계약 준수 검사.
3. M4: 적 500+ 장면 p95 ≤ 16.7ms(폴드7 실측), 화면 녹화 2개와 캡처 세트 Release.
4. 위가 모두 끝나면 **사용자용 빌드 + 해 볼 것 목록**을 준다. 이게 사용자 첫 판정이다.
