## 2. 능력별 수치와 판 안 상한 [가설]

신규 식은 `raw_i = B_i + S_i×(L−1) + R_i×rank`, `bonus_i = min(cap_i, sum(raw_i))`, `multiplier_i = 1000+bonus_i`이다. 단위는 permille(10‰=1%). 선택ID는 중복 불가, 최대3명이다. 동일 능력의 미래 가신이 추가돼도 합산 후 cap을 적용한다. 현재6명은 서로 다른 능력이라 중복 능력은 없다.

| 가신/능력 | B / 레벨당 S / 승급당 R (‰) | L1/R0 | L5/R0 | L20/R5 계산 | 판 안 cap |
|---|---:|---:|---:|---:|---:|
| 고랑 방패수 · 공격 | 10 / 3 / 6 | 1.0% | 2.2% | (10+57+30)=97‰, 9.7% | 100‰, 10% |
| 황금밭 호위 · 최대체력 | 20 / 5 / 10 | 2.0% | 4.0% | (20+95+50)=165→150‰, 15% | 150‰, 15% |
| 귀환 대장 · 이동 | 5 / 1 / 3 | 0.5% | 0.9% | (5+19+15)=39‰, 3.9% | 50‰, 5% |
| 비옥도 측량관 · 농지 성장속도 | 10 / 3 / 5 | 1.0% | 2.2% | (10+57+25)=92‰, 9.2% | 100‰, 10% |
| 징집 조장 · 아군 피해/체력 | 15 / 4 / 8 | 1.5% | 3.1% | (15+76+40)=131‰, 13.1% | 각150‰, 15% |
| 수확 서기 · 판 안 경험치 | 5 / 2 / 4 | 0.5% | 1.3% | (5+38+20)=63‰, 6.3% | 80‰, 8% |

계수와 cap 숫자의 밸런스 지위는 [가설]이지만, **현 버전 구현의 강제 상한은 공격100·체력150·이동50·성장100·아군 피해/체력 각150·XP80‰이며 임의 초과를 금지한다.** 실측 후 cap을 조정할 때는 측정 근거와 변경 이력을 후속 문서에 반영하고 버전을 올린다. 이 값들은 기존 +32%를 wave에 그대로 넣지 않기 위한 첫 실험안이다. 승급·레벨 비용/보상은 이번 설계에서 조정하지 않는다. 체력처럼 cap에 먼저 닿는 경우 이후 레벨의 전투 증가분이0일 수 있음을 UI에 숨기지 않는다. 이런 성장 정체가 적절한지도 실험 항목이며 실측 근거와 변경 이력을 기록하며 계수를 조정한다.

### 적용 지점과 제외 범위 [가설]

| 능력 | 제안 적용 | 제외/중복 방지 |
|---|---|---|
| 공격 | 영주 무기·도구의 최종 피해 계산에서 정확히1회 | 아군 피해는 징집 조장 소관. 건물의 독립 고정피해·지속환경피해는 제외. 진화/특허장/레벨 단계별로 반복 곱하지 않음 |
| 최대체력 | 출정 시작 기본 최대체력에1회 적용, 시작 현재체력은 새 최대체력 | 진행 중 구매/강화로 회복·상한 재설정 금지. 회복은 최종 최대체력까지만 |
| 이동 | 영주 기본 이동속도에1회 | 투사체속도·아군속도·공격속도에는 적용하지 않음 |
| 농지 성장 | 농지 성장 진행량에만 적용 | 사람 모집·건축·계정 생산/공사시간·수확 수량·XP에 추가 곱하지 않음. 기존 FP Growth의 더 넓은 범위와 다른 새 버전임을 기록 |
| 아군 | wave의 기존 WaveGroup 타격 피해 및 생성 최대체력에 각각1회 | 계정 초상을 새 소환개체로 만들지 않음. legacy PersonState와 혼용하지 않음. 영주·건물·적 제외 |
| 경험치 | wave 적 처치 XP 및 완료 보상(growth/irrigation/shipment/mission) 생성 XP에1회 | legacy 세금/이벤트 경로를 새로 만들지 않음. 재화·메타 보상·계정 레벨 제외, 보상 생성과 수집에 두 번 곱하지 않음 |

영지 효과의 Attack/Heal/Magnet은 현행 고정 Amount·PeriodTicks 계약을 그대로 둔다. 가신 공격을 영지 공격에 곱하거나 농지 성장에 영지 자석 보너스를 재적용하지 않는다. 영지+가신을 함께 켠 경우도 별도 조합 관문이며 각각 PASS를 합쳐 전체 PASS라 하지 않는다.

### 정수·누적 계약 [제안]

새 경로는 정수 permille만 사용한다. 체력/이동/피해의 기본식은 `floor(base×multiplier/1000)`, 유효한 양수 피해만 최소1로 보존한다. 기존 FP의 올림 계산은 그대로 둔다. 작은 수치에서 효과가 사라지는 경우는 문서화하고 임의 매 타격 +1로 부풀리지 않는다. 농지 진행·XP처럼 반복 누적하는 값은 소수 나머지를 정수 accumulator로 보존하고 snapshot/runtime state hash에 포함한다. accumulator가 필요 없는 구현을 선택하려면 작은값 편향 검사를 먼저 제시한다. 아래 순서를 이 PR의 검토안으로 제안하며, 실제 함수 연결 및 wire codec은 후속 ADR과 구현 검증으로 확정한다.

### 배율 순서·아군 범위·나머지 수명 [가설·검토안]

- **피해:** 기존 영웅/아이템/특허장/무기레벨/진화 파이프라인이 산출한 피해 `D_existing`에 마지막으로 유효한 `D_existing>0`일 때만 `D=max(1,floor(D_existing×(1000+bAttack)/1000))`를 한 번 적용한다. `D_existing<=0` 또는 기존 무효/완전 차단 판정은 원래0/무효로 유지하여 피해를 새로 만들지 않는다. 기존 파이프라인 내부 반올림을 이동하지 않는다. 아군 피해는 같은 마지막 단계에서 Attack 대신 Allies만 적용한다. 여기서 기존 최종값은 적 HP로 clamp하기 전의 피해 후보값이다. 가신 배율 적용 후 기존 `Math.Min(enemy.Health, requestedDamage)`와 실제 HP 손실/telemetry 집계를 수행하며 이미 clamp된 실제 손실을 증폭하지 않는다.
- **체력/이동:** 기존 영웅·아이템 등으로 계산한 해당 시점의 가신 제외 값 `H_existing`, `V_existing`에 각각 한 번 floor 곱을 한다. 가신 계수는 snapshot 상수이며, 기존 정상 판 안 성장으로 기본값이 바뀌면 원래 값에서 재계산한다. 이전 가신 적용 결과에 다시 곱하지 않는다. 현재체력 증가·회복·부활 규칙은 기존 경로를 따르고 새 최종 최대체력을 넘지 않는다. 계정 변화로는 재계산하지 않는다.
- **아군 적격성:** wave의 [WaveRuntimeState](../../../core/src/SowSiege.Core/WaveRuntimeState.cs) `WaveGroup`을 대상으로 한다. [WaveWorkSystem](../../../core/src/SowSiege.Core/WaveWorkSystem.cs)의 기존 군집 생성과 `TickGroups` 타격(`world.AllyDamage` 집계)이 적용 지점이다. 기존 `GroupCap`·일꾼·임무 조건을 유지하며 추가 소환/군집수를 만들지 않는다. 생성 시 `max(1, gear.Capacity)` 기반 체력을 한 번 증폭해 개체의 가신 적용 최대체력으로 저장하며 이 새 최대체력 필드와 그 기준 버전을 runtime state hash/저장/restore에 포함한다. 판 중 생성도 같은 고정 snapshot을 사용한다. idle 군집 재사용/귀환/훈련/편대 전환은 HP를 다시 곱하거나 무상 회복하지 않는다. `ConsumeMissionFood`의 회복 상한은 기존 gear.Capacity 대신 그 개체의 적용된 최대체력을 사용한다. 사망한 개체의 새 부활 기능은 만들지 않는다. 영주·적·건물·투사체에는 Allies를 적용하지 않는다.
- **역사 사람과 구별:** `PersonState.Role=="vassal"`은 legacy estate 사람 경로다. wave가 그 경로를 건너뛴다는 사실만으로 wave 아군 전체가 없다고 판단하면 안 된다. 앞선 초안의 wave Allies no-op 해석은 WaveGroup 확인으로 정정했다. 이번 opt-in은 WaveGroup에만 적용하고 기존 peasant/militia/guard/returning/vassal 사람 경로는 그대로 둔다.
- **Growth 나머지:** 키는 wave `WaveWork.Kind=="grain"`의 안정적인 entity ID다. [WaveGrowthPrimitives](../../../core/src/SowSiege.Core/WaveGrowthPrimitives.cs)의 `AdvanceTime`에 도달하기 전 기존 생존/휴면/건조/연결건물/workGate 조건을 모두 유지하고, 허용된 grain의 기존 +1 진행량에만 적용한다. building/water/운송에는 적용하지 않는다. `numerator=기존 진행량×(1000+bGrowth)+remainder`, 지급량은 `numerator/1000` 정수몫, 새 나머지는 `%1000`이다. 같은 농지의 성장단계 전환에서는 보존하고 수확/재파종의 새 주기 시작 또는 농지 제거 때 폐기한다. 새 entity에는 이전 ID의 나머지를 재사용하지 않는다. 영주 사망만으로 살아 있는 농지의 나머지를 지우지 않는다.
- **XP 나머지:** 키는 판 영주와 지급 범주(enemy/growth/irrigation/shipment/mission)의 쌍이다. wave는 단일 영주이므로 판 내 고정키 lord를 사용한다. 적은 WaveRuntimeSystem의 처치 XP 지급, 나머지는 WaveCompletionLedger.Claim에서 중복 완료 검사를 통과한 보상을 생성할 때만 적용한다. 이때 kind 인자는 growth/irrigation/shipment/mission으로 이미 구별된다. 만들어진 WaveReward.Experience를 저장·복구하고 Collect는 그대로 지급하며 다시 곱하지 않는다. 미수집 보상이 있어도 생성 때 반영된 나머지를 되돌리지 않는다. 역사 HarvestExperience 합계 집계는 그대로 유지하고 새 범주별 나머지/진단은 별도 필드로 둔다. 같은 몫/나머지 식을 사용하고 범주 사이 나머지를 합치지 않는다. 레벨업·시즌 전환·동일 판의 사망/부활에서는 보존하며 판 종료/새 출정에서 초기화한다. 동일 보상 이벤트 중복 지급 방지는 기존 이벤트 처리 책임이며 나머지로 중복 지급을 정당화하지 않는다.
- **복구/해시:** Growth/XP 키를 안정적으로 정렬한 나머지0..999를 runtime state와 hash에 포함한다. 복구는 저장된 값을 그대로 되살린다. phase 전환 중 유지할 entity와 제거할 entity를 동일 규칙으로 처리하며, 사라진 농지의 고아 키는 거부한다. snapshot은 계수와 버전, runtime state는 변화하는 나머지를 소유한다.

필수 경계 테스트는 기존 배율2종과 가신 배율의 순서/단1회 floor, 판 중 적격 아군 생성·사망·회복·부활, 비적격 legacy 사람/적 제외 및 WaveGroup idle 재사용/식량회복 상한, 농지 단계전환/수확/제거/ID재사용, XP 범주별 작은 지급의 누적, 사망·phase·저장복구 전후 동일 나머지·hash다. 타입 매핑이나 기존 판 안 성장 경로가 이 계약과 충돌하면 구현자가 임의 확장하지 않고 설계 차이를 보고한다.

## 3. 시작 snapshot과 변경 불가 경계 [제안]

1. 출정 확정 직전 Core가 해금·선택ID 중복·최대칸·레벨/승급과 현행 해금 조건을 검증한다. 검증 실패를 자동으로 최대값/0으로 고치지 않는다.
2. 선택ID를 ordinal 순서로 정렬하고 ID/level/rank, 유효칸과 상한 근거, 가신규칙버전·content hash, 계산된6개 bonus, 판에 필요한 반올림/accumulator 버전을 snapshot으로 고정한다. 정의와 계산값 불일치는 거부한다.
3. UI는 시작 snapshot의 읽기 전용 복사본을 표시한다. 시작 이후 live catalog/지갑/편성으로 다시 계산하지 않는다. 필요한 정의는 content hash로 고정된 판 소유 카탈로그 사본을 사용하고 누락·불일치 시 복구를 거부한다.
4. 시작 후 계정 강화·승급·공사완료·보석/권 사용·출전편성 변경은 진행 중 판에 소급하지 않는다. 새 snapshot은 다음 출정에만 사용한다. 초기 snapshot은 복구/재생에서도 동일하다.
5. 계정 재화를 매 틱 읽지 않고 외부시각·네트워크·호스트 상태를 Core 규칙에 넣지 않는다. snapshot은 새 영웅/영지 ID를 하드코딩하지 않고 명시적 opt-in으로 전달한다.
6. 이탈/복구는 시작 snapshot을 복원한다. 새 메타 상태로 재계산해 더 강한 판으로 이어가지 않는다. 중간 업그레이드 허용 여부 자체도 기존 계정 명령 검증을 따른다.

## 4. replay format7·영지 opt-in 호환 검토

[ReplayCodec](../../../core/src/SowSiege.Core/ReplayCodec.cs)의 현재 format7은 estate schema1, 근접조준 포함 시 schema2를 쓴다. 가신 snapshot 필드는 없다. [WaveEstateContract](../../../core/src/SowSiege.Core/WaveEstateContract.cs)의 EstateRunOptions는 Version/LoadoutId/LoadoutCatalogHash이며 가신 정보가 아니다. 기존 `wave-estate-effects-v1`/clock 블록의 뜻을 몰래 넓히지 않는다.

**[확정] 새 replay format8과 독립 `vassal-run-v1` 블록을 사용한다.** format7에 schema3를 추가하는 대안은 채택하지 않는다. 기존 format7 schema1/2의 의미·bytes·golden은 변경하지 않는다. format8은 승인된 후속 구현 계약이며 현재 reader가 이미 지원한다는 뜻은 아니다.

### format8 가신 블록 [확정 방향·미구현]

가신 블록은 다음 계약을 따른다. 새 envelope의 구체 저장 순서는 후속 ADR과 구현 검사에서 확정하되 format8/독립 블록 선택을 다시 미정으로 돌리지 않는다. 유료·무료 출처를 구분하는 자격 원장이나 전용 hash/flag는 넣지 않는다.

| 필드 | 제안 계약 |
|---|---|
| tag/schema | `vassal-run-v1`, schema=1; 알 수 없는 tag/schema 거부 |
| flags | unsigned32; bit0=enabled, bit1–31은0만 허용. unknown bit 거부. 가신 블록 존재 시 bit0 필수 |
| rules/content | 규칙ID·버전, canonical content SHA256, 계산/나머지 버전. 출정 중 다른 catalog 재조회 금지 |
| roster | count0..3, ID ordinal 정렬·유일, 각 level1..20/rank0..5, 현행 계정 해금/선택 조건 충족. count≤effective slots, level≤effective cap 검증; 선택당시 effective slot/level cap과 그 규칙 정본근거 hash 포함(유료 출처/전투자격 hash가 아님) |
| effects | 고정 능력ID Attack/Health/Movement/Growth/Allies/Experience 각각 정수 raw/capped bonus, 해당버전 cap·적용범위. 누락·중복·재계산불일치 거부 |
| restore | 원래 snapshot bytes/hash 및 농지·XP 나머지 state를 저장. 빈 나머지도 버전 정의대로 처리; live 계정으로 복구하지 않음 |

블록 absent이면 기존 format/헤더/옵션/종결 bytes 그대로다. enabled+빈 roster는 명시적 실험 on 상태로 absent와 다르며0효과를 명확히 기록한다. format8을 모르는 reader는 unknown version 오류로 실패해야 하고, 조용히 가신효과를 버려 format7로 재생하면 안 된다. 새 format8 내부에서 estate absent/present 및 melee 옵션의 조합을 검증하며 기존 estate schema의 의미를 재사용·변경하지 않는다.

[ADR 0075](../../adr/0075-independent-vassal-replay-format-eight.md)가 승인된 format8 선택과 호환 경계를 기록한다. 후속 구현은 구체 wire 계약을 기술 문서와 검사로 구체화한다. `null/absent`는 과거와 동일 바이트/실행경로여야 하며, 효과가0인 명시적 enabled snapshot은 absent와 구분한다. 알 수 없는 버전·중복ID·범위 밖 값·hash불일치는 거부한다. 기본 프로필/datahash에 실험값을 섞지 않고 `data/opt-in/` 경계를 유지한다.

- old format1–7, schema1/2, 기존 golden·종결해시는 그대로 보존한다. 새 효과를 켠 결과는 새 fixture/hash로 추가하며 기존값을 재고정하지 않는다.
- 현재 C05/FP01 원본에는 가신 snapshot이 없으므로 원본 재생에 새 계정 snapshot을 주입하지 않는다. 가신 효과는 wave 전용이며 FP01에는 적용하지 않는다. FP01은 가신 블록 absent의 기존 해시·성능 회귀만 검사한다. 가신 없음/최대 효과 비교는 wave 정상 입력과 C05에서 수행하되, C05 후속 비교 입력은 원본의 불변 복사와 새 메타데이터로 분리한다.
- 새 상태 필드/나머지가 없을 때 기존 catalog/state bytes를 그대로 유지하는 음성 대조가 필요하다. 새 on 경로만 두 Core 타깃/Editor/재생 일치를 별도 검사한다.
- save format6 계정과 replay format7은 다른 계약이다. 새 snapshot 저장을 이유로 과거 계정 데이터를 무조건 이관하거나 초기화하지 않는다.

## 5. BM: 간접 성장 허용과 직접 판매 금지 [확정]

2026-10-29 사용자 r2 결정으로 **유료 자원·가속→영지/계정 성장→가신의 간접 전투력 연결을 허용**한다. 무료/유료 재료는 같은 계정 성장 규칙과 능력별 판 안 cap을 따른다. **가신·가신 조각·판 안 능력 자체의 직접 판매는 금지**한다. 유료 전용 가신/추가 슬롯/별도 전투 상한을 만들지 않는다.

| 경로 | 허용된 간접 연결 | 유지 경계 |
|---|---|---|
| 곡물·목재·철재 구매 | 공통 지갑→기존 가신 레벨업→다음 출정 snapshot | 현행 레벨/승급 상한과 능력별 cap 적용 |
| 직접 공사 가속/성장가속권 | 기존 대장간 상한·병영칸 달성 시점 단축 | 슬롯식·레벨 상한식 그대로, 진행 중 판 소급 금지 |
| 연구/생산 가속 | 기존 연구조건·도전 해금·생산재화 경유 성장 | 직접 가신/조각/능력 상품으로 바꾸지 않음 |
| 무료/플레이 보상 | 같은 지갑과 같은 계정 성장 경로 | 유료/무료별 전투자격·계수 차등 없음 |

능력별 cap 적용은 필수다. §2의 구체 cap 값과 계수는 [가설]이며 구현 후 최대 상태 측정으로 조정한다. 시간당 보석 공통 기준과 성장가속권의 소폭 할인 방향은 유지하되 가격/환율/할인율/상품 수량은 미정이다. 현재 #122 결제·판매·SDK는 미구현이며 이 문서 병합은 SDK 도입이나 실제 판매 개시가 아니다. #126의 수치 조정은 이번에 허용된 구현 후 실측·조정 범위에서 근거와 변경 이력을 남긴다.

현행 지갑을 그대로 전제로 하며 earned-only 원장·출처 추적·전투자격 hash/flag·자원 이관을 요구하지 않는다. 게임 코드/데이터 변경은 이번 PR에 없다.

### r1 결정 이력 — r2로 대체됨

r1은 유료 간접 전투력 경로 보류와 earned-only 분리 대안을 검토했다. 사용자가 r2에서 간접 연결 허용을 선택하여 그 대안과 전용 provenance/eligibility hash·flag 제안을 폐기했다. 이 문단과 PR 커밋 이력은 과거 검토 기록이며 현재 구현 요구사항이 아니다. 현재 적용할 정책은 위 r2 표와 직접 판매 금지다.

## 7. 승인된 후속 구현·측정 순서

1. r2 설계·문서 병합은 승인됐다. 후속 Codex 구현 이슈는 format8/독립 블록, 간접 성장 허용/직접 판매 금지, 현행 슬롯·레벨상한 유지와 필수 능력 cap을 인수한다. 계수·cap 값은 가설로 표기한다.
2. 별도 ADR·구현에서 승인된 format8의 직렬화·snapshot/state 복구·적용순서를 구체화한다. 유료 출처 원장/자격 hash/flag는 도입하지 않는다. 이 문서 승인만으로 SDK나 실제 결제를 구현하지 않는다.
3. 공식 경계값(L1/L5/L20, R0/R5, 빈칸/1/3/중복4인), clamp·정수나머지, 구매/강화 중 snapshot 불변, 잘못된 hash/version 거부를 Core에서 검증한다.
4. old replay/golden/format1–7 absent 경로 bytes/hash를 먼저 확인하고 새 on 경로를 별도 fixture로 추가한다. 영지효과 off/on과 가신 off/on 4조합을 검사한다.
5. 정상 A/B 동일seed 최소32개와 실제 종료조건을 고정해 완주율·사망틱·피해몫·농지완료·XP도달·아군수·효과별기여를 보고한다. 32개로 좁은 신뢰구간을 주장하지 않고 실패도 보존한다.
6. 구현 후 가신 효과 없음/최대 레벨·승급·현행 최대3칸 조합 비교는 wave 정상 입력과 C05에서 수행하고 계수/cap 조정 근거를 보고한다. FP01은 가신 블록이 없을 때 기존 해시·성능 회귀만 확인하며 wave 전용 가신 효과를 적용하지 않는다. 원본 C05 Quit/FP01 무적 결과는 정상 생존율로 환산하지 않는다. 전투시간·생존 결과는 무적 없는 wave 정상 입력 표본의 실제 사망/종료시간·완주율로 측정하고, C05 스트레스 성능 및 원본 회귀와 분리한다. 동일기기/설정 Native3회·원본종결hash·적수분포를 기록한다. Editor/IL2CPP·실기 관문은 실제 수행한 것만 보고한다.

현재 완료한 것은 소스 대조와 문서 산술뿐이다. 새 코드·시뮬레이션·플레이·성능 측정·리플레이 실행은 모두 NOT_RUN이다.
