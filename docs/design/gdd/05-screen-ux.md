# 05 · 화면과 유저 편의

버전: 1.2 · 날짜: 2026-10-24 · 변경: M1-1 도전 받기 금빛 강조를 #248 구현으로 고치고 시각·실기 승인과 분리했다([#357](https://github.com/hyunlord/bs-mobile/issues/357) G02). 이전 1.1(2026-10-12): 기본 카메라 1.4배와 가장자리 위험 표시의 승인·가설·검증 경계를 추가했다.
상태: 정본. 배치·흐름 계약과 실제 구현/실기 검증 결과는 구분한다. M1-1 도전 받기 금빛 강조는 main에 구현됐다(#248). 시각 승인과 실기 확인은 별도다.

## 화면을 만드는 기준

[portrait-v0 README](../portrait-v0/README.md)·[보드](../portrait-v0/boards/)·[HTML](../portrait-v0/source/)이 기준이다. 서면과 다르면 그림을 따르며 HTML의390×844pt 좌표·크기·색·폰트와9-slice를 읽는다. Mac은 세로 화면을 가운데 놓고 양옆을 비우며 긴 화면도 safe area 안에 HUD와 버튼을 둔다. 레거시 [screen-flow-v0](../screen-flow-v0.md)의 키 큰 카드 가로3열 설명은 새 그림의 긴 카드 세로3단으로 대체됐다.

본문13pt 이상·보조11pt 이상, 상호작용 영역44pt 이상을 지킨다. 아이콘 자체26pt여도 누르는 영역까지26pt로 줄이지 않는다. 자주 누르는 주 동작은 아래1/3에 둔다. 누름은 다음 프레임에 읽히고 전환 목표는0.2초 이하다. 상시 패널로 전장을 덮거나 전환마다 로딩 스피너를 덧대지 않는다.

## 판 배율과 가장자리 위험 표시 · 2026-10-12 결정

사용자는 [현재/1.4배/1.8배 비교](../../review/m1-2-camera-scale.md) 뒤 **1.4배를 기본 카메라 배율**로 선택했다. 영웅·적·이펙트가 함께 커지는 표시 변경이며 Core 위치·크기·공격 거리·피해·스폰 수치를 바꾸지 않는다. `7bc241f`의 기존 B 그림·역사 경계 지도 비교는 과거 선택 증거로 보존한다. 선택 승인을 새 A 기사 구현 완료나 현재 끝없는 들판의 검증 완료로 쓰지 않는다.

좁아진 시야를 보완하는 **화면 가장자리 위험 화살표 최대 [가설: 6개]**, **돌진 예고 [가설: 0.5초]**는 사용자가 제시한 표시 가설이다. 위험 방향을 알리되 HUD·영주를 가리지 않고 붉은색은 위험에만 쓴다. 이 값은 적 공격 준비 시간·발동 규칙을 조정하는 승인이 아니다. 실제 그림·혼잡 상황 검증 전 구현 완료로 기록하지 않는다.

화면 밖 접근 위험은 실제 피해 사건을 안정 공격자 개체 ID에 귀속해 확인해야 한다. 기존 공격 거리 진입 대리 지표는 실제 피격이 아니다. 같은 입력 재생에서 경고 그림만 켜거나 꺼도 Core 피해는 같아야 하므로, 표시 ON/OFF만으로 피해가 줄었다는 인과를 주장하지 않는다. 경고에 반응한 새 플레이 입력이 있어야 회피 효과를 별도로 판단할 수 있다. 상세 계측 경계는 [06 손맛·연출](06-feedback.md)을 따른다.

## 입력·상태·복귀

[Logic HTML](../portrait-v0/source/Logic.html)과 [보드](../portrait-v0/boards/16-Logic.png)를 확인할 수 있다. 앱 백그라운드와 완전 종료/재실행은 다르다.

- 판의 이동은 한 손뿐이며 조이스틱은 손가락 위치에만 나타난다. 메뉴 진입 때 이동 입력을 정리한다.
- 판 안 화면 전환은 Core를 멈춘 상태에서만 한다. 카드 진입 후0.3초 입력 보호, 진입 전 누름의 전달 금지. 같은 제안 재그리기로 보호 시간을 다시 시작하지 않는다.
- Back은 판→일시정지, 다른 화면→이전 화면, 영지→종료 확인이다. Cards→Pause→계속은 같은 카드 제안으로 돌아온다.
- 전화·백그라운드 전환은 자동 일시정지하며 전경 복귀가 자동 전투 재개를 뜻하지 않는다. 설정은 진입한 화면으로 돌아간다.
- 되돌릴 수 없는 포기·큰 자재 지출은 확인 한 번을 받는다. 취소는 부모 상태로 돌아가며 보상을 소모하지 않는다.
- 완전 재실행: 영지는 영지, 준비는 영지로 복귀하고 선택 챕터는 기억한다. 판/카드/일시정지는 정산 기록이 있으면 결산 복원, 없으면 보상 없는 포기로 정리한다. 판 중 이어하기를 새로 가정하지 않는다.
- 결산 중복 지급은 금지, 가신 지출·도전 받기는 즉시 저장한다. 저장 계약은 [04](04-economy.md), 구현 근거는 [ADR0053](../../adr/0053-explicit-meta-claims-and-wave-accounting.md)이다.

## #235 승인과 M1 후속

[PR235](https://github.com/hyunlord/bs-mobile/pull/235)는2026-10-12 사용자 그림 승인 후 `9387b76`으로 병합됐다. [d12db4a 표본](../../review/portrait-235-cream-actions.md)의 승인 대기는 보고 작성 당시 기록이다. 크림 활성 글자는 `#3B2A18`, 비활성만 회색·반투명이며 ‘1회 남음’은 버튼 안에 둔다. HUD safe area, 부활 뒤 떠오르는 글자 숨김, 진화 조건 잘림, 생산 상자 대비의 검토와 새 기능 승인을 섞지 않는다.

M1-1 후속: 달성미수령 ‘받기’를 잠긴 칸과 구별할 금빛 테두리/강조. **현재 구현됨**(#248, main `792d510`, 2026-10-21): 미수령 도전은 받기 버튼 뒤에 금빛 테두리(`Claim ready gold border`, 누름을 막지 않음)를 두고 활성 ‘받기’ 버튼(높이 44pt 이상)을 그린다. 받은 뒤에는 테두리를 지우고 ‘받음’으로 바꾼다([PortraitMetaPanels.Progress](../../../unity/Assets/Game/App/PortraitMetaPanels.Progress.cs), [PlayMode 검사](../../../unity/Assets/Game/Tests/PlayMode/PortraitMetaFlowTests.cs)). 이것은 코드·테스트 근거이며 금빛 강조의 시각 승인이나 Fold7 실기(#98) 확인이 아니다. 1.1 작성 시점(2026-10-12)에는 **요구 사항**이었고 "이미 구현됐다고 쓰지 않는다"는 당시 기록이다. rare 무기 카드·Lv 화살표·도전 받기·조각 실제 지급 같은 표본은 일반 흐름과 분리해 출처를 남긴다.

화면 합격과 #223 최대 멈춤은 별도다. 390×844·긴 화면 Editor 캡처가 Fold7 실기(#98)를 대신하지 않는다. 화면을 바꾸는 PR은 값이 바뀔 때만 HUD를 갱신하고 풀을 사용하며 성능·재생 안전망을 유지한다.
