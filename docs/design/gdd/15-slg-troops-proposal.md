## 2. 첫 출시 병종과 병영

새 병종 ID는 문서용 제안 이름이며 아직 콘텐츠에 등록되지 않았다. 첫 출시에는 기존 창·방패 계열 아군 실루엣을 활용하는 두 병종을 권고한다. 기병·공성차·새 원거리 병종은 별도 결정 전 추가하지 않는다.

| 병종 [가설] | 역할과 외형 연결 | 훈련 해금 [가설] | 한 명 비용 [가설] | 한 명 훈련 시간 [가설] |
|---|---|---|---|---|
| 징집 창병 `slg:levy` | 기존 징집병 계열 창 실루엣. 낮은 비용, 채집 운반·기본 전열 | 병영 L1 | 곡물 8, 목재 3 | 20초 |
| 방패 수비병 `slg:guard` | 기존 수비대·새싹 방패 계열. 높은 생존력, 길목·거점 방어 | 병영 L2 | 곡물 12, 목재 3, 철재 4 | 40초 |

실제 공격력·체력·이동속도는 별도 전투 밸런스 표로 정한다. 위 역할 설명만으로 특정 병종의 승률을 보장하지 않는다. 창병을 유료 전용 병종으로 대체하거나 가신을 소모해 병사로 바꾸지 않는다.

| 지도 병영 단계 | 총 병력 상한 [가설] | 단일 행군 편성 상한 [가설] | 치료 병상 [가설] | 훈련 운영 [가설] |
|---|---|---|---|---|
| L0 | 0 | 0 | 0 | 훈련 불가; 기사만으로 첫 개척전 가능 |
| L1 | 60 | 20 | 20 | 활성 묶음 1개, 대기 묶음 1개, 묶음당 최대 10명 |
| L2 | 120 | 40 | 40 | 같은 대기 규칙, 묶음당 최대 20명 |
| L3 | 200 | 60 | 80 | 같은 대기 규칙, 묶음당 최대 20명 |

가신 편성 칸은 별도의 승인된 효과 장부/상한을 따른다([가신 설계](13-vassal-combat-proposal.md), [#547 효과 대응표](https://github.com/hyunlord/bs-mobile/pull/547)). 병영 레벨을 읽어 가신 칸과 병력을 동시에 더하는 숨은 효과는 없다. 병영 L0에 병력이 없더라도 첫 전투·첫 병영 건설에 필요한 자원을 얻는 경로는 열려 있어야 한다.

## 3. 훈련과 보존식

계정의 병종별 수량은 `준비 R`, `출전·복귀 중 D`, `부상·치료 중 W`, `훈련 예약 Q`로 나눈다. 정수 인원만 사용한다. **점유량 `O = Σ(R + D + W + Q)`는 총 상한 C 이하**다. 행군에 보낸 병사는 계정에서 사라진 것이 아니라 D에 잠긴다. 치료 중 병사는 W 안의 부분집합이며 별도 인원으로 다시 세지 않는다.

1. 훈련 요청은 서버가 병영 완공·병종 해금·재화·대기 칸·잔여 인원을 검사한다. 허용 인원과 비용을 확인한 뒤 재화를 차감하고 같은 처리에서 Q를 예약한다. 훈련을 마친 순간 상한이 넘지 않도록 시작 때부터 자리를 잡는다.
2. 묶음은 동일 병종이다. 기본 시간은 `인원 × 한 명 시간`이고, 활성 묶음 종료 시 Q에서 R로 한 번 이동한다. 대기는 앞 묶음이 끝난 서버 시각부터 시작한다. 앱 재접속으로 시작 시각을 새로 잡지 않는다.
3. 대기 중인 묶음만 취소할 수 있고, 그 묶음의 실제 차감 재화를 전액 돌려주며 Q를 해제한다. 활성 묶음 취소는 첫 출시에서 제공하지 않는 것을 권고한다. 결제·가속 적용 뒤 중복 환불되는 경로를 만들지 않는다.
4. 서버가 재화 차감과 Q 예약, 완료와 R 증가를 각각 원자 명령으로 확정한다. 같은 요청 ID의 재전송은 기존 결과만 반환한다. 완료 표시를 누르는 동작은 병사를 추가 생성하지 않는다.

영웅·연구·연맹 도움·가속권은 서로 다른 입력이지만 동일 작업의 남은 시간을 줄인다. 신규 수치 [가설]: 훈련 속도 보너스 합계 상한 30%, `duration = ceil(baseDuration / (1 + min(0.30, bonusSum)))`. 작업 시작 시 속도 보너스를 고정하고, 이후 도움/가속은 남은 시간에서만 차감한다. 최종 남은 시간은 0 미만이 될 수 없다. 실제 도움 횟수·초수는 월드/연맹 문서가 정하며 여기서 무료 가속량을 추가하지 않는다.

건물 이동·화면 닫기·재접속은 훈련을 취소하지 않는다. 병영 파괴·강등은 첫 출시 영지 공격의 결과로 제안하지 않는다. 향후 상한이 낮아지는 운영 변경이 필요하면 초과 병력을 삭제하지 않고 신규 훈련만 막는 별도 정책을 승인받는다.

## 4. 출정·부상·치료

### 출전 시 고정하는 것

서버가 `marchId / encounterId / runId`, 계정·대상 버전, 병종별 출전 인원, 영웅·가신·연구 효과, 적용 상한·콘텐츠 버전을 함께 고정한다. R에서 D로 이동한 동일 인원은 다른 행군·영지 수비대에 중복 편성할 수 없다. 출정 확정 후 얻은 영웅·연구·가신 강화는 진행 중 판에 소급하지 않는다. 수비에 남길 준비 병력은 출정 전 표시한다.

월드 전투의 승패·손실은 서버가 승인한 전투 결과만 반영한다. 직접 참전 PvE는 결정론 Core의 검증된 결과를 쓴다. 클라이언트가 보낸 승리 여부·남은 병사 수를 곧바로 원장에 쓰지 않는다. 결과 검증·서버 실행 방법·재생 버전·원자 커밋은 Codex의 C# 서버 ADR 책임이며, 기존 역사 리플레이/골든을 새 병력 필드로 바꾸지 않는다.

### 손실 배분 [가설]

전투 종료 시 서버가 병종별 출전 인원 N과 전투 불능 수 K를 확정한다(`0 ≤ K ≤ N`). 전투 결과는 저장하되 회군 도착 전 병사는 계속 D에 잠긴다. 다음 수량 이동은 **귀환 도착 정산**에서 정수 순서로 적용한다.

- 귀환 생존자 `S = N − K`.
- 부상 후보 `I = floor(K × injuryRate)`. 직접 참전/자동 PvE는 80%, PvP는 60%를 후보로 둔다.
- 신규 입원 `A = min(I, 서버 정산 순서상 남은 병상)`.
- 전사 `L = K − A`. 부상 후보 중 병상 초과분도 L에 포함하므로 미리 경고한다.
- 귀환 정산이 확정되면 D에서 N을 빼고 R에 S, W에 A를 더한다. **`N = S + A + L`**, 계정 전체 점유량은 정확히 L만 감소한다. 같은 정산 재처리는 수량을 바꾸지 않는다.

병상 경쟁은 서버의 확정 정산 순서로 처리하고 동률의 안정된 순서를 ADR에서 정의한다. 출정 화면의 병상 예상은 예약 보장이 아니며 다른 행군의 귀환으로 달라질 수 있음을 표시한다. 첫 출시의 전사·초과 손실 비율은 사용자 검토가 필요한 가설이다. 전사 없는 PvE 대안과 비교해 반복 실패 후 복구 시간·이탈 위험을 측정한다.

| 상태 | 처리 제안 |
|---|---|
| 행군 도착 전 취소 | 전투가 시작되지 않았으면 회군. D는 귀환까지 잠기고 도착 시 R로 이동; 전투 손실 없음 |
| 기사 패배·시간 종료 | 서버가 확정한 K로만 손실 처리. 영웅의 패배를 임의로 전체 병력 전사로 치환하지 않음. 개척 성공 보상은 없음 |
| 직접 참전 중 연결 끊김 | 같은 runId로 재접속. 제한 시간까지 미복귀면 서버가 승인된 종료/퇴각 규칙으로 끝냄. 결과 미확정 동안 D는 잠김; 재접속이 새 판·무료 병사를 만들지 않음 |
| 서버 장애로 결과 불명확 | 정산을 재개하거나 판 취소를 서버가 명시 확정할 때까지 잠금. 클라이언트의 재훈련·복원 명령으로 우회하지 않음 |
| 서버가 전투 시작 전 취소 확정 | R로 원상 복귀. 전투 보상/개척 권리는 없음. 이미 전투가 확정된 판을 이 경로로 돌리지 않음 |
| 결과 확정 뒤 응답 손실 | 기존 정산 영수증을 다시 반환. 병력·재화·구역 해금을 다시 지급하지 않음 |

치료는 병영의 의무 탭에서 시작한다. 별도 건물 그림을 새로 요구하지 않는다. 병종별 한 명 치료 비용/시간 후보 [가설]: 창병 곡물 3·목재 1·10초, 수비병 곡물 5·철재 1·20초. 활성 치료 묶음은 1개, 묶음 상한은 해당 단계 훈련 묶음 상한과 같다. W에서 인원을 예약하고 비용을 한 번 차감하며, 완료 시 W→R로 이동한다. 치료 예약 중 재출정·중복 치료 불가, 치료 완료는 총 병력 상한을 늘리지 않는다. 병상에 있는 동안 자동 사망이나 유료 결제를 요구하는 만료는 없다. 재화가 부족하면 기사만의 개척/채집 경로로 복구할 수 있어야 한다.

## 5. 판이 영지와 월드맵을 바꾸는 연결

영구 병력은 단순 전투력 숫자만 제공하지 않는다. 전투 종료 커밋은 같은 `runId`의 세계 변화·보상 자격·N/K와 회군 상태를 함께 확정하고, 귀환 커밋은 그 결과에서 병력 수량과 운반 자원을 한 번만 반영한다. 세계의 격파를 귀환까지 미루거나, 회군 중 병사를 즉시 재출전 가능하게 만들지 않는다. 두 단계의 완료 상태와 순서가 서버 원장에 필요하며 단일 클라이언트 응답으로 둘을 흉내 내지 않는다.

| 출정 목적 | 판 안 행동 | 서버가 확정하는 변화 |
|---|---|---|
| 영지 인접 땅 개척 | 목표 구역의 적을 물리치고 경계 표식을 지켜 귀환 | 해당 계정의 지정된 닫힌 r8 구역에 **개방 자격** 부여. 승인된 인접·건설/비용 조건 충족 후 실제 구역 개방. 조건 우회나 새 좌표 무한 생성 없음 |
| 월드 자원지 확보 | PvE 방해자를 제거하고 채집대를 방어 | 해당 대상의 채집 행군 진행/채집 가능 상태를 갱신. 그 판에서 얻은 자재는 실제 지급 상한을 거쳐 같은 정산으로 한 번만 지급 |
| 몬스터·거점 직접 참전 | 기사 조작 + 상비 부대의 목표 수비. 뿔나팔 임시 징집으로 부족한 전열 보완 | 예약된 월드 encounter의 격파/거점 상태, 병력 N/K·회군, 지정된 보상 자격을 원자적으로 확정. 귀환 때 그 자격을 한 번 지급; 대상만 죽고 보상 자격이 사라지는 반쪽 결과 금지 |

영지 구역 ID와 월드 타일 ID는 다른 주소다. 월드의 매번 재생성되는 몬스터를 잡을 때마다 r8 구역을 복제하지 않는다. 개방 자격은 계정·대상 구역별 한 번이며 반복 판은 명시된 반복 자재 보상만 준다. 타인 영지 PvP 승리를 개인 r8 신규 땅·무한 연구 해금으로 환산하지 않는다. 공유 거점의 점유/예약 충돌 처리와 공격·보호막은 후속 월드맵 GDD의 책임이다.

임시 징집 인원·구출 주민·화면에 그린 군집 수를 상비 R에 더하지 않는다. 신규 영구 병사는 위 훈련 경로에서만 얻는 것을 첫 출시 기본안으로 둔다. 구출 주민은 별도의 기존 판 보상/성장 역할을 유지하며, 향후 영구 입대 보상을 넣으려면 명시된 원천·상한·중복 방지 규칙을 별도 승인받는다.

## 6. 다른 성장과 BM의 경계

- 영웅은 조작 캐릭터/행군 지휘 역할, 가신은 별도 편성 보너스다. 병사 사망이 영웅·가신을 삭제하지 않는다. 영웅 수집·뽑기는 별도 사용자 허용 범위이며 병력 직접 판매까지 허용한 뜻이 아니다.
- 가신 효과는 승인된 능력별 판 안 cap을 유지한다. 연구·영웅·병력 효과와의 합산 경계는 각 입력을 가진 서버 출정 스냅샷에서 정한다. 기존 가신 cap을 다른 이름의 병력 보너스로 우회하지 않는다.
- 유료 자원·시간 가속을 통한 성장 경로는 허용된 범위다. 병사 묶음 직접 판매·유료 전용 병종·병력 뽑기는 이번 문서에 넣지 않는다. 훈련 가속과 가속권 가격은 승인된 시간당 보석 공통 기준의 후속 상점 설계를 따른다.
- 출시 계정은 서버 저장이다. 개발용 자동 장원을 병력으로 변환하지 않으며, 싱글 수직 조각의 로컬 시험 원장은 개발용일 뿐 정식 계정에 업로드하지 않는다. 서버 저장의 단일 writer·복구·장애 관문은 서버 ADR에서 맡는다.

## 7. 화면에 보여 줄 정보

병영은 준비/출전/부상/훈련 예약과 총 상한을 분리한다. 훈련 확인에는 실제 인원·총 비용·완료 예정·상한 예약량을 보여 준다. 출정 확인에는 이번 병종별 수, 남는 수비대, 부상 병상 여유와 초과 손실 경고를 함께 표시한다. 결과는 `출전 N → 귀환 S / 입원 A / 전사 L` 및 실제 지급 자재·새 개방 자격을 보여 준다. 손실을 임시 징집 사라짐과 섞지 않는다.

390×844 기준 기존 승인 UI 체계를 쓰고 터치 영역은 48×48 이상을 유지한다. 이 문서는 UI 시안을 제작하거나 현재 그림을 바꾸지 않는다.

## 8. 종료 기준과 사용자 결정 대기

다음은 후속 구현 관문이며 이번 문서의 실행 결과가 아니다.

1. 병종별/합계 보존식: 예약·완료·취소·출정·귀환·치료·전사 뒤 O≤C, 음수 인원 없음, 임시 소환의 영구 편입 없음.
2. 비용·병력·효과·세계 변화가 같은 명령 결과에 묶이고 반복 요청·중복 응답·동시 출정·정산 응답 손실에서 중복 지급 없음.
3. 병상 빈 상태/정확히 가득 참/초과 및 동시 귀환, 전사 후 재훈련, 치료 중 출정 거절을 정수 경계까지 확인.
4. 현재 승인 가신 슬롯·cap과 기존 역사 프로필/골든을 유지. 신규 병력 스냅샷을 가진 별도 경로만 전투 결과에 반영.
5. 기사만의 첫 개척→병영→훈련→월드 PvE 직접 참전→부상 치료→되찾은 영지 구역의 실제 변화를 휴대폰에서 확인. 자동 시뮬은 화면·재미 검증을 대체하지 않음.
6. 무과금 기준 손실 복구 시간과 자원 고갈/전열 전멸 후 막힘, 같은 시간 투자에서 자원 가속 유무의 진행 격차를 측정. 결과가 나오기 전 신규 비용·시간·상한을 확정 수치로 취급하지 않음.

사용자 검토 항목은 첫 출시 두 병종, 훈련/치료 상한과 속도, PvE/PvP 부상 비율 및 병상 초과 전사다. 권고안은 위 표이며, 전사 없는 PvE는 비교 대안으로 남긴다. 독립 보병 티어 확장·기병·공성전·부대 거래·실시간 PvP 직접 조작은 이번 문서의 구현 범위에 넣지 않는다.
