## 1. 현재 구현과 새 설계

현재 실행 영웅은 [개척 기사](../../../data/heroes/frontier_knight.json) `core:frontier_knight`다. 데이터의 고유 능력 설명도 일부는 미구현 기획임을 명시한다. 테스트용 [정찰 영웅](../../../data/test/heroes/scout.json)은 확장성 시험이며 출시 영웅으로 세지 않는다. [ADR0004](../../adr/0004-one-default-extensible-model.md)의 기본 하나/복수 모델 전제를 이어받되, 추가 영웅을 확장 뒤로 미뤘던 제품 범위는 이번 사용자 결정으로 대체한다. 원래 ADR과 역사 프로필을 고치지는 않는다.

[계정 데이터](../../../data/meta/progression.json)의 가신 6명은 영웅과 다른 집합이다. 고랑 방패수, 황금밭 호위, 귀환 대장, 비옥도 측량관, 징집 조장, 수확 서기를 모집 풀에 넣지 않는다. 가신 6명의 승인된 레벨/승급/편성식과 [전투 효과 cap](13-vassal-combat-proposal.md)을 영웅 출시를 이유로 늘리지 않는다.

| 구분 | 첫 출시 제안 | 보존 경계 |
|---|---|---|
| 영웅 | 직접 조작 캐릭터이자 행군 지휘관. 판당 직접 조작 1명 [가설] | 영웅 ID/스킬/성장과 화면 참조를 분리. 스킨에 성능 필드 없음 |
| 가신 | 기존 제한된 편성의 계정 지원 보너스 | 영웅과 별도 목록·조각·cap. 영웅을 가신 칸에 넣어 슬롯 제한 우회 불가 |
| 상비 병력 | 병영에서 훈련한 준비/출전/부상 인원 | 영웅·가신을 병사 수에 더하지 않음. 사망한 병사를 영웅 중복으로 복원하지 않음 |
| 임시 아군 | 판 안 징집/소환 | 영웅 해금·영구 군대 재고로 전환하지 않음 |

## 2. 첫 영웅 집합과 무료 경로 [가설]

기존 기사는 시작부터 무료 보유하고 첫 판의 선택을 요구하지 않는다. 나머지는 **신규 설계용 명칭/ID 후보**이며 아트 재사용이나 기능 완성을 주장하지 않는다. 희귀도는 획득 빈도이며 높은 희귀도에 더 큰 기초 능력치/유료 전용 cap을 주지 않는 방향을 권고한다.

| 영웅 후보 | 획득 구분 [가설] | 전투/영지 연결의 설계 방향 | 역할 차이의 비용 |
|---|---|---|---|
| 개척 기사 `core:frontier_knight` | 무료 기본, 모집 풀 제외 | 기존 기사 조작을 기본으로 개척 목표/임시 아군 보호 | 기본 콘텐츠를 이 영웅만으로 완료 가능해야 함 |
| 농로 길잡이 `slg:field_guide` | 일반, 모집 또는 개척 일지 | 밭 방어/수확 목표를 수행해 지정 `zone:inner-fields` 개방 자격에 기여 | 이동/목표 수행 특화 후보, 순수 피해 우월을 보장하지 않음 |
| 강가 수호자 `slg:river_warden` | 희귀, 모집 또는 개척 일지 | 나루·채집대 수비의 직접 참전 목표, 지정 강가 구역/월드 자원지 상태에 기여 | 자리를 지키는 능력과 추격 능력의 교환 |
| 폐허 탐구자 `slg:ruin_seeker` | 서사, 모집 또는 개척 일지 | 폐허 표식 수호·거점 회복 목표, 기록소 연구의 탐사 자격에 기여 | 설치/회수 동선이 필요하며 자동 승리·연구 즉시완료 없음 |

무료 확정 경로 후보 [가설]: 시작 이후 개척 일지에서 미보유 후보 1명을 목표로 고르고, 그 영웅에 대응하는 서버 승인 PvE 목표 완료 20회를 누적하면 해당 영웅을 해금한다. 한 번에 1명만 추적하고 완료 뒤 다음 영웅을 고른다. 동일 runId 재제출은 1회이며 목표 변경으로 진행을 삭제하지 않는다. 반복 가능한 목표는 서버가 새 encounterId를 발급한 유효한 PvE에 한한다. PvP 약탈·클라이언트 방치 시각·개발 저장은 진척 원천이 아니다. 목표는 기사만으로도 수행 가능해야 하고 대상 영웅 보유를 요구하지 않는다.

모집으로 먼저 얻었다면 해당 일지는 무료 중복 조각 보상이 아니라 **이미 보유**로 닫고 누적된 완료 수는 계정의 다음 미보유 후보에 한 번 이어 주는 것을 권고한다. 이전 후보와 다음 후보 양쪽에 같은 누적을 쓰지 않는다. 목록에서 선택 변경·해금 경쟁의 확정 순서를 서버가 정한다. 실제 무료 획득 소요 시간은 정상 플레이 측정 전 미확인이며, 20회를 일/주 단위의 확정 시간으로 보고하지 않는다.

## 3. 모집 풀·확률·천장 [가설]

첫 출시 후보는 **상시 단일 풀**이다. 기간 한정·픽업·다중 배너·유료 전용 영웅은 넣지 않는다. 추후 픽업을 추가하려면 개별 확률과 미획득 보장 이월 규칙을 별도 승인받는다. 첫 풀에서는 아래 개별 확률이 등급 확률과 같다.

| 상태 | 농로 길잡이 | 강가 수호자 | 폐허 탐구자 | 합계 |
|---|---|---|---|---|
| 보통 모집: 연속 서사 미획득 c=0~18 | 70% | 25% | 5% | 100% |
| 천장 모집: c=19 | 0% | 0% | 100% | 100% |

확률은 후보 수가 늘면 재설계해야 하며 같은 등급 안의 개별 영웅 확률을 생략하지 않는다. 소프트 천장·숨은 확률 보정은 없다. 보통 결과에서 서사를 얻으면 c=0, 그 외는 c+1이다. c=19인 다음 모집은 서사를 확정 지급하고 c=0으로 돌아간다. **최대 20회 안에 서사 1회**라는 뜻이며 미보유 서사 보장이 아니다. 이미 보유한 서사도 천장을 소모한다. 무료/유료 보석 출처별 확률·천장은 동일하다.

1회 보석 100개 [가설]. 실제 현금 가격은 정하지 않는다. 처음에는 단일 모집만 제공하는 것을 권고한다. 다회 모집 UI를 나중에 추가해도 순차 1회 명령으로 평가하므로 중간 서사에 즉시 카운터를 초기화한다. 별도 다회 할인·희귀 보장·무료 추가 회차는 승인 없이 만들지 않는다. 보유 보석·차감량·다음 천장까지 남은 횟수·현재 다음 1회의 조건부 확률을 확인 창에 함께 표시한다.

풀은 `poolFamilyId`, 불변 `poolVersion`, 영웅/확률/보장 정책 hash를 갖는다. 같은 상시 family의 문구/그림 수정은 c를 유지한다. 확률·구성·천장을 바꾸는 변경은 새 불변 버전과 사용자 공시/이월 설계를 먼저 검토한다. 첫 출시 기본안은 기존 계정의 c와 이미 진행 중인 요청을 기존 버전으로 끝내며 강제로 새 버전으로 옮기지 않는 것이다. 서버가 지원하지 않는 옛 버전은 모집을 잠그고 이전 c를 보존한다. 새 버전으로 자동 리셋하거나 종료일로 천장을 소멸시키지 않는다.

## 4. 중복·성장과 상한 [가설]

미보유 결과는 영웅 해금으로, 보유 결과는 **해당 영웅 조각**으로 지급한다. 일반/희귀/서사 중복은 각각 5/10/20조각 후보다. 가신 조각과 교환하지 않는다. 서사 중복이 나와도 c는 위 규칙대로 초기화된다. 조각은 지갑 상한으로 소멸시키지 않고 최대 보유/넘침 보관 정책이 구현되기 전 상품을 열지 않는다.

성장 후보: 영웅 레벨 상한 20, 승급 상한 2. 레벨은 서버 검증 PvE 영웅 경험치로 성장하고, 승급은 영웅별 조각 20/40개와 무료 플레이 단계 조건을 함께 요구한다. 기본 기사 조각은 모집 대신 기사 개척 일지의 별도 반복 목표에서 얻는다. 모든 영웅의 최종 stat budget·cap은 같고 역할/스킬 운용으로 차이를 내는 방향이다. 경험치 곡선·레벨별 능력 계수·승급 비용의 자원 부분은 후속 밸런스 표 없이는 실행 콘텐츠로 만들지 않는다.

중복 구매 없이도 승급 가능한 영웅별 일지 조각 경로를 둔다. 후보는 해당 영웅을 편성해 승인 PvE 목표 5회당 5조각, 계정 영웅별 주당 10조각 [가설]이다. 최초 해금용 완료와 승급용 완료는 같은 사건을 두 경로에 중복 계산하지 않는다. 서버 주간 경계·결과 확정 시점을 고정한다. 최대 승급 뒤 조각은 보유하고 현금·보석·병력으로 자동 환전하지 않는다. 모집 화면에서 최대 성장 영웅도 출현함과 조각의 현재 사용처를 숨기지 않는다.

새 영웅 고유 스킬은 “조작 방식의 선택”이고 보너스 cap 밖에 무제한 피해/회복/추가 군대를 만드는 예외가 아니다. 아래 수치 보너스뿐 아니라 발동 빈도·대상 수·기여 피해/회복량을 동일 입력 실험으로 따로 검사한다. 영웅별 기초 전투 계수와 스킬 예산이 승인되지 않으면 영웅의 이름·확률표만으로 상품 출시를 통과시키지 않는다.

## 5. 가신·연구와 함께 적용하는 효과

기존 가신의 개별 계산/cap은 그대로 검사한다. **새 SLG 경로에만** 계정에서 오는 동종 보너스를 합산한 뒤 공통 cap을 한 번 적용하는 후보를 둔다. 같은 피해에 가신×영웅×연구를 차례로 곱하지 않는다. 기존 가신 단독 판과 역사 경로를 소급 변경하지 않는다.

| 효과 | SLG 합산 상한 후보 [가설] | 합산 입력/범위 |
|---|---|---|
| 영웅 피해 | +10% | 가신 Attack + 영웅 계정 성장 + 군사 연구의 동종 피해 보너스 |
| 영웅 최대체력 | +15% | 가신 Health + 영웅 계정 성장 + 동종 연구 |
| 이동 | +5% | 가신 Movement + 영웅 성장 + 동종 연구; 월드 행군속도는 별도 단위 |
| 판 안 성장 | +10% | 가신 Growth + 영웅 성장 + 동종 연구 |
| 아군 피해/최대체력 | 각각 +15% | 가신 Allies + 영웅 지휘 + 군사 연구; 상비/임시 적격성은 별도 명시 |
| 판 안 경험치 | +8% | 가신 Experience + 영웅 성장 + 동종 연구 |
| 훈련 속도 | +30% | 병력 GDD의 영웅·연구 속도 합산 상한 유지; 작업 시작 snapshot 고정 |

위 전투 cap은 승인된 가신 cap을 확대하지 않는 초기 후보다. 가신만으로 상한에 닿으면 같은 종류 영웅/연구 보너스의 추가분은 0이며 UI에 “상한 도달”을 보인다. **강화/연구 비용 확인 전에도 현재 편성의 실제 증가분 0을 표시**해 구매 뒤에야 알게 하지 않는다. 다른 편성에서는 유효할 수 있음을 구별한다. 이것이 조합 선택을 무의미하게 만드는지는 정상/최대 계정 실험으로 판단할 사용자 검토 항목이다. 입력 원천별 raw/capped/최종값을 출정 확인에 보여 주고, 기록소·영웅·가신을 서로 다른 메뉴에 두었다는 이유로 상한을 여러 번 적용하지 않는다.

기존 판 안 무기·도구 성장, 고유 스킬 자체의 기본 파이프라인과 계정 보너스는 분리하되, 이름만 고유 스킬로 바꾼 상시 배율을 cap 바깥으로 빼지 않는다. 단순 곱연산으로 새 스킬의 실효 전투력을 증명하지 않는다. 가신 [format8/독립 블록](13-vassal-combat-proposal.md)은 그대로 유지하고, 영웅/연구/병력의 새 snapshot 계약은 Codex의 별도 규칙/재생 설계에서 명시한다. format7/schema1·2·기존 골든 및 블록 absent 경로는 변경하지 않는다.

## 6. 편성·진행 중 변경·패배

한 영웅은 동시에 한 행군/직접 전투에만 배치한다 [가설]. 배치부터 귀환 확정까지 잠기며 다른 행군·수비에 복제하지 않는다. 직접 조작 영웅 1명, 가신 편성/상한, 상비 병력, 연구·콘텐츠 버전을 출정 확정 시 함께 snapshot으로 고정한다. 진행 중 새 영웅 획득·승급·연구 완료가 그 판을 바꾸지 않는다. 해금/강화가 가능하더라도 진행 중 snapshot은 원래 값을 쓴다.

패배로 영웅/가신이 영구 소멸하거나 유료 부활이 필요해지는 규칙은 넣지 않는다. 영웅은 귀환 확정 후 다시 편성한다. 병력 손실·치료는 병력 GDD의 `N=S+A+L`과 두 단계 정산을 따른다. 연결이 끊겨도 동일 runId를 복구하며 결과가 미확정이면 영웅 잠금도 유지한다. 서버가 전투 전 취소를 확정했을 때만 보상 없이 잠금을 해제한다. 월드 PvP 직접 조작은 이 문서가 추가하는 범위가 아니다. 병력/재화가 0이어도 기본 기사의 무료 기초 개척전을 통해 복구하며 입장비·추가 영웅 수집·연구를 선행 조건으로 붙이지 않는다. 이미 다른 행군에 묶인 기사까지 복제해 이 복구전을 열지는 않으며, 회군/잠금 해제 후 참가한다.

## 7. 서버 모집·결과 확정 계약

정식 계정은 서버가 정본이다. 개발용 자동 장원·보석·영웅 파일은 수입하지 않는다. 모집 난수와 지급은 서버 서비스의 책임이며 클라이언트 seed·기기 시각·광고 완료 주장으로 영웅을 정하지 않는다. 순수 전투 Core의 재생 seed를 유료 모집 난수로 재사용하지 않는다. RNG 구현·보안·저장·운영 감사는 Codex 서버 ADR에서 결정한다.

1. 서버는 계정, 요청 ID, 예상 풀 버전, 비용, c와 지급 가능 상태를 확인한다. 풀/가격이 변경됐으면 차감 없이 재확인을 요구한다.
2. 서버가 결과를 정하고 **보석 차감 + 결과/요청 기록 + c 전이 + 해금/조각 지급**을 같은 확정 거래로 저장한다. 해금 일지와의 경쟁도 이 계정 확정 순서에서 처리한다. 차감만 먼저 확정하는 경로는 허용하지 않는다.
3. 응답 손실/시간 초과는 결과 불명확이다. 같은 요청 ID로 결과를 조회하며 새 난수·추가 차감·자동 환불·새 요청 대체를 하지 않는다. 앱 종료 후에도 진행 중 요청을 조회한다.
4. 확정 전 거절은 차감·카운터·지급 변화 없음. 확정된 모집은 기존 결과를 재전달한다. 이미 지급된 영웅을 유지하면서 클라이언트 실패 명목으로 보석을 돌려주지 않는다. 결제 취소·스토어 환불/부정거래 대응은 운영 정책과 별도 결제 원장으로 설계하며 이 문서가 몰수 정책을 결정하지 않는다.

### 7.1 서버 시제품 구현 기록 (2026-10-30, [#584](https://github.com/hyunlord/bs-mobile/issues/584))

버전 1.1 · 날짜 2026-10-30 · 상태: 서버 시제품 구현, 수치는 [가설] 유지. 위 1~4번을 [ADR0078](../../adr/0078-server-domain-command-transactions.md)의 공통 계정 writer 아래 `recruit` 분야 처리기로 구현했다(`POST /v1/account/commands` 조작 `recruit`, 확률 공개는 `GET /v1/account`의 `domains.recruit`). 설계와 다른 점:

- 모집 수치(70/25/5, c=19 확정, 보석 100, 중복 5/10/20)는 콘텐츠 초안에 없어 [`recruit-pool-v1.json`](../../../data/opt-in/slg/recruit-pool-v1.json)에 두고, 영웅 ID·등급이 초안과 다르면 로드하지 않는다. 정책 hash는 이 파일의 SHA-256이다.
- 보석은 Core 지갑이 아닌 모집 분야 상태의 잔액이며 응답 `resources`에 `slg:gem`으로 노출한다. 보석을 쓰는 두 번째 명령이 생길 때 공통 계정 화폐로 올릴지는 별도 결정이다.
- 결제(#122) 전 보석 원천이 없어 개발 설정 `Prototype:RecruitGems`(Development + `Prototype:Enabled=true`일 때만)로 첫 상태에 지급한다. 콘텐츠 값이 아니며 출시 설정에서는 0이다.
- 난수 seed는 처리기 밖에서 서버 키 HMAC(계정, 모집 순번, 풀 버전)으로 계산해 입력으로 넘긴다. `domain_events`에 seed·roll·c 전후·풀 버전·정책 hash를 남긴다. 개척 일지 해금 경쟁은 미구현.

현금 구매와 보석 모집은 서로 다른 거래다. 실제 결제 SDK·구매 복구는 [#122](https://github.com/hyunlord/bs-mobile/issues/122)의 별도 승인·검증 전까지 구현하지 않는다. 무료/유료별 전투 자격 추적은 만들지 않지만 실제 구매/모집 거래의 중복 방지 기록은 필요하다.

## 8. 판이 영지·월드를 바꾸는 연결

영웅을 뽑았다는 사실만으로 땅·거점·연구를 주지 않는다. 영웅의 역할에 맞는 **실제 판 안 목표 달성**이 서버의 검증된 사건이 돼야 한다. 계약에는 대상 r8 구역 또는 월드 encounter의 ID/세대와 성공 조건을 포함한다.

| 직접 참전 | 결과 정산의 영구 변화 | 금지 |
|---|---|---|
| 농지 경계 수비/개척 | 지정 계정 r8 구역 개방 자격 + 허용 자재/영웅 일지 진척 | 해당 영웅 구매만으로 개방, 동일 완료 재지급 |
| 강가 채집대 방어 | 월드 자원지 확보/채집 진행 상태 + 실제 귀환 적재량 | 가신/영웅 보너스로 채집 재고 생성, 무제한 자원 |
| 폐허 표식·거점 회복 | 공유 거점 상태 변화 + 특정 연구의 탐사 조건 + 영웅 일지 | 반복 몬스터로 개인 구역 복제, PvP 승리로 무한 연구 해금 |

전투 종료에서 세계 변화·보상 자격·병종별 출전 N/전투 불능 K·회군 상태를 함께 확정한다. 이때 입원 A/전사 L까지 확정하는 것은 아니다. 귀환 시 병력 GDD의 병상 정산 순서로 생존 S/입원 A/전사 L을 결정해 `N=S+A+L`을 지키고, 확정 자격에 따른 운반 자재/병력을 한 번 반영한다. 영웅 경험치/일지 진척도 정산 정책의 명시된 시점에 한 번만 부여한다. 첫 출시 후보는 **전투 종료 확정 시**이며 귀환 보상에서 다시 더하지 않는다. 목표의 영구 상태·개방 권리와 운반 중 자원은 UI에서 구분한다. r8는 유한한 승인 구역/인접 조건을 유지하며 특정 영웅이 없으면 출시 구역을 영원히 열 수 없는 유료 문은 만들지 않는다.

## 9. 화면·공시와 구현 종료 기준

모집 버튼 전에 전체/개별 확률, 현재 c·천장까지 남은 횟수, 다음 1회 조건부 확률, 중복 조각, 최대 성장 이후 처리, 풀 버전, 비용/보유량을 열람할 수 있어야 한다. 결과는 영웅명 또는 중복 조각 실제 지급량과 갱신된 c를 보여 준다. 잠긴 영웅에는 무료 일지 경로도 함께 표시한다. 390×844, 48×48 이상 터치 기준을 따르며 지금 새 UI/그림은 제작하지 않는다.

후속 구현 관문:

- 확률표 합계·개별 확률, c=0/18/19 경계, 보통 서사 획득과 천장 후 c=0, 중복 서사도 초기화, 풀 버전 변경·종료 시 c 보존을 명시적 검사로 확인한다. 모집 분포 시험은 구현 검증일 뿐 법적 공시 적합성 증명이 아니다.
- 같은 요청 중복·동시 보석 소진·응답 손실·서버 재시작·지급 저장 실패에서 차감/결과/카운터/지급이 분리되지 않는다. 일지 해금과 모집 해금 경쟁에서 이중 해금/잃어버린 지급이 없다.
- 영웅 하나의 다중 배치 거부, 전투 중 해금/승급/연구 변경 후 snapshot 불변, 패배/재접속 잠금 해제 조건을 검증한다.
- 기사만/무료 획득/최대 수집 계정의 정상 플레이로 완료 가능성·군대 손실·일지 획득 시간·성장 격차·동종 cap을 비교한다. 구매량이나 희귀도만으로 승리하는지, 고유 스킬이 cap을 우회하는지 별도 평가한다.
- 검증된 판→구역 개방 자격/거점 변화/연구 조건→다음 성장의 실제 휴대폰 흐름을 보여 준다. 역사 FP01/C05 회귀와 새 SLG 실험을 구별한다.
- 출시 국가·대상 연령·스토어의 확률형 상품/결제 관련 요구를 출시 전 최신 근거로 별도 검토한다. 이 기획의 확률 공개·천장이 법규/스토어 충족을 보증하지 않는다.

현재는 문서/산술 검토만 수행한다. 서버 RNG·결제·실판매·밸런스·실기 검증 **NOT_RUN**. 사용자 검토 항목: 신규 영웅 수/역할, 단일 상시 풀, 확률/천장·중복, 무료 일지 경로, 성장/합산 cap. 모든 후보는 승인 뒤 구현하며 최종 출시 수치는 관측으로 조정한다.

## 10. 모집 영웅의 기본 공격·고유 스킬 제안

상태: **r2 사용자 승인 — 수치는 [가설] 유지**. 2026-11-03, 추적 [#672](https://github.com/hyunlord/bs-mobile/issues/672). 사용자 결정인 '사이드그레이드 강화·재사용형 능동 효과와 상시 cap 분리'를 반영했다. 스킬 방향·가설 수치·그림 목록은 사용자 승인(2026-11-03)되었다. 수치가 검증된 밸런스라는 뜻은 아니며 Core 구현은 새 능동 효과 계약 설계 메모의 별도 승인 뒤 진행한다. 아래 모든 전투 수치·성장 조건은 **[가설]**이다. 기존 30Hz는 실행 프로토콜이다. 각 영웅은 기본 공격 하나와 고유 스킬 하나로 시작한다.

### 10.1 공통 실행·획득 경계

- 기본 공격은 같은 시작 공격 슬롯의 대체 후보이며 기존 무기 위에 무료 추가 공격을 얹지 않는다. 이후 무기·레벨업 선택 흐름은 유지한다. 현재 영웅 JSON에는 시작 무기/스킬 실행 필드가 없으므로 별도 구현 승인 사항이다.
- 기본 공격과 고유 스킬은 **자동 발동**한다. 이동과 기존 레벨업 선택만으로 플레이하며 수동 스킬·방패 버튼이나 표적 지정 UI를 추가하지 않는다.
- **같은 성장 단계의 총 전투 예산은 개척 기사와 같아야 한다.** 처치·피격·이동·목표 수행과 기회비용을 함께 평가한다. 높은 사거리·군중 제어·방어에 공격 빈도·피해·동선 제약의 대가를 둔다. 아래 후보 수치만으로 동등함이 입증된 것은 아니다. **개척 기사만으로 기본 콘텐츠 전체 완료 가능** 조건을 유지한다.
- 기본 공격은 획득 시 동일 등급의 대체 공격으로 제공한다. 고유 스킬 해금에는 해당 영웅으로 서버가 승인한 무료 PvE 완료 **5회 [가설]**가 필요하다. 수치 강화도 별도의 무료 PvE 단계 조건을 충족해야 한다. 강화 수치는 이번에 정하지 않는다. 중복 영웅·유료 재료로 해금 조건·플레이 횟수·스킬 단계·출정 스냅샷을 건너뛸 수 없다.
- 중복 조각·성장 재료는 §4 규칙을 유지한다. 유료 자원·가속의 간접 성장 허용을 철회하거나 돈 출처별 자격 원장/flag를 만들지 않는다. 무료·유료 계정에 같은 플레이 조건·상한을 적용한다. 구매 전용 스킬·추가 슬롯·유료 재사용 초기화는 없다.
- 재사용형 고유 스킬은 **자동 발동하는 짧은 능동 효과**다. 가신·연구·영웅 패시브의 상시 이동/공격/체력 raw 합산 및 cap과 분리하여 거리·지속·대상 수·동시 인스턴스·세기·재사용으로 제한한다. 상시 cap을 다 채워도 스킬은 작동한다. 스킬 효과를 상시 능력치에 남기거나 패시브·유료 성장으로 자체 상한/재사용을 우회하지 못한다.
- 최초 적용 후보는 **직접 조작 PvE**다. 돌진·도발·방패·투사체·둔화를 `army-auto-v1`에 적용하거나 임의 환산하지 않는다. 자동 전투는 현재 승인된 병력·계수 입력만 소비하며 추가 적용은 별도 데이터와 설계 승인이 필요하다.

### 10.2 역할과 후보 수치

피해 계수는 같은 레벨의 공통 기본 공격 기준 피해 대비 정수 천분율이다. 거리 `U`는 기존 Core 좌표 단위로 변환할 **설계 단위 [가설]**이며 미터나 현재 JSON 필드가 아니다. 변환 계수도 승인 후 콘텐츠 데이터로 정의한다. 충돌·사거리 검사를 유지하며 벽 통과·순간이동·무적을 부여하지 않는다. 동률 대상은 거리 후 안정 ID 오름차순으로 선택한다.

| 영웅 | 기본 공격 [가설] | 고유 스킬 [가설] | 선택의 대가 |
|---|---|---|---|
| 농로 길잡이 | **지팡이 휘두르기**: 피해 800‰, 간격 36틱, 사거리 1.5U, 전방 70도, 최대 2체. 가장 가까운 적 방향 고정, 타격 1회 | **농로 돌파**: 일반 이동 연속 90틱 유지 후 2U 안에 적이 있으면 현재 이동 방향으로 돌진. 최대 12틱·3U, 틱당 0.25U, 재사용 300틱 | 돌진 중 무적·피해 감소·접촉 피해 없음. 기본 공격의 새 발동을 멈추고 경로를 바꿀 수 없어 다른 적/예고로 들어갈 수 있다. 벽·통행 불가 충돌 시 조기 종료 |

돌진·도발 구역·장판은 각각 동시 1개 [가설], 재사용은 발동 시점부터다. 수호자의 갈고리는 적을 순간 이동시키지 않는다. 도발은 접근 목표를 바꾸어 무리가 **자기 이동으로** 모이게 한다. 탐구자는 두루마리를 펼쳐 공간을 제어하고 등불로 바깥에서 공격한다. 서사 등급다운 연출은 문양 전개와 넓은 경계로 표현하며 더 높은 총 전투 예산을 뜻하지 않는다.

**개척 기사와 다른 한 줄:**

- 길잡이: 기사처럼 일반 이동으로 교전·수확을 잇는 대신, 달릴 방향을 미리 잡아 위험 지대를 짧게 돌파한다.
- 수호자: 기사처럼 적을 따라 움직이는 대신, 멈출 자리를 골라 무리를 자기 앞으로 모으고 집중 공격 위험을 감수한다.
- 탐구자: 기사처럼 가까이 들어가는 대신, 넓은 장판 가장자리를 따라 적의 접근을 늦추며 등불로 원거리 지원한다.

#### 같은 판의 예상 차이 [가설]

같은 seed·목표·성장 단계·무기/도구·가신/연구·조작 숙련도에서 영웅 시작 공격과 고유 스킬만 바꾼 비교다. 동일 입력 녹화만 강요하면 역할별 동선 선택을 지우므로 결정론 재생 검사와 동등 숙련도의 역할별 플레이 비교를 분리한다. 현재 개척 기사 고유 능력 설명의 **미구현 부분을 성능 기준에 포함하지 않는다**. 아래는 측정값이나 통과 판정이 아니다.

| 영웅 | 처치 속도 예상 [가설] | 피격량 예상 [가설] | 이동·목표 수행 예상 [가설] |
|---|---|---|---|
| 개척 기사 | 현재 실행 기본 공격/빌드의 기준 | 현재 실행 방어/동선의 기준 | 일반 이동으로 교전·수확·목표 사이를 연결하는 기준 |
| 농로 길잡이 | 돌진 중 공격 기회를 잃어 지속 교전은 느릴 수 있음. 재접근이 잦은 판에서는 접근 손실 감소 | 방향을 잘 고르면 위험 구간 체류가 줄지만 무적이 없어 잘못 고르면 증가 | 순간 탈출·자리 교체가 빠름. 재사용·충돌 중단으로 상시 이동 우위는 보장하지 않음 |
| 강가 수호자 | 광역 무기 사용 시 밀집 처리 구간은 빨라질 수 있음. 기본 단일 찌르기만으로는 모은 무리를 빨리 지우지 못함 | 첫 정면 타격은 감소하나 다방향 집중 공격으로 누적 피격은 오히려 증가 가능 | 한 자리 방어에 무리를 모으기 쉬움. 이동 목표·수확에는 정지 준비와 이동 시 해제가 비용 |
| 폐허 탐구자 | 장판 피해가 없고 기본 피해가 낮아 단일/보스 처치는 느릴 수 있음. 진입로를 유지하는 무리전에서는 공격 가동 시간 증가 | 장판 밖 거리 유지 시 감소 예상. 원거리/면역 적·장판 이탈 시 이득 감소 | 장판 가장자리를 순환하며 시간을 벌지만 고정 장판이라 이동 목표 추적 불리. 영웅 자체 이동속도 증가는 없음 |

동등 예산 검증은 고정 위치 방어·이동 목표·보스/면역·혼합 무리 장면을 함께 본다. 처치 속도·누적 피격·이동/목표 시간을 평균 하나로 숨기지 않고 장면과 무료/최대 성장 조합별로 공개한다. 전반적으로 기사를 압도하면 기본 공격 계수·지속·대상 수·재사용을 데이터에서 조정하고 재검증한다. 돌진의 U 변환/속도 후보는 상시 이동 cap을 채운 일반 걷기보다 순간 이동이 빨라야 하며, 실제 단위 대조에서 충족하지 않으면 구현 전에 재조정한다. 사전에 비교 장면/가중치/허용 범위를 승인하기 전에는 '총 예산 동일'을 입증했다고 하지 않는다.

### 10.3 발동·상태·중첩 규칙

| 항목 | 후보 규칙 |
|---|---|
| 기본 공격 타이밍 | 기존 타격 시점·정수 피해 반올림 계약을 재사용한다. 애니메이션/렌더 시각으로 판정하지 않는다. 돌진 중 새 기본 공격 발동만 억제하고 이미 발생한 타격은 취소하지 않는다. 공격 간격 시계는 정상 진행하며 종료 후 밀린 공격을 몰아서 발동하지 않는다 |
| 돌진 준비·방향 | 실제 위치가 변한 일반 이동 틱만 준비에 센다. 정지·벽 막힘에 초기화, 재사용 중/돌진 이동은 준비에서 제외. 발동 때 비영 입력 방향을 고정하고 준비 초기화. 준비 완료 후 적이 없으면 이동 유지 중 준비만 유지하며 재사용 미소비 |
| 돌진 이동·중첩 | 일반 이동 변위에 더하지 않고 돌진 변위로 대체한다. 최대 12틱·3U·틱당 0.25U [가설] 자체 제한이며 상시 이동 cap/보너스가 이 값을 줄이거나 곱하지 않는다. 매 틱 이동 경로의 충돌·피격을 검사해 빠른 이동으로 얇은 장애물/타격을 건너뛰지 않는다. 통행 불가 충돌 시 종료. 이동 입력을 놓으면 다음 틱 중단하되 재사용 환불 없음. 재발동·지속 연장·무적·적 충돌 무시는 없다 |
| 도발 준비·방향 | 실제 위치가 같은 연속 정지 틱만 준비에 센다. 이동·발동 시 준비 초기화, 재사용 중 누적 없음. 대상 없으면 정지 유지 중 준비만 유지, 구역/재사용 미시작. 구역 중심은 발동 위치, 방패 방향은 발동 때 가장 가까운 도발 가능 적 방향으로 고정한다(거리→안정 ID 순). 같은 좌표면 현재 영웅 조준 방향을 사용한다. 방패는 추적 회전하지 않는다 |
| 도발 대상·합류 | 보스/도발 면역 제외, 중심 거리→ID로 최대 6체 [가설] 선택. 범위 안 기존 대상을 유지하고 빈 자리만 같은 순서로 보충. 범위 이탈·사망·면역 시 제외. 기존 속도·충돌·경로로 수호자를 우선 추적한다. 공격 사이 이동의 추적 정지 반경은 1.5U [가설]로 제한해 이미 영웅을 노리던 원거리 적도 더 가까이 모이게 한다. 이동 불가 적은 도발 대상에서 제외한다. 순간 끌어당김 없음. 확정된 공격의 대상·타격·예고·타이머는 취소하지 않고 다음 목표 선택/이동부터 적용하며 공격 사거리·주기는 바꾸지 않는다 |
| 도발 충돌·해제 | 같은 적의 도발 대상은 하나. 중복 구역은 먼저 적용된 유효 인스턴스, 같은 틱이면 소유자 안정 ID 순으로 선택하며 지속 합산 없음. 해제 뒤 현재 상태로 기존 목표 선택 재실행. 구역 종료·수호자 이동·사망 시 도발/방패 즉시 해제 |
| 보조 방패 피해 | 기존 결정적 피해 사건 순서의 첫 해당 양수 타격만 줄이고 소비. 반사·흡수 체력·회복·무적·아군 피해 이전 없음. 구역이 살아 있어도 방패 소모 뒤 재충전하지 않는다 |
| 능동 피해 감소 상한 | 상시 체력/공격 cap과 분리한 새 계약 후보. 같은 피해 사건의 유효 능동 감소 raw를 합산해 250‰ [가설] 자체 공통 상한을 한 번 적용한 뒤 한 번 계산한다. 다른 방패와 순차 곱하지 않는다. 새 효과/상한 승인 전 구현하지 않는다 |
| 장판 예고·입출입 | 대상 없으면 재사용 미소비. 발동 때 좌표와 재사용 시작 고정. 최초 대상 생존 여부와 무관하게 예고 종료 뒤 범위 내 살아 있는 비면역 적을 다시 판정. 매 틱 중심 거리→ID로 동시 최대 12체 [가설]를 선택한다. 범위 이탈·선택 제외·면역·장판 종료 시 이 장판의 둔화 인스턴스를 즉시 해제해 잔류로 동시 대상 수를 넘기지 않는다. 다른 소유자의 상태는 그대로 둔다 |
| 둔화 중첩 | 적 상태의 별도 정책이며 상시 WorldResolvedEffect raw 합산을 대체하지 않는다. 같은 종류는 가장 강한 값 하나만 적용, 합산/곱연산 없음. 같은 강도 재적중은 남은 지속과 새 지속 중 큰 값으로 갱신하고 더하지 않는다. 다른 강도 인스턴스는 각각 만료를 보존해 강한 효과 종료 후 유효한 약한 효과만 남는다. 이 장판의 인스턴스 유효성은 앞의 범위/선택/소유자 조건에 종속되며 지속 갱신이 해제 조건을 연장하지 않는다. 능동 둔화 자체 공통 상한 300‰ [가설] |
| 둔화 제외 | 보스/이동 제어 면역 제외. 피해 증가·방어 감소·공격 속도 감소·기절 없음. 적 이동만 바꾸고 예고·공격 타이머 유지 |
| 죽음·종료 | 영웅 사망 시 준비·돌진·도발·방패·미발동 예고·장판과 그 영웅의 둔화 인스턴스를 해제한다. 다른 소유자의 유효 상태 보존. 출정 종료 뒤 다음 판 이월 없음. 이미 발사한 기본 공격은 기존 공격 소유자 생명주기를 따라 별도 fixture로 고정한다 |

`hold-marker`는 살아 있는 영웅·실제 범위 내 위치·살아 있는 적 유무를 기존 계약대로 검사한다. 도발·장판은 점유자가 아니고 둔화/도발된 적도 살아 있는 적이다. 돌진의 실제 위치로 점유를 판정하며 경로/입력 검증을 건너뛰지 않는다. 적을 실제로 밖으로 유도하는 전술은 가능하지만 도발 플래그만으로 성공을 주지 않는다. 같은 틱 실패→성공→시간 초과 판정 순서도 유지한다.

무료 PvE 조건이 너무 짧거나 모집 영웅이 전반적으로 기사를 압도하면 실질 구매 우위가 남는다. 무료 경로가 있다는 이유로 BM 적합성/밸런스를 통과시켜서는 안 된다. 무료 플레이 조건과 동일 총 예산 검증은 출시 전 필수다. 유료 출처를 전투 자격으로 추적하지 않는 기존 원칙은 유지한다.

### 10.6 Astra 그림 요청 후보 목록

**§10 신규 그림 표 전체는 2026-11-03 사용자 승인된 최종 요청 규격이다. 사용자가 Astra에 요청하며 이 세션은 제작 요청을 보내지 않는다.** [승인 원본 Release](https://github.com/hyunlord/bs-mobile/releases/tag/hero-attack-consumables-20261101-r1)의 길잡이 지팡이 공격과 수호자 왼손 방패 유지 장대 찌르기는 재사용한다. 원본은 320×240 셀, 8열×1행, 외곽 2px, 발 y=184, 시트 2564×244, 2배본 5128×488이다. 승인 원본 보유와 런타임 연결 완료는 별개다.

### 10.4 Core 구현 진행 (2026-11-04, #678)

상태: **농로 돌파 구현·검증 진행 중**, §10 r2의 수치는 계속 [가설]이다. [첫 돌진 구현 계약](../../review/hero-dash-678.md)은 명시적 능동 옵션과 시작 공격 슬롯 결속, 틱 내 벽/적 몸체 충돌·경로 피격, 복구와 역사 바이트 보존을 다룬다. 기존 기본 공격 하나를 임의로 길잡이 공격 완성으로 간주하지 않으며, 실제 영웅 데이터 배포·동등 전투 예산·아트/화면 검증은 별도다. 나루의 도전과 봉인의 서고는 후속 PR로 진행한다. 무료 PvE 해금, 자동 발동, army-auto-v1 비적용 및 개척 기사로 기본 콘텐츠 전체 완료 가능 원칙은 유지한다.

### 10.5 나루의 도전 Core 구현 진행 (2026-11-04, #686)

상태: **도발·방향 방패 구현·검증 진행 중**. [도발 구현 계약](../../review/hero-taunt-686.md)에 정지 준비 자동 발동, 고정 중심 접근 유도, 기존 공격 유지, 단발 방향 피해 감소와 자체 상한을 구체화했다. 실제 이동·넉백·사망 시 해제하며 hold-marker는 기존 실제 위치만 사용한다. 기존 돌진·월드 전투 바이트를 보존한다. §10 r2 수치는 계속 [가설]이고 무료 PvE 해금·자동 발동·army-auto-v1 비적용·개척 기사 완주 및 동일 성장 단계 전투 예산 원칙은 유지한다. 실제 영웅 콘텐츠와 아트/시인성·밸런스 검증은 별도다.
