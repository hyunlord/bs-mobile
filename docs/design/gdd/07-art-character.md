### B. 선택 배율에서 A 기사와 (c) 모션

A 원화를 지금 B 시안의 부위 구성을 참고해 분리·리깅한다. 영웅 1명만 무료 Unity 2D Animation 실시간 뼈대를 사용하며 적은 구운 이미지를 유지한다. 동작 7종은 **서기, 걷기, 이동하면서 철날 검 휘두르기, 진화 후 큰 휘두르기, 피격, 쓰러짐, 레벨업 포즈**다. 걷기 방향 수는 선택된 1.4배 화면에서 정한다. 하체 걷기와 상체 공격의 혼합이 자연스러운지 확인하고, 1.4배에서 적 사이에 섞여도 영주 실루엣이 한눈에 보여야 한다. 영웅 선택·제작 승인을 이 동작들의 완성이나 실루엣 관문 통과로 표현하지 않는다.

### C. 선택 배율에서 손맛 전후 재촬영

지난 VFR 녹화 실패 표본은 보존한다. 새 영상은 **1.4배·오프라인 고정 60fps에 소리 트랙 포함**으로 만들고, 같은 입력·장면·시점의 적용 전후를 나란히 놓는다. 영웅 주변을 2배 확대한 비교본도 함께 낸다. 이 영상은 표현 판정용이며 실제 프레임 비용의 증거는 캡처 없는 실행에서 얻는다. 프레임·소리 동기를 검증하기 전 완료로 쓰지 않는다.

화면 가장자리 화살표 최대 [가설: 6개]·돌진 예고 [가설: 0.5초]는 위험 판독을 보완하는 사용자 제시값이다. Core 공격 준비 시간이나 밸런스 수치를 바꾸지 않는다. 실제 공격자별 피해 귀속과 동일 입력에서 경고 표시가 피해를 바꾸지 않는 경계는 [06](06-feedback.md)을 따른다.

[#223](https://github.com/hyunlord/bs-mobile/issues/223)은 10/13 01:00–06:00 야간 측정을 유지한다. 사용자가 전원 연결·방해 금지를 준비한다고 답했으며 실제 상태·측정 결과는 별도로 확인한다. #126·#98·#224·1b 보류와 광고·결제·분석 SDK 미도입을 유지한다.

## 세계와 시각 우선순위

채택된 세계는 [A 휴경의 왕국](../world-directions/A-fallow-kingdom.md)이다. 계절이 멈춘 잿빛 들판에 개척 기사가 씨앗을 심어 색을 되돌린다. 성·밭·공성의 판타지 안에서 쓸쓸하지만 다정한 복구 동화를 지향한다. 새봄의 터는 사방으로 이어지고 출발점의 집·작업장은 귀환 장소로 남는다. 소품과 세계 별칭을 새 충돌·자원 규칙으로 바꾸지 않는다.

잉크·과슈, 3/4 탑다운, 낮은 대비의 회색 흙/돌길/죽은 나무/물길/폐허가 바탕이다. 파종→싹은 세이지, 익음은 황금, 건물 완성은 따뜻한 회벽과 창빛으로 번진다. 성장 상태와 실제 수확 사건이 색 복구를 이끈다. 영주의 코발트·상아와 적의 위험 표식은 회색에서도 남는다.

판독 우선순위는 적 > 내 공격 > 아군 > 익음/완성 > 나머지다. 평소 적 몸은 잿빛 갈색/숯빛, 돌진 예고·돌진만 붉게 강조한다. 빨강을 아군 이펙트에 쓰거나 수확 보석을 영주보다 두드러지게 하지 않는다. 색만 바꾼 적, 피폐 고어, 무지개 폭발, 시안 전체를 배경에 붙여 실행 화면처럼 보이는 방식은 금지한다.

### 캡처 없는 모션 비용·메모리 비교

`8097c5c` Release에서 같은 역사 411마리 입력의 10,800–11,530틱(각 약 24.33초)을 ABBA 순으로 실행했다. 화면은 1920×1080 안에 세로 전장을 가운데 두며, 120Hz 화면의 vSyncCount=2로 60fps를 맞췄다(`targetFrameRate=-1`). 영상 캡처는 끄고 비교 계측만 켰다. 전경 유지·경계가 아닌 프레임만 집계하며 네 실행 모두 같은 입력·최종 해시와 계측 자격을 확인했다. 일반 무계측 플레이나 Fold7 성능 증거는 아니다.

| 순서·방식 | 장 p95(ms) | >25ms 비율 | 화면 구성 p95(ms) | GPU p95(ms) | Unity 할당 메모리 중앙값(MiB) | Gen0/초 |
|---|---:|---:|---:|---:|---:|---:|
| a1-baked | 16.786 | 0.000% | 2.180 | 0.474 | 171.75 | 0.206 |
| b1-live | 17.586 | 0.554% | 2.142 | 0.480 | 211.25 | 0.205 |
| b2-live | 17.006 | 0.206% | 2.142 | 0.480 | 210.81 | 0.205 |
| a2-baked | 16.979 | 0.069% | 2.173 | 0.447 | 172.25 | 0.206 |

실시간 방식의 >25ms 비율은 두 실행에서 0.554%·0.206%로 구운 방식보다 높았다. 이 짧은 비교만으로 원인을 실시간 뼈대에 귀속하거나 방식의 우열·최종 채택을 확정하지 않는다. 실시간 관절 적용 자체의 p95는 0.0079·0.0078ms지만 SpriteSkin LateUpdate 마커는 수집 불가이므로 이를 스키닝 전체 비용으로 쓰지 않는다. 구운 방식의 별도 포즈 타이머도 없으며 0으로 보고하지 않는다.

메인 스레드 시간에는 프레임 대기가 포함된다. GPU·렌더 스레드는 최신 비동기 관측값으로 같은 프레임의 원인 분해가 아니다. Unity 할당 메모리는 초당 표본 24개의 중앙값이며 프로세스 RSS나 최종 단독 방식 빌드의 메모리가 아니다. 원자료는 `artifacts/m1-246/motion-metrics-8097c5c/`, 재생성은 `.omo/evidence/m1-motion-metrics-summary.mjs`다. C05 800+의 손맛 효과 회귀 측정은 별도이며 이 표로 대체하지 않는다.

### 무기 유형 하나를 늘릴 때의 제작 범위

현재 철날 검 시제품은 같은 [저작 정의](../../../tools/art-authoring/hero-b/motion-clips.json)로 일반 휘두름 6·진화 큰 휘두름 6·피격 4개의 표본을 만들고, 하체 걷기 12자세를 공유한다. 이는 실제 시제품 구성이지 앞으로 모든 무기에 적용할 고정 프레임 수나 작업 시간 견적이 아니다.

| 작업 | (b) 관절 저작 후 굽기 | (c) 실시간 뼈대 |
|---|---|---|
| 새 무기 유형 저작 | 무기 부위·쥐는 위치·상체 회전 키·실루엣을 저작하고 일반/큰 공격을 검증 | 같은 무기 부위·쥐는 위치·상체 회전 키가 필요하며 뼈대·가중치 연결도 검증 |
| 현재 검 기준 산출 | 일반 6+진화 6 표본을 상체 아틀라스에 굽고 영역 연결; 피격 4는 공통 재사용 가능 | 같은 6+6 표본의 관절 값을 보간; 피격 4는 공통 재사용 가능. 공격별 이미지 아틀라스 굽기는 불필요 |
| 걷기와 공격 결합 | 공통 하체 12와 상체를 층별 합성; 12×공격 수의 전신 조합을 만들지 않음 | 공통 하체 걸음과 상체 관절을 독립 적용; 연속 보간의 자연스러움은 영상에서 판정 |
| 추가 검토 | 아틀라스 크기·잘림·발 접촉·진화 범위 | 관절 교차·부위 틈·실시간 변형·그리기 비용 |

새 무기 한 유형에 몇 시간이 드는지는 기록하지 않았다. 두 방식의 실제 작업 시간을 재지 않고 빠르다는 비율이나 시간 수치를 만들지 않는다. (a) 프레임 원화는 영주 전체 방식의 후보가 아니라 휘두름 잔상 같은 효과에만 사용한다.

기존 바이블의 하단 장비 칸과 역사 프로필 적 전신 붉은색·2–4프레임 공통 bob 문구는 최신 세로 HUD/위험색/B 모션보다 우선하지 않는다. [portrait-v0](../portrait-v0/README.md)는 화면 배치 기준이며 HUD는 소형 한 줄, 하단 막대 없음이다. 원본 바이블·A/B/C 세계안은 삭제·덮어쓰기하지 않는다. 타이틀 로고는 현재 “휴경의 왕국” 유지, 최종 제목 결정은 별도다. 새 자산은 생성 출처·저작 파일·atlas 연결·라이선스를 함께 기록한다.

## 공식 자료와 비용 판단

확인일 2026-10-12. Unity 6.6 호환표는 [2D Animation 16.0.1](https://docs.unity3d.com/6000.6/Documentation/Manual/com.unity.2d.animation.html)을 명시한다. [SpriteSkin](https://docs.unity3d.com/Packages/com.unity.2d.animation@16.0/manual/SpriteSkin.html)은 SpriteRenderer 메시와 뼈대 Transform/가중치를 사용한다. 이는 기존 SpriteBatch에 패키지만 넣어 자동 연결되는 구조가 아니다.

[GPU 변형 지침](https://docs.unity3d.com/Packages/com.unity.2d.animation@16.0/manual/GPUDeformation.html)은 URP와 CPU/GPU 방식의 비용 비교를 요구한다. MaterialPropertyBlock·SpriteMask의 SRP Batcher 제한, Android OpenGLES3 GPU 변형 미지원도 고려한다. 이 문서는 Mac 영주 1명 시험을 Fold7 통과로 확대하지 않는다. 하체 걷기와 상체 공격 혼합은 [Animation Layers](https://docs.unity3d.com/6000.6/Documentation/Manual/AnimationLayers.html)와 [Transform 계층 마스크](https://docs.unity3d.com/6000.6/Documentation/Manual/class-AvatarMask.html)를 참고하되 실제 시험 결과로 확인한다.

제작량은 전신 방식에서 `무기 유형 × 동작 × 방향 × 프레임`, 층별 방식에서는 `공유 하체 + 무기별 상체 + 전신 동작`으로 비교한다. 12걷기×8공격을 모두 굽는 96개 대신 12+8층을 합성할 수 있다는 것은 상태 수 산식이며, 메모리 절감률 실측이 아니다. 예를 들어 2048² RGBA32·mip 없음은 산술 16MiB지만 실제 압축·읽기 복사·메시·버퍼를 포함한 빌드 메모리는 별도로 잰다. PNG 파일 크기를 GPU 메모리로 쓰지 않는다.
