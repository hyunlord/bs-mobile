# 14 · r8 지도 영지의 정식 전환·저장·롤백 제안

상태: **사용자 검토 대기인 설계 제안**. 추적 [#546](https://github.com/hyunlord/bs-mobile/issues/546). 2026-10-30. 구현은 Codex 후속이며 이 PR은 문서만 변경한다. 사용자 승인 전 병합하지 않는다.

## 1. 확정된 화면과 아직 제안인 전환 정책

[확정: 사용자 결정] 정식 영지 화면을 r8 지도로 바꾸고 신규 계정의 첫 영지 진입부터 지도를 쓴다. [첫 접속 시안](https://github.com/hyunlord/bs-mobile/releases/tag/onboarding-first10-542-20261030)의 07~09(터 선택→비용 확인→착공)가 기준이다. 첫 타이틀 탭→첫 출정→카드→첫 판 종료·귀환의 순서는 유지한다. “지도로 시작”은 타이틀 다음에 첫 전투를 취소하고 지도부터 보여 준다는 뜻이 아니다. 첫 판 종료·건설·재출정을 10분 안에 강제로 발생시키지 않는다.

[제안] 신규는 영지가 포함된 저장 v6을 처음부터 생성한다. 영지가 없는 기존 계정은 안전한 비전투 시점에 한 번 변환하고, 구형 장원을 별도 활성 계정으로 병행하지 않는다. 변환 전 원본은 복구용으로 보존한다. 두 지갑·두 생산기를 독립적으로 계속 쓰는 정책은 재화 중복과 진행 분기를 만들므로 거절한다.

[확정된 배치 계약] r8의 13구역·총1,664칸·중앙 시작12×12·시작 건물10채·r3~r7 동결은 [r8 배치 설계](../m3a-r8-layout-proposal.md)를 따른다. 건물45~55px 축소/75px 기본 등의 시각 배율은 승인 그림 계약이며 경제 보상이 아니다.

[가설: 출시 경제 후보] 현행 r8 시제품의 초기 지갑 곡물120·목재180·철재60, 곡창 L1 목재30·60초 등은 화면 검토용 후보다. 이를 첫 판 보상으로 지급하거나 기존 계정에 추가하지 않는다. 신규 초기 지급의 최종값·보호 경로·생산속도는 #126의 경제 검토와 아래 관문을 통과해야 한다. 저장 버전6·리플레이 버전7/8·설정 ID 숫자는 형식 식별자이며 밸런스 가설이 아니다.

### 기존 v6 계정의 생산 정책 전환

기존 v6 r8과 호환 예외 r2~r7도 **정식 지도 경로에서는 새 legacy 방치 생산을 중단**한다. 위 표의 ‘정상 재개/원래 규칙 유지’는 지도 설정·공사·재고·시계를 보존한다는 뜻이며 두 생산기의 병행을 허용하지 않는다. 현재 `MetaProgression` 생성자의 무조건 `AdvanceIdle` 호출을 그대로 통과시키면 이 계약을 어기므로 호스트 연결 전에 분기해야 한다.

[권고: 별도 표식 없는 보수적 전환] 기존 v6에는 v5용 `Migrate`나 ‘마지막 legacy 구간 정산’을 다시 실행하지 않는다. 이미 저장된 legacy pending claim·나머지는 보존하고 한 번 받을 수 있는 장부만 유지한다. 아직 저장/관측되지 않은 legacy 방치 시간은 추가 지급하지 않으며, 지도 시계도 다시 초기화하지 않는다. 정상 지도 Advance가 원래 검증된 구간만 적용한다. 이 정책은 미관측 legacy 보상을 기대한 사용자의 수령량에 영향을 줄 수 있으므로 사용자 승인 대상이다. r8/r2~r7 모두 같은 정책을 적용하고 ConfigVersion에 따라 중단 여부를 바꾸지 않는다.

이 권고는 ‘Estate 존재 + 정식 단일 생산 정책’으로 매번 결정되어 일회 지급 표식이 필요 없다. 반대로 기존 v6의 미관측 legacy 시간을 한 번 더 지급하기로 바꾸면 이미 지도에서 생산한 구간과의 겹침, 완료 표식의 내구 저장·재시작 정합을 먼저 설계해야 한다. 현행 v6 필드로 증명할 수 없으면 새 형식/호스트 원장 ADR을 승인받기 전 출시를 막으며 Origin 문자열이나 최초 실행 preference로 추측하지 않는다. 롤백 호환 빌드도 동일한 legacy 중단 정책을 유지해야 한다.

`Origin = new-prototype`/`migrated-v5` 문자열만으로 테스트 저장 여부를 판정할 수 없다. 저장 디렉터리·호스트 실행 프로필·검증된 계정 파일을 기준으로 개발 경로와 제품 경로를 분리하며, 출처 불명 v6은 임의 수입하지 않는다. 기존 v6 호환 예외는 기존 사용자 진행을 지키기 위한 경계이고, 신규 정식 기본값 r8 결정을 뒤집지 않는다.

## 4. 기존 자동 장원 → r8 전환의 불변량

- 변환 직전 지갑, 가신 레벨/승급/조각/해금/편성, 챕터, 완료 도전·해금 콘텐츠·메트릭, 판/받기 순번·완료 판 수, pending claim, 보상 영수증, 결과 보상 기준을 그대로 복사한다. 변환 보상을 새로 지급하지 않는다.
- 대장간·기록소·곡물창고·병영은 종류 ID로 대응한다. 기존 완료 레벨을 r8 시각 최대레벨 안에서 표시하고 비용·시간을 다시 청구하지 않는다. **ManorLevels 원본은 절대로 L3으로 잘라 저장하지 않는다.** 높은 기존 효과와 업적을 보존한다. 나머지 시설은 r8 초기 상태이며 임의 완공·구역 개방 없음.
- 자동 장원에는 진행 중 공사/예약이 없으므로 미완료 공사 시간을 만들어 환급하지 않는다. 기존 v6의 공사·예약·구역 준비는 이 전환 대상이 아니며 원래 설정에 고정한다.
- legacy 우선 깃발은 저장에 남기되 자동 성장/자동 지출은 정지한다. 새 공사의 자동 착공은 동의 전 꺼짐이다. 완공을 기다리지 않고 두 번째 출정을 할 수 있다.
- 전환 시각에 구형 방치의 검증된 구간을 마지막으로 정산하고, pending claim과 나머지를 보존한다. 그 뒤 **새 구형 방치 적립은 중단하고 지도 생산만 진행**하는 것을 권고한다. 기존 pending claim은 동일 순번으로 한 번 받을 수 있다. 이전 구간을 지도 생산에 다시 소급하지 않는다. 잔여 구형 나머지는 소급 현금화하지 않고 보존한다. 향후 보상 정책 승인 없이 지도 나머지에 합치지 않는다.
- 지도 시계는 첫 관측을 기준으로 잡는다. 두 시계 역행·불일치 처리, 생산/재고 상한, 공사 순서를 유지한다. 구형 방치 정책 변경은 [ADR0071](../../adr/0071-account-estate-state-and-save-version-six.md)의 미정 병행 생산 부분을 명시적으로 대체하는 **승인 대기 제안**이다.

### 기존 효과와 새 건설 효과의 경계

기존 `ManorLevels`는 가신 레벨상한·슬롯·연구·방치 효과를 정한다. r8 시각 L1~L3과 기존 효과 레벨은 같지 않다. 변환 순간의 효과 계산값·가신 칸수·레벨상한을 그대로 유지하고 이미 완료한 건물의 효과를 다시 더하지 않는다.

[권고] 후속 효과 정책은 ID별 데이터 표로 `max(보존된 기존 효과, 승인된 지도 성장 효과)`를 계산하며 합산하지 않는다. 저장 v6의 `ManorLevels`를 호환 효과 장부로 사용하되, 지도 원본 레벨과 혼동하지 않는다. 신규 효과를 승인할 때만 단조롭게 올리고, 변환 자체로 기존 효과가 오르거나 내리지 않게 imported 완료 단계의 기준을 정의해야 한다. 가신의 기존 슬롯식·레벨상한식·능력별 판 안 cap은 변경하지 않는다.

**출시 차단 조건:** 현재 3단계 지도와 기존 효과 레벨의 대응표, imported 완료 단계의 기준, 신규·이관 계정의 동등한 장기 성장 경로는 아직 승인된 수치가 없다. 이 PR은 임의 3→10 환산/추가 효과를 만들지 않는다. 대응표와 보존 증거가 승인되기 전에는 정식 전환을 켜지 않는다. 이를 우회해 신규 가신 성장이 멈추거나 기존 슬롯이 줄어드는 구현을 내보내지 않는다. 필요 필드가 현행 v6에 없다고 판명되면 필드 추가를 숨기지 말고 별도 새 저장 버전 ADR을 먼저 제출한다.

## 5. 호스트 트랜잭션과 장애 복구

제안 순서(아직 구현 안 됨):

1. 한 계정에 단일 writer를 잡고 판/카드/정산 중 전환을 막는다. `terminal.bin`의 기존 exactly-once 복구를 먼저 완료한다. pending 판은 기존 정책대로 정산/포기 처리하며 전환을 위해 보상 사실을 새로 만들지 않는다.
2. 구형 규칙의 마지막 방치 정산을 한 번 반영한 v5 체크포인트를 먼저 `Publish`한다. 정산 전에 찍은 복사본만으로 이후 재시도해 중복 지급하지 않는다.
3. 전환 직전의 검증된 progress와 그에 대응하는 terminal 기록을 별도 불변 복구 사본으로 내구 저장한다. 일반 `.bak`은 다음 저장 때 교체되므로 전환 원본의 대체물이 아니다. 사본 쓰기 실패면 원본을 건드리지 않고 중단한다.
4. 동일 r8 설정을 고정한 메모리 사본에서 `Migrate`를 호출한다. v6 encode→decode→계정/영지 검증, 전후 보존 필드 비교를 통과시킨다. ConfigVersion/설정 출처 hash·전환 전후 save hash는 호스트 진단 기록에 두며 Core에 시각/파일 I/O를 넣지 않는다.
5. 기존 원자 저장 경로로 v6 후보를 커밋하고 다시 읽어 검증한다. 커밋 성공 전까지 지도 명령·새 판 출정을 허용하지 않는다. 성공 후에만 지도 라우트를 연다. `Estate != null`과 ConfigVersion이 재실행 방지 정본이며 별도 UI flag만으로 성공을 판정하지 않는다.
6. 종료/실패 재시작 시 유효 v6면 그대로 재개, 유효 v5면 단계를 재시도한다. 미완료 임시 파일은 성공으로 보지 않는다. 원본/백업이 충돌·손상되면 현재 복구 규칙대로 중단하며 새 계정을 만들지 않는다. terminal 순번이 앞서 있으면 이를 지우거나 낡은 progress로 롤백해 우회하지 않는다.

복구 사본·진단 파일은 호스트 로컬 운영 자료다. 신규 Release 증거 ZIP/CRC/영수증 패키지를 만들라는 요구가 아니다.

## 7. 롤백

- **아직 v6 커밋 전:** v5 정산 체크포인트를 계속 쓴다. 지도 라우트만 끄며 이미 한 번 정산된 보상을 되감지 않는다.
- **v6 커밋 후, 지도 표시 문제:** v6을 읽을 수 있는 호환 패치로 지도 표시만 이전 메뉴/안전한 읽기 화면으로 전환한다. `Estate`와 최신 지갑·받기·재고·공사·가신·판 진행을 보존하고 자동 장원 성장은 재개하지 않는다. UI 롤백이 생산기를 둘로 만들면 안 된다.
- **변환 직후 데이터 결함:** 전환 후 어떤 판/공사/받기/강화/시간 생산도 커밋되지 않았고 최신 hash가 최초 v6 후보와 같을 때에만 검증된 변환 직전 사본 복원을 검토할 수 있다. 복원은 지원 도구의 명시적 절차이며 앱 자동 로딩 경로가 아니다. 원본과 실패 후보를 모두 보존한다.
- **이미 새 진행이 있음:** 구형 사본 복구는 새로 얻은 자재·조각·해금·건설을 잃으므로 금지한다. 최신 v6을 보존하는 수정 패치/전진 복구를 한다. 범용 v6→v5 역변환은 제공하지 않는다.
- **옛 앱 바이너리 다운그레이드:** v6 미지원 앱은 unsupported-version으로 쓰기 중단해야 한다. 낡은 `.bak`을 읽어 새 진행 위에 쓰지 않는다. 되돌릴 호환 빌드의 v6 읽기·효과·단일 생산 경계가 확보되지 않으면 바이너리 롤백 대신 기능을 잠그고 전진 수정한다.

## 8. 구현 승인·전달 관문

아래는 향후 실행할 검사이며 이번 문서 PR의 통과 실험이 아니다.

1. **저장 행렬:** v1~5 각각, 높은/낮은 장원 레벨, 0/상한 지갑, 가신·조각·미수령 도전/방치·보상 영수증, pending/terminal 복구 표본에서 보존량과 exactly-once를 비교한다. 시제품 초기 지갑 덮어쓰기 0건.
2. **실패 주입:** 사본 쓰기/정산 publish/후보검증/원자 replace/재읽기 전후에서 종료·디스크 실패를 넣는다. 재시도는 동일 상태이며 중복 지급·초기화·이중 변환 0건. 미래버전/설정불일치/손상백업은 fail-closed.
3. **시간·생산:** 전환 경계에서 legacy의 마지막 인정 구간과 지도의 첫 관측이 겹치지 않음. 기존 pending claim과 지도 claim 독립 exactly-once. clock 역행·부팅 기준변화·장기 방치에서도 기존 방어 유지.
4. **효과:** 모든 이관 장원 레벨의 슬롯/가신상한/연구가 변환 전후 동일. 새 건설의 승인 효과표·cap·단일 투영을 확인하고 신규/이관 장기 진행의 막힘을 비교한다. 미승인 대응표로 출시는 금지.
5. **기존 v6:** r2~r7 샘플은 자기 설정의 지도·좌표·공사·재고로 재개. 비저장 개발 사본은 제품으로 수입되지 않음. r8 계정은 반복 접속/이관 시 초기화 없음.
6. **롤백:** 새 진행 없는 전환 실패와 새 진행 있는 UI 롤백을 분리한다. 후자의 최신 지갑·조각·공사·순번 손실 0, legacy 생산/자동 성장 재개 0을 증명한다.
7. **화면:** 정식 빌드 신규 첫 타이틀→첫 판→귀환 지도→비용 확인/착공/닫기→재출정, 기존 계정 전환 후 지도, 재시작 공사 유지. 개발 표시 없음·48pt 터치·승인 r8 배율을 실제 게임 화면으로 점검한다. 10분 완주나 게임 재미는 정적 검사로 대체하지 않는다.

이 문서가 승인돼도 경제 가설·효과 대응표·실제 저장 전환 검증까지 완료된 것은 아니다. 코드 구현 PR은 사용자 결정을 참조하고 위 관문 결과를 별도로 보고한다.
