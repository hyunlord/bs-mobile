# 06 손맛·연출

버전: v1.1 · 날짜: 2026-10-12 · 바뀐 점: wave 사건 연결의 공백, 치명타 신호 부재, M1 비교와 검증 경계를 명시했다.
상태: 정본(현재 상태·사용자 승인 방향); M1-1 수치는 [가설], 적용·영상 판정은 미완료.

## 목적과 판정

2026-10-12 승인 기둥은 타격감, 캐릭터·무기별 몸동작, 시도하고 싶은 무기·진화 규모다. 영지가 힘이 된다는 재미는 아직 가설이며 M1 실험으로 판정한다. 손맛을 먼저 갖춰 영지 도구 A/B/C 실험을 공정하게 한다. 이 문서는 구현 완료 보고가 아니다.

관문 질문은 **“소리를 끄고 봐도 맞았다는 게 느껴지나”**다. 같은 seed의 현재/적용 후 30초 영상 두 개를 앱 내부 캡처로 만든다. OS 화면 녹화 권한을 요구하지 않는다. 효과를 켠 C05 800+의 25ms 초과 비율이 기준보다 나빠지지 않아야 한다. #223 야간 원인 측정은 별도로 유지한다.

## 타격감 기준표 v1

아래는 사용자 승인된 구현 방향이고 시간·픽셀·개수는 모두 **[가설]**이다. 화면만 바꾸고 Core 규칙·입력·역사 리플레이 해시를 바꾸지 않는다.

| 등급 | 화면 | 소리·진동 | 금지/경계 |
|---|---|---|---|
| 일반 타격 | 맞은 적만 흰 번쩍임 60ms, 그림만 뒤로 2–3px/80ms, 작은 파편 3–5개 | 음높이 ±5% 변주 | 실제 위치/판정 반경은 그대로 |
| 치명타·처치 | 치명타 숫자는 크게 다른 색; 처치 조각·먼지와 경험치 보석 튀어나옴 | 처치음 별도 | 치명타 규칙을 새로 만들지 않고 실제 사건만 표현 |
| 큰 기술·진화 | 0.05초 이하 흔들림과 큰 이펙트 | 짧은 진동, 최소 간격 보존 | 소리·진동·흔들림 끄기를 존중 |
| 보스 타격·처치 | 보스 타격만 전체 히트스톱 40–80ms; 처치 슬로 0.3초 | 보스 판독 우선 | Core 시각이나 명령을 바꾸지 않는 표시 연출. 처리 방식은 구현 검토 필요 |

현재 Core의 wave 사건에는 치명타 여부 신호가 없다. 피해량이 크거나 임의 확률이라는 이유로 치명타를 만들어 표시하지 않는다. 치명타 숫자 스타일은 정본 사건 신호를 별도로 승인·구현하기 전까지 [보류]다. 일반 타격·처치 작업은 이 결정 때문에 멈추지 않는다.

일반 적 처치에는 전체 히트스톱을 쓰지 않는다. 같은 적의 짧은 시간 피해는 합산하고 동시 숫자 수를 제한한다. 합산 창·파편 풀 상한·큰 기술 분류·픽셀 기준 해상도는 [미정]이며 구현 때 명시한다. 모두 풀에서 꺼내 쓰며 매 프레임 임시 할당을 추가하지 않는다. 실제 밀려남은 무기 데이터 속성으로 별도 결정한다. 새 손맛 표현의 기본값은 ON이고 소리·진동·흔들림·피해 숫자 끄기는 유지한다.

## 모순·역사와 현재 기본값

[ADR0050](../../adr/0050-opt-in-movement-and-hit-feel.md)의 “모두 기본 OFF·B는 기본 A를 교체하지 않음”은 초기 실험 기록이다. 현재 [RunPreferences](../../../unity/Assets/Game/App/RunPreferences.cs)는 설정 버전1 최초 적용 때 빠른 걸음과 영주 피격 표현을 ON, 접촉/체력 실험은 OFF로 저장하며 B 기본 선택은 ON이다. 기존 사용자가 이후 끈 값은 버전이 같으면 보존한다. M1 의뢰의 “ADR0050 기본 OFF”를 현재 코드 사실로 반복하지 않는다.

“적을 때릴 때의 반응 없음”도 문자 그대로의 구현 부재와 다르다. 90ms 대상 flash와 hit 소리는 있지만 사용자에게 충분히 읽히지 않았으며 새 기준표는 그 부족을 해결한다. 설정의 흔들림 ON과 실제 흔들림 0 역시 구분한다. 현재 기본값을 이 문서 작업에서 변경하지 않는다.

[부드러움·표시 계약 ADR0048](../../adr/0048-continuous-presentation-and-live-capture.md), [아트·캐릭터](07-art-character.md), [소리](08-audio.md)를 함께 갱신한다. #126·#98·1b·#224는 계속 보류한다.

## M1-1 적용·증거 경계

[#246](https://github.com/hyunlord/bs-mobile/issues/246)에서 표현 계층을 구현 중이다. 기존 wave hit/death 사건을 화면으로 연결하며, 대상 ID·실제 피해량·사망 사건만 소비한다. 사건에 실제 공격 시작점이 없으면 영주에서 적으로 향하는 표시용 반동 방향을 쓰고, 이를 실제 무기 밀려남이라고 부르지 않는다. Core 좌표·충돌·RNG·시간·리플레이 명령은 그대로다. 보스 히트스톱과 슬로 역시 표시 시간에만 적용하며 `Time.timeScale`이나 Core 틱을 늦추지 않는다.

`--autoplay-capture --impact-comparison baseline|applied`는 별도 저장 경로에서 판의 60–90초(30게임초)를 앱 내부로 녹화한다. 0초부터 정상 속도·같은 입력으로 진행하며 앞부분을 건너뛰거나 사건을 부여하지 않는다. seed 30000의 기존 5초 방향 전환 입력과 실제 카드 선택 코드를 Core로 검사했을 때 0–30초는 타격 1회·처치 0회, 60–90초는 타격 37회·처치 16회였으므로 반복 타격·처치를 볼 수 있는 뒤 구간을 선택했다. 이는 사건 수 사전 검사이며 실제 영상 판독 증거가 아니다. 최초 0–30초 캡처 실패는 보존한다. 두 실행은 같은 seed와 틱 기준 입력 경로를 사용하며, 실제 기록된 명령과 상태 해시가 같음을 확인한 뒤에만 같은 입력 비교라고 보고한다. 카드 선택 중 정지는 실제 영상 길이를 늘릴 수 있다. `--feel-comparison rules-off/rules-on`은 규칙이 달라지므로 이 관문에 쓰지 않는다. 녹화는 실제 혼합 오디오를 포함하며, 캡처를 켠 프레임 비용을 C05 성능 증거로 쓰지 않는다.

아직 실제 전후 영상·사용자 손맛 판정·효과 ON의 C05 800+ 비용은 확인하지 않았다. 풀 상한과 합산 창은 구현 확정값을 기록하되, 구현 존재를 군중 비용 통과로 바꾸어 쓰지 않는다. 도전의 실제 청구 가능한 `받기`에는 금빛 테두리를 추가하고, 지급 후와 잠긴 상태에는 붙이지 않는다. 보상·저장 규칙은 바꾸지 않는다.

### #246 표현 구현값 (영상·군중 비용 검증 전)

다음은 구현 담당이 확인한 코드값이며 모두 가설 튜닝값이다. 실제 전후 영상·비용 통과를 의미하지 않는다.

| 항목 | 구현값·상한 | 경계 |
|---|---|---|
| 대상 번쩍임·반동 | 60ms; 실제 화면 2.5px, 80ms 동안 감쇠 | baseline은 역사 90ms flash. 반동은 그림만, 표시 중인 영주 반대 방향 |
| 파편 | 고정 1,024개 풀; 일반 3–5개, 160ms | 풀이 차면 새 파편을 버리고 카운터 기록 |
| 처치 | 파편 + 먼지 320ms + 경험치 pop 420ms | 경험치 Amount가 양수인 처치만 보석 pop |
| 피해 숫자 | 64개 논리 숫자, 슬롯당 사전 생성 TextMesh 최대 5개, 같은 적 120ms 합산 | 첫 표시 기준 창, 합산으로 수명 연장 안 함. 큰 수는 미리 만든 4자리 문자열 조각으로 정확히 표시; long 합산 초과는 별도 숫자로 보존 |
| 큰 기술·진화 | 45ms 흔들림, 축당 최대 2px | 흔들림 끄기 존중; 일반 처치에는 적용하지 않음 |
| 보스 | 표시 정지 60ms, 재요청 간격 180ms; 처치 300ms 동안 표시 속도 0.25배 | 32개 재사용 표시 스냅샷, 세계·효과·소리만 지연. Core·HUD는 실제 시점 유지. 회복 속도 1.75배. 영상 검증 대기 |

기본 `ImpactFeedbackEnabled=true`. 비교 baseline에서는 새 파편·반동·흔들림을 끄지만 역사 flash와 원래 규칙을 유지한다. 보스 정지/슬로가 Core를 늦추거나 공유 스냅샷을 보관하는 방식으로 구현되어서는 안 된다.

치명타 판정 신호가 없는 문제는 [#247](https://github.com/hyunlord/bs-mobile/issues/247)에 분리했다. 피해량으로 치명타를 추측하거나 새 치명타 규칙을 만들지 않는다. Unity 집중 검사 38건과 PlayMode 7건은 통과했으며 실제 영상·성능 관문을 대신하지 않는다.
