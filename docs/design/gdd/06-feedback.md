## 목적과 판정

2026-10-12 승인 기둥은 타격감, 캐릭터·무기별 몸동작, 시도하고 싶은 무기·진화 규모다. 영지가 힘이 된다는 재미는 아직 가설이며 M1 실험으로 판정한다. 손맛을 먼저 갖춰 영지 도구 A/B/C 실험을 공정하게 한다. 이 문서는 구현 완료 보고가 아니다.

관문 질문은 **“소리를 끄고 봐도 맞았다는 게 느껴지나”**다. 현재 제출은 위 M1-3 무기별 영상이며 아래 M1-2의 **1.4배·오프라인 고정60fps·소리 포함** 계약·결과는 역사 기록이다. VFR 실패도 보존한다. OS 화면 녹화 권한을 요구하지 않는다. 효과 ON의 C05 800+ >25ms 비율 비악화와 #223 야간 원인 측정은 별도로 유지한다.

## M1-2 배율 선택 후 계약 · 2026-10-12

사용자는 카메라 **1.4배**를 선택하고 A 기사 실시간 뼈대와 손맛 재촬영 진행을 승인했다. A 기사의 실제 구현·동작 증거는 [07](07-art-character.md)에 기록하며, 이번 승인을 완성 판정으로 쓰지 않는다.

손맛 전후는 **같은 입력·같은 장면·같은 시점**, 선택된 1.4배로 오프라인 고정 60fps를 렌더하고 실제 게임 소리 트랙을 포함한다. 나란히 전후 영상과 영웅 주변 2배 확대본을 제출한다. 프레임 수·시점·오디오 동기 검증이 필요하며, 무음 모션 영상이나 VFR 실패 표본으로 대체하지 않는다. 오프라인 렌더 비용은 실시간 성능 증거가 아니다. 이전 `7bc241f` 배율 비교와 #246의 실패·성공 표본은 역사 기록으로 유지한다.

### 실제 피해 귀속과 경고의 인과 경계

`7bc241f`의 화면 밖 진입 지표는 공격 거리 진입 대리 지표였고 실제 피해 사건은 0건이었다. **새 지표는 피해가 실제 발생한 사건과 안정 공격자 개체 ID를 연결**해야 한다. 적 정의 ID나 근처 적 추정으로 공격자를 채우지 않는다. 화면 밖→안 이력과 실제 피해 시점을 연결해 진입 1초 이내 피해의 분자·분모 및 이력 미확인 건수를 보고한다. 분모 0·귀속 불가이면 미확인으로 남기고 0%로 쓰지 않는다.

가장자리 화살표 최대 [가설: 6개]·돌진 예고 [가설: 0.5초]는 **표시만** 보완한다. 같은 입력에서 경고 ON/OFF는 Core 명령·피해·해시를 바꾸지 않아야 하므로, 같은 재생에서 피해 감소를 만들어 경고 효과로 보고하면 안 된다. 실제 회피 개선은 경고를 보고 달라진 플레이 입력의 별도 관찰이 있어야 판단할 수 있다. 적 수·피해량·공격 거리·Core 공격 준비 시간을 조정하지 않는다.

#223의 **10/13 01:00–06:00** 야간 측정과 사용자 전원 연결·방해 금지 준비는 유지한다. #126·#98·1b·#224 보류와 광고·결제·분석 SDK 미도입도 그대로다.

일반 적 처치에는 전체 히트스톱을 쓰지 않는다. 같은 적의 짧은 시간 피해는 합산하고 동시 숫자 수를 제한한다. 합산 창·파편 풀 상한·픽셀 기준은 아래 구현값에 명시하며 영상으로 조정할 [가설]이다. 모두 풀에서 꺼내 쓰며 매 프레임 임시 할당을 추가하지 않는다. 실제 밀려남은 무기 데이터 속성으로 별도 결정한다. 새 손맛 표현의 기본값은 ON이고 소리·진동·흔들림·피해 숫자 끄기는 유지한다.

## 모순·역사와 현재 기본값

[ADR0050](../../adr/0050-opt-in-movement-and-hit-feel.md)의 “모두 기본 OFF·B는 기본 A를 교체하지 않음”은 초기 실험 기록이다. 현재 [RunPreferences](../../../unity/Assets/Game/App/RunPreferences.cs)는 설정 버전1 최초 적용 때 빠른 걸음과 영주 피격 표현을 ON, 접촉/체력 실험은 OFF로 저장하며 B 기본 선택은 ON이다. 기존 사용자가 이후 끈 값은 버전이 같으면 보존한다. M1 의뢰의 “ADR0050 기본 OFF”를 현재 코드 사실로 반복하지 않는다.

“적을 때릴 때의 반응 없음”도 문자 그대로의 구현 부재와 다르다. 90ms 대상 flash와 hit 소리는 있지만 사용자에게 충분히 읽히지 않았으며 새 기준표는 그 부족을 해결한다. 적용 전에는 설정의 흔들림 ON과 실제 흔들림 0이 달랐다. #246은 큰 기술·진화 사건에만 짧은 흔들림을 연결하며 일반 피격의 전역 흔들림은 추가하지 않는다.

[부드러움·표시 계약 ADR0048](../../adr/0048-continuous-presentation-and-live-capture.md), [아트·캐릭터](07-art-character.md), [소리](08-audio.md)를 함께 갱신한다. #126·#98·1b·#224는 계속 보류한다.

## M1-1 적용·증거 경계

[#246](https://github.com/hyunlord/bs-mobile/issues/246)에서 표현 계층을 구현 중이다. 기존 wave hit/death 사건을 화면으로 연결하며, 대상 ID·실제 피해량·사망 사건만 소비한다. 사건에 실제 공격 시작점이 없으면 영주에서 적으로 향하는 표시용 반동 방향을 쓰고, 이를 실제 무기 밀려남이라고 부르지 않는다. Core 좌표·충돌·RNG·시간·리플레이 명령은 그대로다. 보스 히트스톱과 슬로 역시 표시 시간에만 적용하며 `Time.timeScale`이나 Core 틱을 늦추지 않는다.

`--autoplay-capture --impact-comparison baseline|applied`는 별도 저장 경로에서 판의 60–90초(30게임초)를 앱 내부로 녹화한다. 0초부터 정상 속도·같은 입력으로 진행하며 앞부분을 건너뛰거나 사건을 부여하지 않는다. seed 30000의 기존 5초 방향 전환 입력과 실제 카드 선택 코드를 Core로 검사했을 때 0–30초는 타격 1회·처치 0회, 60–90초는 타격 37회·처치 16회였으므로 반복 타격·처치를 볼 수 있는 뒤 구간을 선택했다. 이는 사건 수 사전 검사이며 실제 영상 판독 증거가 아니다. 최초 0–30초 캡처 실패는 보존한다. 두 실행은 같은 seed와 틱 기준 입력 경로를 사용하며, 실제 기록된 명령과 상태 해시가 같음을 확인한 뒤에만 같은 입력 비교라고 보고한다. 카드 선택 중 정지는 실제 영상 길이를 늘릴 수 있다. `--feel-comparison rules-off/rules-on`은 규칙이 달라지므로 이 관문에 쓰지 않는다. 녹화는 실제 혼합 오디오를 포함하며, 캡처를 켠 프레임 비용을 C05 성능 증거로 쓰지 않는다.

실제 전후 영상은 아래의 60Hz 실패 표본으로 확보했다. C05 800+의 같은 빌드 ON/OFF와 M1 이전 빌드 비교에서는 각각 25ms 초과 비율이 모두 0%였다. 실행당 한 번의 제한된 관찰이며 사용자 손맛 판정은 아직 미완료다. 풀 상한과 합산 창은 구현 확정값을 기록하되, 구현 존재를 군중 비용 통과로 바꾸어 쓰지 않는다. 도전의 실제 청구 가능한 `받기`에는 금빛 테두리를 추가하고, 지급 후와 잠긴 상태에는 붙이지 않는다. 보상·저장 규칙은 바꾸지 않는다.

### 공격 상체 동작 (설계 · 구현 전, 2026-10-16)

목표는 무기가 공격할 때마다 영웅 몸이 그 무기를 쓰는 동작을 짧게 보이는 것이다. 그림(동작 프레임)은 Astra가 시험 중이고, 코드는 그림 판정 뒤에 만든다. 아래는 코드 쪽 설계다.

**경계**

- View 전용이다. Core 판정·피해·타이밍·재생 해시는 바꾸지 않는다.
- View는 Core가 이미 내보내는 공격 사건을 받아 동작을 고른다. 동작은 피해가 나는 시점을 미루거나 앞당기지 않는다.
- 하체는 걷기 자세를 그대로 둔다. 기사 리그는 이미 엉덩이·무릎 관절을 걷기 프레임에서 가져오고 나머지 관절만 동작 클립으로 덮어쓴다(`HeroLiveRig.Present`의 `lowerBody`). 새 동작도 같은 길로 상체만 덮어쓴다.
- 영웅 피격 동작(`hit`)이 공격 동작보다 앞선다(지금과 같음).

**동작 5종**

| 동작 | 길이 | 모양(그림 판정 대상) |
|---|---|---|
| 베기 | 0.26초 | 들었다가 가로로 휘두름. 철날 검과 장창이 함께 쓴다(장창은 앞으로 내지르는 마지막 프레임만 다르게 할지 그림 판정에서 정함) |
| 쏘기 | 0.22초 | 앞쪽 팔을 뻗고 뒤쪽 팔을 당겼다 놓음 |
| 시전 | 0.28초 | 한 팔을 머리 위로 들었다 내림 |
| 불기 | 0.30초 | 뿔나팔을 입으로 올렸다 내림 |
| 던지기 | 0.24초 | 몸 앞에서 바깥으로 팔을 뻗음 |

길이는 0.2~0.3초 안에서 정했고, 그림이 들어오면 프레임 수에 맞춰 조정한다. 기존 `swing`(0.36초)·`evolved-swing`(0.48초)은 이 범위보다 길어, 베기에 쓰려면 다시 맞춰야 한다.

|---|---|---|---|

`review-impact-tell`·`chain-link`·`hit`는 한 번의 공격에 여러 개가 같은 틱에 온다. 선택기는 (출처, 틱)마다 처음 것 하나만 받는다.

**우선순위와 간격**

1. 같은 틱에 여러 무기가 공격하면 하나만 고른다. 진화한 무기가 먼저이고, 그다음은 피해량이 큰 무기다. 피해량은 그 장비의 Core 데이터 `Damage`(장비 1회 피해)를 읽기만 한다. 같으면 장비 id 순서로 정해 재생마다 같은 결과가 나오게 한다.
2. 같은 동작은 시작 사이를 최소 0.4초 둔다. 0.4초 안에 같은 동작이 다시 오면 버린다(쌓아 두지 않는다).
3. 동작 중에 더 높은 우선순위의 공격이 오면 그 동작으로 바꿔 처음부터 시작한다. 같거나 낮으면 버린다. 바뀐 동작도 2번 간격 규칙을 따른다.
4. 영웅 피격이 오면 피격 동작이 공격 동작을 덮는다. 피격이 끝나면 남은 공격 동작은 다시 잇지 않는다.

**구현 구조(그림 판정 뒤)**

- `HeroActionSelector`(View, 순수 클래스, EditMode 테스트 대상)를 둔다.
  - 입력: `Offer(tick, source, kind, evolved, damage, time)`
  - 출력: `Current(time)` → (동작, 진행 0~1) 또는 없음
  - 상태: 현재 동작·시작 시각·우선순위, 동작별 마지막 시작 시각
- `WorldWave`의 사건 루프(지금 `heroAttackUntil`을 갱신하는 자리)에서 위 매핑표의 사건을 `Offer`로 넘긴다.
- `HeroLiveRig.Present`가 동작 id와 진행을 받아 해당 클립의 상체 관절만 덮어쓴다(클립은 `motion-runtime.json`에 동작별로 추가).
