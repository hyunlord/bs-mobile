## 지급과 저장의 불변 조건

판 결과에서 남은 성장물·사람·수확·레벨·보스 결과를 정해진 원천으로 환산한다. 식량 재고 자체는 점수가 아니다. 최소 시간, 결과·반복 배율, 판당·지갑 상한을 적용하고 같은 판은 한 번만 정산한다. 결산에는 요청량이 아니라 실제 지급량과 상한을 보여 준다.

클리어 조각은 조건을 충족한 기존 규칙의 실제 지급이 있을 때만 표시한다. 죽음·포기·최소 시간 미달에 무조건 `+2`를 그리지 않는다. 미정 결산 광고 배율·상한은 [n]이며 보류 상태에서 생산 지급을 열지 않는다.

**장원과 계정 영지.** 영지가 없는 계정(지금 모든 실제 계정)의 장원은 자재로 자동 성장하며 플레이어는 우선 깃발 하나를 고른다. 대장간·기록소·곡물창고·병영은 각각 강화 상한·도전 연구·방치 상한·편성 슬롯에 관계한다. 가신 역할의 다음 방향은 M1 영지 실험 뒤 결정한다. 현재 계정 데이터와 저장을 문서 정리 때문에 초기화하지 않는다.

도전·방치의 명시적 받기는 pending claim과 완료 원장으로 정확히 한 번 처리한다. 구형 자동 지급 기록을 새 받기 대상으로 되살리지 않는다. 결산 도중 앱 종료도 정산 저널의 완료 여부로 복구하며 같은 판 보상을 다시 주지 않는다. 시계 역행·불일치의 처리와 손상 백업·미래 저장 버전 보호를 유지한다. 파일 체크섬은 결제 보안이나 서버 권위가 아니다.

**계정 영지 Core 구현 상태(1.1, M3a-1, 화면 없음).** 설계는 [M3 계정 영지](https://github.com/hyunlord/bs-mobile/pull/360) 6절(열린 설계 PR)이다. 모든 수치는 opt-in 시제품 설정 `m3a-prototype-r2`의 [가설]이며 #126 전에는 출시 기본값이 아니다.

- 계정 상태에 선택 필드 `Estate`가 생겼다. 영지가 있는 계정만 저장 버전 6으로 쓴다. 영지가 없는 계정은 버전 5 바이트 그대로다.
- 영지가 있는 계정에서는 자동 장원 성장이 돌지 않는다. 대신 명시적 공사(동시 1건, 예약 2건, 자동 착공은 기본 꺼짐)로만 자라고, 생산 터가 시간에 따라 재고를 쌓는다.
- 공사·생산 시간은 방치 보상과 같은 시계 방어를 거친 구간만 인정한다. 첫 관측은 기준만 잡고, 시계 역행이나 차이가 크면 0초다.
- 받기는 영지 지갑 상한까지만 옮긴다. 생산 재고·보관 시간 상한이 있고, 같은 받기·과제 보상은 한 번만 준다.
- 첫 생산 경로(곡창·대장간·생산 터 3곳)의 착공비는 보호 예약으로 남긴다. 다른 공사로 그 경로가 막히지 않는다.
- 2A 이관: 진행 중 판을 구형 규칙으로 먼저 정산한 계정만 이관한다. 네 장원 레벨을 비용 없이 완성 건물로 옮기고(시제품 최고 L3), 지갑·받기·영수증·방치 나머지는 그대로 둔다. 자동 착공은 동의를 기다린다. 구형 장원 레벨은 남아 기존 효과(가신 상한·슬롯·연구·방치 상한)를 계속 정한다.
- M3a-2 화면 시제품(1.2, [#366](https://github.com/hyunlord/bs-mobile/issues/366)): 개발 빌드의 설정 "영지 지도 시제품 (개발)"을 켜면 영지 탭이 장원 화면 대신 격자 지도를 연다. 출시 빌드에는 옵션이 없고 늘 장원 화면이다. 지도는 계정 상태의 메모리 사본(영지가 없으면 현재 장원을 2A 이관한 사본)에서만 움직이고 저장하지 않는다. 이동 미리보기와 확정은 Core `AccountEstate.Move`가 마지막 관측 시각에서 판정해 시간을 인정하지 않는다. 그림은 기존 장원 건물 4장과 단색 판이다(Astra 영지 그림 승인 전 임시). 화면 규칙은 [05](05-screen-ux.md)에 있다.
- M3a-4 흐름 시제품(1.3, [#370](https://github.com/hyunlord/bs-mobile/issues/370)): 지도에서 공사 시작·예약·예약 취소·예약 시작·자동 착공, 생산 재고 받기, 생활 과제 보상 받기, 최고 레벨 건물의 전문화, 구역 개방을 Core 명령으로 실행한다.
  - 영지가 없는 계정은 이제 장원 이관 사본 대신 새 시제품 영지(집·폐허 터·시작 지갑 곡물120·목재180·철재60 [가설])로 시작한다. 장원 이관 사본은 지갑이 비어 공사를 보여 줄 수 없었기 때문이다. 영지가 저장된 계정은 그 영지의 사본을 쓴다.
  - 사본의 시계는 실제 시간을 따르고, 개발용 +1분·+10분 건너뛰기가 있다. Core가 구간을 검증하고 상한을 적용한다. 세션 동안 유지되며 저장하지 않는다.
- 넓은 지도(1.4, [#374](https://github.com/hyunlord/bs-mobile/issues/374)): 화면 시제품은 `m3a-prototype-r3`을 쓴다. r2 경제 값은 그대로이고 지도만 설계 r3(중심 + 안쪽 고리 4구역)이다. 버전 이름은 opt-in 스키마의 `m3a-prototype-r<숫자>` 형식을 따른다.
  - r2 경제(지갑·공사·생산·보관·과제·보호 경로)는 바이트 단위로 같고, 격자만 설계 r3의 중심 + 안쪽 고리 4구역으로 넓혔다. 중심은 20×20이고, r2 배치를 (+26,+26) 옮겨 둔다. 고리 구역도 각 20×20이다.
  - 마을 확장 구역만 r2 인접 구역 조건(생산 터 2곳·목재 60·30초)으로 열린다.
  - 강가·서쪽 언덕·북동 숲은 탐사전(M3c)으로 열 땅이다. Core 설정 검증이 닫힌 구역마다 개방 조건을 요구하므로, 이 시제품에서 도달할 수 없는 "생산 터 4곳"(생산 종류는 3)을 자리표시로 둔다. 화면에는 "탐사로 열 땅 · M3c"로 보인다. Core 규칙은 바꾸지 않았다.
- 시작 땅 축소(1.6, [#379](https://github.com/hyunlord/bs-mobile/issues/379)): 화면 시제품은 `m3a-prototype-r5`를 쓴다. r4에서 열린 시작 땅만 (23,23)의 14×14로 줄였다. r2 건물 배치(26~34)는 그대로다. 옛 20×20 중심의 나머지는 "마을 둘레" 4구역이고, r2 조건(생산 터 2곳·목재 60·30초)으로 열린다. 마을 확장은 둘레를 연 뒤에 맞닿는다. 열린 땅(폭 28)이 영지 폭(40)보다 좁아, 첫 화면 "영지" 배율이 전체와 동네 사이에 온다. 경제·건물·나머지 구역은 r4와 같고, Core 테스트가 이를 확인한다.
- 세로 지도(1.5, [#375](https://github.com/hyunlord/bs-mobile/issues/375)): 화면 시제품은 `m3a-prototype-r4`를 쓴다. 경제·건물·중심 구역·마을 확장 개방 조건은 r3과 같고, 구역 배치만 다르다. r3 파일과 그 테스트는 그대로 남는다.
  - 축에 맞춘 직사각형 구역은 등각 화면에서 늘 가로 2:1 마름모다. 그래서 구역을 화면 세로(격자 u+v) 방향으로 엇갈려 쌓고, 모든 구역을 중심 구역의 폭(u−v가 −20~20) 안에 둔다. 영지 전체는 배율 1에서 1280×2048(약 1:1.6)이다.
  - 승인 키 아트 A·C처럼 위는 북동 숲(오른쪽)·서쪽 언덕(채석장, 왼쪽 위)·풍차(왼쪽), 가운데는 중심 마을, 아래는 밭(왼쪽)·마을 확장(오른쪽, 강가)·휴경·폐허·강가다. 9구역이다.
  - 마을 확장(8×12)만 중심과 맞닿고 r2 조건으로 열린다. 나머지 7구역은 r3과 같은 "생산 터 4곳" 자리표시다. 모든 구역은 맞닿음으로 중심까지 이어진다.
  - r2 파일과 Core 테스트는 그대로다.
- 아직 없는 것: 실제 계정의 이관 실행과 영지 저장(호스트), 판 연결(M3b). 판 효과 분기(검술 공방·호위 병영 등)는 이름과 [가설] 설명만 있다. 기존 방치 보상은 영지 모드에서도 그대로 돌며, 영지 생산과 함께 줄지는 정하지 않았다.

## 계정 화면과 전투력은 별개

wave 계정 화면은 `AccountOnlyWave` 경계로 원래 전투 카탈로그를 쓴다. 가신 레벨·장원 화면이 있다는 이유로 first-playable의 메타 능력 배율을 wave에 새로 투영하지 않는다. 능력 투영과1b는 보류다. 도전20개·계정 가신6명은 기존 데이터이며 설계 가신8명과 다른 집합이다.

D3의 출처별 재료·목표 도구 보장·클리어 기본 지급은 [설계 계약](../10_D3-v1.1-wave-1a-decision.md)을 따른다. 보장 도구가 없는 프로필 목표를 열지 않고 지급량은 [미정]을 유지한다. 목표 재료 기능의 존재를 전체 경제 완성으로 보고하지 않는다.

## 힘은 팔지 않는다

기존의 자재 판매 금지는 2026-10-29 r2 사용자 결정으로 대체됐다. 유료 자원·가속을 통한 가신 간접 전투력 성장은 허용하되 능력별 cap은 필수다. 가신·조각·판 안 능력 직접 판매, 에너지·확률 뽑기 금지는 유지한다. 외형·영지 테마·고정 보상 패스·광고 제거 자리는 별도로 유지하며 SDK나 실제 결제는 아직 구현하지 않는다. 광고 정책과 첫 판·첫날 숨김은 [09](09-monetization-live.md)의 소관이다.

## 남아 있는 실패와 결정

[sim-v0](../../economy/sim-v0.md)의420판·방치63행은 당시 가정과 프로필의 관측이다. 지갑·장부 보존 통과, 페이싱 실패를 함께 보존한다. 보통 계정 챕터6·10 첫 시도가 빨랐고, 목재 경쟁과 보스 미처치가 관측됐다. 하나의 봇 계정 결과를 사용자 리텐션·다수 유저 분포로 일반화하지 않는다.
