## 1. 현재 기록소와 연구 트리를 구분한다

[progression.json](../../../data/meta/progression.json)의 `meta:scriptorium`은 `ManorEffect.Research`를 주고, [MetaEngine.CompleteChallenges](../../../core/src/SowSiege.Core/MetaEngine.cs)는 이 값과 도전 메트릭을 검사한다. 현재의 Research는 선택 노드·연구 큐가 아니다. [r8 설정](../../../data/opt-in/account-estate/m3a-prototype-r8.json)에 기록소와 분기 `scriptorium:card-research`/`scriptorium:city-records`가 있어도 아래 트리가 구현됐다는 뜻은 아니다.

기존 도전 조건용 효과 장부 E와 신규 노드 완료 장부를 분리한다. #547의 기록소 L1/L2/L3→E3/E6/E10 [가설] 대응은 그대로 유지한다. E를 새 트리 완료 수로 바꾸거나 E6을 보고 노드 여섯 개를 무료 완료시키지 않는다. 새 노드 완료가 E를 올리거나 이미 받은 도전 보상을 다시 열지도 않는다. 서버 스키마·직렬화 형식은 Codex 서버 ADR이 정하며 로컬 v6 필드에 임의로 숨기지 않는다.

## 2. 첫 출시 트리 [가설]

경제·군사·영지 각 3개 노드, 노드별 최대 3단계를 권고한다. 표의 E/M/A 번호와 `slg:research-*` 이름은 **문서용 후보 ID**다. 기존 콘텐츠 ID와 혼동하지 않는다. 각 단계 k를 시작하려면 기록소 Lk, 해당 노드의 k−1 완료, 표의 선행 조건을 모두 만족해야 한다. 표의 다른 노드 선행은 명시된 L1만 요구한다. 기존 건물 완공 자체에 새 연구를 선행 조건으로 붙이지 않는다.

비용 단위는 곡물/목재/철재다. 표의 기본 비용 벡터 B와 기본 시간 T에 대해 **k단계 비용=B×k, 시간=T×k** [가설]이며, 이전 단계 비용을 다시 청구하지 않는다. 효과는 단계당 증가분을 합산한 **최종 노드 레벨 값**이다. 연구 후 자원 생산이 늘어도 이미 확정한 연구 비용을 할인·환급하지 않는다.

| 노드 후보 | 선행 건물·노드 [가설] | 기본 비용 B / 시간 T [가설] | 단계당 효과 / 노드 최대 [가설] | 필요한 전투 탐사 증명 |
|---|---|---|---|---|
| E1 `slg:research-field-yield` · 밭 순환 | 경작지 `m3a:field` L1 | 60/40/0 · 120초 | 지도 곡물 생산속도 +5% / +15% | 밭 경계 수비 |
| E2 `slg:research-wood-yield` · 목재 선별 | 벌목장 `m3a:lumber_camp` L1, E1 L1 | 80/50/10 · 180초 | 지도 목재 생산속도 +5% / +15% | 숲 작업대 구출 |
| E3 `slg:research-iron-yield` · 광석 분류 | 제철소 `m3a:ironworks` L1, E2 L1 | 100/60/20 · 240초 | 지도 철재 생산속도 +3% / +9% | 언덕 광석길 확보 |
| M1 `slg:research-training` · 훈련 교범 | 병영 `meta:barracks` L1 | 80/40/10 · 150초 | 훈련속도 +5% / +15% | 경계 초소 수비 |
| M2 `slg:research-formation` · 전열 협동 | 병영 L2, 대장간 `meta:forge` L1, M1 L1 | 100/60/25 · 240초 | 판 안 아군 피해 +2% / +6% | PvE 전열 목표 수비 |
| M3 `slg:research-cover` · 엄호 교범 | 병영 L2, 대장간 L2, M2 L1 | 120/80/40 · 300초 | 판 안 아군 최대체력 +2% / +6% | PvE 표식 생존 목표 |
| A1 `slg:research-building` · 공사 도면 | 집 `m3a:home` L1 | 50/60/0 · 120초 | 건설속도 +5% / +15% | 시작 땅 기초 개척 |
| A2 `slg:research-storage` · 보관 기록 | 곡창 `meta:granary` L1, A1 L1 | 80/80/15 · 210초 | 지도 보관시간 +600초 / +1,800초 | 폐허 기록 회수 |
| A3 `slg:research-road-survey` · 행군 측량 | 망루 `m3a:watchtower` L2, A2 L1 | 100/100/30 · 300초 | 월드 행군속도 +2% / +6% | 강가 통로 수비 |

트리는 `E1→E2→E3`, `M1→M2→M3`, `A1→A2→A3`의 단방향이다. 분기 사이 필수 선행은 없다. 세 분야를 병렬로 해금할 수 있지만 실제 연구 작업은 아래의 계정 공용 큐 하나를 쓴다. 우물사당은 이번 첫 트리의 필수 선행에 넣지 않는다. 현재 10개 건물을 억지로 모두 연구 관문으로 만들거나 새 건물 그림을 요구하지 않는다.

탐사 증명은 노드마다 계정에 한 번 기록하는 해금 자격이며 단계마다 소비하는 재화가 아니다. 이미 자격이 있다면 해당 목표를 다시 강제하지 않는다. 세 단계의 깊이는 기록소·자원·시간이 조절한다. 단계별 추가 전투 목표를 넣는 변경은 별도 검토한다.

## 3. 서바이버 전투가 연구·땅·월드를 바꾸는 방식

표의 목표는 아직 없는 **설계 후보**다. 서버가 발급한 `runId`, 목표 ID, 대상 r8 구역 또는 월드 encounter의 ID/세대, 규칙 버전으로 성공을 검증한다. 전투 종료에서 세계 변화·보상 자격·군대 N/K·회군 상태와 함께 탐사 증명을 한 번 확정한다. 운반 자재는 귀환 때 지갑 상한을 거쳐 한 번 지급한다. 탐사 증명을 귀환 보상에서 다시 더하지 않는다.

| 판 안 결과 | 연구의 변화 | 영지·월드의 실제 변화 |
|---|---|---|
| 밭 경계·숲 작업대·광석길의 지정 목표 성공 | 대응 E 노드의 탐사 조건 충족 | 지정 r8 구역의 개방 자격 또는 월드 자원지 확보 상태. 건설·인접·구역 비용은 별도 조건 유지 |
| 초소·전열·표식을 지킨 PvE 성공 | 대응 M 노드 해금 자격 | 예약된 몬스터/거점 상태 변경과 군대 귀환. 연구가 부상자를 무료 생성·회복하지 않음 |
| 기초 개척·폐허 기록·강가 통로 목표 성공 | 대응 A 노드 해금 자격 | 유한한 개인 r8 회복 자격 또는 공유 거점 회복 상태. 행군 길/대상 접근 조건을 월드 계약에 따라 갱신 |

탐사 증명이 있다고 구역을 즉시 무료 개방하거나 연구를 즉시 완료하지 않는다. 반대로 연구 버튼만 눌러 전투 승리·거점 회복을 만들지 않는다. r8 구역 ID와 월드 타일 ID는 별도 주소다. 반복 몬스터·PvP 약탈로 개인 땅을 복제하거나 같은 탐사 증명을 팔 수 없다.

모든 목표는 기본 기사와 연구 미완료 상태로 달성 가능한 기본 경로를 가진다. 특정 뽑기 영웅·해당 노드 효과·유료 가속을 선행 조건으로 두지 않는다. 상위 월드 PvE 접근이 늦으면 같은 탐사 목적을 가진 개인 개척 임무로 증명을 얻는 경로를 제공하는 것을 권고한다. 이 경로도 실제 전투·서버 검증을 거치며 단순 버튼 수령이 아니다. 해당 임무를 연구 완료 뒤에만 열어 순환 잠금하지 않는다.

**무자원 복구는 연구 밖이다.** 병영 L0·병력0·지갑0에서도 기본 기사의 무료 개인 기초 개척전은 열려 있다. 기록소 건설·연구·추가 영웅·적재량을 요구하지 않는다. 유한한 판당/지갑 보상 상한과 실제 플레이 시간을 통해 첫 병영·훈련·치료 자원을 얻는 병력 GDD 경로를 유지한다. 연구는 회복 속도를 개선할 수 있지만 회복 가능성 자체를 판매하지 않는다.

## 4. 연구 큐·비용·완료 [가설]

계정 활성 연구 1건, 대기 예약 1건을 권고한다. 대기는 활성 연구와 다른 노드이며 이미 완료된 선행 조건만으로 예약할 수 있다. 아직 진행 중인 연구 완료를 예상해 자식 노드를 예약하지 않는다. 같은 노드/단계 중복 예약은 거절한다.

1. 서버가 노드/설정 버전, 현재 단계, 모든 선행·탐사 증명, 지갑, 큐 슬롯을 검사한다. 인원·행군과 연구는 별도 장부다. 비용 차감과 작업 생성은 같은 확정 거래다. 화면만 닫거나 응답을 잃었다고 새 작업을 만들지 않는다.
2. 대기 예약은 비용을 먼저 차감하고, 실제 활성화 때도 선행 조건을 확인한다. 시작할 수 없으면 차감 사실을 보존한 보류 상태로 두고 다른 작업을 몰래 시작하지 않는다. 정상 출시에서는 건물 파괴/강등을 도입하지 않아야 한다는 병력 제안을 따른다.
3. 취소는 대기·보류 작업에만 허용하고 실제 차감량을 한 번 반환한다. 환불 때문에 지갑 상한을 넘는 분량은 손실시키지 않는 서버 반환 보관을 사용하며 그 계약이 없으면 취소 기능을 열지 않는다. 활성 연구는 취소·일시정지를 제공하지 않는 첫 출시 안이다.
4. 활성화 때 서버 시작/종료 시각·비용/효과 버전을 고정한다. 앱 종료는 작업을 정지하지 않는다. 서버 재시작은 같은 작업을 복구하며 처음부터 비용·시간을 다시 부과하지 않는다. 클라이언트 시각으로 완료하지 않는다.
5. 완료 시 작업 완료와 해당 노드 단계 증가를 원자적으로 확정한다. UI의 “완료 확인”은 읽기/알림 제거이며 효과를 다시 지급하지 않는다. 다음 작업은 앞 작업의 확정 종료 시점에 시작한다. 재접속 때 두 작업이 모두 지났다면 서버 사건 순서대로 각각 한 번 처리한다.

### 4.1 서버 시제품 구현 기록 (2026-10-30, [#587](https://github.com/hyunlord/bs-mobile/issues/587))

버전 1.1 · 날짜 2026-10-30 · 상태: 서버 시제품 구현, 수치는 [가설] 유지. [ADR0078](../../adr/0078-server-domain-command-transactions.md)의 `research` 분야 처리기로 위 1·4·5번을 구현했다(조작 `start-research`, `complete-research`). 설계와 다른 점:

- 콘텐츠 초안의 Lv1 노드 10개만 다룬다. k=2·3 단계, 대기 예약, 취소·보류는 아직 없다. 활성 연구는 초안 `queues.activeResearch`=1.
- 작업 시각은 ADR0078 high-watermark UTC로 시작 때 고정한다. 서버 시각이 거꾸로 가도 종료 시각은 그대로이며, 완료는 모든 요청의 Advance에서 종료 순서대로 한 번 정산된다. `complete-research`는 정산 결과를 보고만 한다.
- 탐사 증명은 분야 상태에서 검사하지만 전투 정산이 없어 지급 경로가 없다. 시제품 API만으로는 시작 가능한 노드가 없다.
- 효과는 동종 합산 후 `sharedCaps` 1회 clamp 값으로 조회만 하며 영지 생산·훈련·건설·행군 계산에는 아직 반영하지 않는다(Core 무수정).

초기 트리에는 연구속도 자체를 올리는 노드를 넣지 않는다. 연구 시간은 표의 T×k이며 유료 추가 큐도 없다. 연맹 도움과 승인된 시간 가속은 **해당 작업의 남은 시간만** 줄이고 0 아래로 내리지 않는다. 도움 횟수/초수/최소 작업 시간은 월드/연맹 GDD에서 정하며 여기서 새 무료 가속량을 중복 추가하지 않는다. 같은 도움·가속권 요청의 재전송은 같은 결과를 반환한다. 완료된 작업에 도움·가속 비용을 뒤늦게 소비하지 않는다.

즉시 가속과 가속권은 승인된 시간당 보석 공통 기준을 따르고 할인은 별도 상점 설계 대상이다. 연구 노드 완성품·연구 전용 유료 cap·유료 전용 기술은 제안하지 않는다. SDK·실판매는 별도 승인 전 구현하지 않는다.

### 4.2 개척전 보상 보관 상한 (2026-10-30 사용자 결정)

- 개척전(개인 대체 판) 재료 보상의 보관 합계는 `personalFallback.pendingMaterialCap`(60, [가설])까지다.
- 판 **발급 때** 지급량을 확정·예약해 화면에 미리 보인다. 보관 여유가 없으면 "재료 0 · 증명만 획득"으로 표시하고 탐사 증명은 그대로 얻을 수 있다.
- 정산 때는 약속한 양을 그대로 지갑 또는 공통 보관함에 넣는다(GDD15 §3.1의 발생 시각 순서 지급). 다시 계산해 줄이지 않는다.

## 5. 효과 적용·상한·기존 계약

### 판 안 전투와 훈련

신규 SLG 경로는 영웅 GDD의 동종 합산 후 한 번 clamp를 따른다. 가신×영웅×연구를 곱하지 않는다. 가신 개별 cap도 먼저 기존대로 검증한다. 합산 상한 후보 [가설]는 영웅 피해10%·최대체력15%·이동5%·판 안 성장10%·아군 피해/최대체력 각각15%·판 안 XP8%다. M2/M3는 **상비 아군**에만 각각 피해/체력 입력을 추가하며, 임시 징집에는 연구 추가분을 주지 않는 첫 안이다. 가신의 기존 아군 적용 범위는 그대로 유지한다. 아군 유형별 raw 합과 cap 이후 값을 따로 계산해 상비·임시 사이에 보너스를 복사하지 않는다.

예: 상비 아군 피해의 가신12%+영웅2%+M2 L2 4%=18%이면 실제는15% [가설]. 임시 징집은 M2의4%를 제외한14%다. 이미 가신으로15%에 도달했다면 연구의 현재 편성 증가분은0이다. 비용 확인 **전에** “상한 도달 — 현재 편성 전투 효과 +0%”를 보여 준다. 연구가 다른 편성에서는 유효할 수 있음을 구별하며, 최대 가신 상태에서 연구 선택이 무의미해지는지는 밸런스 검토 대상이다.

훈련속도는 병력 GDD의 합산30% 상한과 `ceil(baseSeconds/(1+bonus))`를 유지한다. M1 L3의15%와 영웅20% 후보가 있어도 합산30% [가설]다. 기본200초 작업은154초가 되며 200×0.7=140초로 계산하지 않는다. 시작한 훈련·치료·공사는 해당 작업의 시작 snapshot을 유지한다. 연구 완료가 진행 중 작업의 전체 기간을 다시 계산하지 않는다. 이 트리는 병영 총 병력60/120/200, 단일 행군20/40/60, 병상20/40/80 [가설]을 늘리지 않는다.

### 영지 생산·보관·건설·월드 행군

| 효과 후보 | 최종 계산 [가설] | 적용 경계 |
|---|---|---|
| E1/E2/E3 생산속도 | 자원별 `baseRate × (1+min(20%, 해당 자원 속도 보너스 합))` | 지도 생산만. 전투 보상·월드 채집량·구형 방치 생산에 재적용하지 않음. 연구 완공 시각 전 구간은 옛 속도로 정산 |
| A2 보관시간 | `min(18000초, max(지도 기본/분기 보관시간, #547 효과 E 하한) + 600초×A2레벨)` | 생산속도/재고 수량/지갑 상한은 아님. 이미 최종 상한이면 증가분0. 늘어난 시간으로 과거 초과 방치분을 되살리지 않음 |
| A1 건설속도 | `ceil(baseSeconds/(1+min(30%, 건설속도 보너스 합)))` | 연구 완료 뒤 새로 시작하는 공사에만. 대기 공사는 실제 시작 snapshot, 완료 공사에 환급/시간 지급 없음 |
| A3 월드 행군속도 | `ceil(baseTravelSeconds/(1+min(10%, 월드 행군속도 보너스 합)))` | 판 안 이동5%와 다른 단위. 행군 발령 때 왕복 구간용 속도 snapshot 고정; 왕복/중도 회군의 실제 거리 규칙은 월드 GDD 소관 |

행군속도10%와 건설속도30%, 생산속도20%는 새로운 합산 상한 후보이며 각 원천이 자신의 상한을 따로 적용해 연속 곱하지 않는다. 채집 속도·적재량·행군 칸 수·연맹 도움 횟수는 이번 트리에서 바꾸지 않는다. 후속 월드맵 GDD는 이 입력 경계를 그대로 사용하거나 명시적으로 변경 제안을 해야 한다.

생산 속도 변경 예: 같은 자원 기본10개/시간, E1 완료 전1시간은10개, 완료 후1시간의+5%는10.5개에 해당한다 [가설]. 서버는 고정 정밀도 누적/나머지 정책으로 정수 지급과 나머지를 보존하고 전체2시간을21개로 소급 재계산하지 않는다. 기존 Core의 어떤 나머지 필드가 이 계산을 이미 지원한다고 가정하지 않는다. 새 서버 생산 codec/반올림 계약은 ADR과 구현에서 검증한다.

상한·할인·보관 보너스는 적용 대상과 단위가 다른 경우만 별도다. 시간 단축률과 속도 증가율을 같은 숫자로 표시하지 않는다. 유료 자원으로 연구해도 같은 cap을 적용하며 별도 earned-only 전투 자격 장부는 만들지 않는다.

## 6. 서버·재생·화면 경계

정식 연구 상태는 서버 정본이다. 개발 자동 장원 파일이나 기존 Research E를 서버 완료 노드로 수입하지 않는다. 단일 writer의 구현 형태, 원자 저장·권한·서버 시각·복구·장애 주입은 Codex C# 서버 ADR에서 정한다. 이 문서는 DB/큐/프로토콜을 선택하지 않는다.

전투/행군 계약은 완료 노드와 적용 효과·cap·콘텐츠 버전을 출정 시 고정한다. 진행 중 연구 완료는 이미 시작한 판을 바꾸지 않는다. format7/schema1·2와 가신 format8 독립 블록 및 역사 골든을 고치지 않는다. 새 병력/영웅/연구 snapshot의 버전 계약은 후속 규칙·재생 설계가 담당한다.

연구 화면은 분야·현재/다음 단계, 선행 건물/노드/탐사 목표, 실제 비용·시간, raw/현재 적용량/상한을 보여 준다. 잠금 사유는 “기록소 L2 필요”, “폐허 기록 회수 필요”처럼 구체적으로 표시한다. 현재 효과가0인 강화, 큐 대기·가속 비용, 완료 후 바뀌는 대상은 확인 전에 읽혀야 한다. 승인된 양피지·어두운 바·광택 아이콘 체계와 390×844/48×48 이상 터치를 유지하며 이번 작업에서 UI 그림은 제작하지 않는다.

## 7. 검증과 사용자 검토 항목

후속 구현 종료 기준은 다음과 같다. 이번 문서는 코드/서버/실기 검증을 실행한 증거가 아니다.

1. 모든 노드의 단계·건물·탐사 조건을 검사하고 DAG에 순환이 없음. 기본 기사·연구0·지갑0의 무료 복구 경로는 잠기지 않음.
2. 노드별 k=1/2/3 비용·시간·효과 산술, 최대 단계 재시도, 같은 노드 중복 예약·중복 완료·환불·지갑 초과 반환 보존.
3. 같은 요청/서버 재시작/응답 손실/동시 소비에서 비용·작업·완료 단계가 분리되지 않음. 완료 작업에 도움·가속 차감 없음.
4. 전투 종료의 탐사 증명과 귀환 자재 지급 시점을 구별하고 반복 runId·PvP·개발 저장으로 연구/구역을 중복 해금하지 않음.
5. 전투 cap·훈련30%·건설30%·행군10%·생산20%·보관18000초 후보의 경계, 실제 증가0 표시, 생산 변경 시각 전후·나머지 보존·소급 지급0을 확인.
6. 연구 중/완료 직전 출정의 snapshot 고정, 기존 가신·FP01 블록 absent 역사 회귀를 새 SLG 효과 검증과 구별.
7. 휴대폰에서 판 목표 성공→탐사 증명→연구→영지 생산/다음 출정/행군 변화가 보임. 정상/최대 계정의 완료 시간·무료 회복 가능성·가속 격차를 측정하고 이후 수치를 조정.

검토가 필요한 후보는 9개 노드/각3단계의 깊이, 탐사 자격의 개인 개척 대체 경로, 상비 아군 한정 M2/M3, 활성 연구 취소 없음, 분야별 상한과 무료/가속 페이싱이다. 명시된 가설 이외의 신규 상품·영토·시즌 연구는 첫 출시 범위에 추가하지 않는다. 문서/산술 검사 외 서버·경제·전투·실기 관문은 **NOT_RUN**이다.
