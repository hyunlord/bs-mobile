## P1. 맥에서 바로 해 보기 (최우선, 짧게)
1. **macOS 실행 빌드**: first-playable 프로필 그대로, 세로 창(예: 900×1950 비율, 창 크기 조절 가능, 접힌·펼친 비율 프리셋 단축키). 마우스를 누르고 끌면 떠다니는 조이스틱, 키보드 WASD도 지원. 카드 선택은 클릭.
2. 개발 메뉴는 Release 빌드에서 빼고, 설정의 자동 조준만 남긴다.
3. **게임 화면 영상 2개**(Unity Recorder, 에디터 또는 맥 빌드): 정상 속도·무적 없음. ① 첫 판 처음 3분(이동·카드·첫 수확·징집) ② 판 후반 3분(겨울·보스·결산). 사람 손 입력이 아니면 자동 입력임을 영상 설명에 적는다.
4. Release `phase2a-mac-play-01`에 맥 빌드(zip 1개는 허용: .app 배포용), 영상 2개, 해 볼 것 목록을 올린다. 맥 실행 시 Gatekeeper 경고를 넘는 방법(우클릭 → 열기)을 해 볼 것 목록 첫 줄에 적는다.
5. **관문**: 깨끗한 맥 사용자 계정에서 압축을 풀고 실행 → 타이틀 → 한 판 완주 → 재시작이 되는 것을 스크린샷 4장으로 증빙. 영상에 도형·기본 UI 컨트롤 0.

## P2. 판 밖 성장 v0 (Core 우선, 헤드리스 검증)
02 BM·경제 골격 §3~5와 #32·#42 결정(가신이 초기 유일한 힘 축, 장비 보류, 스킨은 외형만, 판 밖 환산 상한)을 따른다.

1. **챕터 구조**: 챕터 1~10. 챕터마다 지도 변형(강·숲·언덕·터 배치), 적 구성, 난이도 배수, 보스. 챕터 클리어 = 겨울 보스 처치 + 생존. 챕터 선택 화면.
2. **판 결과 환산**: 결산에서 판의 영지 구성 → 자재 4종(곡물·목재·석재·마력 등 이름은 데이터)으로 환산. **상한이 있고**, 재고가 점수가 되지 않는다(지난 모바일 탐사 실패 원인). 사망·중도 포기·같은 챕터 반복 시 규칙을 정한다.
3. **영구 장원**: 가져온 자재로 장원이 **스스로** 자란다(플레이어는 방향만 정함: 어느 건물을 우선할지 깃발 1개 정도). 장원 건물 v0: 대장간(가신 강화), 필사실(해금 연구), 곡창(방치 생산 한도), 막사(가신 슬롯). 시간 기반 방치 생산은 상한이 있고, 기기 시계 조작에 대비해 단조 시간 + 상한으로 막는다.
4. **가신**: 6명(시작 1 + 해금 5). 가신마다 판 안 능력 1개, 레벨 1~20, 조각으로 승급. 판 안 주입은 01 §14·02 §5의 지점(시작 레벨·가신 레벨·전역 배율)만 쓴다.
5. **해금 도전**: 20개. "만드라고라 500 수확 → ○○ 해금" 형식. 해금이 판 안 콘텐츠 풀을 넓힌다(처음엔 일부 무기·도구·물품만 열려 있게).
6. **저장**: 로컬 저장, 스키마 버전과 단계별 이행, 손상 시 복구(직전 정상본). 저장 왕복·이행 테스트를 CI에.
7. **경제 시뮬레이션**: 봇이 하루 N판(예: 하루 6판, 2주) 하는 가상 플레이어 3유형(가벼움·보통·많이)으로 챕터 도달일, 자재 흐름, 막히는 지점을 계산. 산출: `docs/economy/sim-v0.md` + 정본 CSV.
   - 관문: 무한 누적 없음 / 보통 유저가 챕터 3을 1~2일, 챕터 6을 1주 안팎, 챕터 10을 2주+에 도달(임시 목표, 근거 기록) / 막히는 지점이 **어디서 무엇 때문에** 생기는지 표로.
   - 과금·광고는 이번에 붙이지 않지만, **막힘을 풀 수 있는 지점**(어디에 광고 보상·결제가 걸릴 수 있는지) 후보를 표로 남긴다.
8. **Unity 화면**: 챕터 선택, 결산 → 환산 연출, 장원 화면(건물이 자라는 모습), 가신 화면, 도전 목록. 1단계 B와 같은 화풍·UI 디자인 시스템. 새 그림은 그림 계약으로.

## P3. 모바일 F2P 운영 스택 조사 (문서, P2와 병행)
2단계 후반에 광고·결제·분석을 붙이기 전, 한 번 고르면 바꾸기 어려운 선택을 근거로 정한다. `docs/research/ops-stack.md`.

- 대상: 광고 중개(AppLovin MAX / Unity LevelPlay / AdMob 중개), 분석(Firebase / GameAnalytics / Unity Analytics), 원격 설정·A/B, 결제(Unity IAP 등)와 영수증 서버 검증, 크래시 수집, 백엔드(UGS / PlayFab / Firebase / Nakama 자체 호스팅), 어트리뷰션(AppsFlyer / Adjust / Singular).
- 각 항목: 비용 구조(소규모·성장 시), Unity 6.6 호환, IL2CPP·용량 영향, SDK 충돌, 데이터 소유·이전 가능성, 개인정보(ATT·Google Play 데이터 안전 섹션·GDPR·한국 개인정보보호법), 한국 확률형 아이템 표시 의무, 종속 위험.
- 결론: 조합 권고 1개 + 대안 1개, 결정 질문 목록(needs-decision 이슈로). 모든 수치·정책은 출처·확인일, 확인 못 한 것은 "미확인".
- SDK 설치는 하지 않는다.
