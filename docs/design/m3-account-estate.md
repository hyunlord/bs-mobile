# M3 · 계정 영지 — 방치로 키우고 판에서 깨우는 영지

버전: 0.1 · 날짜: 2026-10-24 · 상태: **초안 / 설계 검토용** · 추적: [#358](https://github.com/hyunlord/bs-mobile/issues/358).
변경: 2026-10-13·10-24 사용자 방향, 비교 게임 조사, 기존 장원/M2 흡수, 성장 판매와 판 안 상한, 단계별 완료 조건을 묶었다. 코드·데이터·그림·기존 ADR은 바꾸지 않는다.

**읽는 법:** [확정]은 사용자 결정, [현행]은 명시한 소스에서 확인한 동작, [권고]는 이 초안의 선택, [가설]은 검증 전 구조·수치, [미정]은 아직 정하지 않은 값이다. 이 문서의 병합도 구현·재미·경제 관문 통과를 뜻하지 않는다. 가격·생산량·건설 시간·효과 상한의 실제 값은 모두 #126 이후이며 지금 채우지 않는다.

## 1. 방향과 설계의 중심

[확정] 게임은 **뱀서 + 방치형 영지 키우기**다. 끌어 둘러보는 큰 영지를 키우고, 영지의 힘·자원을 바탕으로 직접 뱀서 판에서 살아남는다. 이후 영지 전투를 섞고, 장기적으로 서버 기반 실시간 4X·월드맵·연맹을 검토한다. 지금은 혼자 하는 PvE다. 약탈병 r2의 사용자 판정 대기와 #98·1b·#224 보류는 이 문서가 바꾸지 않는다.

여기서 ‘계정’은 판을 넘어 보존되는 성장 상태를 뜻한다. 현재 로컬 저장을 온라인 로그인·클라우드 동기화가 구현된 계정이라고 부르지 않는다. 서버·인증 도입은 별도 계약이다.

[확정, 2026-10-24] **성장 가속·자원 판매를 허용한다.** 판 안 효과에는 상한과 체감 감소를 두며, 유료 성장도 직접 이동·회피·선택해야 한다. 결제·광고 SDK는 #122 보류다. 뽑기는 이번 지시로 도입을 확정한 것이 아니며, 도입한다면 한국 확률 공개 요건을 처음부터 설계하고 출시 전 재확인한다.

[권고] 핵심 순환은 **영지에서 성장 방향 선택 → 방치·출정으로 자원 획득 → 구역 복원·건물 성장 → 출정 건물 목록 확정 → 판에서 건물을 찾아 깨우기 → 결산으로 귀환**이다. 기다림은 다음 목표를 만들고, 뱀서 판은 기다리는 동안 할 일이 아니라 주요 플레이로 남긴다. 대기열이 꽉 차거나 구매하지 않아도 출정을 막지 않는다.

### ‘자유롭게’의 세 가지 약속 [권고]

| 자유 | 플레이어가 바꾸는 것 | 바꾸지 않는 것 / 이유 |
| --- | --- | --- |
| 장소 | 열린 구역 안 건물 위치·길·장식·동네 모양 | 배치 잘못으로 생산이 영구 정지하지 않게 한다 |
| 성장 방향 | 생산·수비·회복/지원·연구 중 무엇을 먼저 키우고 어느 분기를 활성화할지 | 중앙 본관 레벨 하나를 올려야 모든 가지가 열리는 단일 사다리를 피한다 |
| 판의 계획 | 보유한 건물 중 다음 판에 가져갈 종류·레벨 조합 | 영지의 모든 건물/배율을 무제한 합산하지 않는다 |

같은 자원·같은 경과 시간을 준 두 계정이 **다른 활성 분기와 출정 건물 조합**을 만들고, 사용자가 왜 다르게 골랐는지 설명할 수 있어야 한다. 단순히 집 위치나 지붕 색만 다른 것은 성장 자유도 관문을 통과하지 못한다.

### 대안 비교

| 안 | 장점 | 비용·거절 이유 |
| --- | --- | --- |
| A. 고정 터 + 중앙 건물 선행 레벨 | 이해·제작이 쉬움, 2A 화면과 가깝다 | 성장 선택이 순서 차이만 남기 쉬워 요구에 부족 |
| **B. 구역 개방 + 격자 이동 + 건물 전문화** [권고] | 배치와 성장 방향을 각각 선택, M2 건물을 점진 연결 | 배치 편집·분기 저장·되돌리기 설계 필요 |
| C. 자유 좌표 + 도로/인접 보너스 + 실시간 침입 | 도시 운영·전투 선택이 크다 | 배치 실수 벌금, 경로 탐색, PvP/서버 범위까지 번짐. 이후 4X 검토로 넘김 |

## 4. 영지 화면과 구역 확장 [권고]

### 조작과 확대

- 세로 화면에서 빈 땅 한 손 드래그로 둘러보고 두 손 핀치로 확대한다. 건물 터치와 드래그를 분리해 둘러보다 건설하지 않게 한다. 확대 단계 수는 **3단계 [가설]**: 영지 전체(구역·진행 아이콘), 동네(건물·길), 상세(건물 선택·수령)다. 확대 배율 숫자는 화면 시제품에서 정한다.
- 상단은 기존 네 자재·보석, 하단은 출정 주 버튼과 영지/가신/도전/상점 진입. 편집 중에는 이동 확정/취소만 두고 출정과 겹치지 않는다. 중앙 집으로 복귀와 진행 중 공사 찾기를 제공한다. 기존 390×844·안전 영역·44pt 터치 계약을 유지한다.
- 영지는 처음부터 여러 화면 크기로 **보이되**, 처음 조작하는 구역은 작다. 가려진 땅의 건물 터·하천·폐허로 확장 목표를 예고한다. 전체 지도 면적·구역 수는 [가설/미정]. 화면 밖 건물은 진행 계산에서 사라지지 않는다.

### 배치 계약

[권고] 논리 배치는 정수 격자, 그림은 기존 등각 시점. 건물은 footprint로 충돌 검사하고 길·장식은 별도 층을 쓴다. 이동 미리보기→확정까지 기존 위치는 보존하며, 취소하면 비용 없이 복귀한다. 완성 건물 이동은 무료·즉시, 레벨·생산 재고·작업 진행을 보존한다. 길 연결은 v1에서 장식이며 숨은 생산 보너스나 접근 불가 벌점이 없다. 회전 가능 방향과 footprint 크기는 아트/화면 시제품 뒤 정한다.

건설 중 이동은 보류하고 진행 완료 후 옮긴다. 지형·다른 건물·닫힌 구역과 겹치면 이유를 표시한다. 저장 복구 때 배치가 충돌하면 인벤토리로 지우지 않고 복구 대기 터에 옮겨 보유 권리를 보존한다. 확대·드래그 위치는 View 저장이며 전투 해시 입력이 아니다.

### 어둠과 복원색의 두 시간축

| 구분 | 계정 영지 | 뱀서 판 |
| --- | --- | --- |
| 어둠 | 미개방 구역, 계정에 영구 저장 | M2 밝힘 원 밖의 판 안 위협 |
| 회색 | 열린 구역의 미개발 땅·잠든 폐허 | 영웅 임시 시야/휴경 표현 |
| 복원색 | 건물 복구·조경 완료가 남기는 성장 표현 | 그 판에 깨운 건물의 영구 밝힘과 기존 돌봄 색 |

같은 화풍을 쓰지만 **계정 개방 비트와 판 안 EstateLight 상태를 공유하지 않는다.** 판이 끝나도 계정 영지가 어두워지지 않고, 계정의 모든 밝은 땅을 판의 안전지대로 복사하지 않는다. 구역 개방은 인접 구역·탐사/챕터 이정표·자재 중 명시한 조건으로 하며, 기다림 단축 구매만으로 모든 플레이 이정표를 건너뛰지 못하게 한다 [권고].

### 성장 트리

- 기본 단계는 보유→건설/복구→완성→레벨 성장→전문화다. prerequisite는 데이터의 유향 비순환 그래프로 표현한다. 본관 레벨 하나가 전 건물의 동일한 문턱이 되는 구조 대신 **구역 이정표 + 계열별 선행 건물**로 나눈다.
- 수직 레벨은 같은 역할의 효율/기능 단계, 수평 분기는 같은 레벨에서 도움의 방식 선택이다. 동일 건물에서 한 번에 활성화할 분기 수는 하나 [가설]. 사용자는 수비 영지·긴 방치 영지·탐사 준비 영지 등 서로 다른 계획을 만들 수 있다.
- 분기는 출정 중 바꾸지 않고 귀환 후 재선택 가능 [권고]. 초기에는 무료 재선택을 권고한다. 환불 비율·재선택 비용은 #126 결정 전 만들지 않는다. 전문화 재선택으로 이미 받은 보상·연구 해금이 중복되지 않게 완료 원장을 유지한다.
- 생산량을 극대화하려고 자정에 건물 배치를 바꾸는 식의 숨은 인접 조합은 v1에서 제외한다. 분기 효과·다음 해금·기회비용을 선택 전에 보여 준다.

### 건설 시간과 우선 깃발

[권고] 기존 ‘자원이 모이면 자동 레벨업’을 **선택한 건물의 명시적 성장 계획 + 유한 대기열**로 바꾼다. 깃발은 새 계획에서 먼저 진행할 대상을 고르는 기능으로 남긴다. 자동 예약/소비는 사용자가 켠 경우에만 적용하고 비용을 미리 표시한다. 계정 전체 자재가 모르는 사이 가신 강화와 경쟁 소비되지 않게 한다.

시간 곡선은 레벨별 데이터 표로 둔다. 초반은 조작 피드백을 바로 확인하는 구간, 중반은 한 판 뒤 돌아와 완료를 보는 구간, 후반은 다시 접속할 목표를 남기는 구간으로 설계한다 [가설]. 초·분·시간 수치와 증가율은 미정이다. 반복 레벨을 늘려 판매 압박을 만드는 지수 곡선을 비교 게임에서 그대로 복사하지 않는다. 조기 구간에서도 기다려야만 뱀서 판을 시작할 수 있는 연결은 금지한다 [권고].

가속은 남은 작업량만 줄이고 이미 완성한 작업에는 소비되지 않아야 한다. 건설 완료가 생산률을 바꾸면 완료 전/후 시간 구간을 분리한다. 접속 때의 최고 레벨을 방치 전체 시간에 소급 적용하지 않는다. 동시 공사 수·연구 슬롯 판매 여부는 자원/가속 판매 허용과 별도의 결정이다.

[권고] 생산량은 건물별 누적 내부 장부로 계산하되 UI는 통합 상자로 받을 수 있다. 논리식은 **승인된 경과 시간 구간의 정수 생산량 → 남은 보관량 제한 → claim 생성 → 지갑 여유만큼 실제 수령**이다. 지급·버림/잔류 정책은 원장에 남기고 화면도 같은 값을 사용한다. 수령 직전 지갑이 찼다면 사라지는 몫을 미리 알린다. 상한 때문에 자원이 사라지는 유료 구매는 결제 전에 차단하거나 보관 정책이 승인된 뒤에만 허용한다.

### 시간: 기존 방어를 유지하되 서버라고 부르지 않는다

[현행] `MetaEngine.AdvanceIdle`은 외부에서 받은 monotonic/wall 초를 비교한다. 첫 관측은 기준 초기화이고 지급하지 않는다. 역행·차이 초과는 `clock-mismatch`, 지급 0이며 관측 기준을 갱신한다. 유효 구간도 방치 시간 상한과 미수령 보관 시간의 잔여를 넘지 않는다. Core가 시스템 시각을 읽지 않는다.

[권고] M3 건설·생산도 같은 검증된 시간 구간을 입력받는다. 시계 검증 실패 때 생산뿐 아니라 공사 완료/연구 완료를 별도 wall-clock 경로로 확정하면 우회가 되므로 함께 보류한다. 재부팅·절전·오프라인 복귀·수동 시각 변경·시간대 변경의 복구 표본을 새 저장 버전 관문에 포함한다. **로컬 파일·기기 시계를 함께 조작하는 공격까지 방지하는 구조는 아니다.** 구매 지급과 이후 4X 시간은 #122 서버 권위 계약이 생기기 전 안전하다고 주장하지 않는다.

### 2A 저장 이관 [권고]

1. 구형 저장과 pending claim/완료 도전/진행 중 판 저널을 백업하고 버전별로 읽는다. 현재 저장 번호에 새 필드를 몰래 덧붙이지 않는다.
2. 먼저 구형 규칙으로 terminal intent의 Before/After를 대조·복구하고, 남은 구형 PendingRun은 기존 계약에 따라 구형 규칙으로 종료·정산한다. 현재 호스트는 직렬화 바이트로 상태를 대조하므로 그 전에 M3 필드를 쓰지 않는다. 충돌 시 reset·덮어쓰기 없이 중단한다.
3. 네 장원 ID와 완료 레벨·가신·조각·지갑·우선 깃발을 보존하고 결정적인 기본 배치에 놓는다. schema5의 지급 원장/보상 기준·run/claim sequence·완료 횟수·마지막 시각/방치 나머지도 보존한다. 과거 자동 성장으로 완료한 레벨에 건설 시간이나 비용을 다시 요구하지 않는다.
4. 새 M3 성장 모드는 기존 자동 성장 함수와 동시에 실행하지 않는다. 구형 계정 이관 시 자동 소비 옵션은 명시적으로 확인하도록 하고, 동의 전에는 기존 보유값을 보존한다.
5. 이관 자체로 pending 방치 보상을 재계산하거나 완료 도전을 재지급하지 않는다. 새 계정의 최초 생산도 기존 계정의 누적 시간으로 부풀리지 않는다.
6. 이관 완료 ID·저장 성공을 함께 확정한 뒤 UI를 공개한다. 저장 실패·강제 종료·중복 복구·미래 버전 파일은 기존 안전 계약을 유지한다.

## 7. 영지 → 뱀서 판 계약

### 경계 변경 표

| 현행 | 유지 | M3b에서 바꿀 것 [권고] |
| --- | --- | --- |
| ADR0053 `AccountOnlyWave` | 기존 wave/역사 재생은 원본 Catalog, 가신 배율 미투영 | 새 정책에서 **선택한 계정 건물 ID·완성 레벨·승인된 분기**만 투영 |
| ADR0064 M2 L1/L3 | 고정 비교 목록, 항상 밝은 집, 깨우기·판당 1회·T1·밝힘 수명 | 계정 스냅샷→검증된 건물 정의 목록으로 대체하는 별도 실행 경로 |
| 계정 저장 | 생산/배치/구매 기록은 계정 소유 | Core는 전체 저장파일·현재 지갑·결제 내역을 읽지 않음 |

| 판 안 자원 | 기존 수확·소비·경험치 규칙 | 계정 자재는 먼저 건물/출정 준비로 환원. 계정 지갑을 판에 실시간 주입하지 않음 |

ADR0064는 계정 건물 목록 연결 방향을 이미 승인했다. 이 초안은 그 상세안을 작성하며, **현재 ADR을 즉시 대체하지 않는다.** M3b 구현 전 별도 ADR에서 ADR0053의 좁은 예외, ADR0064 목록 버전, 새 BM 경계의 효력 범위를 선언한다. 번호는 그 PR의 최신 main 기준으로 정한다. 계정 자원을 직접 판 시작 곡물/목재로 바꾸는 보급품은 상한·무료 접근·환불 계약이 추가로 필요하므로 첫 연결에서 제외 [권고].

### 출정 스냅샷 — 필드 계약 초안 (코드/스키마 아님)

| 필드 | 의미·검증 |
| --- | --- |
| projection version / rules revision | 목록 형식과 상한·분기 해석 버전. 미지원이면 묵시적 보정 대신 거부 |
| run sequence / chapter / seed | 기존 출정 원장과 같은 판 식별. 계정 개인 정보는 넣지 않음 |
| entries | 계정 instance ID, building definition ID, 완료 level, branch ID, slot ID. 건설 중 다음 레벨은 제외 |
| catalog hash / cap-policy revision | 선택 목록이 반영된 실행 정의와 적용한 상한 규칙의 일치 증거 |
| stable order | 정수 slot→definition ID→instance ID 순서, 문자열은 Ordinal. slot/instance ID 중복 거부. 같은 definition ID 허용 여부는 종류별 한도 정책으로 별도 검증 |

출정 시 한 번 동결하고 이후 계정 성장·상품 구매·배치 변경이 진행 중인 판에 영향을 주지 않는다. ID·레벨·분기는 허용 범위와 보유 상태로 검증하고, 건물 ID를 Core 코드에 하드코딩하지 않는다. 현재 목록이 없으면 L1로 조용히 대체하지 않고 설정 불일치를 알린다. 무료 계정도 같은 종류와 최대 효과 단계에 도달할 수 있게 한다 [권고].

**재생:** M2 형식 7에는 선택 LoadoutId와 catalog hash가 있으며, 현행 근접 조준을 담는 estate header schema 2와 옛 schema 1이 있다. 새 계정 목록 필드는 새 opt-in 버전으로 기록한다(번호 미예약). 실제 엔트리 또는 그 내용을 재구성할 불변 데이터와 해시를 기록해야 하며 계정 저장을 다시 읽어 재생하지 않는다. L1/L3와 형식 1–7의 기존 기록을 보존한다. 전역 data tree hash만으로 계정 목록을 식별할 수 없다. #323의 ADR0069/구현이 병합될 때 닫힌 소비 데이터 집합과 호환 경로를 다시 확인한다.

### 판 안 효과 상한과 체감 감소 [구조 권고, 값 #126]

- **명시적 두 단계:** 계정 레벨을 출정 유효 단계로 제한하고, 각 효과를 적용할 때도 전체 합산 상한을 검사한다. 한 건물의 cap만 두고 여러 건물/병력/연구를 합쳐 우회하지 못하게 한다.
- **계정 레벨→유효 단계 표:** 높은 계정 레벨은 초반에 눈에 띄고 이후 추가 효과가 줄어드는 비감소 표로 설정한다. 레벨별 증가분·포화 단계는 [가설/미정]. 어떤 분기의 값이 감소하거나 다른 효과를 과도하게 보상하면 검토 대상이다.
- **효과별 cap:** 건물 사격 피해·발동 빈도/동시 투사체, 회복/재생, 자석/군중 제어 범위·지속, 병력 동시 수/기여량, 밝힘 면적, 수확 보너스 각각에 범주 상한. 가산/곱연산 순서·중복 적용·정수 반올림은 데이터 버전 계약에 포함한다. 출정 가능 슬롯도 유한하다.
- **깨우기는 생략 불가:** 구매한 단계라도 집 외 건물은 잠들어 시작하며, 찾아가서 해당 정의의 버티기 또는 그 판의 자원 소비(또는 둘 다)로 깨운다. 기존 channel/spend/both 구분을 유지한다. 돈으로 전체 맵 밝힘·즉시 승리·회피 무시 상태를 사지 않는다 [권고].
- **가설 검증:** 무성장/중간/효과 포화 계정에 동일 seed와 입력을 주어 기여량·회복·피격·유효 단계/cap 도달을 비교한다. ‘서 있기’도 포함해 포화 계정의 무조작 생존 가능성을 기록한다. 수치상 cap 통과만으로 ‘직접 살아남아야 함’을 입증했다고 하지 않는다. 사용자가 최대 성장 상태에서도 피하고 깨우고 카드를 고를 필요가 있다고 판정해야 한다.
- **유료 원천 불변:** 같은 엔트리·레벨이면 무료/유료 원천과 관계없이 동일 해시·효과. 결제 원천은 계정 지급 감사에만 남고 전투 배율로 읽히지 않는다. 상품 설명에 계정 레벨과 이번 챕터의 유효 단계/상한을 함께 보여 준다.
