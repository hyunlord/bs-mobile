# M1-4 · 선택된 2D 영웅과 읽히는 타격

버전: 1.0 · 결정일: 2026-10-13 · 상태: 제작 승인, 영상 관문 미통과.
정본: [#258](https://github.com/hyunlord/bs-mobile/issues/258). 이번 선택은 방식의 선택이며 완성된 그림·손맛 승인이 아니다.

## 선택과 범위

기본 A 개척 기사·1.4배를 유지하고 **2D 프레임 애니메이션을 채택**한다. **3D 굽기 작업은 중단**한다. 관절 잘라붙이기는 역사 비교 기준선으로만 보존한다. M1-3 원화·실패·Release·측정은 삭제하거나 새 방식의 통과 자료로 바꾸지 않는다.

영웅은 서기·걷기·검 베기·피격·쓰러짐의 필수5동작부터 만든다. 원화 실측 머리53/전신441 기준±10%, 스타일·채도·표시 크기를 일관되게 맞춘다. 방향별 검은 오른손에 유지한다. 비대칭 방향을 독립 저작하며 좌우 반전으로 검 쥔 손을 바꾸는 대체를 허용하지 않는다. 파일·프레임별 랜드마크, 손·검 연결, 출처와 생성/수정 과정을 남긴다. 독립 저작이 없는 방향·동작을 완료로 세지 않는다.

## 실제 공격과 화면 판독

- [ADR0059](../adr/0059-opt-in-melee-aim-review.md)의 가까운 적 조준을 켠 검토 프로필로 촬영한다. 연속 프레임에서 실제 표적·공격 방향·피해 사건을 함께 확인한다. 검 그림만 회전시킨 표본은 조준 증거가 아니다.
- 철날 검·연쇄 번개·뿔나팔의 검토용 진화는 형태와 크기가 화면에서 읽히도록 수정한다. 창 그림은 키워 판정·피해 변화와 구분한다. 회오리·방패·곡창의 방향은 유지하며 방패의 화면 가림은 View 표현으로 줄인다.
- 검토 단계의 `lv1/max/evolved`는 여전히 사전 구성한 가설이다. 수치를 production 밸런스나 정상 진화 획득으로 확정하지 않는다. 실제 피해·처치와 화면 안 사건을 연결하고 발동 수명 누적 처치를 순간 동시 처치로 쓰지 않는다.
- 무기 쇼케이스의 영웅도 선택된 2D로 교체한다. 같은 입력·장면의 전후2배 비교, 연속 프레임 시트, 무기8종 각각30초(단계별10초) 영상을 제공한다. 실제 소리와 고정60fps 오프라인 캡처를 사용하며 소스·입력·데이터·프레임·오디오 출처를 연결한다. 오프라인 영상은 실시간 성능 증거가 아니다.

## 성능과 재생 계약

최적화 진단은 기존 실제8종 결합 입력과 카탈로그를 **불변 기준선**으로 고정한다. 기준 최종 해시는 `C5050C0EE8DBF8837865CFBE83E7C59113109C0439BDE89B8BA9EB851CE5510F`다. 기존 `2dfad7e` 실행의 p95 33.3361ms·최대53.7928ms·25ms 초과206/982(20.9775967%) 실패를 보존한다. 원인 분해의 Core 비용 후보를 검증 없이 근본 원인으로 확정하지 않는다.

실제 두 Core DLL의 같은 입력 해시와 역사 C05를 유지하는 최적화를 우선한다. 바뀐 최종 쇼케이스 입력은 그 뒤 **별도 후보**로 측정해 기준선 개선과 콘텐츠 변경을 섞지 않는다. 후보별 입력·설정·데이터·앱 커밋·전체/화면 안 적 수를 기록한다. 전체 적800+가 화면 안800+를 의미하지 않는다.

최종 후보는 캡처OFF·전경 인정 구간의 네이티브 Release로 **3회** 측정하며 각 실행에서 최대≤50ms, 25ms 초과 비율≤0.2%를 확인한다. 전경 제외·실패·수집 불가 항목은 숨기지 않는다. 기존 네이티브 표본이나 CI로 이번3회 관문을 대신하지 않는다. 현재 새 결과는 미측정이다.
