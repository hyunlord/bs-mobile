## r7 시작 배치

새 개발 시제품만 `m3a-prototype-r7`을 선택한다. r3~r6 JSON과 기존 저장의 ConfigVersion은 바꾸지 않는다. 저장 버전 6, Core 규칙, 판 리플레이, 기본 데이터 트리 해시는 변경 대상이 아니다.

중심 열린 땅은 (24,24)에서 12×12, 건물은 열 채 모두 2×2다. 부지끼리 변·모서리가 맞닿지 않게 최소 한 칸을 비운다. 집 앞 (28,29)의 2×2는 광장으로 남기고 우물은 옆 (30,30)에 둔다. 생산은 서쪽, 원정은 동쪽, 기록소는 집 가까이에 둔다. 건설 비용·시간·생산·상한·진행 조건은 r6과 동일하다.

| 건물 | 좌상단 (x,y) | 역할 |
|---|---|---|
| 집 | 28,27 | 시작부터 완성·불 켜짐 |
| 기록소 | 28,24 | 집 근처 |
| 우물·사당 | 30,30 | 광장 옆 |
| 곡창 | 24,24 | 생산 |
| 경작지 | 24,28 | 생산 |
| 벌목장 | 24,32 | 생산 |
| 대장간 | 33,24 | 원정 |
| 병영 | 33,27 | 원정 |
| 제철소 | 33,30 | 원정 |
| 망루 | 33,33 | 원정 |

각 문에서 집 문까지 열린 빈칸을 따라 자동 길을 연결한다. r7 View가 고정 순서의 격자 탐색으로 길을 만들며 Core 상태나 저장에 도로를 추가하지 않는다. r3~r6은 밀집 부지에서 문이 이웃 부지에 걸리는 역사 배치가 있으므로 기존 길 그리기를 보존한다. 건물 선택·이동·미리보기는 같은 2×2 논리 부지를 사용한다.

## 구역과 어둠 변화

전체 중심 20×20의 합계 400칸과 바깥 8구역은 유지한다. 시작 면적을 넓히기 위해 인접한 4구역 경계를 조정한다. 구역 해금 비용·선행 조건은 동일하다.

| 구역 | r6 칸 수 | r7 칸 수 | 변화 |
|---|---:|---:|---|
| 시작 | 64 | 144 | 각 방향으로 2칸 확장 |
| 북쪽 외곽 | 120 | 80 | 시작 경계로부터 바깥 띠 6→4칸 |
| 동쪽 외곽 | 48 | 48 | 폭 6→4, 길이 8→12 |
| 남쪽 외곽 | 120 | 80 | 시작 경계로부터 바깥 띠 6→4칸 |
| 서쪽 외곽 | 48 | 48 | 폭 6→4, 길이 8→12 |
| 나머지 8구역 | 기존과 동일 | 기존과 동일 | 좌표·크기·해금 규칙 유지 |

같은 지도 좌표를 기준으로 시작 땅의 닫힌 경계가 동서남북 각각 2칸 멀어진다. 실제 집 위치도 바뀌므로 집에서 어둠까지의 거리는 별도로 측정한다. 둥글게 퍼지는 따뜻한 빛과 청회색 어둠 표현은 #386 계약을 유지한다.

## Lv0 표현 계약: 모든 설정 공통

아직 짓지 않은 Lv0는 완성 건물을 그리지 않는다. 기존 폐허 기초·빈 울타리·돌·마른 풀 조각으로 ‘되찾을 터’를 표현한다. 필수 부지 표시는 장식 끄기에서도 남는다. 공사 중은 빈 고랑과 공사 표지, Lv1 이상은 해당 단계 건물이다. 시작 집은 StartsComplete 계약대로 완성 상태다. 선택·이동·공사 조작은 단계와 무관하게 유지한다.

새 그림 제작은 이번 작업에 포함하지 않는다. 기존 그림으로 부족한 부분은 낮 화면 확인 후 아래 제작 필요 후보를 판정한다.

| 후보 | 크기/칸 [가설] | 용도 | 상태 |
|---|---|---|---|
| 공통 빈 기초 윤곽 | 128×64, 1칸, 2×2 부지 기준 | 반복 폐허 벽이 높아 보일 경우 낮은 윤곽 대체 | 기존 조각 화면 확인 후 필요 여부 결정 |
| 건물 종류별 되찾을 터 | 128×96, 종류당 1칸 | 열 부지의 용도를 실루엣으로 구별 | 이번 범위 밖, 이름/선택 시트로 우선 구분 |

## 검증 상태와 다음 낮 순서

밤에는 코드·데이터·문서와 가벼운 정적 검사만 한다. 런타임 통과를 선언하지 않는다.

1. 새 설정 유효성·배치·경제 동등성, r3~r6 역사 저장 바이트, 리플레이/골든 및 crowd-411 종료 해시, 기본 데이터 트리 해시를 검사한다.
2. 공유 Mac 잠금과 시간대를 확인한 뒤 두 프로필 EditMode/PlayMode 전체를 실행한다. 새 영지는 정상 선행 곡창 건설·완료 후 경작지 건설·완료를 검사한다. 자원 지급으로 조건을 우회하지 않는다.
3. native 기존 실패 경로는 거부 사유 로그를 포함해 단 한 번 재시도한다. 정적 분석상 새 영지의 곡창 Lv0에서 경작지를 바로 요청하면 `parent-required`가 예상된다. 이 확인은 건설 흐름 성공과 구분한다.
4. 청록 감시는 유지한다. 첫 접속/전체 보기/건설 중/완성 후를 키 아트 C와 비교하고 묶음 수를 기록한다. 첫 화면은 열린 땅 전체와 45~55px 건물 목표를 실제 캡처로 확인한다.
5. 같은 실패 두 번, Core·해시·저장 형식 변경 필요, 다른 작업 폴더나 보호된 MV 쓰기가 필요하면 중단한다. PR은 사용자 승인 전 초안 유지·병합 금지.

## 첫 화면 배율 계산 근거

r7만 열린 구역 바깥 여백을 0셀로 두어 12×12 투영 폭 768을 화면 폭 390에 맞춘다. 배율은 390/768 ≈ 0.5078, 건물의 View 내 배율은 1.5 [가설]다. 건물 모양을 찌그러뜨려 같은 높이로 만들지 않는다.

원본 그림의 불투명 영역 기준 계산상 시작 집 46px, 망루 51px다. 자연스러운 높이 차이 때문에 우물 약38px, 기록소 약60px 등은 목표45~55px 밖이다. 첫 화면의 완성 건물은 집 한 채이며, 다른 Lv0는 낮은 부지로 보인다. 이 값은 원본 manifest와 배율로 계산한 예측이지 실제 캡처 측정이 아니다. 내일 화면 비교에서 판정한다.
