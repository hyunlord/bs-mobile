# M1-3 · 캐릭터 제작 방식과 무기 손맛 비교

버전: 1.2 · 날짜: 2026-10-12 · 상태: 제작 승인, 사용자 시각 관문 미통과.
정본 요청: [#256](https://github.com/hyunlord/bs-mobile/issues/256). M1-2는 사용자 **실패** 판정이며 [PR255](https://github.com/hyunlord/bs-mobile/pull/255)는 초안·미병합으로 유지한다. 기존 영상·수치·실패 원본을 지우지 않는다.

## 현재 결정

A 정통 개척 기사와 카메라1.4배는 유지한다. 기존 (c) 실시간 뼈대는 이번 비교의 **기준선**이며 최종 제작 방식은 다시 사용자 영상 선택을 받는다. 부자연스러운 걷기, A 원화 비례 이탈, 느껴지지 않는 타격, 부족한 무기 형태·규모가 출발점이다. 코드·해시·프레임 수는 안전망이며 캐릭터·모션·손맛 통과를 대신하지 않는다. 제작은 추가 승인 질문 없이 진행하되 유료 도구·자산을 승인 없이 도입하지 않는다.

## 같은 조건의 모션3안

| 방식 | 시제품 | 범위 경계 |
|---|---|---|
| 3D 저작·기성 모션 → 이미지 굽기 | 무료 또는 허용 라이선스 모델·모션, 7동작·8방향 | 실행은 구운 이미지; 단순 이미지 회전을 8방향 저작으로 세지 않음 |
| 프레임 그림2D | 걷기8프레임·검 휘두름1종 | 미제작 동작·방향을 완성 개수나 공수에 포함하지 않음 |
| 보존 관절 기준선 | 기존 A 기사 구현 | 과거 선택 기록 보존, 새 최종 방식으로 자동 승인하지 않음 |

공통 조건은 A 원화·1.4배·장면·입력·소리다. 3D 비교의 필수 7동작은 걷기, 달리기, 가벼운 베기, 크게 내려치기, 회전 베기, 피격, 쓰러짐이다. 2D 비교는 걷기8프레임과 휘두름1종을 제작한다. 3안 나란히 영상과 초당12장 포즈 시트를 제출한다. 하체 이동·상체 공격·발 접촉이 읽혀야 한다.

사용자의 **약7등신(1:7)** 표현과 승인 원화 실측은 일치하지 않는다. 원화는 머리53px/전신441px = 0.12018, 약8.32등신이다. 따라서 **같은 랜드마크로 잰 실제 원화 비율 대비 ±10%를 우선**한다. 3D 후보는 약7.7등신으로 조정했으며 숫자 범위 충족과 사용자 시각 승인은 별개다. 머리 꼭대기·턱·접지 발끝을 표시하고 검·망토 끝·그림자를 신장에 포함하지 않는다. 원근·무릎 굽힘을 서기 기본 비례와 혼동하지 않는다.

실측에는 시작/끝·중단시간·산출물·수정 횟수를 남긴다. 라이선스 검토·리깅·손 수정·굽기·엔진 연결을 빼고 자동 생성 시간만 비교하지 않는다. 추정값은 실측과 분리해 가정·범위를 적는다.

외부 모델·모션·텍스처·도구마다 이름/버전·원출처 URL·취득일·라이선스 원문·상업 사용/개작/재배포 조건·저작자 표기·비용·저장소 수록 범위를 기록한다. 무료 다운로드를 자유 재배포로 해석하지 않는다. 생성 그림은 참조 원화·프롬프트·결과·수정 저작 파일을 연결한다. 권한 미확인 자산을 실행에 넣지 않으며 유료 도구는 사용자 승인 전 쓰지 않는다.

### 현재 제작물의 한계

[3D 저작 기록](../../tools/art-authoring/hero-a-3d/README.md): 모델은 프로젝트 저작 메시이며 표면은 imagegen 그림, 기성 모션만 Quaternius CC0다. 얼굴·갑옷이 각져 보이고 머리카락이 모자처럼 보이며 망토는 단순 지연 변형이다. 전체 manifest는64클립·2,000장 굽기 완료를 기록하지만 death/SE frame026의 검 잘림 검증 실패도 기록한다. 별도 재구도 굽기 비용190.98초가 있으며 최종 아틀라스·네이티브 검증 전 전체 무잘림 통과를 주장하지 않는다.

[2D 저작 기록](../../tools/art-authoring/hero-a-frames/README.md): 사람이 손으로 그린 원화가 아닌 AI 생성48개 후보 자세다. 걷기5방향×8장, 베기E8장이며 나머지 걷기3방향·베기W는 반전이라 검 쥔 손도 바뀐다. 독립8방향 원화가 아니다. 서기는 걷기 첫 장 대체, 나머지 공격 방향·7동작 전체는 미제작이다. 비례 수정 뒤 공격 채도가 걷기보다 높고 뒷머리 턱 위치는 대용 주석이므로 연속 동작·스타일 일관성은 영상 관문으로 남는다. 초기 비례 이탈과 검 잘림 원본을 보존한다.

위 시간은 서로 범위가 다른 벽시계·렌더 실측이다. 병렬 대기·라이선스 조사·수정·통합을 동일 범위로 통제한 인력 생산성 비교가 아니며 이를 시간 비율의 우열로 계산하지 않는다.

## 무기8종과 손맛

서로 구별되는 무기8종을 **Lv1 10초 → 최대레벨10초 → 진화10초**, 무기당30초로 보여 준다. 진화는 화면 절반 또는 수십 적을 쓸어 가는 규모를 실제 표본으로 보여 준다. 형태·리듬·소리·피격 반응이 구별되어야 한다. 무기 ID·단계·입력·데이터 버전을 실행 목록으로 고정한다. 검토용 장비 부여·장면 구성은 쇼케이스로 표시하며 정상 성장·생존·밸런스 증거로 쓰지 않는다. 그림만 확대해 판정이 커졌다고 주장하지 않는다.

새 표현 가설은 **맞은 적만 국소 히트스톱3–5표시프레임, 흰 번쩍임2표시프레임, 몸 너비0.3–0.5배 표시 반동**이다. 일반 타격마다 전역 화면을 멈추지 않고 Core 시간·위치·판정·피해를 유지한다. 처치 터짐·먼지·경험치, 큰 기술 흔들림·진동·소리 변주를 연결하고 끄기 설정·최소 간격·풀 상한을 유지한다. 기존 번쩍임을 신규 차이라고 쓰지 않는다.

**근접 최근접 적 조준은 별도 Core 규칙 변경**이다. 데이터·규칙 버전으로 분리해 이전 재생은 이전 조준 계약으로 그대로 실행한다. 거리 동률·표적 없음·사망/소멸 표적을 결정론적으로 처리한다. 구체 계약은 구현 ADR에 기록하며 번호는 main·열린 작업 확인 뒤 정한다. 표시의 Core 불변 주장을 새 조준 규칙에 적용하지 않는다. 피해·경제·스폰 수치를 함께 조정하지 않는다.

## 실제 전투 검토와 초기 시각 모드의 경계

초기 visual-only 쇼케이스는 형태 시안이며 실제 타격·처치 증거로 쓰지 않는다. 후속24사례는 [검토 카탈로그](../../core/src/SowSiege.Core/ReviewShowcaseCatalog.cs)와 [ADR0059](../adr/0059-opt-in-melee-aim-review.md)의 실제 Core 전투다. 각 사례는10초 준비+10초 촬영이고, 무기별3단계를 이어30초로 제출한다. `lv1/max/evolved`는 사전 장비 구성 가설이며 정상 성장으로 얻은 최대레벨·진화가 아니다. 다른 공격·성장·물품·진화·보스는 표본에서 억제한다.

공격·arena 수치는 격리된 검토 전용이다. 예를 들어 `enemyDamage=1`은 장면 지속을 위한 가설이며 production 체력·피해·스폰량 변경이 아니다. 예약 타격의 배치·지연·간격·반경은 `WaveAttackComposition`으로 실제 피해와 사건을 만들고 입력·카탈로그·해시로 추적한다. 시각 전용 증거와 실제 전투 표본, 정상 플레이를 보고에서 구분한다.

초기52개 조준 검사는 역사 실적으로 남긴다. 후속 candidate2의 집중 검사56/56,24개 전투 사례와 C05 역사 해시 유지 근거는 로컬 `.omo/evidence/m1-256-combat-candidate2/`다. 검사 개수를 합산하지 않으며 이 증거만으로 사용자 영상 관문을 통과시키지 않는다.
