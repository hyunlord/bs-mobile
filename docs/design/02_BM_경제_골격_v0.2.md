## 1. 판매 원칙과 범위

[확정] 기본 영웅1·영지 전통1을 먼저 완성한다. 초기 힘 축은 가신이며 장비는 보류한다. 스킨은 외형만 바꾸고 영주·영지 ID에 따른 코어 분기를 만들지 않는다. 이 범위는 #32·#42 결정과 [P2 #115](https://github.com/hyunlord/bs-mobile/issues/115)의 실행 범위다.

판 안 선택이 판 밖 장원의 성격을 바꾸되 식량 재고를 점수로 삼지 않는다. 판 밖 지갑을 직접 전투력으로 읽지 않고, 활성 가신의 제한된 배율만 승인된 경로로 주입한다. 장원의 연구·상한·슬롯은 가신과 콘텐츠를 열며 별도 장비 힘 축을 만들지 않는다.

광고·결제·분석 SDK, 서버, 추가 영웅·영지, 장비, PvP·동맹은 이번에 구현하지 않는다. 가격·유료 통화·상품 확률·광고 빈도는 아직 없다. 소비자를 막은 뒤 결제를 붙이는 것을 기본값으로 삼지 않으며 먼저 무료 플레이의 병목을 측정한다.

## 3. 판 결과 환산과 반복

[구현] 판 시작 전에 증가 순번·챕터·seed를 가진 미정산 판을 저장한다. 종료할 때 일치하는 판 한 번만 정산하며 이미 처리한 판은 다시 지급하지 않는다. 챕터 클리어는 `포기 아님 + 생존 + 보스 처치 + 27,000틱 도달`이다. 클리어한 최댓값으로 다음 챕터가 열린다.

작성 시점 원시 환산식 [가설]:

| 자재 | 원시 요청량 |
|---|---|
| 곡물 | 남은 밭 수 + 누적 수확 수 + 도달 레벨 + 보스 처치 시10 |
| 목재 | 살아 있는 완성 건물 수×3 + 도달 레벨 + 보스 처치 시10 |
| 철재 | 살아 있는 완성 건물 수 + 도달 레벨 + 보스 처치 시10 |
| 인장 | 남은 사람 구성원 수 + 보스 처치 시5 |

처치 수는 도전 지표이며 현재 직접 환산 계수는 없다. 식량 재고·미완성 건물·파괴된 건물은 자재 점수로 더하지 않는다. 사람은 표시 개체 수가 아니라 구성원 합이다.

순서는 **최소 시간 검사 → 자재별 원시량을 챕터 상한으로 제한 → 결과 배율 적용·정수 버림 → 지갑 여유만 지급**이다. 지갑 초과분은 별도 초과량으로 기록하며 다음 판으로 무한 이월하지 않는다. 이후 장원 자동 성장과 도전 보상이 처리되므로 화면의 지급량과 최종 지갑 증가량이 같지 않을 수 있다.

| 결과 | 배율 [가설] | 기타 |
|---|---:|---|
| 최초 챕터 클리어 | 100% | 다음 챕터 해금 |
| 이미 클리어한 챕터 재클리어 | 60% | 제한된 반복 수입 |
| 사망 또는 클리어 조건 미충족 | 40% | 챕터 해금 없음 |
| 중도 포기 | 10% | 조각 없음, 클리어 없음 |
| 1,800틱(60초) 미만 | 0% | 환산·도전 누적·조각 없음 |

앱 중단 후 정산 전·후 스냅샷이 담긴 터미널 저널이 있으면 완료 정산을 복원한다. 저널이 없는 미정산 판은 보상 없는 포기로 정리하며 실전 사실을 추정해 지급하지 않는다. 최소 시간 이후의 포기는 현재 완료된 수확·처치 등 도전 진행에 기여할 수 있지만 보스 도전과 클리어에는 기여하지 않는다.

| 2 | 200 | 140 | 90 | 36 |
| 3 | 230 | 165 | 110 | 44 |
| 4 | 260 | 190 | 130 | 52 |
| 5 | 290 | 215 | 150 | 60 |
| 6 | 320 | 240 | 170 | 68 |
| 7 | 350 | 265 | 190 | 76 |
| 8 | 380 | 290 | 210 | 84 |

상한 표는 가능한 최대 요청을 제한할 뿐 실제 평균 획득량을 뜻하지 않는다. 최종 CSV에서 실지급·소비·초과·잔고를 각각 확인한다.

## 4. 스스로 자라는 영구 장원

플레이어는 우선 건물 하나에 깃발을 둔다. 비용을 낼 수 있는 건물이 우선순위와 ID의 결정적인 순서로 성장하며, 우선 건물이 막혔어도 다른 건물이 성장할 수 있다. 가능한 성장이 없거나 모든 건물이 상한이면 멈춘다. 직접 배치·부채·무한 단계는 없다.

| 건물 데이터 이름 | 기능 | 현재 상한 [가설] |
|---|---|---|
| 대장간 | 가신 강화 가능 레벨을 연다 | 건물10레벨; 가신 상한 `min(20, 5 + 2×대장간 레벨)` |
| 기록소(의뢰서의 필사실) | 도전의 연구 조건을 연다 | 건물10레벨, 현재 도전 조건0~4 |
| 곡물창고(곡창) | 한 번의 방치 생산 인정 시간을 늘린다 | 건물10레벨; 2시간+레벨당12분, 최대4시간 |
| 병영(막사) | 활성 가신 자리를 연다 | 건물10레벨; `min(3, 1 + floor(병영 레벨/4))` |

초기 출전1칸, 병영4레벨2칸, 병영8레벨3칸이다. 이것은 무기5/도구4/특허장4 슬롯과 무관하다. 대장간은 강화 권한을 열 뿐 가신 레벨을 무료로 올리지 않는다.

장원 비용은 `기본 비용 + 현재 건물 레벨×단계 비용`이다. 네 건물의 최초 비용은 곡물35·목재25·철재15·인장5이며 이후 기울기가 건물마다 다르다. 비용 원본은 데이터로 관리하고 경제 CSV 결과로 다시 검토한다. 자동 장원 지출과 수동 가신 강화가 같은 지갑을 쓰므로 둘의 경쟁을 병목으로 측정한다.

## 5. 가신 강화·승급·주입

가신6명 중1명이 시작 해금이고5명은 도전으로 열린다. 레벨1~20, 승급0~5이며 활성 가신만 능력을 주입한다. 현재 각각 공격/체력/이동/성장/아군/경험치 채널 하나를 가진다. 이름과 실제 효과는 01 §10에 정리했다.

[가설] 채널 보너스는 `30 + (레벨−1)×10 + 승급×20` 퍼밀이다. 활성 가신의 같은 채널을 더해1000에 합산한다. 현재 명단은 여섯 채널이 서로 다르므로 각 채널 최대1.32배다. 정수 처리로 실제 낮은 수치의 증가 비율은 반올림 없는 실수32%와 다를 수 있다.

| 항목 | 현재 데이터 [가설] |
|---|---|
| 레벨업 비용 | 기본(곡물12·목재8·철재6·인장2) + (현재 레벨−1)×(10·8·6·3) |
| 승급 조각 비용 | 단계별5 / 10 / 20 / 40 / 80 |
| 조각 획득 | 유효 클리어마다 출전 가신 각2, 사망0, 포기0 |
| 레벨 제한 | 가신 최대20과 대장간 상한 중 작은 값 |
| 승급 제한 | 최대5와 보유 조각 |

주입 경로는 별도 콘텐츠 사본이다. 무기/도구 피해, 영주 체력·이동, 농지/건설/모집 기간, 아군 피해·체력, 경험치 출처를 유한 배율로 바꾼다. 시작 레벨이나 시작 도구를 추가 보상으로 바꾸지는 않는다. 장원 잔고를 공격력으로 직접 바꾸지 않는다.

## 6. 20개 해금 도전

도전은 누적 지표와 기록소 연구 레벨을 함께 요구한다. 조건 달성 시 한 번만 자재·콘텐츠·가신을 지급한다. 잠긴 무기·도구·물품은 실제 카드·획득 풀에서 빠지고, 해금이 입력을 완성하면 관련 진화도 가능해진다. 기존 캐릭터의 시작 장비는 항상 열려 있다.

| 지표 | 현재 사용 의미 | 예시 목표 [가설] |
|---|---|---|
| 출정 | 최소 시간 이상 판 종료 수 | 1, 8 |
| 수확 | 누적 수확 횟수 | 10, 200 |
| 처치 | 누적 처치 수 | 100, 3,000 |
| 건물 | 종료 시 살아 있는 완성 건물 수 누적 | 10, 80 |
| 사람 | 종료 시 사람 구성원 수 누적 | 30, 300 |
| 클리어 | 전체 생존+보스 처치 판 수 | 2, 8 |
| 최고 챕터 | 클리어한 최고 챕터 | 3, 7 |
| 생존 시간 | 인정 판의 틱 합 | 54,000, 350,000 |
| 가신 레벨 | 강화로 도달한 최고 가신 레벨 | 5, 15 |
| 보스 | 포기하지 않은 판의 보스 처치 | 3, 10 |

v0.1의 “만드라고라500 수확”은 예시였으며 현재 지표는 작물 ID별 수확을 구분하지 않는다. 기록소 연구만 올려도 누적 목표가 부족하면 해금되지 않는다. 잠긴 가신은 조각 구매 없이 해당 도전으로 열린다.

## 7. 방치 생산·시간·저장

[구현] 호스트가 단조 초와 UTC초를 명시적으로 전달한다. 처음 관측은 기준만 세우고, 두 시간 차가 비음수이며 허용 오차120초 이내일 때만 단조 경과를 인정한다. 역행·재시작 불일치·벽시계 급변은 지급 없이 기준을 갱신한다. 인정 시간은 곡물창고 상한으로 자르며 10분 미만 나머지는 유한하게 보관한다.

[가설] 600초마다 곡물3·목재2·철재1·인장1을 요청한다. 지갑 상한은 동일하게 적용하고 장원이 자동 소비할 수 있다. 정상적 종료·재실행 사이의 실제 단조 시계 연속성은 호스트 검증 항목이다. 단순 UTC 경과만으로 무조건 보상하지 않는다.

현재 저장 버전은3이다. v1→v2에서 시계 기준을 초기화하고 v2→v3에서 완료 판 수를 이행한다. 바이너리 길이·SHA-256 체크섬·범위·참조를 검증하며 호스트는 임시 파일 완전 기록 후 원자적으로 교체하고 직전 정상본을 보존한다. 손상은 정상 백업으로 복구하고 알 수 없는 미래 버전은 자동 초기화하지 않는다. 체크섬은 우발적 손상 검출이며 파일 수정 공격 방지나 결제 영수증 검증이 아니다.

종료 정산은 `terminal.bin`에 정산 전·후 상태를 원자적으로 기록한 뒤 `progress.bin`을 교체한다. 저널 기록 뒤 진행 저장 교체 전에 중단되어도, 재실행 시 미정산 판과 정산 전 상태가 정확히 일치하면 정산 후 상태를 게시한다. 이미 게시된 순번은 다시 지급하지 않으며 같은 판의 결과를 바꾸는 재시도는 거부한다. 저널은 적용 뒤에도 남겨 멱등 복구에 사용한다. 진행 상태보다 앞선 저널이나 상태 불일치는 오류로 중단하고 초기화하지 않는다. 이는 단일 호스트의 정상 저장·복구 계약이며 변조 방지 서버 원장이 아니다.

## 8. 경제 시뮬레이션과 관문

아래 표는 성장/도전 보상 연쇄 처리 수정 전후에 동일한 관측이다. [경제 보고](../economy/sim-v0.md)의 보고 커밋 `658a384`는 소스 `b5c8524`에서 재실행한420판의 [정본 CSV](../economy/sim-v0.csv)가483행 전체에서 직전 파일과 바이트까지 같음을 기록한다. 표본은 21일 실제 Core 전투420판과 방치 청구63행, 총483행이다. 가벼움/보통/많이는 하루2/6/12판이며 유형당 가상 계정1개다. `mixed` 카드 봇·`circuit` 이동·사람규칙C로 최고 해금 챕터에 도전한다. 가신 공격→체력→ID 순 선택, 구매 가능한 강화·승급, 대장간 우선 깃발을 사용한다. 하루 한 번만 방치 수입을 청구하며 첫날은 설치 이전 보상을 주지 않는다.

각 판은 실제 투영 콘텐츠와27,000틱 정상 전투를 실행한다. 승패 확률·챕터 도달 정답표를 주입하지 않는다. seed는 `710000 + 유형번호×100000 + 일차×100 + 일중판수`다. 수정 전 관측 당시 데이터 동결 후 전420판을 다시 실행해 입력 파일 해시를 제외한483행의 전투·상태 해시와 경제 수치가 원관측과 일치했다. 경제 계수를 목표에 맞춰 변경하지 않았다.

| 유형 | 하루/전체 판수 | 챕터3 첫 시도 / 첫 클리어 | 챕터6 첫 시도 / 첫 클리어 | 챕터10 첫 시도 / 첫 클리어 | 최고 클리어 |
|---|---:|---|---|---|---:|
| 가벼움 | 2 / 42 | 3일 / 4일 | 18일 / 21일 | 미도달 / 미클리어 | 6 |
| 보통 | 6 / 126 | 2일 / 2일 | 3일 / 3일 | 12일 / 15일 | 10 |
| 많이 | 12 / 252 | 1일 / 1일 | 2일 / 3일 | 6일 / 7일 | 10 |

**수정 전·후 페이싱 관문: 실패. 지갑 상한·장부 보존: 통과.** 사전에 정한 도달은 ‘실제로 그 챕터를 처음 시도한 날’이다. 보통 목표는 챕터3 1~2일, 챕터6 5~9일, 챕터10 14일 이후이며 챕터6·10이 너무 이르다. 챕터10 클리어15일로 기준을 바꿔 성공 처리하지 않는다. [#126 결정 대기](https://github.com/hyunlord/bs-mobile/issues/126)는 첫 시도/첫 클리어 의미와 다음 후보의 채택 여부다.

**다음 후보 하나, 미적용:** 챕터4~6 적 체력 배율만10% 높인다(1210→1331,1380→1518,1550→1705). 챕터7의1720보다 낮은 순서를 유지하고 후반 피해·출현·자원 계수는 같이 바꾸지 않는다. 통과를 예측하지 않으며 승인 후 별도 이슈→PR→CI와 새 관측으로 비교한다.

병목은 중복되므로 합산하지 않는다. 보통 최종 최대 가신15레벨, 대장간5·기록소4·곡창4·병영4다. 많이 유형도 최대 가신15레벨이다. 해금 콘텐츠는 가벼움40/보통44/많이44개(전체48)다. 유형당 계정1개와 서로 다른 seed이므로 판수 차이의 인과 효과·모집단 생존율·리텐션을 주장하지 않는다. 하루6판을 모두 생존하면90분이므로 ‘보통’ 명칭도 아직 사용자 조사 없는 가설이다.

재생성은 `tools/meta-economy.sh`와 `tools/meta-economy-report.mjs`를 사용한다. 원관측·초기 실패는 덮어쓰지 않으며 전체 원시 JSON이나 CSV에서 재생성할 보고물을 중복 배포하지 않는다. 입력 해시·실행 바이너리·초기 시간 가정 실패의 정확한 provenance는 경제 보고에 보존한다.

## 11. 검증·전달 경계

P2는 Core 실행 효과·결정론·확장성·저장 왕복/이행/복구·경제 시뮬·메타 없는 기존 리그 (b)/c′를 각각 확인한다. 소스가 존재하는 것과 최종 CI가 통과한 것, Editor에서 읽히는 것, 사용자가 재미있다고 판단한 것은 다른 증거다.

[보류] [Fold7 M4 #98](https://github.com/hyunlord/bs-mobile/issues/98)은 사용자 재개 전까지 손대지 않는다. P4 맥 Release `phase2a-mac-play-02`는 별도 실행물이며 폴드7 성능·조작 관문을 대신하지 않는다. 사용자 후속 결정과 [ADR0035](../adr/0035-opt-in-native-mac-capture.md)에 따라 깨끗한 OS 계정·외부 클릭/캡처 관문은 앱 내부 `--autoplay-capture`로 대체한다. 화면 기록·손쉬운 사용 권한을 요청하지 않고 게임 자신의 화면만 저장한다. 빈 독립 저장/출력 경로에서 타이틀→정상 속도 한 판 생존·보스 처치→결산→재시작과 리플레이를 검증하며, 실패를 성공 화면으로 대체하지 않는다. 일반 실행에는 자동 조작·자동 종료를 적용하지 않는다. 사람이 클릭·키보드로 조작하는 검증은 사용자가 직접 맡는다.

새 네이티브 관문 [#129](https://github.com/hyunlord/bs-mobile/issues/129)은 아래 native03 증거로 통과했으며 P1 정상 Recorder 영상 [#113](https://github.com/hyunlord/bs-mobile/issues/113)도 아래 Recorder06 증거로 통과했다. Recorder는 Editor 증거이며 네이티브나 사람 입력 검증으로 확대하지 않는다. [#114](https://github.com/hyunlord/bs-mobile/issues/114)의 과거 OS 계정 미검증 기록은 보존하되 현행 차단 관문으로 유지하지 않는다.

보고는 관문 결과를 첫 줄에 적고 커밋·PR·CI 링크를 남긴다. 원자료는 필요한 Release 태그로 연결하고 CSV에서 재생성할 표·그래프를 중복 업로드하지 않는다. 이번 의뢰서의 예외는 맥 실행 앱 배포용 ZIP 하나이며 증거 ZIP·CRC·전달 영수증은 만들지 않는다.


Recorder03의 Editor 전용 MonoBehaviour 시작 거부와 이후 실패 기록은 보존한다. 최종 성공은 별도의 Recorder06 실행으로 판정하며 과거 실패를 성공으로 바꾸지 않는다.
