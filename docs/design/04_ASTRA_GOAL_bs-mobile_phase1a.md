# Astra 의뢰서 — bs-mobile 1단계 A: Unity 기반 + 회색 상자 한 판

작성 2026-10-08 · 기준 main `6220396` · 공통 규칙은 AGENTS.md 그대로(이슈 → PR → CI, 보고 첫 줄 관문 + 커밋·PR·CI 링크, ZIP 없음, needs-decision 이슈, Charter & Kin 커밋 금지).

## 목표
맥북 에디터와 **갤럭시 Z 폴드8 실기**에서 회색 도형으로 한 판(1년·4계절)을 처음부터 끝까지 할 수 있다. 사용자가 손으로 해 보고 "한 판 더"인지 판정할 수 있는 상태가 이번 목표다. 아이폰은 Xcode 준비가 끝나면 같은 빌드를 올린다(이번 관문 아님).

## 원칙
- **Core가 규칙, Unity는 화면.** 판 진행은 Core가 고정 틱으로 돌리고, Unity는 입력 전달·보간·그리기만 한다. Unity 쪽에 게임 규칙·수치를 새로 만들지 않는다.
- **정본은 하나.** Core 소스와 `data/` JSON을 복사본으로 두지 않는다. Unity가 쓰는 형태로 만드는 단계는 스크립트로 생성하고, 생성물은 커밋하지 않거나 생성됐음을 검사한다.
- 성능·판독성은 일회성 합격이 아니라 **상시 계측**으로 쌓는다.

---

## U0. 환경 확인 (먼저, 짧게)
- 에디터 6000.6.4f1, Android Build Support(OpenJDK·SDK·NDK), iOS Build Support 설치 여부를 확인한다. **Android 모듈이 없으면 여기서 멈추고 보고한다.** iOS 모듈과 Xcode가 없는 것은 진행을 막지 않는다.
- Unity CLI(batchmode)로 에디터를 띄울 수 있는지, 라이선스가 잡혀 있는지 확인한다.
- 폴드8이 USB 디버깅으로 연결돼 있으면 `adb devices`로 확인한다. 연결이 안 돼 있으면 사용자 할 일로 보고하고, 실기 단계 전까지 다른 작업을 진행한다.

## U1. 정리 (Unity 들어가기 전 부채 청산)
1. **무기 수치의 정본 하나**: 지금 무기 레코드의 `activation`과 `weapon-growth-79.json`의 레벨 1이 같은 값을 두 군데 갖고 있다. 성장표를 무기 레코드 안으로 넣든 레코드가 성장표를 참조하든 하나로 합치고, 이중 정의를 막는 스키마 검사를 추가한다. 레코드의 `form` 설명 문장도 바라보는 방향 부채꼴로 고친다.
2. **실험 파일 위치**: `data/` 최상위의 `tuning-s4b-01/02.json`, `weapon-growth-79.json` 같은 실험 이름 파일을 `data/experiments/`로 옮기고, 실제 게임이 쓰는 정본 설정이 무엇인지 한 파일(`data/tuning.json` + 정본 프로필)로 분명히 한다. 과거 리그 재현은 계속 되게 한다.
3. ADR로 기록한다.

## U2. Unity 프로젝트 기반
1. `unity/` 에 프로젝트 생성: URP Universal 2D, Force Text 직렬화, Visible Meta Files, `.gitattributes`(LFS 대상: 이미지·소리·바이너리), Unity용 `.gitignore`.
2. **Core 연결 방식**: Core를 Unity가 쓰는 방식을 정하고 ADR로 남긴다. 후보는 ① `core/` 소스를 가리키는 로컬 패키지(asmdef `noEngineReferences`) ② 빌드한 netstandard2.1 DLL을 생성 단계로 넣기. 어느 쪽이든 Core 소스 복사본이 생기면 안 된다.
3. **데이터 연결**: `data/` JSON을 빌드에 넣는 생성 단계(StreamingAssets 등). 기기에서 읽는 데이터의 해시를 디버그 화면에 표시한다.
4. **asmdef 경계**: `Game.View`(그리기), `Game.Input`, `Game.App`(부팅·씬), `Game.Debug`, `Tests.EditMode`, `Tests.PlayMode`. View가 Core 내부 상태를 고치지 못하게 한다.
5. **명령 하나**: `tools/check-unity.sh` — batchmode로 EditMode·PlayMode 테스트, Android IL2CPP 빌드까지. Unity 검사는 맥북 로컬에서 돌리고(라이선스 제약), GitHub Actions는 지금처럼 Core만 본다. PR 보고에 로컬 Unity 검사 결과를 붙인다.
6. **결정론 교차 검증**: 같은 seed·입력 기록으로 ① .NET CLI ② Unity 에디터(Mono) ③ Android 기기(IL2CPP)에서 한 판을 돌려 결과 해시가 같은지 확인한다. 다르면 원인을 찾는다(부동소수점, 정렬, 사전 순회 등).

## U3. 회색 상자 한 판
- **씬 셋**: Boot, Meta(시작 버튼과 설정만), Run. 나머지는 코드·데이터로 조립.
- **조작**: 한 손. 화면 아무 곳이나 누르면 그 자리에 생기는 떠다니는 조이스틱. 공격·도구 발동은 자동.
- **바라보는 방향**: 기본은 이동 방향. 검 허공 발동이 70%라 손맛이 나쁠 수 있으므로, Core 설정 값으로 "가까운 적 쪽으로 자동 조준"을 켤 수 있게 하고 디버그 메뉴에서 바꿀 수 있게 한다. 기본값은 사용자 플레이 후 정한다.
- **그리기**: 전부 도형. 적·투사체는 풀링 + 인스턴싱(적 하나에 GameObject 하나 금지). 고정 틱 사이 보간.
- **판독성 층**(01 P5): 적이 가장 진하고 대비가 크게 / 내 공격 반투명 / 아군 사람은 영주와 같은 색 테두리 / 익은 작물·완성된 건물만 반짝임 / 나머지 성장물은 바닥 층에 채도를 낮게. 경험치 구슬은 사냥과 수확 색을 다르게.
- **HUD 최소**: 경험치 바, 계절과 남은 시간, 영주 체력. 레벨업 시 판 정지 + 카드 3장(리롤·금지·고정 포함). 그 밖의 상시 패널 없음.
- **카메라**: 영주 추적, 영지가 커질수록 천천히 줌아웃(범위는 데이터). 화면 밖 위협은 가장자리 표식.
- **판 끝**: 결산 화면(생존 여부, 레벨, 경험치 출처 비율, 도구 대 무기 피해 비중). 다시 하기 버튼.
- **폴드 대응**: 판 도중 접기·펼치기를 해도 재시작 없이 카메라와 HUD가 다시 배치된다. 긴 세로 화면부터 정사각형에 가까운 화면까지 같은 판독성. 안전 영역(접힘부·카메라 구멍) 지키기. 가로 회전은 이번엔 고정(세로)으로 하고 ADR에 남긴다.

## U4. 디버그와 계측
- **디버그 오버레이**(개발 빌드만): seed, 틱, FPS, 프레임 시간, 개체 수(적·투사체·사람·밭 칸·건물), 데이터 해시. 시간 배속(×1·×2·×4), 레벨업 즉시, 무적, 적 출현량 조절.
- **입력 기록과 재생**: 판마다 seed + 입력 기록을 남기고, 그 기록을 Core 헤드리스로 재생해 같은 결과가 나오게 한다. 버그 보고는 이 기록 파일 하나로 재현한다. 기기에서 기록을 꺼내는 방법(adb pull 경로)을 런북에.
- **상시 성능 지표**: 기기 실행마다 프레임 시간 분포·최대 개체 수·기기 온도 상태(가능하면)를 남기고, 기존 지표 축적에 기기 축을 추가한다.

## 하지 않을 것
그림·소리, 메타(판 밖 성장), 광고·결제·분석 SDK, 서버, 추가 영웅·영지, 밸런스 리그 확대.

## 관문
1. `tools/check-unity.sh` 통과(EditMode·PlayMode·Android IL2CPP 빌드).
2. 결정론: .NET / Unity Mono / Android IL2CPP 세 곳에서 같은 기록의 결과 해시 일치(5 seed 이상).
3. 폴드8 실기: 판 막바지(적 최대 구간) 프레임 시간 p95가 16.7ms 이하(60fps)를 목표로 측정치 보고. 못 미치면 병목 위치와 개선안.
4. 폴드8 실기: 판 도중 접기·펼치기 각 3회 이상에서 멈춤·재시작·HUD 깨짐 없음. 접힘·펼침 각각 판 막바지 화면 캡처(adb screencap)를 PR에 첨부.
5. 입력 기록 하나를 기기에서 꺼내 헤드리스로 재생해 같은 해시.
6. **사람 판정은 사용자가 한다**: 설치 가능한 빌드와 "해 볼 것 목록"(바라보는 방향 두 방식 비교, 도구 위주 판 1회, 무기 위주 판 1회, 접기·펼치기)을 보고에 넣는다. 1단계 B(손맛 다듬기)는 사용자 피드백을 받은 뒤 따로 의뢰한다.

## 참고: 리그에서 넘어온 신호
- 혼합 정책이 세 묶음 모두 가장 낮다(0.74~0.84). 이 게임의 논지가 "무기와 도구를 섞는 것"이라 중요한 신호지만, 봇이 범주를 고르게 채우다 얇게 퍼지는 탓일 수도 있다. 이번엔 고치지 말고, 사용자 플레이 피드백과 함께 1단계 B에서 본다.
