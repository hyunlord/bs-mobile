# SLG 출시 로드맵

상태: **사용자 방향 결정 반영 / 상세 단계·담당 배분은 승인 대기**. 2026-10-30. 추적 [#549](https://github.com/hyunlord/bs-mobile/issues/549). 이 문서는 구현 완료 보고가 아니다. 신규 게임 코드·데이터·SDK·아트 제작은 이번 범위가 아니다. 문서 PR도 사용자 승인 전 병합하지 않는다.

## 방향과 기존 결정의 대체 범위

- [확정: 사용자 결정] 개발 우선순위를 서바이버 단독 게임에서 SLG로 옮긴다. 서바이버 판은 폐기하지 않고 영지·월드의 자원, 구역 회복, PvE 거점 상태를 실제로 바꾸는 직접 참전 수단으로 남긴다. 그림 다듬기는 중지한다.
- [확정] 직접 만드는 C# 서버가 정식 계정·월드 상태의 권위를 소유한다. 서버 아키텍처 ADR은 **Codex가 별도 작성**한다. 여기서 DB·호스팅·전송 프로토콜·배포 구조를 선결하지 않는다.
- [확정] 신규 정식 계정은 r8 지도 영지를 쓴다. 출시 전 실제 사용자 저장은 없다는 사용자 전제에 따라 개발 자동 장원 저장을 이관하지 않는다. 개발 저장은 개발 빌드에서만 읽는다. [#547](https://github.com/hyunlord/bs-mobile/pull/547)의 축소 ADR0076/GDD14와 효과 대응표를 따른다.
- [확정] 첫 출시에 월드맵을 포함하며 아래 출시 범위를 모두 통과해야 한다. 싱글 조각이나 서버 없는 빌드를 출시 완료로 부르지 않는다.
- [확정] 영웅 수집과 확률 공개·천장이 있는 영웅 뽑기를 설계한다. 과거 추가 영웅·서버·PvP 제외는 이번 승인 범위에서 대체한다. 뽑기 금지의 대체 범위는 **영웅**이며 가신·가신 조각·판 안 능력 직접 판매를 함께 허용한 것은 아니다. 자원·성장 가속 허용과 전투 효과 상한은 유지한다.
- 현행 소스·역사 프로필·리플레이와 골든을 그대로 보존한다. 새 규칙에는 명시적인 규칙/콘텐츠/재생 계약이 필요하다. [기술 GDD](../design/gdd/11-technology.md)의 Core/Unity 경계는 유지하며 서버 I/O를 순수 Core 안으로 넣지 않는다. [#122](https://github.com/hyunlord/bs-mobile/issues/122)의 SDK 보류는 별도 구현 승인 전 유지한다.

## 개발 순서와 끝나는 기준

표의 번호는 작업 순서다. 게임 밸런스·용량·시간 목표 수치는 모두 **[가설]**이며 실제 측정 후 조정한다. 담당 배분은 작업 제안이고 다른 담당자가 실행했다고 주장하지 않는다. 각 단계의 실행 PR·CI·빌드·실측 결과를 종료 증거로 연결하며, 문서 승인만으로 완료 표시하지 않는다.

| 단계 | 범위 / 끝나는 기준 | 의존 관계 | 담당 제안 |
|---|---|---|---|
| ① 싱글 수직 조각 + 실제 휴대폰 빌드 | 타이틀→첫 판→귀환 r8→첫 공사→병력 준비→다음 출정이 한 흐름으로 작동. 승인된 UI를 실제 화면에서 확인. 설치 가능한 휴대폰 빌드에서 정상 플레이·앱 중단/재접속·터치/판독을 검증. 한 번의 성공적 판 결과가 지정 영지 구역 또는 건설 자원에 반영되고 반복 수령되지 않음을 관측 | 현재 구현 결과와 승인 UI, 축소 #547, 병력 GDD 최소 루프. 서버 전에는 분리된 개발 계정 adapter로 검증하며 정식 저장/경제로 승격·이관하지 않음 | Codex: Core·영지/판 연결과 통합. | ③ SLG 핵심 루프 | 병력 훈련→영웅/가신 편성→직접 전투→부상/치료→영지 생산/연구→다음 출정이 서버 계정에 일관되게 남음. 각 승인 GDD의 보존식·cap·시간/비용·중복 처리 관문 통과. 영웅 모집은 먼저 비결제 검증 경로, 실판매는 ⑥ 관문 전 금지 | ② 계정 권위 + 병력→영웅→연구 GDD 순차 승인. 월드 상태 변경은 ⑤에서 완성하며 ③의 전투 결과 계약을 재사용 | Astra: GDD·경제/UX 검토. Codex: Core·서버 명령·Unity 연결. Claude Code: 정상/최대 계정 회귀·리플레이·기기 검증 |
| ④ 서버 운영 + 연맹 | ② 서버 위에서 생성/가입/탈퇴, 채팅, 도움 가속 완성. 권한·신고/차단/속도 제한, 중복 도움·탈퇴/재가입 우회·완료 작업 가속 방어 검증. 여러 계정 동시 사용과 배포/복구/관측 흐름 확인 | ②·③, 월드 GDD의 연맹/가속 계약. 타일과 무관한 연맹 기능을 먼저 완성. 연맹 영토는 포함하지 않음 | Codex: 서비스·권한·도움 원장. Claude Code: 다계정/운영·채팅 악용 검증. Astra: 연맹 UX·사회 규칙 |

| ⑥ 출시 준비 | 실제 휴대폰에서 신규→SLG 성장→행군→직접 PvE→귀환→연맹 도움의 완전 흐름, 정상 사용자/최대 상태 성능, 서버 용량·장애 복구·고객지원 관문 통과. 계정 삭제/개인정보/채팅 운영, 스토어 정책·출시 국가, 영웅 확률·천장·결제 복구를 확인. 출시 체크리스트에 증거와 미해결 차단 항목 없음 | ①~⑤ 전부, BM/상점 별도 승인과 법무/스토어 확인. 신규 그림 제작은 실제 화면 검토에서 필요가 입증되고 다시 지시받을 때만 | Codex: 결함·운영/보안 보완. 의존 그래프: **① → ② → ③ → ④ → ⑤ → ⑥**. GDD 작성과 서버 ADR 조사는 선행 가능하다. 검증 가능한 작은 기능 조각을 먼저 연결하되 앞 단계의 종료 증거 없이 뒤 단계를 완료로 표시하지 않는다. 일정·인원/동접 목표는 아직 약속하지 않는다.

실기 ①는 필수지만 기존 [#98](https://github.com/hyunlord/bs-mobile/issues/98)의 특정 Fold7 연결/조작 보류를 이 문서 작성으로 해제하지 않는다. 후속 구현 착수 시 사용할 기기와 보류 해제를 명시해야 하며, 확보 전에는 설치 빌드까지만 전달하고 실기 관문은 미통과로 둔다. CI·Editor·Mac 측정을 휴대폰 관측으로 대체하지 않는다.

## 첫 출시 범위와 출시 후

| 첫 출시 필수 | 명시적 경계 |
|---|---|
| 서버 하나의 타일 월드 | 개인 r8 영지 좌표와 공유 월드 좌표는 별도 공간/ID. 서버간 이동·전쟁 없음 |
| 자원지와 채집 행군 | 서버 예약/도착/채집/귀환 상태, 적재량·병력·자원 보존과 경합 처리 |
| PvE 몬스터·거점 | 직접 서바이버식 참전 가능. 서버가 발급한 대상/전투 계약에 따른 검증된 결과만 반영 |
| 정찰·공격·보호막 | 정보 공개 범위, 착수/도착 시점 보호 규칙, 피해/약탈·회복 경로와 초보 보호를 월드 GDD에서 검토 |
| 연맹 생성·채팅·도움 가속 | 중복 도움 금지, 작업별 단축 하한과 동시 처리, 신고/차단/권한. 정치/영토/서버 통합 기능으로 확장하지 않음 |
| 출시 후 | 연맹 영토, 서버전, 시즌. 기존 시즌 패스 후보가 월드 시즌 구현 승인인 것은 아님 |

## 서바이버 판이 SLG를 바꾸는 공통 계약

[설계 제안] 출정 전 서버가 계정·군대/영웅·가신·연구 snapshot, 규칙/콘텐츠 버전, 대상 타일/거점 세대, 보상/손실 정책을 묶은 전투 계약을 발급한다. 순수 Core에는 확정 입력을 주입한다. 클라이언트가 보낸 승리/자원 숫자를 그대로 저장하지 않는다. 검증 실행 위치와 부정행위 대응은 Codex 서버 ADR의 필수 결정이다. format7/8의 기존 바이트를 변경해 조용히 새 데이터를 끼우지 않는다.

검증된 완료 ID 하나로 부대 귀환/부상, 허용 자원, 개인 구역 회복 자격, 공유 거점 상태를 일관되게 정산한다. 불명확한 정산은 확정 조회가 끝나기 전 다시 지급하지 않는다. 개인 r8는 유한한 승인 구역/인접 조건을 쓰며 월드 타일을 무한 복제해 영지를 늘리지 않는다. 공유 타일 점유와 개인 회복 보상은 별개다. 실패/재접속/대상 소멸/승인 지연에도 결과를 중복 적용하지 않는다.

각 GDD는 이 공통 경계를 해당 시스템의 구체 입력·결과·cap·UI로 내린다. 단순 보너스 설명만 있고 땅/군대/자원/거점 변화의 증거가 없는 구현은 차별점 관문을 통과하지 못한다.

## 문서 PR 순서와 서버 ADR 인계

1. 축소 [#547](https://github.com/hyunlord/bs-mobile/pull/547): 신규 r8·서버 정본, 개발 저장 이관 제외, 장원 효과 대응 유지. 이전 승인/06시 예약 병합은 새 범위 승인 대기로 대체한다.
2. 이 로드맵 [#549](https://github.com/hyunlord/bs-mobile/issues/549).
3. 병력 [#550](https://github.com/hyunlord/bs-mobile/issues/550) → 영웅 [#551](https://github.com/hyunlord/bs-mobile/issues/551) → 연구 [#552](https://github.com/hyunlord/bs-mobile/issues/552) → 월드 [#553](https://github.com/hyunlord/bs-mobile/issues/553). 각각 별도 문서 PR이며 가설/의존/미구현을 표시한다.

서버 ADR에 넘기는 필수 질문: 계정/월드의 명령 직렬화·소유권(로컬 단일 writer를 그대로 서버 전체 lock으로 옮기지 않음), 저장 원자성/복구 세대·백업·배포 롤백, 장애 주입·재시도/중복 요청, 서버 시간과 예약 완료, 전투 결과 검증, 군대·행군·보상 동시 갱신, 인증/권한·채팅 악용·모니터링, 운영 비용과 목표 용량. 로컬 v6 유지가 서버 스키마 고정이라는 뜻은 아니다. 데이터베이스·큐·오케스트레이션·서버 프레임워크는 이 문서에서 임의 채택하지 않는다.

설계 PR 검증은 문서 링크·형식·범위와 상호 불변량 검토다. 실제 서버·핸드폰·경제 시뮬·재생/장애 실험은 **NOT_RUN**이며 각 구현 단계에 남긴다.
