# A 기사: 독립 프레임 그림 시제품 (#256)

**상태: 사용자 영상 검토 대기.** 사람 손으로 그린 원화라고 주장하지 않는다. OpenAI imagegen으로 각 자세를 독립적으로 생성한 프레임 그림이다. 기존 관절 리그·부위 잘라 붙이기·리그 베이크는 사용하지 않았다. 참고는 사용자 `heroes.png` 왼쪽 A(성인 금발 개척 기사)다.

## 재생성

```sh
swift tools/art-authoring/hero-a-frames/assemble.swift artifacts/m1-256/authoring/hero-a-frames artifacts/m1-256/frames
```

입력은 `source/`의 투명 PNG다. 조립기는 정확한 RGBA 복사와 프레임 전체의 정수 좌표 이동만 한다. 그림 편집, 관절 변형, 프레임별 확대·축소는 하지 않는다. 원본 발바닥 높이가 달라 공통 발 기준선으로 정렬한다. 머리·망토·다리의 실제 그려진 차이는 남는다.

## 범위와 계약

- 걷기: S, SE, E, NE, N 각각 8개 자세 = 40개 독립 그림. W/SW/NW는 E/SE/NE 전체 프레임의 런타임 좌우 반전이다. 검 쥔 손과 비대칭 장비도 반전된다. 이를 독립 8방향 원화로 세지 않는다.
- 검 휘두르기: E 8개 자세, W는 반전. 다른 방향 공격은 이번 그림 세트에 없다. 서기는 각 방향 걷기 첫 프레임을 정지해서 쓰는 대체이며, 독립 idle 원화로 세지 않는다.
- 총 48개 채택 후보 자세. 각 걷기 8fps, 1초 반복. 공격은 8fps, 1초 1회 재생 후보다. 최종 속도·동작 수락은 게임 영상 검토 대상이다.
- `manifest.json`: 행 우선, 위에서 아래 순서. `bodyHeightPixels`는 방향/클립의 고정 성인 서기 기준이다. 공격에서 몸을 숙였다고 프레임 bbox에 맞춰 크기를 늘리면 안 된다.
- `frame-landmarks.json`: 알파 128 이상 bbox 실측, 프레임 전체 이동량, 발 기준선, 머리 꼭대기(머리카락 포함)·턱 위치의 수동 근사 주석. 쇄골/칼라와 머리카락 끝을 헷갈리지 않도록 ±몇 픽셀의 판독 오차를 인정한다. 자동 정밀 해부학 판정이 아니다.
- 고정 머리/몸 비율: E 63/436=.1445, S 62/443=.1400, SE 62/455=.1363, NE 62/441=.1406, N 64/475=.1347, 공격 32/214=.1495. 목표1/7±10% 안인 후보다. 구부린 개별 자세의 bbox 비율을 성인 비율로 재해석하지 않는다.
- 알파 픽셀 손실 검사는 조립 때 0이어야 한다. 런타임 Texture Filter는 Bilinear, Wrap Clamp 권고. Unity 임포트/네이티브 재생은 부모 통합 작업이다.

## 채택하지 않은 생성물

- `slash-light-e.png`: 첫 4×2 공격 시트. 검이 셀 경계를 넘어가고 오른쪽 날이 잘렸다. `slash-light-e-v2.png`의 넓은 2×4 셀로 대체했다.
- `walk-n.png`, `walk-n-v2.png`: 아래 줄에서 검 쥔 손이 바뀌었다. 재수정에도 남아 보존하며, `walk-n-v3.png`에서 8자세 오른손 일관성을 다시 확인했다.
- SE 아래 줄은 위 줄보다 정면에 가깝고, S의 무릎 들기가 크다. 정지 시트만으로 자연스러운 걷기를 통과 처리하지 않는다. 네이티브 연속 재생에서 방향 전환·발 미끄러짐·프레임 간 형태 흔들림을 사용자에게 보여 준다.

## 제작 비용

2026-10-12 12:08:14–12:26 UTC (KST21:08–21:26), 약18분 경과. 이미지 생성 대기와 병렬 생성, 검수·추출·재시도 포함의 벽시계 시간이며 전문 원화가 작업시간이 아니다. 채택5방향 걷기+공격1시트, 실패3시트, 사용하지 않은 투명배경 추출 재시도1건이 있었다.

**추정**: 같은 영웅의 무기 유형1개 추가는 최소 방향별 공격8프레임×5방향=40개 신규 그림과 기존 걷기에서 무기 모양 재작업/검수까지 필요하다. 이번 1방향 검만의 생성속도를 근거로 최종 품질 인시를 확정하지 않는다. AI 시제품은 30–90분/무기형 범위를 계획 가설로 둘 수 있으나, 방향·형태 일관성 재시도에 따라 늘어난다. 직접 관절을 재사용하는 제작비와 별도로 비교해야 한다.

## 투명 배경 검증 (추가)

일부 이미지 뷰어는 alpha=0인 픽셀의 숨겨진 RGB를 표시해 파랑/갈색 연무 사각형처럼 보인다. 이를 실제 배경으로 오인하지 않도록 `check-alpha.swift`로 RGBA SourceOver 합성을 직접 수행했다. 6개 아틀라스 모두 `artifacts/m1-256/frames/*-checker.png`의 불투명 자홍/녹색 체크 배경에서 사각형 연무가 없는 것을 확인했다. E 첫 셀 내부 배경 (100,100), (350,100), (380,250)은 alpha=0, (400,100)은1/255다. 원본 아트는 재생성하거나 수정하지 않았다.

```sh
swift tools/art-authoring/hero-a-frames/check-alpha.swift artifacts/m1-256/frames/walk-e-atlas.png artifacts/m1-256/frames/walk-e-checker.png
```

alpha=0 픽셀: E2,042,709 / S2,040,003 / SE1,986,911 / NE2,048,723 / N2,006,691 / slash2,522,177. 모든 시트의 캐릭터 내부 최대 알파도254로 생성되어 alpha=255 개수는0이다. 이것은 배경이 불투명하다는 뜻이 아니다. 체크 PNG와 제작 스크립트는 진단용이며 게임 아틀라스가 아니다.

## 원본 비율 우선 수정 (ratio-v2)

초기 1:7 목표와 원본 A 실측은 달랐다. 원본 왼쪽 정면 A의 머리카락 꼭대기15 / 턱68 / 부츠456 픽셀: 머리53 / 몸441 = .1202(8.32등신). 초기 E 그림 .1425와 3D revision5 .1452는 원본 대비 +18.6%, +20.8%로 ±10%를 벗어났다. 원판정은 `proportion-measurements-original-failure.csv`에 보존한다.

부모 지시에 따라 원본±10%를 우선하여 imagegen으로 머리만 작게 다시 그렸다. 걷기 E 수정본 실측 crown46/chin101/sole477 →55/431=.1276(+6.2%). 공격 첫 자세는56/81/249 →25/193=.1295(+7.8%). 목 연결을 확대해 확인했다. 수동 판독 약±2px의 불확실성이 있고 숫자 통과가 동작·아트 승인은 아니다. S 최종 첫 자세50/104/488→54/438=.1233; NE/N은 턱이 가려져 뒤통수/목 경계가 대용 주석이므로 정확한 턱 실측 통과를 주장하지 않는다.

```sh
swift tools/art-authoring/hero-a-frames/assemble-ratio-v2.swift artifacts/m1-256/authoring/hero-a-frames artifacts/m1-256/frames/ratio-v2
```

새 native 입력은 `artifacts/m1-256/frames/ratio-v2/manifest.json`. 기존 manifest와 소스는 수정하지 않았다. S는 여러 수정에서 머리가 거의 줄지 않아 더 강한 축소 요청 후 v4를 채택 후보로 만들었다. 공격 머리 수정 후 셀 경계를 넘은 실패도 보존하고, v5에서 전신을 셀 안 여유 공간에 다시 배치했다. 공격 authored body193px는 클립 전체 고정이며 프레임마다 확대하지 않는다. 공격 그림은 수정 과정에서 채도가 더 높아져 걷기와의 스타일 일관성은 영상 검토가 필요하다.

최초 생성 시작12:08:14UTC부터 비율 수정 완료12:51UTC까지 전체 경과 약43분이다. 병렬 생성·소스 동결 대기·진단 시간이 포함되며, 추가 수정 순수 작업시간은 별도 계측하지 않았다. 전문 원화 인시로 해석하지 않는다. `proportion-measurements-ratio-v2.csv`는 실제 그림 주석, `playback-manifest-ratio-v2.json`는 재생 설정이다. 둘을 혼동하지 않는다.

## 큰 원화의 보관

저장소의 PR 5MB 상한을 지키기 위해 원본 PNG는 `artifacts/m1-256/authoring/hero-a-frames/source/`에 보존한다. 재생성 CSV가 아닌 원화이므로 선택된 제작 원본은 Release 개별 자산으로 전달한다. 조립기·작은 manifest·실측 CSV만 Git에 둔다. 실패 원본도 로컬에서 삭제하지 않는다.
